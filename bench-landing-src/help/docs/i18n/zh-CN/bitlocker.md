# BitLocker

BitLocker 会检查驱动器加密、保护器和恢复信息，然后帮助你备份、保护或更改驱动器。它仅在此计算机上工作。

操作指南：[使用 BitLocker 加密驱动器](encrypt-with-bitlocker.html)。

## 使用 BitLocker 工具

选择驱动器号和一项 **操作**，然后按 **运行诊断**。

- **检查** 读取加密状态、保护状态和保护器标识。这是默认操作，不会更改任何内容。
- **备份恢复信息** 将所选的恢复密码写入受保护驱动器之外的新文件并进行验证。请先按 **查找恢复保护器**，选择保护器，然后确认备份。
- **加密** 备份所选的恢复密码，验证备份，然后使用你选择的方法开始一次加密。Windows 驱动器需要 TPM 保护器和恢复密码。数据驱动器只需要恢复密码。
- **恢复保护** 会为保护已暂停的完全加密驱动器重新开启保护。

以上每项操作都需要其单独的确认框，并且 KillerBench 会在执行前立即重新检查驱动器。

## 更多 BitLocker 操作

对于 **运行诊断** 之外的更改，请打开 **更多 BitLocker 操作**。选择一项操作，按 **预览** 查看其确切要求，然后确认并按 **运行操作**。

- **启用自动解锁** 可以让已加密的数据驱动器在 Windows 启动时解锁。Windows 驱动器必须已完全加密且保护已开启。
- **添加 TPM 保护器** 或 **添加恢复密码** 会创建一个新的保护器。KillerBench 绝不会显示或记录新的恢复密码，因此请立即备份。
- **将恢复密码备份到 Active Directory** 或 **Microsoft Entra ID** 会发送你在上方选择的保护器。KillerBench 会报告 Windows 已接受请求。它无法读取目录中的副本，因此请在那里确认。
- **解密此驱动器** 会开始解密，例如在使用所需方法重新加密之前。由于驱动器在之后将不受保护，因此需要第二次确认；当其他驱动器正从 Windows 驱动器自动解锁时，它会拒绝对 Windows 驱动器执行此操作。

## TPM 和 FIPS

如果 TPM 存在但尚未就绪，安全分区可以在不清除的情况下准备它。KillerBench 绝不会清除 TPM，因为这会销毁 BitLocker 和 Windows Hello 持有的密钥。FIPS 算法策略开关作为明确且可撤消的修复提供，适用于需要符合 FIPS 的 BitLocker PIN 的组织。

## 本分区的工具

检查加密、保护器和恢复信息，然后备份它们或保护驱动器。

### BitLocker

预览 BitLocker 选项并检查所选卷。此工作流程不会执行加密或恢复备份。
