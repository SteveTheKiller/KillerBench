# ネットワーク

ネットワークでは、接続、DNS、ルート、ワイヤレスと有線のサインイン、ファイル共有、リモート アクセスを確認します。ほかのホストに接続するツールは設定したターゲットとタイムアウトを使い、修復を承認しない限り何も変更されません。

手順ガイド: [ネットワークとインターネットの問題を解決する](fix-network.html)。

## このセクションのツール

接続、DNS、ルート、ワイヤレス、共有、リモート アクセスを確認します。

### ネットワーク

アダプター、アドレスの状態と取得元、ゲートウェイ、DNS の構成、有効な DNS 名前空間ポリシー、TCP の設定、ネイティブの Winsock プロトコルと名前空間プロバイダーのカタログ構造、IP ルーティング テーブル、Hosts ファイルの対応付けを確認します。自動修復では、有効な DNS Client、DHCP Client、SMB クライアント、Network Location Awareness、Network List、IP Helper の各サービスを開始でき、使用可能な IPv4 アドレスがない接続済みの物理 DHCP アダプターのリースを更新できます。ネットワーク識別サービスを開始すると、ネットワークの識別が再計算され、別の既存のファイアウォール プロファイルが適用される場合があります。IP Helper によって、既存の IPv6 移行、ポート プロキシ、ネットワーク通知の機能が有効になる場合があります。サービスの回復で検証されるのは実行中の状態であり、名前解決の成功、ルートの選択、ネットワークの識別、トンネルの動作は検証されません。ルート、Hosts のエントリ、DNS サーバー、プロファイル、ファイアウォール規則、Winsock プロバイダー、移行の構成、スタートアップの種類、ポリシーは保持されます。更新によってリースされたアドレスが変わり、接続が中断される場合があります。静的な設定と仮想アダプターは保持されます。ゲートウェイからの正確な ICMP 応答は、インターネットへの到達を検証するものではありません。

### ワイヤレス ネットワーク

ネットワーク デバイスと WLAN AutoConfig の可用性を確認します。オプションの回復では、依存関係を確認した後で、有効かつ停止しているサービスのみを開始します。保存済みのプロファイルが自動的に再接続する場合があります。プロファイル、資格情報、ポリシー、無線の設定、スタートアップの種類は保持されます。アダプターのリセットやドライバーのインストールは行いません。検証の対象は実行中の状態で、ワイヤレス認証や接続は含まれません。

### 有線認証 (802.1X)

802.1X が必要なネットワーク向けに、ネットワーク デバイスと Wired AutoConfig を確認します。オプションの回復では、依存関係を確認した後で、有効かつ停止しているサービスのみを開始します。既存の認証プロファイルが有効になり、ネットワーク アクセスが変わる場合があります。証明書、資格情報、プロファイル、ポリシー、スタートアップの設定は保持されます。検証の対象は実行中の状態のみで、認証や接続は含まれません。

### ネットワーク接続

現在のネットワーク プロファイルの割り当て、サービスの正確な障害履歴、ネットワーク接続サービスの現在の準備状態を、範囲を限定して確認します。不完全な証拠が優先されます。パブリック プロファイルや過去の障害は参考情報にとどまり、回復やネットワークの変更が許可されることはありません。オプションの回復では、新たな依存関係チェックの後で、有効かつ停止している対象のサービスのみを開始します。既存のネットワーク管理インターフェイスが再開する場合があります。アダプター、アドレス、ルート、DNS の設定、接続プロファイル、資格情報、ファイアウォールの構成、ポリシー、スタートアップの種類は保持されます。接続やネットワークの設定は変更されません。検証の対象はサービスの安定した状態のみで、アダプターの動作、アドレスの割り当て、ルーティング、名前解決、接続は含まれません。

### WinHTTP 自動プロキシ

保存された WinHTTP の既定値、現在のアカウントのインターネット設定、サービスの正確な障害履歴、WinHTTP 自動プロキシの現在の準備状態を確認します。不完全な証拠が優先されます。プロキシの構成や過去の障害によって、サービスの回復や検出が許可されることはありません。停止している手動開始のサービスは正常な場合があります。このツールを選択した場合に限り、オプションの回復では、新たな依存関係チェックの後で、停止している有効なサービスのみを開始できます。既存のアプリケーションが、現在の設定で WPAD または PAC の検出を再開する場合があります。プロキシの定義、PAC URL、資格情報、ネットワークの設定、ファイアウォールの構成、ポリシー、サービスのアクセス許可、スタートアップの種類は保持されます。URL の取得や、プロキシとネットワークの設定の変更は行いません。検証の対象はサービスの安定した状態のみで、検出、到達性、認証、ポリシーの所有、アプリケーションによる使用は含まれません。

### Windows 接続マネージャー

現在のネットワーク プロファイルの割り当て、サービスの正確な障害履歴、Windows 接続マネージャーの現在の準備状態を、範囲を限定して確認します。不完全な証拠が優先されます。パブリック プロファイルや過去の障害は参考情報にとどまり、回復や接続の判断が許可されることはありません。オプションの回復では、新たな依存関係チェックの後で、有効かつ停止している対象のサービスのみを開始します。Windows が、既存のプロファイルとポリシーに従って自動接続の判断を再開する場合があります。アダプター、プロファイル、資格情報、従量制課金、コスト、ローミング、ファイアウォール、VPN、認証の設定、スタートアップの種類は保持されます。プロファイル、アダプター、設定は変更されません。検証の対象はサービスの安定した状態のみで、プロファイルの適用可能性、接続の選択、認証、ルーティング、名前解決、接続は含まれません。

### ネットワーク セットアップ サービス

現在のアダプターのプロトコル バインド、サービスの正確な障害履歴、ネットワーク セットアップ サービスの現在の準備状態を、範囲を限定して確認します。不完全な証拠が優先されます。バインドの状態や過去の障害によって、サービスの回復やセットアップの変更が許可されることはありません。オプションの回復では、新たな依存関係チェックの後で、有効かつ停止している対象のサービスのみを開始します。保留中の既存のネットワーク セットアップが、Windows のポリシーに従って再開する場合があります。アダプター、ドライバー、ドライバー パッケージ、バインド、アドレス、ルート、DNS の設定、プロファイル、資格情報、ファイアウォールの構成、ポリシー、スタートアップの種類は保持されます。KillerBench は、ドライバーや構成の変更を選択しません。検証の対象はサービスの安定した状態のみで、アダプターの可用性、ドライバーの適合性、セットアップの完了、アドレスの割り当て、ルーティング、名前解決、接続は含まれません。

### ファイル共有 (SMB)

Windows の SMB サーバーの可用性を確認します。オプションの回復では、新たな依存関係チェックの後で、有効かつ停止している Server サービスのみを開始します。既存のファイル共有とプリンター共有が、現在のアクセス許可とファイアウォール ポリシーのもとで利用可能になる場合があります。共有、アクセス許可、SMB の設定、ファイアウォール規則、資格情報、ポリシー、スタートアップの種類は変更されません。検証の対象はサービスの安定した状態のみで、クライアントのアクセスやファイル転送は含まれません。

### リモート アクセス接続マネージャー

シークレットを収集せずに、現在のアカウントの VPN プロファイルの構成、サービスの正確な障害履歴、リモート アクセス接続マネージャーの現在の準備状態を、範囲を限定して確認します。一覧が空なのは意図的な場合があり、プロファイルの存在、接続のラベル、過去の障害によって、回復や接続の試行が許可されることはありません。オプションの回復では、新たな依存関係チェックの後で、有効かつ停止している対象のサービスのみを開始します。既存のダイヤルアップと VPN の要求が再開する場合があります。接続プロファイル、資格情報、ルート、アダプター、認証の設定、ポリシー、スタートアップの種類は保持されます。接続は開始されません。検証の対象はサービスの安定した状態のみで、プロファイルの適用可能性、サーバーへの到達、認証、トンネルのネゴシエーション、ルートのインストール、名前解決、接続は含まれません。

### リモート デスクトップ サービス

ローカルのリモート デスクトップの有効化、ネットワーク レベル認証とリスナー ポート、範囲を限定した接続とセッションの履歴、サービスの正確な障害履歴、サービスの現在の準備状態を確認します。不完全な証拠が優先されます。過去の記録によって、サービスの回復や構成の変更が許可されることはありません。オプションの回復では、新たな依存関係チェックの後で、有効かつ停止している対象のサービスのみを開始します。既存のリスナーが、現在のポリシー、NLA、ファイアウォール規則、アクセス許可のもとで到達可能になる場合があります。リモート デスクトップの有効化、リスナー、証明書、ポート、ファイアウォール規則、NLA、アクセス許可、セッション、ポリシー、サービスのアクセス許可、スタートアップの種類は保持されます。リスナー、ファイアウォール規則、アカウントのアクセス、証明書、セッションの作成や変更は行いません。検証の対象はサービスの安定した状態のみで、有効なポリシー、リスナーのバインド、ファイアウォール経由のアクセス、証明書の識別、アクセス許可、認証、ネットワークの到達性、接続の成功、セッションの作成は含まれません。

### Windows リモート管理

範囲を限定した WinRM リスナーの構成、動作履歴、サービスの正確な障害履歴、サービスの現在の準備状態を確認します。不完全な証拠が優先されます。無効なリスナーや現在のサービスの懸念がある場合は確認が求められますが、過去の記録によって回復や構成の変更が許可されることはありません。オプションの回復では、新たな依存関係チェックの後で、有効かつ停止している対象のサービスのみを開始します。既存の WS-Management リスナーが、現在の認証、証明書、ファイアウォール、TrustedHosts、ポリシーの設定のもとで到達可能になる場合があります。リスナー、アドレス、ポート、証明書、認証、暗号化、TrustedHosts、ファイアウォール規則、アクセス許可、クォータ、ポリシー、サービスのアクセス許可、スタートアップの種類は保持されます。リスナー、ファイアウォール規則、信頼のエントリ、証明書、資格情報、リモート セッションの作成や変更は行いません。検証の対象はサービスの安定した状態のみで、有効なポリシー、リスナーのバインド、ファイアウォール経由のアクセス、証明書の有効性、認証、アクセス許可、クライアントからの到達性、リモート コマンドの実行は含まれません。
