# Knowledge generator tooling

This contains a standalone reviewed-JSON catalog builder, a reviewed reference CSV importer, IEEE MAC-assignment, UEFI PNP and ACPI vendor ID, Bluetooth SIG company identifier, pci.ids, usb.ids and Microsoft bug-check reference importers, a reviewed driver-reference CSV importer and installed Windows Win32, NTSTATUS and HRESULT message-table generators for Engine consumers. Other source-specific importers are not implemented yet.

Successful builds report SHA-256 fingerprints for the exact input and normalized output, plus output byte length. Retain these with the reviewed source revision when preparing pack updates. Fingerprints identify bytes; they do not establish source trust, licensing, signatures or factual accuracy.

Run `dotnet run --project Tools/Knowledge/KillerBench.KnowledgeBuilder.csproj -- REVIEWED_JSON NEW_OUTPUT_JSON` from the KillerBench directory. Both files use the documented knowledge schema. The builder validates input, sorts entries by context/code, validates normalized output and creates a new unsigned file. Existing output files are never overwritten. It does not fetch vendor data, validate factual accuracy, sign or publish. An interrupted output must not be published; rebuild to a fresh path.

For read-only schema validation, run `dotnet run --project Tools/Knowledge/KillerBench.KnowledgeBuilder.csproj -- --check REVIEWED_JSON`. This creates no output and does not verify signatures or factual accuracy. Exit codes are 0 for success, 1 for validation or I/O failure, 2 for incorrect argument count, and 130 for user cancellation.

To build a MAC-vendor reference pack from retained IEEE MA-L, MA-M and MA-S CSV snapshots, run `dotnet run --project Tools/Knowledge/KillerBench.KnowledgeBuilder.csproj -- --ieee-oui OUI_CSV MAM_CSV OUI36_CSV REVISION YYYY-MM-DD "LICENSE" NEW_OUTPUT_JSON`. Use the official files from `https://standards-oui.ieee.org/oui/oui.csv`, `https://standards-oui.ieee.org/oui28/mam.csv` and `https://standards-oui.ieee.org/oui36/oui36.csv` in that order. The date records when the retained snapshots were reviewed. The importer requires the IEEE Registry, Assignment and Organization Name columns, validates registry-specific prefix lengths, rejects malformed or duplicate assignments, and emits the `ieee-mac-vendors` pack with `mac-vendor` context. It excludes organization addresses.

The importer does not download source files, establish their revision, determine redistribution rights, verify organization accuracy, sign output or publish it. Record the exact source hashes printed by the tool, retain the source acquisition evidence outside the repository, and confirm the license text and redistribution terms before a generated pack is distributed. Existing outputs are never overwritten.

To build firmware and legacy device vendor references from retained UEFI Forum registry CSV snapshots, run `dotnet run --project Tools/Knowledge/KillerBench.KnowledgeBuilder.csproj -- --uefi-vendor-ids PNP_CSV ACPI_CSV REVISION YYYY-MM-DD "LICENSE" NEW_OUTPUT_JSON`. Obtain the complete CSV exports from the official [PNP ID registry](https://uefi.org/PNP_ID_List) and [ACPI ID registry](https://uefi.org/ACPI_ID_List). The importer requires the Company, matching ID and Approved On Date columns, accepts documented three-letter PNP and four-character ACPI vendor IDs, validates every approval date, rejects duplicate contextual identities and emits the `uefi-pnp-acpi-vendors` pack with separate `pnp-vendor` and `acpi-vendor` contexts. A source row with no company name remains explicit instead of being discarded or assigned to a guessed company.

The UEFI importer fingerprints both exact source files and never downloads, signs or publishes content. Registry assignments identify the registered holder of a vendor prefix. They do not establish a device's present manufacturer, product model, driver package or support location. Record the retained snapshot date and confirm the UEFI Forum redistribution terms before distributing a generated pack.

To build Bluetooth company references from a retained official Assigned Numbers YAML snapshot, run `dotnet run --project Tools/Knowledge/KillerBench.KnowledgeBuilder.csproj -- --bluetooth-company-ids COMPANY_IDENTIFIERS_YAML REVISION YYYY-MM-DD "LICENSE" NEW_OUTPUT_JSON`. Retain `assigned_numbers/company_identifiers/company_identifiers.yaml` from the Bluetooth SIG [Assigned Numbers repository](https://bitbucket.org/bluetooth-SIG/public/src/main/assigned_numbers/) and record the exact upstream commit separately. The importer accepts only the documented YAML root, 16-bit hexadecimal values and quoted company names. It rejects malformed, incomplete and duplicate assignments, emits the `bluetooth-company-identifiers` pack with `bluetooth-company` context, fingerprints the exact input and validates the result through the Engine.

The Bluetooth importer does not clone the repository, infer a device vendor from radio data, sign or publish content. The public repository does not by itself establish redistribution rights. Record the retained snapshot date and confirm Bluetooth SIG licensing and redistribution terms before distributing a generated pack.

To build PCI vendor and device references from a retained pci.ids snapshot, run `dotnet run --project Tools/Knowledge/KillerBench.KnowledgeBuilder.csproj -- --pci-ids PCI_IDS REVISION YYYY-MM-DD "LICENSE" NEW_OUTPUT_JSON`. Obtain and retain the source from `https://pci-ids.ucw.cz/`, record its upstream revision separately, and review its license before distribution. The importer reads four-digit vendor rows and their four-digit device rows, emits `pci-vendor` keys such as `VEN_8086` and `pci-device` keys such as `VEN_8086&DEV_1234`, and intentionally excludes subsystem and class records. It rejects malformed and duplicate contextual identities, validates the complete unsigned pack through the Engine, fingerprints the exact input, and never downloads, signs or publishes data. Existing outputs are never overwritten.

To build USB vendor and product references from a retained usb.ids snapshot, run `dotnet run --project Tools/Knowledge/KillerBench.KnowledgeBuilder.csproj -- --usb-ids USB_IDS REVISION YYYY-MM-DD "LICENSE" NEW_OUTPUT_JSON`. Obtain and retain the source from `https://usb-ids.gowdy.us/`, record its upstream revision separately, and review its license before distribution. The importer reads four-digit vendor rows and their four-digit product rows, emits `usb-vendor` keys such as `VID_046D` and `usb-device` keys such as `VID_046D&PID_C534`, and intentionally excludes interface and class records. It rejects malformed and duplicate contextual identities, validates the complete unsigned pack through the Engine, fingerprints the exact input, and never downloads, signs or publishes data. Existing outputs are never overwritten.

To build an offline Windows bug-check identity pack from a retained Microsoft reference snapshot, run `dotnet run --project Tools/Knowledge/KillerBench.KnowledgeBuilder.csproj -- --bugcheck-markdown BUG_CHECK_REFERENCE_MD REVISION YYYY-MM-DD "LICENSE" NEW_OUTPUT_JSON`. Retain `windows-driver-docs-pr/debugger/bug-check-code-reference2.md` from the official `MicrosoftDocs/windows-driver-docs` repository and record the exact upstream commit separately. The importer accepts only the reference table's hexadecimal code, uppercase symbolic name and relative Microsoft documentation link. It normalizes codes to eight hexadecimal digits, rejects duplicate or malformed identities, emits the `windows-bug-checks` pack with `bugcheck` context and validates it through the Engine. It does not clone the repository, download linked pages, parse crash dumps, infer causes, select drivers, sign or publish data. Confirm the retained source license and redistribution terms before distributing a generated pack.

To build a schema 2 driver-reference pack, run `dotnet run --project Tools/Knowledge/KillerBench.KnowledgeBuilder.csproj -- --driver-csv REVIEWED_CSV PACK_ID REVISION YYYY-MM-DD "LICENSE" NEW_OUTPUT_JSON`. The CSV columns are `Context`, `Code`, `Title`, `Explanation`, `SourceUrl`, `AppliesTo`, `HardwareId`, `Architecture`, `WindowsProduct`, `MinimumBuild`, `MaximumBuild`, `Vendor`, `DriverVersion` and `DownloadUrl`. The importer validates the complete output through the Engine, fingerprints the input and never downloads or selects a driver.

To build a schema 1 error-code or vendor-reference pack from reviewed rows, run `dotnet run --project Tools/Knowledge/KillerBench.KnowledgeBuilder.csproj -- --reference-csv REVIEWED_CSV PACK_ID REVISION YYYY-MM-DD "LICENSE" NEW_OUTPUT_JSON`. Columns must be exactly `Context`, `Code`, `Title`, `Explanation`, `SourceUrl` and `AppliesTo`. Context and code remain opaque exact keys, so separate Win32, HRESULT, NTSTATUS, bugcheck, product and vendor namespaces explicitly. The importer does not infer numeric aliases. It rejects duplicate contextual keys, insecure source URLs, malformed rows and unsupported metadata through the same Engine validation used at runtime. It fingerprints the retained source and creates a new unsigned output without downloading, signing or publishing it.

On Windows, `dotnet run --project Tools/Knowledge/KillerBench.KnowledgeBuilder.csproj -- --windows-message-csv 0 15999 YYYY-MM-DD NEW_REVIEW_CSV` reads the installed system message table and creates a new review CSV for defined Win32 codes in the selected inclusive range. Bounds must stay between 0 and 15999. Codes use exact decimal `win32` keys, undefined codes are omitted, text is normalized to one line, and each row links to the matching Microsoft system-error range. Output depends on the installed Windows build and language. The command fingerprints its new file but does not create a pack, grant redistribution rights, infer HRESULT or NTSTATUS aliases, sign, or publish. Review the rows and license before passing the file to `--reference-csv`.

On Windows, `dotnet run --project Tools/Knowledge/KillerBench.KnowledgeBuilder.csproj -- --ntstatus-message-csv 0xC0000000 0xC000FFFF YYYY-MM-DD NEW_REVIEW_CSV` reads the installed ntdll message table and creates a new review CSV for defined NTSTATUS values in the selected inclusive range. Bounds use `0x` plus exactly eight hexadecimal digits, and one run can inspect at most 65,536 values. Codes use normalized `ntstatus` keys such as `0xC0000005`, undefined values are omitted, text is normalized to one line, and each row links to Microsoft's NTSTATUS reference. Output depends on the installed Windows build and language. The command fingerprints its new file but does not create a pack, establish symbolic names, grant redistribution rights, infer Win32 or HRESULT aliases, sign, or publish. Review the rows and license before passing the file to `--reference-csv`.

On Windows, `dotnet run --project Tools/Knowledge/KillerBench.KnowledgeBuilder.csproj -- --hresult-message-csv 0x80070000 0x8007FFFF YYYY-MM-DD NEW_REVIEW_CSV` reads the installed system message table and creates a new review CSV for defined HRESULT values in the selected inclusive range. Bounds use `0x` plus exactly eight hexadecimal digits, and one run can inspect at most 65,536 values. Codes use normalized `hresult` keys such as `0x80070005`, undefined values are omitted, text is normalized to one line, and each row links to Microsoft's HRESULT reference. Output depends on the installed Windows build and language. The command fingerprints its new file but does not create a pack, grant redistribution rights, infer Win32 or NTSTATUS aliases, sign, or publish. Review the rows and license before passing the file to `--reference-csv`.

After building the tool, run `Checks/Test-KnowledgeBuilder.ps1` from PowerShell to check validation, repeatable normalization, IEEE, UEFI PNP and ACPI, Bluetooth company, PCI ID, USB ID, bug-check, driver and reviewed reference imports, installed Win32, NTSTATUS and HRESULT message generation, malformed input rejection and preservation of existing output. Tests use scratch files outside the project and do not download data or start the desktop app.

Each generator must document its input source, redistribution license, supported source revision and invocation. It must emit the [Engine knowledge schema](../../KNOWLEDGE-PACKS.md), retain provenance and verification dates, and validate the output with the Engine before publication. Inputs must be reproducible and generation must not require the WPF application.

Keep downloaded source snapshots and intermediate output outside the application source tree. Reviewed catalog source content belongs in `Knowledge`; generated release packs belong in release artifacts. Signing credentials must remain external to the generator and repository. Generation, signing and publication are separate operations.

Engine consumers use the runtime catalog APIs without installing generator dependencies. Generated IEEE packs can be queried through `MacVendorLookup.Find` or `killerbench-cli mac-vendor PACK_PATH MAC_ADDRESS`. Generated PCI packs can be queried through `PciHardwareLookup.Find` or `killerbench-cli pci-vendor PACK_PATH PCI_HARDWARE_ID`. Generated USB packs can be queried through `UsbHardwareLookup.Find` or `killerbench-cli usb-vendor PACK_PATH USB_HARDWARE_ID`. Generated UEFI packs can be queried through `UefiVendorLookup.Find` or `killerbench-cli uefi-vendor PACK_PATH PNP|ACPI VENDOR_ID`. Generated Bluetooth packs can be queried through `BluetoothCompanyLookup.Find` or `killerbench-cli bluetooth-company PACK_PATH DECIMAL_OR_0xHEX_ID`. Bug-check packs use the ordinary `KnowledgeCatalog` API or `killerbench-cli knowledge PACK_PATH bugcheck CODE`. These lookups are local and retain pack provenance. Registry assignments do not establish the complete product manufacturer or select a driver, and a bug-check identity does not establish a crash cause or repair. The importers do not add device collection or lookup to the desktop by themselves.

Activation is a separate signed runtime operation. `killerbench-cli knowledge-activate PAYLOAD_JSON SIGNATURE_FILE PUBLIC_KEY_FILE PACK_ID MINIMUM_REVISION STORAGE_DIRECTORY` verifies and activates a local candidate. `killerbench-cli knowledge-active STORAGE_DIRECTORY PUBLIC_KEY_FILE PACK_ID MINIMUM_REVISION` verifies and reports the current selection. `killerbench-cli knowledge-recover STORAGE_DIRECTORY PUBLIC_KEY_FILE PACK_ID MINIMUM_REVISION` selects the newest verified retained container when the active pointer or data is damaged. The builder remains unsigned and never supplies a trusted key, downloads a pack or publishes an update.
