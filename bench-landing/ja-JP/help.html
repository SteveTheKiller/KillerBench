ここから開始

KillerBench は、技術者向けの Windows 診断・修復ワークベンチです。まずコンピューターを確認し、見つかった内容をそれぞれの結論の裏付けとなる証拠とともに説明します。Windows を変更するのは、具体的な修正を選んで確認したときだけです。

KillerBench は開発中です。公開ダウンロードはまだありません。これらのページでは現在のビルドについて説明します。

できること

  • Windows Update、デバイス、ストレージ、ネットワーク、印刷、セキュリティ、アプリ、プロファイルにわたって読み取り専用の診断を実行し、読みやすいレポートを作成します。
  • 新しい証拠が問題を正確に証明した場合にのみ実行される保護付きの修復を提供し、その後で結果を検証します。
  • BitLocker、プライバシー設定、Windows の軽量化、新しいコンピューターの準備など、セットアップと強化の作業に対応します。
  • 診断とレポート分析は、AI や KillerBench アカウントなしでローカルに実行されます。ダウンロードや Entra ID への回復キーのバックアップなど、選択した操作は外部サービスに接続する場合があります。
  • コンソール、レポート、確認画面、および [開く]、[保存]、[フォルダー] ダイアログには、アプリの現在のテーマが使われます。

Windows とランタイム

  • 現在の公開対象は Windows x64 です。Windows 11 x64 が現在のネイティブ検証の基準です。ネイティブの ARM64、x86、Windows Server 向けの配布は提供されません。
  • KillerBench は 2 種類の形でパッケージ化されています。インストーラーは フレームワーク依存 で、.NET Desktop Runtime 10 for Windows x64 が必要です。通常の .NET Runtime、ASP.NET Core Runtime、.NET Framework には WPF が含まれません。ポータブル版は独自のランタイムを含み、別途インストールする必要はありません。コマンド ライン ツール killerbench-cli.exe には .NET 10 Runtime for Windows x64 が必要です。SDK は開発に必要なもので、通常の使用には必要ありません。
  • .NET 10 on Windows がサポートする Windows バージョンを使用してください。ランタイムがサポートされていても、KillerBench の修復がサポート対象のすべてのエディションやビルドで検証済みであることを意味するわけではありません。Windows 10 への対応は保留中で、サポートされるエディションは Microsoft の現在のライフサイクル要件によって制限されます。
  • Desktop Runtime は Microsoft の .NET 10 ダウンロード ページ からのみ入手し、.NET Desktop Runtime、Windows、x64 を選択してください。組織のソフトウェア インストール規則に従ってください。

dotnet が使用できる場合、dotnet --list-runtimes を実行すると x64 インストールの Microsoft.WindowsDesktop.App 10.0.x が表示されるはずです。別のアーキテクチャ用にのみインストールされたランタイムでは、x64 のインストーラー パッケージの要件を満たしません。

パッケージが公開されたら

  1. この Web サイトからリンクされている公式ダウンロードを使用してください。KillerBench のダウンロード リンクはまだ有効になっていません。
  2. そのパッケージの要件、GPLv3 ライセンス、対応するソースの入手方法、同梱のサードパーティ通知、署名とチェックサムの情報をお読みください。ファイル名だけでは真正性は証明されません。
  3. 現在のアカウント用に、または昇格のプロンプトの後にすべてのユーザー用に、インストーラーを実行します。スタート メニューのショートカット、任意のデスクトップ ショートカット、プログラムの追加と削除のエントリが追加されます。ポータブル版はインストールせずに実行できます。
  4. 通常のアカウントで KillerBench を起動し、初めての診断 に従ってください。診断時のアクセス エラーは表示されたままになります。昇格は別の意図的な選択です。

未検証のコピーを実行するために Windows のセキュリティ警告を回避しないでください。コンピューターを変更する操作を選ぶ前に、最新のバックアップを保持してください。

起動時に KillerBench は GitHub で新しい安定版リリースを確認し、インストールする前に確認を求めます。ダウンロードは公開されている SHA-256 チェックサムと一致する必要があります。この確認は、このアプリについての 起動時に更新を確認する でオフにできます。

現在の制限

現在のビルドには、12 のセクション、読み取り専用の診断、レポート、個別に選択する修復機能があります。ネイティブ修復の検証はまだ進行中です。動作する UI、ビルドの成功、テスト データでの結果は、実際のコンピューターでの修復の動作を証明するものではありません。変更の安全性を保つ仕組み を参照してください。

ランディング ページの説明用コンソールは合成された出力です。最初の公開パッケージはまだ準備中です。

ソース、ライセンス、サポート

KillerBench は GPLv3 でライセンスされています。最初の公開パッケージに向けたソースの提供方法とサードパーティ フォントの使用許可は、まだ保留中です。ソースの入手可能性、配布に関する通知、証拠のプライバシー、サポート情報については KillerBench について をお読みください。Engine ガイド は、許可されたソースのチェックアウトを持つ開発者向けです。公開された Engine パッケージがあることを意味するものではありません。

ダウンロードとセットアップ から始めて、システム全体のスキャンを実行します。スキャンは診断の証拠を収集してローカルのジャーナルを保存しますが、修復は実行しません。結論は確認した範囲を説明するもので、コンピューターで起こりうるすべての障害を示すものではありません。

スキャンを実行する

  1. KillerBench を開きます。診断 セクションが開き、システム全体のスキャン が選択されています。
  2. 初回の実行では、確認された問題を自動修復 をオフのままにします。
  3. 診断を実行 を押します。各チェックの実行中は、右側の 生の出力 に進行状況が表示されます。
  4. 完了すると、出力ペインが 読みやすいレポート に切り替わります。

まずは昇格せずに始めてください。BitLocker の保護機能や保護されたサービスなど、一部の Windows の証拠には管理者権限が必要です。標準アカウントでは、これらのチェックは証拠を取得できなかったと報告します。その証拠が必要な場合は、現在の実行を完了してレポートを保存してから、管理者として実行 で意図的に KillerBench を開き直してください。昇格によって修復が選択されたり承認されたりすることはありません。

レポートを読む

レポートの冒頭には 要確認、検証済みの修復、未完了、確認済み の件数が表示され、その後に推奨される次の手順が続きます。

  • 注意が必要な点 には、証拠が裏付ける問題が重要なものから順に表示されます。
  • 収集した情報 には、不完全だった証拠や取得できなかった証拠を含め、読み取った内容が表示されます。
  • 過去のイベントは履歴としてラベル付けされます。先月のエラーは現在の障害として扱われません。

証拠が欠けている場合に正常とみなされることはありません。チェックを実行できなかった場合は、レポートにそう記載されます。

チェックを自分で選ぶ

システム全体のスキャンではなく個別のチェックを選ぶには、チェックを選択（上級者向け） を開きます。アプリの各セクションにも専用のツールがあり、このガイドの セクション のページで説明しています。

見つかった問題を修正する

レポートが修正を推奨する場合は、開くべきセクションとツールが示されます。最初の修復の前に 変更の安全性を保つ仕組み をお読みください。ネイティブ検証はまだ進行中です。診断が成功しても、提示されたすべての修復がお使いの Windows ビルドでテスト済みであることにはなりません。変更の前には必ずバックアップを保持し、対象と影響を正確に確認してください。

KillerBench のウィンドウには、作業の流れに沿った 3 つのペインがあります。左でセクションを選び、中央でツールのオプションを設定し、右で出力を読みます。オプションの下にはアクティビティ ログを開くことができます。

セクション

左側のサイドバーには、すべてのツールが 12 のセクションに分けて表示されます。診断、修復、更新、デバイス、ネットワーク、アプリ、メンテナンス、マシンの準備、セキュリティ、BitLocker、プライバシー、ストレージです。端をドラッグするとサイズを変更でき、最小幅を超えてドラッグすると閉じます。

ツールのオプション

中央のペインには、選択したセクション、そのツール一覧、選択したツールのオプションが表示されます。コンピューターを変更する可能性のあるオプションは、既定で常にオフです。ツールを開始するには 診断を実行 を押します。確認された問題を自動修復 がオンのときは、同じボタンが 修復を実行 になります。停止 を押すと、現在のコマンドが終わった時点で実行が終了します。

出力

右側の出力ペインには 2 つの表示があります。

  • 生の出力 には、収集中の技術的な証拠が元の行番号とともに表示されます。ツールの実行中は自動的に開きます。
  • 読みやすいレポート には、最後の実行の完成したレポートが表示されます。実行が終わると生の出力に代わって表示されます。

生の出力のフィルター ボックスを使うと、一致する行だけを表示できます。レポートをエクスポート は、ソースのパスと証拠の抜粋を含めてレポートを保存します。セッションソース には、このセッションで収集したすべての証拠が一覧表示されます。

アクティビティ ログ

ツールのオプションの下にあるアクティビティ ログには、このセッションで KillerBench が行ったことが記録されます。

テーマ、言語、ショートカット

サイドバーとツールのオプションの間にあるレールには、テーマの選択、言語の選択、ショートカット一覧、アクティビティ ログの切り替えがあります。KillerBench には 13 のテーマと 20 の言語があります。

スモークガラス風のコンソールと読みやすいレポートは、現在のテーマに従います。確認画面と [開く]、[保存]、[フォルダー] ダイアログも、98SE テーマを含めて同じファミリーのスタイルを使います。ワークフロー全体で同じ外観を使うには、ダイアログを開く前にテーマを選んでください。

KillerBench は、診断と変更を別々の作業として扱います。診断は読み取るだけです。システム全体のスキャンが修復を実行することはありません。具体的な修復や操作を選び、そのオプションと前提条件を確認してから、提案された変更を承認してください。

変更の前に

  1. 新しい証拠。 ツールは現在の状態を読み直します。保存済みのレポートや古いイベントによって変更が許可されることはありません。
  2. 正確な適格性。 証拠が、その変更で修正する問題と正確に一致する場合にのみ、変更が提示されます。不完全な点があれば変更はブロックされます。
  3. ユーザーの確認。 選択した操作を確認ダイアログで確認します。ドライブの暗号化解除など、一部の操作では 2 回目の確認が必要です。ダイアログはアプリの現在のテーマに従いますが、外観によって操作の要件が変わることはありません。
  4. 前提条件。 管理者権限、再起動の状態、ポリシーやデバイス管理による所有が確認されます。ポリシーが所有する設定は変更されません。
  5. 保留中のレコード。 KillerBench は、Windows に処理を依頼する前に、これから行う内容を記録します。
  6. 最終確認。 要求の直前にすべてをもう一度確認するため、その間に状態が変わった場合は処理が停止します。

変更の後に

  • KillerBench は結果を読み直し、Windows が期待どおりの状態を示した場合にのみ 検証済み と報告します。
  • Windows が成功を返しても状態が変わっていない場合は、結果にそのことが示され、何も繰り返されません。
  • 各変更は %LOCALAPPDATA%\KillerBench のジャーナルに保存されます。

処理が中断された場合

対応するジャーナル付きの操作は、要求が Windows に届いた可能性があり検証が完了していない場合に、保留中のレコードを保持します。そのレコードを確認するには、操作のドキュメントに記載された照合の手順、または対応する -recover コマンドを使います。照合は自動ロールバックではありません。結果が不確かなときはジャーナルを保持し、変更を手動で繰り返さないでください。クラッシュ、キャンセル、次回起動時の動作については、操作ごとの実機検証がまだ必要です。

KillerBench が行わないこと

  • TPM のクリア、自身が作成していない保護機能の削除、回復パスワードの表示。
  • グループ ポリシーやデバイス管理が制御する設定の変更。
  • 過去のイベントやインポートしたレポートが問題に触れているという理由だけでの修復の実行。

診断とレポート分析はローカルで実行されます。選択した操作は、ソフトウェアのダウンロードや Active Directory または Entra ID への回復キーのバックアップなど、外部の接続先に接続する場合があります。確認する前に対象を確認してください。保存したキャプチャや生の証拠には、コンピューターの識別情報やソースのパスが含まれる可能性があるため、共有する前に確認してください。

開発状況

修復の対象範囲は拡大を続けています。ビルドの成功やシミュレーションによるチェックは、実機での修復の動作を証明するものではありません。

手順ガイド

更新プログラムが失敗する、止まる、何度も再インストールされる場合に使います。KillerBench はまず更新のチェーンを読み取り、障害をその裏付けとなる証拠とともに説明します。サービスの開始やコンポーネント ストアの修復は、新しい証拠がその問題を正確に証明した場合にのみ行います。

始める前に

  • KillerBench を管理者として実行してください。完全な証拠を得るには、更新サービス、コンポーネント ストア、保護されたシステム ファイルに昇格が必要です。
  • Windows が再起動を待っている場合は、先に再起動してください。再起動の状態が解消されるまで、多くの更新修復はブロックされます。
  • サービシング作業中は、コンピューターを AC 電源に接続しておいてください。

更新が失敗する理由を調べる

  1. 更新 を開き、ツール一覧で Windows Update を選びます。
  2. 最初は 確認された問題を自動修復 をオフのままにして、診断を実行 を押します。
  3. 読みやすいレポート を読みます。停止している更新サービス、保留中の再起動、空き容量の不足、コンポーネント ストアの破損、Windows が記録した正確なエラー コードが、推奨される次の手順とともに一覧表示されます。
  4. レポートにエラー コードが記載されている場合は、対応する追加チェックが自動的に実行されます。killerbench-cli update-code 0x80070002 で自分で調べることもできます。

止まっているように見える更新を監視する

更新 で サービシング アクティビティ モニター を選び、診断を実行 を押します。更新、Setup、Installer のアクティビティ、転送量の合計、再起動のインジケーターを繰り返しスナップショットとして取得します。アクティビティは証拠として表示されるだけで、それ自体が停止や障害を主張することはありません。

レポートで見つかった問題を修復する

  1. 確認された問題を自動修復 をオンにして、もう一度 Windows Update を実行します。停止が確認された有効な更新サービスを開始でき、DISM または SFC はライブ チェックで破損が確認された場合にのみ実行します。
  2. 個別のサービスについては、BITS サービス、暗号化サービス、Windows Modules Installer、Update Orchestrator サービス などの専用ツールを選びます。それぞれ、そのサービスに限って回復を提示します。
  3. レポートで再起動が求められた場合は、ほかの操作を実行する前に再起動してください。KillerBench は再起動が必要な結果を記録し、再起動が完了するまで後続の作業を延期します。

すべての修復はジャーナルに記録され、読み直されます。全体の手順については 変更の安全性を保つ仕組み を参照してください。

特定の更新プログラムをインストールする

  1. 更新 で 利用可能な更新プログラム を選び、診断を実行 を押して、構成されたソースから更新プログラムを検索します。
  2. 必要な更新プログラムを選び、選択内容をプレビュー を押します。プレビューには、インストールされる内容と再起動の要否が正確に表示されます。
  3. プレビューを読み、確認のチェックボックスをオンにしてから インストール を押してください。チェックボックスは実行のたびにクリアされます。KillerBench が更新プログラムを選んだり承認したりすることはありません。

コマンド ラインから

killerbench-cli update-search
killerbench-cli update-history
killerbench-cli servicing-monitor --samples 10
killerbench-cli update-plan --select GUID:REVISION --execute

update-search、update-history、servicing-monitor、update-plan を参照してください。インストールが中断された場合は update-recover を実行します。このコマンドは結果を確認し、更新を再試行することはありません。

関連項目

  • 更新セクション
  • システム ファイルを修復する
  • トラブルシューティング

Windows のコンポーネントが破損している場合に使います。機能をインストールできない、更新プログラムがコンポーネントのエラーを報告する、システム ツールがクラッシュする、といった場合です。KillerBench は、ライブ チェックで破損が確認された後にのみ DISM と SFC を実行し、その後で結果を検証します。

始める前に

  • KillerBench を管理者として実行してください。
  • 保留中の再起動を先に済ませてください。
  • 管理されたコンピューターの場合は、ポリシーが DISM に特定の修復ソースを指定していないか確認してください。KillerBench はそのポリシーを報告しますが、変更はしません。

破損を確認する

  1. 修復 を開き、システム ファイル を選びます。
  2. 確認された問題を自動修復 をオフのままにして、診断を実行 を押します。
  3. レポートを読みます。サービシング パッケージ、オプション機能、機能の状態を一覧にし、前提条件を確認して、保護されたシステム ファイルをスキャンします。問題がなければ修復は提示されません。

確認された破損を修復する

  1. 確認された問題を自動修復 をオンにして、修復を実行 を押します。KillerBench は、ライブ チェックで破損が確認された場合にのみ DISM または SFC を選びます。
  2. 検証を待ちます。レポートに 検証済み と表示されるのは、追加のチェックで修復された状態が読み取れた場合だけです。
  3. ストアを回復できない、または修復ソースを利用できないとレポートに表示された場合は、そこで止めてください。修復を繰り返しても結果は変わりません。

中断された DISM や SFC の実行は、次回の起動時にサービシング コマンドを繰り返さずに照合されます。

コンポーネント ストアをクリーンアップする

更新 で コンポーネント ストアのクリーンアップ を選びます。まず、クリーンアップが推奨されるかを Windows に問い合わせます。オプションのメンテナンスでは、置き換えられたコンポーネントを削除して再度分析します。ResetBase を使うことも、WinSxS の内容を手動で削除することもありません。

コマンド ラインから

killerbench-cli component-repair-source
killerbench-cli repair dism
killerbench-cli repair sfc --execute
killerbench-cli servicing-logs

component-repair-source、repair、servicing-logs を参照してください。repair は既定でプレビューを表示し、--execute を指定した場合にのみ実行します。

関連項目

  • Windows Update を修正する
  • 修復セクション
  • 変更の安全性を保つ仕組み

ドライブの空き容量が少なくなったときに使います。KillerBench は容量の使われ方を示し、各クリーンアップ対象が何を削除するかをプレビューし、完全なクリーンアップをオンにした後にのみ削除します。

残りの容量を確認する

  1. ストレージ を開き、ストレージ を選びます。
  2. 診断を実行 を押します。レポートでは、空き容量が 10% 未満のドライブ文字付きボリュームがすべて示され、シャドウ コピーの割り当て、クォータの既定値、ストレージ センサーのポリシーが表示されます。
  3. クラッシュ ダンプや古い更新プログラムのコンテンツについては、診断 の 主要指標 と 更新 の Windows Update も実行してください。更新キャッシュのサイズはそこに表示されます。

クリーンアップをプレビューする

  1. メンテナンス を開き、クリーンアップ を選びます。
  2. 現在のユーザーの一時ファイル、Windowsの一時ファイル、現在のユーザーのブラウザキャッシュ、配信最適化キャッシュ、現在のユーザーのごみ箱 など、必要な対象にチェックを入れます。対象にポインターを合わせると、対象となるフォルダーを正確に確認できます。
  3. 最小経過日数 と ターゲットごとの最大ファイル数 を設定します。
  4. 新たなチェックの後で、選択した完全なクリーンアップを実行 をオフにしたまま 診断を実行 を押します。レポートには、対象ごとの候補と見込みの容量が表示されます。何も削除されません。

ファイルを削除する

  1. 新たなチェックの後で、選択した完全なクリーンアップを実行 をオンにして、診断を実行 を押します。
  2. KillerBench は削除する前に各候補を再確認し、最近のファイル、保護されたファイル、使用中のファイルをスキップして、各結果をジャーナルに記録します。

完全なクリーンアップはごみ箱を経由せず、元に戻せません。エラー レポートやクラッシュ ダンプを削除すると、クラッシュの調査に必要になる可能性のある証拠が失われるため、先に確認してください。

以前の Windows のインストールを削除する

機能更新の後、クリーンアップ の 以前のWindowsインストール で、Windows がサポートするロールバック削除の要求を使ってロールバック用のコピーを削除できます。この操作は単独で実行され、以前のインストールから必要なファイルと設定をバックアップしました。 が必要で、以前のバージョンに戻す機能が完全に失われます。

コマンド ラインから

killerbench-cli volume-capacity C:
killerbench-cli cleanup --user-temp --windows-temp --days 7 --max-files 500
killerbench-cli cleanup --user-temp --windows-temp --days 7 --max-files 500 --execute

volume-capacity、cleanup、previous-windows を参照してください。

関連項目

  • メンテナンス セクション
  • ストレージ セクション
  • ドライブを確認して修復する

ボリュームがエラーを報告する、Windows がドライブのスキャンを求める、ファイルが開けない場合に使います。KillerBench はまずボリュームを読み取り専用で確認し、バックアップを確認した後にのみファイル システムの修復をスケジュールまたは実行します。

始める前に

  • ボリューム上の重要なデータをバックアップしてください。ファイル システムの修復では、破損したファイルが変更または削除される場合があります。
  • KillerBench を管理者として実行してください。

ボリュームを確認する

  1. ストレージ を開き、ストレージ を選びます。
  2. チェックするボリューム でドライブを選び、診断を実行 を押します。
  3. レポートを読みます。ディスクとボリュームの正常性、ダーティ ビット、NTFS のオンライン自己修復、コントローラーとディスク デバイスのエラー、信頼性カウンター、リセット、再試行、予期しない取り外しなど最近のストレージ イベントが表示されます。

問題がなければ修復は提示されません。ディスクの温度、摩耗、未訂正の I/O カウンターは確認用の証拠であり、それだけで修復が実行されることはありません。

ファイル システムを修復する

  1. ファイルシステム修復を確認 を押し、スポット修復 または オフラインスキャンと修復 を選びます。
  2. データ ボリュームの場合、それを使用しているものをすべて閉じられるなら システム以外のボリュームをオフラインにすることを許可 にチェックを入れます。Windows のボリュームはオフラインにできないため、その修復は次回の再起動時にスケジュールされます。
  3. このボリュームの重要なデータはバックアップ済みです にチェックを入れます。
  4. 修復を確認します。KillerBench は実行の直前に対象のボリュームを再確認し、先に保留中のエントリを記録します。
  5. スケジュールされた修復の場合は、都合のよいときに再起動します。KillerBench は再起動後に、修復を再実行せずに結果を検証します。

最適化または再トリム

同じツールで、ボリュームを分析し、Windows が推奨する最適化、ソリッドステートストレージを再トリム、またはハード ディスクのデフラグを実行できます。いずれも、正常な 1 つのボリュームに対する個別に確認する操作です。

コマンド ラインから

killerbench-cli storage-check C
killerbench-cli storage-repair-plan D: OfflineScanAndFix --allow-dismount
killerbench-cli storage-repair D: OfflineScanAndFix --allow-dismount --backup-confirmed --execute
killerbench-cli storage-repair-recover

storage-check、storage-repair-plan、storage-repair、volume-optimize を参照してください。

関連項目

  • ストレージ セクション
  • ディスク領域を解放する
  • トラブルシューティング

コンピューターがインターネットに接続できない、サーバーや名前に到達できない、接続が頻繁に切れる場合に使います。KillerBench はアダプター、アドレス、ゲートウェイ、DNS、ファイアウォールを順に確認し、新しい証拠で必要性が証明された場合にのみリースの更新やサービスの開始を行います。

接続を確認する

  1. ネットワーク を開き、ネットワーク を選びます。
  2. 特定の対象をテストするには、ホスト名の検索（オプション）、または TCP宛先（オプション） と TCPポート に入力します。ローカルの構成だけを確認する場合は空欄のままにします。アプリケーション データは送信されません。
  3. ネットワークが遅い場合は、検索または接続ごとのタイムアウト（秒） を設定します。
  4. 確認された問題を自動修復 をオフのままにして、診断を実行 を押します。
  5. レポートを読みます。アドレスの欠落、ゲートウェイの欠落または到達不能、DNS 構成の問題、プロキシ設定、ファイアウォール プロファイルの不一致、検索または接続の失敗が区別され、それぞれに次の手順が示されます。

ゲートウェイから応答があってもインターネットへのアクセスが証明されるわけではなく、構成されたリゾルバーでの検索が失敗してもサイトが停止しているとは限りません。

レポートで見つかった問題を修復する

  1. 確認された問題を自動修復 をオンにして、もう一度 ネットワーク を実行します。有効な DNS Client、DHCP Client、SMB クライアント、Network Location Awareness、Network List、IP Helper の各サービスを開始でき、使用可能な IPv4 アドレスがない接続済みの物理 DHCP アダプターのリースを更新できます。
  2. 更新の際は、接続が一時的に切れることがあります。静的アドレスと仮想アダプターが変更されることはありません。
  3. キャッシュされた 1 つの名前が誤っている場合は、すべてを消去するのではなく、そのホストに限定した DNS キャッシュのフラッシュを使います。

ルート、Hosts のエントリ、DNS サーバー、ファイアウォール規則、Winsock プロバイダー、ネットワーク プロファイルは常に保持されます。

ワイヤレス、有線サインイン、プロキシ

  • ワイヤレス ネットワーク はアダプターと WLAN AutoConfig を確認し、サービスが停止している場合は開始できます。
  • 有線認証 (802.1X) は、ポートでのサインインが必要なネットワーク向けに Wired AutoConfig で同じことを行います。
  • WinHTTP 自動プロキシ は、コンピューターと現在のアカウントの保存済みプロキシ設定を表示します。KillerBench が診断中に PAC URL を取得したりプロキシ設定を変更したりすることはありません。

コマンド ラインから

killerbench-cli workflow network --host example.com --tcp example.com 443
killerbench-cli dns-check example.com --timeout-seconds 5
killerbench-cli tcp-check fileserver 445
killerbench-cli dhcp-renew
killerbench-cli dns-cache example.com --execute

workflow、dns-check、tcp-check、dhcp-renew、dns-cache を参照してください。

関連項目

  • ネットワーク セクション
  • 印刷の問題を解決する
  • 変更の安全性を保つ仕組み

ジョブがキューに残り続ける、プリンターがオフラインと表示される、既定のプリンターが間違っている場合に使います。KillerBench はまずスプーラー、キュー、ジョブ、ドライバー、ポートを読み取り、その後で特定の 1 つのキューまたはジョブを修正できるようにします。

プリンターを確認する

  1. デバイス を開き、印刷 を選びます。
  2. ローカルプリンターを探す を押し、問題のあるキューを選びます。すべてのキューを確認するには、一般的な印刷チェックを使用 を選びます。
  3. 確認された問題を自動修復 をオフのままにして、診断を実行 を押します。
  4. レポートを読みます。Print Spooler の状態、一時停止中のキュー、オフライン モード、表示されているジョブ、ドライバーの状態、ポートの登録、最近の PrintService のエラー、さらにネットワーク プリンターについてはプリンターに割り当てられたアドレスへの 1 回の接続試行が表示されます。

接続の成功や問題のない状態コードは、プリンターに用紙やトナーがあることや、機構が正常に動作することを証明するものではありません。

キューを修復する

  1. 確認された問題を自動修復 をオンにして、もう一度 印刷 を実行します。有効なスプーラーの開始、待機中のジョブがある特定の一時停止キューの再開、オフライン モードの解除ができます。
  2. オフライン モードを解除すると待機中のジョブが送られる場合があるため、それらのジョブを本当に印刷してよいか確認してください。
  3. 誰かが意図的に一時停止し、待機中のものがないキューは一時停止のままになります。

詰まった 1 つのジョブを消去する

  1. ブロックされた印刷ジョブを探す を押します。
  2. Error または Blocked と表示されているジョブを選び、この選択したジョブのみをキャンセル にチェックを入れます。
  3. 診断を実行 を押します。そのジョブだけがキャンセルされ、結果が読み直されます。

既定のプリンターを修正する

既定にするキューを選び、このキューで欠落または競合する既定のプリンターを修復 にチェックを入れてから、診断を実行 を押します。この操作は、既定のプリンターが欠落しているか競合している場合にのみ実行されます。

コマンド ラインから

killerbench-cli printer-list
killerbench-cli printer-check --queue "Office Laser"
killerbench-cli printer-repair --queue "Office Laser" --execute
killerbench-cli print-job-list
killerbench-cli print-job-cancel "Office Laser" 12 --execute

printer-list、printer-check、printer-repair、print-job-cancel、default-printer-set を参照してください。

関連項目

  • デバイス セクション
  • ネットワークとインターネットの問題を解決する

BitLocker を有効にし、回復キーをバックアップして、ドライブが保護されていることを確認するために使います。KillerBench は暗号化を開始する前に回復パスワードをバックアップして検証し、回復パスワードを表示したりログに記録したりすることはありません。

始める前に

  • KillerBench を管理者として実行してください。
  • Windows ドライブには TPM 保護機能と回復パスワード保護機能が必要です。データ ドライブに必要なのは回復パスワードだけです。
  • 回復キーのバックアップ先を決めます。暗号化するドライブ以外にあるファイルと、必要に応じて Active Directory または Microsoft Entra ID です。

ドライブを確認する

  1. BitLocker を開き、ボリューム でドライブを選びます。
  2. 操作を 検査 のままにして、診断を実行 を押します。レポートには、暗号化の状態、保護の状態、保護機能の識別情報が表示されます。
  3. TPM はあっても準備ができていない場合は、先に セキュリティ で準備してください。KillerBench が TPM をクリアすることはありません。

必要な保護機能を追加する

  1. その他の BitLocker 操作 を開きます。
  2. TPM 保護機能を追加 または 回復パスワードを追加 を選び、プレビュー を押し、[操作を実行] を押したら選択したドライブにこの変更を行う にチェックを入れてから、操作を実行 を押します。
  3. 新しい回復パスワードはすぐにバックアップしてください。KillerBench はそれを表示しません。

回復キーをバックアップして暗号化する

  1. 回復用の保護機能を検索 を押し、回復パスワード保護機能を選びます。
  2. 暗号化するドライブ以外の場所にあるバックアップ ファイルの完全なパスを入力します。
  3. 暗号化 を選び、暗号化方式を選んで、[診断を実行] を選択したときに、選択した回復キーをバックアップしてから暗号化を開始する にチェックを入れます。
  4. 診断を実行 を押します。KillerBench はバックアップを書き込んで検証し、その後で暗号化を 1 回だけ開始します。
  5. 暗号化はバックグラウンドで続行されます。後で 検査 を実行し、ドライブが完全に暗号化され保護がオンになっていると報告されることを確認してください。

Active Directory または Entra ID にバックアップする

その他の BitLocker 操作 で、選択した保護機能のディレクトリへのバックアップを選びます。KillerBench は Windows が要求を受け付けたことを報告しますが、ディレクトリ上のコピーは読み取れないため、Active Directory または Entra 管理センターで確認してください。

データ ドライブと自動ロック解除

データ ドライブを暗号化した後、自動ロック解除をオンにする を使うと、Windows の起動時にドライブのロックが解除されます。Windows ドライブは、保護がオンの状態で完全に暗号化されている必要があります。

コマンド ラインから

killerbench-cli bitlocker-protectors C:
killerbench-cli bitlocker-protector-add C: recovery --execute
killerbench-cli bitlocker-encrypt C: RECOVERY_PROTECTOR_GUID D:\Keys\C-recovery.txt --execute
killerbench-cli bitlocker-escrow C: RECOVERY_PROTECTOR_GUID entra --execute

bitlocker-protectors、bitlocker-protector-add、bitlocker-encrypt、bitlocker-escrow を参照してください。それぞれに、中断された要求のための対応する -recover コマンドがあります。

関連項目

  • BitLocker セクション
  • セキュリティ セクション
  • 変更の安全性を保つ仕組み

Windows が予期せず再起動する、停止エラーが表示される、アプリケーションがクラッシュし続ける場合に使います。KillerBench は、クラッシュ、シャットダウン、ハードウェア エラー、信頼性の証拠を 1 つのレポートにまとめます。記録された内容を説明するだけで、根本原因を推測することはありません。

コンピューターを確認する

  1. 診断 を開き、主要指標 を選びます。
  2. 診断を実行 を押します。レポートには、メモリ、ディスクの正常性、デバイスの問題、信頼性モニターの履歴、ハードウェア エラーの記録、クラッシュ レポート、予期しないシャットダウン、Windows メモリ診断の結果がまとめられます。
  3. 結論とその下の証拠を読みます。過去のクラッシュは何が起きたかを説明しますが、障害がまだ存在することを証明するものではありません。

範囲を絞り込む

  • ハードウェア エラーの履歴 は、WHEA とメモリ診断の記録を、デバイスの問題やディスクの正常性とあわせて読み取ります。
  • 信頼性の履歴 は、過去 14 日間のアプリケーションのクラッシュ、応答停止、予期しないシャットダウンをまとめます。
  • アプリケーションの障害 は、クラッシュしているプログラムに焦点を当てます。
  • ドライバーのインストール履歴 は、現在存在するデバイスと照合した、失敗したドライバーのインストールを表示します。
  • デバイスの問題 は、デバイス マネージャーのエラー コードがあるデバイスを一覧表示します。

調査が終わるまでダンプは保持してください。クリーンアップ で削除できますが、証拠も失われます。

セクション

どの作業も、まず診断から始めます。各ツールはコンピューターを読み取り、レポートを作成します。ここで Windows が変更されることはありません。既定のツールであるシステム全体のスキャンは、読み取り専用のチェックを幅広く実行し、注意が必要な点を重要度順に並べます。

手順ガイド: クラッシュとブルー スクリーンを調査する と システム ファイルを修復する。

このセクションのツール

まずコンピューターを確認し、次にレポートで注意が必要な点と安全な次の手順を読みます。

システム全体のスキャン

49 の診断領域を確認し、インストール済みの修復レシピを現在の証拠に基づいて評価します。チェックには数分かかる場合があります。システム全体のスキャンは診断専用です。新しい前提条件を確認した後に、サポートされている操作を 1 つ選択して確定するには、対象を絞った修復ワークフローを使用してください。過去、バックアップ、転送のスナップショットは読み取り専用のままです。ダンプの内容は開かれません。ダーティ ビットの確認で修復や再起動がスケジュールされることはありません。このスキャンでは、更新プログラムのインストール、ドライバーの変更、ファイルの削除、完全なハードウェア テストは行いません。

主要指標

利用可能なメモリ、プロバイダーが報告するディスクの正常性、BitLocker の保護の状態を取得し、現在の指標をデバイスの問題、信頼性の履歴、ハードウェア エラーの記録、クラッシュの証拠、予期しないシャットダウン、Windows メモリ診断の結果と照合します。再起動のインジケーター、システム ディスクの空き容量、昇格、更新サービスの構成も表示されます。回復パスワードは収集されません。このワークフローで修復は実行されません。まとめた結果は、ハードウェア、ソフトウェア、安定性の完全なテストではありません。

信頼性の履歴

Windows 信頼性モニターの過去 14 日間の記録を、最近の Application のエラーや予期しないシャットダウンのイベントとあわせて読み取り、範囲を限定した 1 つの履歴上の結論を返します。過去の記録によって現在の正常性や根本原因が確定することはありません。修復は選択されず、アプリケーション、サービス、設定も変更されません。

起動時のパフォーマンス

Windows の起動とシャットダウンのパフォーマンス イベントについて過去 14 日間のメタデータを読み取り、プロバイダーの識別情報と範囲を限定した数値の所要時間フィールドだけを保持して、対応する保留中の再起動インジケーターと照合します。パス、プロセス名、アカウント、その他のイベントの内容は、証拠の保存前に削除されます。過去の低下の記録によって現在のボトルネックが特定されたり、スタートアップ、サービス、アプリケーション、ドライバー、タスク、電源、再起動、ポリシーの変更が許可されたりすることはありません。

ハードウェア エラーの履歴

Windows Hardware Error Architecture とメモリ診断の過去 14 日間の履歴、現在のプラグ アンド プレイ デバイスの問題、物理ディスクの正常性、プロバイダーの信頼性カウンターを読み取り、範囲を限定した 1 つのハードウェアに関する結論を返します。記録は、その内容、ファームウェアの診断、ベンダーのハードウェア テストと照合する必要があります。故障したコンポーネントや根本原因は推測されず、修復は選択されず、ハードウェア、ファームウェア、ドライバー、ディスク、プール、ボリューム、ファイル、サービス、電源、再起動、設定は変更されません。

ドライバーのインストール履歴

Windows SetupAPI のデバイス インストール履歴のうち保持されている末尾部分を読み取り、失敗したセクションを現在の正確なプラグ アンド プレイの識別情報と照合して、範囲を限定した 1 つの結論を返します。過去のログ セクションは、デバイスがまだ存在することや障害が現在も起きていることを証明するものではありません。ドライバーのインストール、削除、ロールバック、更新は行いません。

システムの復元ポイント

利用可能なシステムの復元ポイントを最大 256 件一覧にし、作成の明示的な適格性を確認して、範囲を限定した 1 つの準備状態に関する結論を返します。一覧は、すべてのボリュームで保護が有効であることや、復元が成功することを証明するものではありません。診断中に復元ポイントが作成、削除、適用されることはありません。

Windows 回復環境

REAgentC を使って現在の Windows 回復環境の構成を読み取り、有効なローカルの場所を現在の正確なディスクとパーティションに照合して、範囲を限定した 1 つの準備状態に関する結論を返します。オプションの自動修復では、無効になっている既存の構成を有効にし、報告された状態を検証できます。回復イメージのダウンロード、移動、置き換えは行わず、回復モードでの起動も開始せず、Windows も再起動しません。有効な状態とパーティションの存在は、回復イメージでこの PC を起動または修復できることを証明するものではありません。

Windows のライセンス認証

プロダクト キーの全体も一部も収集せずに現在の Windows のライセンス状態を読み取り、過去 7 日間のソフトウェア保護の警告、エラー、重大イベントについて内容を除去したメタデータを保持して、範囲を限定した 1 つの動作に関する結論を返します。イベントの内容は、証拠の保存前に削除されます。現在のライセンスが Licensed と報告されている場合、過去の記録は参考情報として扱われます。ライセンス認証、プロダクト キー、トークン、ライセンス、アカウント、サービス、ポリシーの操作は選択されません。プロバイダーの状態とイベントの履歴は、サブスクリプションの権利、ライセンス認証サーバーへの到達、トークン ストアの整合性、将来の有効性、根本原因を証明するものではありません。

Windows サービス

アカウント、実行可能ファイルのパス、回復コマンド、再起動メッセージを収集せずに、インストールされているサービスの名前、表示名、状態、開始モード、プライバシーに配慮して範囲を限定した回復アクションの種類を一覧にします。開始モードの整合性、直接の依存関係の識別情報と循環を確認し、正確な保留中の状態を繰り返し確認し、対応するサービスと停止中のサービスの依存関係を調べてから、正確なサービス名または一意の表示名が 1 つだけある場合に限り、最近のサービス コントロール マネージャーの障害と照合します。読み込み順序グループの使用はメンバーを展開せずに数え、あいまいな識別情報は未解決のままにします。停止している手動開始のサービスは正常な場合があります。サービスは開始されず、スタートアップ、依存関係、回復の設定は保持されます。特定の機能の回復が必要な場合は、対応する修復のワークフローを使ってください。

アプリケーションの障害

最近の Application のエラーと重大イベントを、範囲を限定した信頼性モニターの履歴とあわせて読み取り、安定性の履歴に関する 1 つの結論を返します。過去の記録は、現在の障害や根本原因を証明するものではなく、より絞り込んだ診断への手がかりにとどまります。アプリケーションの停止、修復、削除、再構成は行いません。

ディスプレイ デバイス

グラフィックス アダプターとモニターについて、報告されたデバイスのエラー、ハードウェア ID、インストールされているドライバーのバージョンを確認します。ドライバーのインストール、デバイスのリセット、解像度の変更は行いません。画質と物理的な接続はテストされません。

入力デバイス

キーボード、マウス、HID デバイスのエラーとドライバーの一覧を確認します。キー入力の記録、デバイスのリセット、ドライバーの変更は行いません。物理的な入力の動作はテストされません。

デバイスの問題

すべてのデバイス クラスについて 0 以外のプラグ アンド プレイ構成エラー コードを探し、存在するデバイスの証拠を、ドライバーのインストール、デバイスのセットアップ、プラグ アンド プレイに関する範囲を限定した SetupAPI の履歴と照合します。過去の記録だけで現在の障害が確定することはありません。ハードウェア、ドライバー、構成を変更せずに、デバイスの正確な識別情報と承認済みドライバーの証拠を確認してください。存在しないデバイスと物理的な動作は検証されません。

修復には、何かを修正できるツールがまとめられています。いずれも最初に診断を行います。修復が提示されるのは、新しい証拠がその修復で直す問題を正確に示した場合だけで、確認された問題を自動修復 をオンにするか、個別の修復を自分で承認した後にのみ実行されます。すべての修復はジャーナルに記録され、その後で検証されます。

手順ガイド: システム ファイルを修復する と Windows Update を修正する。

自動修復と手動修復

確認された問題を自動修復 を使うと、診断ツールはスキャンの後で、必要性を証明した修復を実行できます。既定ではオフです。

個別のサービシング修復を行うには、上級者向け：ログと手動修復 を開いて 修復 を選びます。コンポーネントストア（DISM） または システムファイル（SFC） を選び、プレビューを読み、このPCでこの修復を実行 にチェックを入れて 修復を実行 を押します。変更の前後に何が行われるかについては、変更の安全性を保つ仕組み を参照してください。

このセクションのツール

診断で問題が特定された後に使います。修復には、確認された証拠と明示的な承認が必要です。

Windows のコア サービス

Power、Plug and Play、User Manager、Group Policy Client、Network Store Interface、RPC Endpoint Mapper、Remote Procedure Call、DCOM Server Process Launcher、Background Tasks Infrastructure、CoreMessaging の各サービスをまとめて確認します。オプションの回復では、起動時の猶予期間と完全な依存関係チェックの後で、新しい証拠によって停止が確認された、有効な自動開始の対象サービスのみを開始します。手動開始のサービスは、アイドル状態であれば変更されません。電源プラン、デバイス、ドライバー、アカウント、資格情報、プロファイル、ポリシー、アダプター、アドレス、ルート、DNS、ファイアウォールの構成、登録、エンドポイント、タスクの登録、アプリケーション データ、サービスのアクセス許可、スタートアップの種類は保持されます。ポリシーの更新、デバイスのスキャン、アカウントの操作、ネットワークの変更、電源設定の変更、登録の変更、タスクの起動は要求されません。検証の対象はサービスの安定した状態のみで、機能全体の動作は含まれません。

システム ファイル

Windows のサービシング パッケージ、オプション機能、機能の状態を範囲を限定して一覧にし、前提条件を確認し、保護されたシステム ファイルをスキャンして、ライブ チェックで破損が確認された場合にのみ SFC を自動的に選びます。パッケージ、オプション機能、機能が保留中の状態であれば確認が求められますが、インストール、削除、クリーンアップ、ロールバック、有効化、無効化が許可されることはありません。

WMI リポジトリ

WMI サービスの可用性を確認し、次にリポジトリの整合性を確認します。自動修復では、適格な停止中のサービスを開始し、確認された破損からデータを回収した後、それぞれの結果を検証できます。無効になっているサービスの設定は保持されます。読み取り可能な登録は統合され、読み取れない内容についてはプロバイダーの再インストールが必要になる場合があります。管理クライアントが中断される場合があります。リセット、削除、自動ロールバックは行いません。

Windows システム通知

最近のサービス コントロール マネージャーの履歴を読み取り、COM+ Event System と System Event Notification Service をまとめて確認します。オプションの回復では、SENS を開始する前に COM+ Event System の準備状態を検証します。既存のログオン、ネットワーク、電源、COM+ の通知が、現在の構成で再開する場合があります。COM+ カタログ、サブスクリプション、通知の登録、コンシューマー、アカウント、アクセス許可、回復の設定、ポリシー、スタートアップの種類は保持されます。サブスクリプション、登録、コンシューマー、アカウント、アクセス許可、ポリシーは変更されません。検証の対象はサービスの安定した状態のみで、通知の配信全体は含まれません。

診断ポリシー サービス

範囲を限定した診断ポリシーの動作履歴、サービスの正確な障害履歴、サービスの現在の準備状態を確認します。不完全な証拠が優先されます。過去の記録によって、サービスの回復やトラブルシューティングの操作が許可されることはありません。オプションの回復では、新たな依存関係チェックの後で、有効かつ停止している対象のサービスのみを開始します。既存の診断シナリオが再開する場合があります。ポリシー、トラブルシューティングのデータ、スタートアップの種類は保持されます。トラブルシューティング ツールや提案された修正は実行されません。検証の対象はサービスの安定した状態のみで、障害の検出、診断の完了、修復の結果は含まれません。

Windows エラー報告

クラッシュ ダンプの構成、範囲を限定したダンプ ファイルのメタデータ、最近のシステム クラッシュ レポート、Windows エラー報告サービスの正確な障害履歴、サービスの現在の準備状態を確認します。過去のレポートによって現在の障害や根本原因が確定することはなく、回復が許可されることもありません。オプションの回復では、新たな依存関係チェックの後で、有効かつ停止している対象のサービスのみを開始します。キューにある既存のレポートが、現在のポリシーに従って再開する場合があります。レポートのアーカイブ、ダンプ、同意、アップロードのポリシー、スタートアップの種類は保持されます。アップロードや削除は要求されません。検証の対象はサービスの安定した状態のみで、レポートの作成、アップロード、配信、問題の解決、クラッシュの診断は含まれません。

Windows イベント コレクター

範囲を限定した Windows イベント コレクターのサブスクリプション一覧、サービスの正確な障害履歴、サービスの現在の準備状態を確認します。一覧が空なのは意図的な場合があり、サブスクリプションの数や過去の障害によって回復が許可されることはありません。オプションの回復では、新たな依存関係チェックの後で、有効かつ停止している対象のサービスのみを開始します。既存のサブスクリプションによって、リモートのイベント収集が再開する場合があります。サブスクリプション、転送されたイベント、資格情報、チャネルの設定、ポリシー、スタートアップの種類は保持されます。検証の対象はサービスの安定した状態のみで、ソースへの到達、認証、リモート配信、イベントの新しさ、サブスクリプションの正常性は含まれません。

Windows イベント ログ

4 つの診断チャネルについて、有効状態、保持モード、現在のサイズ、構成された上限、レコード数、使用率を確認した後、Windows イベント ログ サービスの可用性を確認します。自動修復では、依存関係を確認した後で停止している有効なサービスを開始し、実行中の状態を検証できます。個別に確認する対象限定の操作では、報告されたほかのすべての設定を保持したまま、管理されていない無効な診断チャネルを 1 つだけ有効にできます。ログ、チャネルのアクセス許可、保持、サイズの上限、スタートアップの種類、管理された設定は保持されます。イベントの配信の成功とアーカイブの容量は未検証のままです。

Windows Time サービス

Windows Time の構成、サービス、同期を確認します。現在の状態が正確に停止中のサービスのエラーを報告し、ポリシー、モード、依存関係の新たなチェックに合格した場合、自動修復で W32Time を開始し、再同期を要求して新しい状態を検証できます。これにより、既存の構成済みソースを使って時計が調整される場合があります。スタートアップの種類、ソースの構成、管理された設定は保持されます。

タスク スケジューラ サービス

スケジュールされたタスクの状態、実行結果、実行されなかった回数を範囲を限定して一覧にし、サービスの現在の可用性を確認する前に、タスク スケジューラ サービスの正確な障害履歴と組み合わせます。タスクの所見やサービスの過去の障害によって、サービスの開始が許可されることはありません。オプションの回復では、新たな依存関係チェックの後で、有効かつ停止している対象のサービスのみを開始します。既存の有効なタスクが、実行されなかったトリガーを含め、構成されたアカウントで開始される場合があります。タスクの定義、プリンシパル、資格情報の参照、ポリシー、スタートアップの種類は変更されず、タスクを直接開始したり削除したりすることもありません。検証の対象はサービスの安定した状態のみで、アクションの成功、資格情報の有効性、今後のタスクの結果は含まれません。

ユーザー プロファイル サービス

ユーザー プロファイル サービスの可用性を確認します。オプションの回復では、新たな依存関係チェックの後で、有効かつ停止している対象のサービスのみを開始します。既存のサインインとプロファイルの要求が再開する場合があります。プロファイル フォルダー、レジストリ ハイブ、アクセス許可、プロファイル一覧の登録、資格情報、ユーザー データ、ポリシー、サービスのアクセス許可、スタートアップの種類は保持されます。プロファイルの操作は要求されません。検証の対象はサービスの安定した状態のみで、サインイン、プロファイルの読み込み、ユーザー データへのアクセスは含まれません。

バックアップ サービス

Volume Shadow Copy、Microsoft Software Shadow Copy Provider、Windows Backup、Block Level Backup Engine の各サービスを確認し、VSS ライターの状態、登録されたプロバイダーの種類、現在のスナップショット、シャドウ ストレージの割り当てを読み取ります。停止している手動開始のサービスは、アイドル時には正常な場合があります。オプションの回復では、依存関係を確認した後で停止している自動開始のサービスのみを開始し、実行中の状態を検証します。スケジュールされたバックアップや中断されたバックアップの既存の作業が再開する場合があります。無効と手動開始のスタートアップ設定、スナップショット、シャドウ ストレージ、プロバイダーの登録、バックアップ計画、カタログ、スケジュール、保存先、資格情報、保持期間は保持されます。バックアップの選択や再構成、サービスの再起動、スナップショットやカタログの削除は行いません。プロバイダーの登録、ライターの状態、ストレージの割り当て、サービスの安定した状態は、バックアップの完了、保存先へのアクセス、復元の成功を検証するものではありません。

更新では、Windows Update、それを支えるサービス、コンポーネント ストアを扱います。インストール済みのもの、保留中のもの、更新が失敗する理由を確認でき、インストールするものを選ぶ前に利用可能な更新プログラムを確認できます。

手順ガイド: Windows Update を修正する と システム ファイルを修復する。

このセクションのツール

サービシングの活動を監視し、利用可能な更新プログラムを確認し、Windows Update のチェーンを修復します。

サービシング アクティビティ モニター

Windows Update と Setup のサービシング活動を、1 回または複数回のスナップショットで範囲を限定して観察します。オプションでは、更新の間隔と、更新イベント、更新履歴、Windows Update の正確なスケジュール タスク、サービスの正確な状態、再起動のインジケーター、現在のアカウントのバックグラウンド転送、配信の最適化の活動、プライバシーに配慮して範囲を限定した Windows Installer の活動を含めるかどうかを制御します。プロセス ID、コマンド ライン、ユーザー、パスは除外されます。活動は、進行、完了、停止、障害を証明するものではありません。更新、セットアップ、転送、タスク、サービス、プロセス、ポリシー、再起動、修復の操作は要求されません。

利用可能な更新プログラム

構成されたソース、Windows Update、またはすでに登録されている Microsoft Update サービスを使って、選択したソフトウェアとドライバーの更新プログラムを検索します。検索の前にソースの準備状態を確認します。検索ではインストール、ライセンスの同意、ソースの登録、ポリシーの変更は行いません。選択した更新プログラムは、確認のチェックボックスをオンにした後でのみ、別途インストールできます。これはサービシングの修復とは別の機能です。

Windows Update

Windows のサービシング パッケージ、オプション機能、機能の状態を範囲を限定して一覧にし、再起動のインジケーター、空き容量、更新サービスを確認し、配信の最適化を開始せずに観察してから、コンポーネント ストアと保護されたシステム ファイルをスキャンします。パッケージ、オプション機能、機能が保留中の状態であれば確認が求められますが、コンポーネントの操作が許可されることはありません。自動修復では、停止していて自動開始に設定されている Windows Update、BITS、暗号化サービス、Windows Modules Installer、Update Orchestrator の各サービスを開始できます。停止している手動開始のサービスは報告するだけで、開始しません。Update Orchestrator を開始すると、既存のスケジュールされた更新活動が現在のポリシーに従って再開する場合があります。パッケージ、オプション機能、機能、配信の最適化のキャッシュ、ピア、帯域幅、ポリシー、ソースの登録、スケジュール、スタートアップの設定は保持されます。DISM や SFC には破損のライブの証拠が必要です。このワークフローが更新プログラムを選択または承認することはありません。

Windows Update サービス

Windows Update サービスの正確な状態、登録されたサービス DLL、範囲を限定した現在の更新活動、サービスの正確な障害履歴を確認します。DLL の観察、更新活動、過去の障害によって、サービスの開始や更新の操作が許可されることはありません。オプションの回復では、依存関係と実行可能ファイルの登録を新たに確認した後で、停止している自動開始のサービスのみを開始します。停止している手動開始のサービスは情報として扱われます。既存の更新活動が、現在のポリシーに従って再開する場合があります。更新ポリシー、ソースの登録、スケジュール、再起動の設定、パッケージ、BITS ジョブ、サービスのアクセス許可、スタートアップの種類は保持されます。KillerBench が更新プログラムを選択、承認、インストールすることはありません。検証の対象はサービスの安定した状態のみで、ソースへの到達、適用可能性、ダウンロード、インストール、完了、再起動の準備状態は含まれません。

配信の最適化

配信の最適化サービスの正確な状態を確認します。停止している手動開始のサービスは情報として扱われます。回復が提示されるのは、正確に Paused の状態の場合のみです。オプションの回復では、状態の確認を繰り返し、範囲を限定した続行要求を 1 回送信して、一貫した Running の観察を 2 回必要とします。スタートアップの種類、キャッシュの内容、ピア、帯域幅、更新ソース、管理されたポリシーは保持されます。転送の活動、キャッシュの正常性、更新の進行と完了は未検証のままです。

BITS サービス

Background Intelligent Transfer Service の正確な状態、現在のアカウントの転送ジョブ、範囲を限定したサービスの正確な障害履歴を確認します。過去の障害や転送のスナップショットによって、サービスの開始が許可されることはありません。オプションの回復では、新たな依存関係チェックの後で、対象のサービスが停止していて自動開始に設定されている場合にのみ、そのサービスを開始します。停止している手動開始のサービスは情報として示すだけです。既存のアプリケーションが、キューにあるバックグラウンド転送を再開する場合があります。ジョブ、優先度、所有者、転送先、プロキシ設定、ポリシー、スタートアップの種類は保持されます。検証の対象はサービスの安定した状態のみで、転送の進行、アプリケーションの所有、完了は含まれません。

バックグラウンド転送 (BITS)

選択したアカウント範囲の BITS 転送ジョブを読み取り、ジョブの正確な識別情報を確認します。キュー名によってアプリケーションの所有が確定することはありません。転送の再開、完了、キャンセル、削除、再割り当ては行いません。

暗号化サービス

暗号化サービスの正確な状態、登録されたサービス DLL、範囲を限定したサービスの正確な障害履歴を確認します。過去の障害や DLL の観察によって、サービスの開始やコンポーネントの置き換えが許可されることはありません。オプションの回復では、新たな依存関係チェックの後で、対象のサービスが停止していて自動開始に設定されている場合にのみ、そのサービスを開始します。停止している手動開始のサービスは情報として示すだけです。既存のカタログ、証明書、更新の操作が再開する場合があります。証明書、キー、カタログ、信頼の設定、ポリシー、スタートアップの種類は保持されます。検証の対象はサービスの安定した状態のみで、証明書、署名、カタログ、信頼の検証は含まれません。

Windows Modules Installer

Windows Modules Installer の正確な状態、範囲を限定したサービシング パッケージの遷移、サービスの正確な障害履歴を確認します。過去の障害やパッケージの状態によって、サービスの開始やパッケージの操作が許可されることはありません。オプションの回復では、新たな依存関係チェックの後で、対象のサービスが停止していて自動開始に設定されている場合にのみ、そのサービスを開始します。停止している手動開始のサービスは情報として示すだけです。既存のサービシング活動が再開する場合があります。パッケージ、コンポーネント ストアの内容、ソース、ポリシー、スタートアップの種類は保持されます。検証の対象はサービスの安定した状態のみで、コンポーネント ストアの正常性、パッケージの適用可能性、サービシングの完了、再起動の準備状態は含まれません。

Windows Update Medic サービス

Windows Update Medic サービスの正確な状態、登録されたサービス DLL、範囲を限定した現在の更新活動、サービスの正確な障害履歴を確認します。DLL の観察、更新活動、過去の障害によって、サービスの開始やコンポーネントの操作が許可されることはありません。停止している手動開始のサービスは正常な場合があります。このツールを選択した場合に限り、オプションの回復では、新たな依存関係チェックの後で、停止している有効なサービスのみを開始できます。Windows による修復が現在のポリシーに従って再開し、更新コンポーネントを修復したり更新活動を引き起こしたりする場合があります。更新ポリシー、ソースの登録、スケジュール、パッケージ、BITS ジョブ、再起動の設定、サービスのアクセス許可、スタートアップの種類は保持されます。KillerBench は更新プログラムを選択せず、更新の設定も変更しません。検証の対象はサービスの安定した状態のみで、修復、コンポーネントの正常性、適用可能性、ダウンロード、インストール、再起動の準備状態は含まれません。

Update Orchestrator サービス

Update Orchestrator サービスの正確な状態、組み込みの Windows Update の正確なタスク、範囲を限定した現在の活動、サービスの正確な障害履歴を確認します。タスクの結果、更新活動、過去の障害によって、サービスの開始や更新の操作が許可されることはありません。オプションの回復では、依存関係と実行可能ファイルの登録を新たに確認した後で、停止している自動開始のサービスのみを開始します。停止している手動開始のサービスは情報として扱われます。既存のスケジュールされた更新活動が現在のポリシーに従って再開し、すでに承認された更新プログラムをダウンロードまたはインストールする場合があります。更新ポリシー、ソースの登録、スケジュール、再起動の設定、パッケージ、BITS ジョブ、サービスのアクセス許可、スタートアップの種類は保持されます。KillerBench が更新プログラムを選択または承認することはありません。検証の対象はサービスの安定した状態のみで、適用可能性、ダウンロード、インストール、完了、再起動の準備状態は含まれません。

BitLocker ツールを使う

ドライブ文字と 操作 を選び、診断を実行 を押します。

  • 検査 は、暗号化の状態、保護の状態、保護機能の識別情報を読み取ります。これが既定で、何も変更しません。
  • 回復情報のバックアップ は、選択した回復パスワードを保護対象のドライブ以外の新しいファイルに書き込み、検証します。先に 回復用の保護機能を検索 を押して保護機能を選び、その後でバックアップを確認します。
  • 暗号化 は、選択した回復パスワードをバックアップしてそのバックアップを検証し、選んだ方式で暗号化を 1 回だけ開始します。Windows ドライブには TPM 保護機能と回復パスワードが必要です。データ ドライブに必要なのは回復パスワードだけです。
  • 保護の再開 は、完全に暗号化されていて保護が中断されているドライブの保護をオンに戻します。

いずれの操作にも専用の確認ボックスが必要で、KillerBench は実行の直前にドライブを再確認します。

その他の BitLocker 操作

診断を実行 の対象外の変更には、その他の BitLocker 操作 を開きます。操作を選び、プレビュー を押して必要な条件を正確に確認してから、承認して 操作を実行 を押します。

  • TPM 保護機能を追加 または 回復パスワードを追加 は、新しい保護機能を 1 つ作成します。KillerBench が新しい回復パスワードを表示したりログに記録したりすることはないため、すぐにバックアップしてください。
  • 回復パスワードを Active Directory にバックアップ または Microsoft Entra ID は、上で選択した保護機能を送信します。KillerBench は Windows が要求を受け付けたことを報告します。ディレクトリ上のコピーは読み取れないため、そちらで確認してください。
  • このドライブを暗号化解除 は、必要な方式で再度暗号化する前などに暗号化の解除を開始します。解除後はドライブが保護されなくなるため 2 回目の確認が必要で、ほかのドライブが Windows ドライブから自動ロック解除されている間は、Windows ドライブに対しては拒否されます。

プライモーディアル以外の記憶域スペースのプールと仮想ディスクを、正常性、動作状態、容量、割り当て、回復性を含めて一覧にし、範囲を限定した 1 つの動作に関する結論を返します。この読み取り専用のクエリに応答する間、Windows が記憶域スペース管理プロバイダーを要求時に開始する場合があります。プール、仮想ディスク、物理ディスク、ボリューム、回復性、割り当て、メンテナンス設定、ポリシー、スタートアップの種類は保持されます。プール、ディスク、ボリューム、割り当て、接続、修復、最適化、設定の操作は要求されません。プロバイダーの結果は、プールへのアクセス、冗長性、データの整合性、バックアップからの回復可能性、アプリケーションの I/O を検証するものではありません。

ストレージ サービス

Storage モジュールの現在のジョブ、サービスの正確な障害履歴、ストレージ サービスの現在の準備状態を、範囲を限定して確認します。不完全な証拠が優先されます。ジョブの状態や過去の障害によって、サービスの回復やストレージの変更が許可されることはありません。オプションの回復では、新たな依存関係チェックの後で、有効かつ停止している対象のサービスのみを開始します。既存のストレージ通知とポリシーで管理されたストレージの活動が再開する場合があります。ボリューム、パーティション、ファイル システム、マウント ポイント、デバイス、ドライバー、ストレージ センサーの設定、メンテナンス ポリシー、サービスのアクセス許可、スタートアップの種類は保持されます。KillerBench は、ジョブ、ボリューム、パーティション、マウント ポイント、ファイル、デバイス、ドライバー、ストレージ設定の操作を選択しません。検証の対象はサービスの安定した状態のみで、ジョブの結果やデバイス、ボリューム、ストレージ ポリシーの動作は含まれません。

ドライブの最適化サービス

ドライブの最適化サービスの可用性を確認します。オプションの回復では、新たな依存関係チェックの後で、有効かつ停止している対象のサービスのみを開始します。Windows がスケジュールした既存の最適化の活動が、現在のメンテナンス ポリシーに従って再開する場合があります。ボリューム、ファイル システム、データ、最適化のスケジュール、メンテナンス ポリシー、サービスのアクセス許可、スタートアップの種類は保持されます。KillerBench がボリュームを選択したり、ドライブの分析、トリム、デフラグ、最適化、スケジュール設定を行ったりすることはありません。検証の対象はサービスの安定した状態のみで、分析、最適化、デバイスの正常性は含まれません。

リファレンス

実行のたびに、読む、フィルターする、エクスポートすることができるレポートが作成されます。レポートでは、証明されたことと観察されただけのことが常に区別されます。

表示される状態

状態意味

生の出力と読みやすいレポート

生の出力 は、技術的な証拠を元の行番号とともに保持するため、どの結論もそのソースまでたどることができます。読みやすいレポート は、同じ実行をわかりやすい言葉で要約し、安全な次の手順を最初に示します。

保存されたログ

KillerBench は、コンピューターで何も実行せずに、CBS や Setup のログなど保存済みの Windows ログを読み取ることもできます。結論は、それを生み出した行に正確にリンクします。セッションソースの サンプルを読み込む を使うと、安全に試せる合成の例が開きます。

エクスポート

レポートをエクスポート は、ソースのパス、解析済みのエントリ、証拠の抜粋を含めてレポートを保存するため、チケットに添付する前に確認できます。エクスポートしたレポートにはこのコンピューターの名前が含まれ、生のログや証拠の抜粋にも、アカウント、パス、機密性のあるソース テキストが含まれる可能性があります。保護付きのコレクターは保持する内容を制限しますが、インポートした証拠が編集済みである保証はありません。共有する前に機密情報を確認して削除してください。

killerbench-cli は、デスクトップ アプリと同じ Engine を PowerShell やリモート コンソールから実行します。コンピューターを変更する可能性のあるコマンドは、すべて既定でプレビューを表示し、実行するには --execute などの明示的なフラグが必要です。コマンドは JSON の証拠を標準出力に、進行状況を標準エラーに出力します。

手順ガイド: スクリプトから KillerBench を実行する。

終了コード 0 はプレビューまたは検証済みの結果が成功したこと、1 は起動、入力、ジャーナルのエラー、2 は引数を認識できなかったこと、3 はブロック、失敗、または未検証、4 はワークフローの検証の前に再起動が必要なこと、130 はユーザーが停止したことを意味します。

引数なしで killerbench-cli を実行すると、お使いのコンピューターでこの一覧を表示できます。

操作がブロックされたと表示される

ブロックされたという結果は、要求した操作を続行できなかったことを意味します。メッセージとジャーナルを読み、送信前に停止したのか、前の手順の後で停止したのかを確認してください。一部だけ完了した操作がロールバックされたとは考えないでください。よくある前提条件の理由を以下に示します。

  • 管理者アクセスが必要です。 KillerBench を閉じ、管理者として実行 でもう一度起動してください。
  • 再起動の状態が解消されている必要があります。 Windows が再起動を待っています。コンピューターを再起動してから、もう一度操作を実行してください。
  • 管理されたポリシーがあります。 グループ ポリシーまたはデバイス管理がその設定を所有しています。そちらで変更してください。
  • 証拠が変化しました。 最初のチェックから最終確認までの間に何かが変わりました。ツールをもう一度実行して新しい状態を読み取ってください。

以前の要求の照合が必要

KillerBench が、中断された要求の保留中のレコードを見つけました。同じ操作をもう一度実行してください。何が起きたかを確認し、要求を繰り返さずに実際の結果を報告します。コマンド ラインでは、対応する -recover コマンドを使います。例: killerbench-cli bitlocker-auto-unlock-recover。

チェックに未完了または不明と表示される

証拠を読み取れませんでした。多くの場合、KillerBench が管理者として実行されていないか、Windows のサービスが利用できなかったことが原因です。KillerBench はコンピューターが正常だと仮定せず、このことを正直に報告します。

ファイルの保存場所

ジャーナル、保留中のレコード、保存した証拠は %LOCALAPPDATA%\KillerBench にあります。保護付きの操作ごとに専用のフォルダーがあります。変更内容の記録が必要な場合は保持してください。

問題を報告する

KillerBench は開発中です。問題を報告するときは、エクスポートしたレポートとアクティビティ ログを添付し、共有したくない内容は削除してください。
