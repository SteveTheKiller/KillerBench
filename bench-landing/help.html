Start here

KillerBench is a Windows diagnostic and repair workbench for technicians. It checks a computer first, explains what it found with the evidence behind each finding, and only changes Windows when you pick a specific fix and confirm it.

KillerBench is in development. There is no public download yet. These pages describe the current build.

What it does

  • Runs read-only diagnostics across Windows Update, devices, storage, networking, printing, security, apps and profiles, then writes a readable report.
  • Offers guarded repairs that run only when fresh evidence proves the exact problem, and verifies the result afterwards.
  • Covers setup and hardening work such as BitLocker, privacy settings, decluttering Windows and onboarding a new computer.
  • Runs diagnostics and report analysis locally without AI or a KillerBench account. Selected actions, such as downloads and recovery-key backup to Entra ID, can contact external services.
  • Uses the active app theme for the console, reports, confirmations, and Open, Save, and Folder dialogs.

Windows and runtime

  • The current publish target is Windows x64. Windows 11 x64 is the current native validation baseline. Native ARM64, x86 and Windows Server distributions are not provided.
  • KillerBench is packaged two ways. The installer is framework-dependent and requires .NET Desktop Runtime 10 for Windows x64. The plain .NET Runtime, ASP.NET Core Runtime and .NET Framework do not supply WPF. The portable edition carries its own runtime and needs no separate install. The command-line tool killerbench-cli.exe needs the .NET 10 Runtime for Windows x64. An SDK is needed for development, not for ordinary use.
  • Use a Windows version supported by .NET 10 on Windows. Runtime support is not a claim that KillerBench repairs are validated on every supported edition or build. Windows 10 coverage remains pending and its supported editions are limited by Microsoft's current lifecycle requirements.
  • Obtain the Desktop Runtime only from Microsoft's .NET 10 download page, choosing .NET Desktop Runtime, Windows, x64. Follow your organization's software-installation rules.

If dotnet is available, dotnet --list-runtimes should list Microsoft.WindowsDesktop.App 10.0.x for the x64 installation. A runtime installed only for another architecture does not satisfy the x64 installer package.

When a package is published

  1. Use the official download linked from this website. No KillerBench download link is active yet.
  2. Read that package's requirements, GPLv3 license, Corresponding Source instructions, included third-party notices, signature and checksum information. A filename alone does not establish authenticity.
  3. Run the installer for the current account, or for all users after an elevation prompt. It adds a Start menu shortcut, an optional desktop shortcut and an Add or Remove Programs entry. The portable edition runs without installation.
  4. Start KillerBench as your normal account and follow Your first diagnosis. Diagnostic access failures stay visible; elevation is a separate deliberate choice.

Do not bypass Windows security warnings to run an unverified copy. Keep a current backup before selecting any action that changes the machine.

At startup KillerBench checks GitHub for a newer stable release and asks before installing it. The download must match the published SHA-256 checksum. Turn the check off with Check for updates on startup in About.

Start with Download and setup, then run a Full system scan. It collects diagnostic evidence and saves a local journal; it does not run repairs. A finding describes the inspected scope, not every possible fault on the computer.

Run the scan

  1. Open KillerBench. The Diagnostics section opens with Full system scan selected.
  2. Leave Auto-repair confirmed issues turned off for your first run.
  3. Press Run diagnosis. Progress appears in Raw output on the right while each check runs.
  4. When it finishes, the output pane switches to the Readable report.

Start without elevation. Some Windows evidence, such as BitLocker protectors and protected services, needs administrator rights. Those checks report unavailable evidence under a standard account. If you need that evidence, finish the current run, keep the report, then deliberately reopen KillerBench with Run as administrator. Elevation does not select or approve a repair.

Read the report

The report starts with counts for Needs review, Verified repairs, Incomplete and Checked, then a recommended next step.

  • What needs attention lists problems the evidence supports, most important first.
  • Collected information shows what was read, including evidence that was incomplete or unavailable.
  • Historical events are labeled as history. An error from last month is not treated as a current fault.

Missing evidence never counts as healthy. If a check could not run, the report says so.

Choose checks yourself

Open Choose checks (advanced) to pick individual checks instead of the full scan. Each section in the app also has focused tools, described in the Sections pages of this guide.

Fix what you found

When the report recommends a fix, it names the section and tool to open. Read How changes stay safe before your first repair. Native validation is still in progress; a successful diagnosis does not establish that every offered repair has been tested on your Windows build. Keep backups and review the exact target and consequences before any change.

The KillerBench window has three panes that follow the way you work: pick a section on the left, set the tool's options in the center, and read the output on the right. An activity log can open under the options.

Sections

The sidebar on the left lists every tool in twelve sections: Diagnostics, Repair, Updates, Devices, Network, Apps, Maintenance, Onboarding, Security, BitLocker, Privacy and Storage. Drag its edge to resize it, or drag it past its minimum width to snap it closed.

Tool options

The center pane shows the selected section, its tool list and the options for the chosen tool. Options that could change the machine are always off by default. Press Run diagnosis to start the tool. When Auto-repair confirmed issues is turned on, the same button reads Run repair. Stop ends the run after the current command finishes.

Output

The output pane on the right has two views.

  • Raw output shows the technical evidence as it is collected, with original line numbers. It opens on its own while a tool runs.
  • Readable report shows the finished report for the last run. It replaces the raw output when the run finishes.

Use the filter box in Raw output to show only matching lines. Export report saves the report with its source paths and evidence excerpts. Session sources lists every piece of evidence gathered in this session.

Activity log

The activity log under the tool options records what KillerBench did in this session.

Themes, languages and shortcuts

The rail between the sidebar and the tool options holds the theme picker, the language picker, the shortcut list and the activity log toggle. KillerBench has 13 themes and 20 languages.

The smoked-glass console and readable reports follow the active theme. Confirmations and Open, Save, and Folder dialogs use the same family styling, including the 98SE theme. Choose the theme before opening a dialog to use that appearance throughout the workflow.

KillerBench treats diagnosis and change as different jobs. Diagnosis only reads. The full system scan never runs repairs. Select a specific repair or action, review its options and prerequisites, and confirm the proposed change.

Before a change

  1. Fresh evidence. The tool reads the current state again. A saved report or an old event never authorizes a change.
  2. Exact eligibility. The change is offered only when the evidence matches the exact problem it fixes. Anything incomplete blocks it.
  3. Your confirmation. Review the selected action in its confirmation dialog. Some actions, such as decrypting a drive, need a second confirmation. The dialog follows the active app theme; its appearance does not change the action's requirements.
  4. Prerequisites. Administrator rights, restart state and ownership by policy or device management are checked. Settings that a policy owns are left alone.
  5. A pending record. KillerBench writes down what it is about to do before it asks Windows to do it.
  6. A final recheck. Everything is checked again immediately before the request, so a change in the meantime stops it.

After a change

  • KillerBench reads the result back and reports Verified only when Windows shows the expected state.
  • If Windows returns success but the state did not change, the result says so and nothing is repeated.
  • Each change is saved in a journal under %LOCALAPPDATA%\KillerBench.

If something is interrupted

Supported journaled actions retain a pending record when a request may have reached Windows and verification has not completed. Use the action's documented reconciliation path, or its matching -recover command, to inspect that record. Reconciliation is not an automatic rollback. Keep the journal when an outcome is uncertain, and do not manually repeat the change. Crash, cancellation and later-boot behavior still need action-specific native validation.

What KillerBench will not do

  • Clear a TPM, delete protectors it did not create, or display recovery passwords.
  • Change a setting that group policy or device management controls.
  • Run a repair just because a historical event or imported report mentions a problem.

Diagnostics and report analysis run locally. An action you select can contact an external destination, including software downloads or recovery-key backup to Active Directory or Entra ID. Review the target before confirming. Saved captures and raw evidence can include machine identity and source paths, so review them before sharing.

Development status

Repair coverage is still expanding. A successful build or simulated check does not establish native repair behavior.

How-to guides

Use this when updates fail, stall or keep reinstalling. KillerBench reads the update chain first, explains the failure with the evidence behind it, and only starts a service or repairs the component store when fresh evidence proves that exact problem.

Before you start

  • Run KillerBench as administrator. Update services, the component store and protected system files need elevation for complete evidence.
  • Restart first if Windows already has a restart pending. Many update repairs are blocked until restart readiness is clear.
  • Keep the computer on AC power for servicing work.

Find out why updates fail

  1. Open Updates and choose Windows Update in the tool sidebar.
  2. Leave Auto-repair confirmed issues off for the first pass and press Run diagnosis.
  3. Read the Readable report. It lists stopped update services, pending restarts, low free space, component-store corruption and the exact error codes Windows recorded, with a recommended next step.
  4. If the report names an error code, the matching follow-up checks run automatically. You can also look one up yourself with killerbench-cli update-code 0x80070002.

Watch an update that seems stuck

Choose Servicing activity monitor in Updates and press Run diagnosis. It takes repeated snapshots of update, Setup and Installer activity, transfer totals and restart indicators. Activity is shown as evidence only; it never claims a stall or a fault on its own.

Repair what the report found

  1. Run Windows Update again with Auto-repair confirmed issues turned on. It can start enabled update services that are confirmed stopped, and it runs DISM or SFC only when the live check confirms corruption.
  2. For a single service, choose its focused tool instead, such as BITS service, Cryptographic Services, Windows Modules Installer or Update Orchestrator Service. Each one offers recovery only for that exact service.
  3. When the report says to restart, restart before running anything else. KillerBench records restart-required outcomes and defers later work until the restart is done.

Every repair is journaled and read back. See How changes stay safe for the full sequence.

Install a specific update

  1. Choose Available updates in Updates and press Run diagnosis to discover updates from the configured source.
  2. Select the updates you want and press Preview selected. The preview lists exactly what would install and any restart requirement.
  3. Read the preview, tick the confirmation checkbox, then press Install. The checkbox clears after each run, and KillerBench never selects or approves an update for you.

From the command line

killerbench-cli update-search
killerbench-cli update-history
killerbench-cli servicing-monitor --samples 10
killerbench-cli update-plan --select GUID:REVISION --execute

See update-search, update-history, servicing-monitor and update-plan. If an install was interrupted, run update-recover; it checks the outcome and never retries the update.

Use this when Windows components are corrupted: features fail to install, updates report component errors, or system tools crash. KillerBench runs DISM and SFC only after a live check confirms corruption, then verifies the result.

Before you start

  • Run KillerBench as administrator.
  • Clear any pending restart first.
  • If the machine is managed, check whether policy points DISM at a specific repair source. KillerBench reports that policy and does not change it.

Check for corruption

  1. Open Repair and choose System files.
  2. Leave Auto-repair confirmed issues off and press Run diagnosis.
  3. Read the report. It inventories servicing package, optional-feature and capability states, checks prerequisites and scans protected system files. A clean result means no repair is offered.

Repair confirmed corruption

  1. Turn on Auto-repair confirmed issues and press Run repair. KillerBench chooses DISM or SFC only when the live check confirms corruption.
  2. Wait for verification. The report shows Verified only when the follow-up check reads back a repaired state.
  3. If the report says the store is unrecoverable or the repair source is unavailable, stop there. Repeating the repair will not change the outcome.

An interrupted DISM or SFC run is reconciled on the next boot without repeating the servicing command.

Clean up the component store

Choose Component-store cleanup in Updates. It first asks Windows whether cleanup is recommended. Optional maintenance removes superseded components and analyzes again. It never uses ResetBase and never deletes WinSxS content by hand.

From the command line

killerbench-cli component-repair-source
killerbench-cli repair dism
killerbench-cli repair sfc --execute
killerbench-cli servicing-logs

See component-repair-source, repair and servicing-logs. repair previews by default and acts only with --execute.

Use this when a drive is running low. KillerBench shows where space is going, previews what each cleanup target would remove, and deletes only after you turn on permanent cleanup.

See how much space is left

  1. Open Storage and choose Storage.
  2. Press Run diagnosis. The report flags every drive-letter volume under 10% free space and shows shadow-copy allocation, quota defaults and Storage Sense policy.
  3. For crash dumps and old update content, also run Vitals in Diagnostics and Windows Update in Updates; the update cache size appears there.

Preview a cleanup

  1. Open Maintenance and choose Cleanup.
  2. Tick the targets you want, such as Current user temporary files, Windows temporary files, Current user browser caches, Delivery Optimization cache or Current user Recycle Bin. Hover a target to read exactly which folders it covers.
  3. Set Minimum age (days) and Maximum files per target.
  4. Press Run diagnosis with Perform the selected permanent cleanup after fresh checks turned off. The report lists candidates and estimated space for each target. Nothing is deleted.

Remove the files

  1. Turn on Perform the selected permanent cleanup after fresh checks and press Run diagnosis.
  2. KillerBench rechecks every candidate before removing it, skips files that are recent, protected or in use, and records each outcome in the journal.

Permanent cleanup bypasses the Recycle Bin and cannot be undone. Removing error reports and crash dumps discards evidence you may need to investigate crashes, so review those first.

Remove the previous Windows installation

After a feature upgrade, Previous Windows installation in Cleanup can remove the rollback copy through the supported Windows rollback-removal request. It runs by itself, needs I backed up any files and settings I need from the previous installation, and permanently removes the ability to go back to the earlier version.

From the command line

killerbench-cli volume-capacity C:
killerbench-cli cleanup --user-temp --windows-temp --days 7 --max-files 500
killerbench-cli cleanup --user-temp --windows-temp --days 7 --max-files 500 --execute

See volume-capacity, cleanup and previous-windows.

Use this when a volume reports errors, Windows asks to scan a drive, or files fail to open. KillerBench checks the volume read-only first and only schedules or runs a filesystem repair after you confirm a backup.

Before you start

  • Back up important data on the volume. A filesystem repair can change or remove damaged files.
  • Run KillerBench as administrator.

Check the volume

  1. Open Storage and choose Storage.
  2. Pick the drive in Volume to check and press Run diagnosis.
  3. Read the report. It shows disk and volume health, the dirty bit, online NTFS self-healing, controller and disk device errors, reliability counters and recent storage events such as resets, retries and unexpected removal.

A clean check means no repair is offered. Disk temperature, wear and uncorrected I/O counters are review evidence and do not trigger a repair by themselves.

Repair the filesystem

  1. Press Review filesystem repair and choose Spot repair or Offline scan and repair.
  2. For a data volume, tick Allow a non-system volume to go offline if you can close everything that uses it. The Windows volume cannot go offline, so its repair is scheduled for the next restart instead.
  3. Tick Important data on this volume is backed up.
  4. Confirm the repair. KillerBench rechecks the exact volume immediately before it acts and records a pending entry first.
  5. For a scheduled repair, restart when convenient. KillerBench verifies the result after the restart without running the repair again.

Optimize or retrim

The same tool can analyze the volume and run the Windows-recommended optimization, Retrim solid-state storage or a hard-disk defragmentation. Each is a separate confirmed action on one exact healthy volume.

From the command line

killerbench-cli storage-check C
killerbench-cli storage-repair-plan D: OfflineScanAndFix --allow-dismount
killerbench-cli storage-repair D: OfflineScanAndFix --allow-dismount --backup-confirmed --execute
killerbench-cli storage-repair-recover

See storage-check, storage-repair-plan, storage-repair and volume-optimize.

Use this when a computer has no internet, cannot reach a server or name, or keeps dropping its connection. KillerBench checks the adapter, address, gateway, DNS and firewall in order, and only renews a lease or starts a service when fresh evidence proves it is needed.

Check the connection

  1. Open Network and choose Network.
  2. To test something specific, fill in Hostname lookup (optional), or TCP destination (optional) and TCP port. Leave them blank to check only the local configuration. No application data is sent.
  3. Set Timeout per lookup or connection (seconds) if the network is slow.
  4. Leave Auto-repair confirmed issues off and press Run diagnosis.
  5. Read the report. It separates a missing address, a missing or unreachable gateway, DNS configuration problems, proxy settings, firewall profile mismatches and a failed lookup or connection, and gives the next step for each.

A reply from the gateway does not prove internet access, and a failed lookup through your configured resolver does not mean the site is down.

Repair what the report found

  1. Run Network again with Auto-repair confirmed issues turned on. It can start enabled DNS Client, DHCP Client, SMB client, Network Location Awareness, Network List and IP Helper services, and renew connected physical DHCP adapters that lack a usable IPv4 address.
  2. Expect the connection to drop briefly during a renewal. Static addresses and virtual adapters are never changed.
  3. For one bad cached name, use the DNS cache flush for that exact host instead of clearing everything.

Routes, Hosts entries, DNS servers, firewall rules, Winsock providers and network profiles are always preserved.

Wireless, wired sign-in and proxies

  • Wireless networking checks the adapter and WLAN AutoConfig, and can start the service if it is stopped.
  • Wired authentication (802.1X) does the same for Wired AutoConfig on networks that need sign-in at the port.
  • WinHTTP Auto-Proxy shows stored proxy settings for the machine and the current account. KillerBench never fetches a PAC URL or changes proxy settings during diagnosis.

From the command line

killerbench-cli workflow network --host example.com --tcp example.com 443
killerbench-cli dns-check example.com --timeout-seconds 5
killerbench-cli tcp-check fileserver 445
killerbench-cli dhcp-renew
killerbench-cli dns-cache example.com --execute

See workflow, dns-check, tcp-check, dhcp-renew and dns-cache.

Use this when jobs sit in the queue, a printer shows offline, or the wrong printer is the default. KillerBench reads the spooler, queues, jobs, drivers and ports first, then lets you fix one exact queue or job.

Check the printers

  1. Open Devices and choose Printing.
  2. Press Find local printers and pick the queue that is misbehaving. To check every queue, choose Use general printing checks.
  3. Leave Auto-repair confirmed issues off and press Run diagnosis.
  4. Read the report. It shows the Print Spooler state, paused queues, offline mode, visible jobs, driver conditions, port registrations, recent PrintService errors and, for network printers, one connection attempt to the printer's assigned address.

A successful connection or a clean condition code does not prove the printer has paper, toner or a working mechanism.

Repair the queue

  1. Run Printing again with Auto-repair confirmed issues turned on. It can start the enabled spooler, resume an exact paused queue that has jobs waiting, and clear offline mode.
  2. Clearing offline mode can release waiting jobs, so make sure those jobs should still print.
  3. A queue someone paused on purpose with nothing waiting stays paused.

Clear one stuck job

  1. Press Find blocked print jobs.
  2. Select the job that shows Error or Blocked and tick Cancel only this selected job.
  3. Press Run diagnosis. Only that job is canceled, and the result is read back.

Fix the default printer

Choose the queue that should be the default and tick Repair a missing or conflicting default with this queue, then press Run diagnosis. This only acts when the default is missing or conflicting.

From the command line

killerbench-cli printer-list
killerbench-cli printer-check --queue "Office Laser"
killerbench-cli printer-repair --queue "Office Laser" --execute
killerbench-cli print-job-list
killerbench-cli print-job-cancel "Office Laser" 12 --execute

See printer-list, printer-check, printer-repair, print-job-cancel and default-printer-set.

Use this to turn on BitLocker, back up the recovery key and confirm the drive is protected. KillerBench backs up and verifies the recovery password before it starts encryption, and it never shows or logs a recovery password.

Before you start

  • Run KillerBench as administrator.
  • The Windows drive needs a TPM protector and a recovery password protector. A data drive needs only a recovery password.
  • Decide where the recovery key backup goes: a file outside the drive you are encrypting, and optionally Active Directory or Microsoft Entra ID.

Check the drive

  1. Open BitLocker and choose the drive in Volume.
  2. Leave the operation on Inspect and press Run diagnosis. The report shows encryption state, protection status and protector identities.
  3. If the TPM is present but not ready, prepare it from Security first. KillerBench never clears a TPM.

Add the protectors you need

  1. Open More BitLocker actions.
  2. Choose Add a TPM protector or Add a recovery password, press Preview, tick Make this change on the selected drive when I press Run action, then press Run action.
  3. Back up a new recovery password straight away. KillerBench does not display it.

Back up the recovery key and encrypt

  1. Press Find recovery protectors and select the recovery password protector.
  2. Enter a full backup file path outside the drive you are encrypting.
  3. Choose Encrypt, pick the encryption method, and tick Back up the selected recovery key, then start encryption when I select Run diagnosis.
  4. Press Run diagnosis. KillerBench writes the backup, verifies it, then starts encryption once.
  5. Encryption continues in the background. Run Inspect later to confirm the drive reports fully encrypted with protection on.

Back up to Active Directory or Entra ID

In More BitLocker actions, choose the directory backup for the selected protector. KillerBench reports that Windows accepted the request but cannot read the directory copy, so confirm it in Active Directory or the Entra admin center.

Data drives and auto-unlock

After a data drive is encrypted, Turn on auto-unlock makes it unlock when Windows starts. The Windows drive must already be fully encrypted with protection on.

From the command line

killerbench-cli bitlocker-protectors C:
killerbench-cli bitlocker-protector-add C: recovery --execute
killerbench-cli bitlocker-encrypt C: RECOVERY_PROTECTOR_GUID D:\Keys\C-recovery.txt --execute
killerbench-cli bitlocker-escrow C: RECOVERY_PROTECTOR_GUID entra --execute

See bitlocker-protectors, bitlocker-protector-add, bitlocker-encrypt and bitlocker-escrow. Each has a matching -recover command for an interrupted request.

Use this when Windows restarts unexpectedly, shows a stop error, or an application keeps crashing. KillerBench gathers crash, shutdown, hardware-error and reliability evidence into one report. It describes what was recorded and never guesses a root cause.

Check the computer

  1. Open Diagnostics and choose Vitals.
  2. Press Run diagnosis. The report combines memory, disk health, device problems, Reliability Monitor history, hardware-error records, crash reports, unexpected shutdowns and Windows Memory Diagnostic results.
  3. Read the conclusion and the evidence under it. Historical crashes explain what happened; they do not prove a fault is still present.

Narrow it down

  • Hardware error history reads WHEA and memory diagnostic records together with device problems and disk health.
  • Reliability history groups the last 14 days of application crashes, hangs and unexpected shutdowns.
  • Application errors focuses on crashing programs.
  • Driver installation history shows failed driver installs matched to devices that are present now.
  • Device problems lists devices with Device Manager error codes.

Read crash dumps

KillerBench lists dump configuration and dump-file metadata and can analyze minidump structure for the exception and module names. Dump contents are never opened in the desktop app. With a bug-check knowledge pack loaded, stop codes resolve to their documented meaning.

Keep the dumps until you finish investigating. Cleanup can remove them, but that discards the evidence.

From the command line

killerbench-cli vitals-check
killerbench-cli crash-config
killerbench-cli crash-dumps
killerbench-cli crash-review
killerbench-cli device-code 43

See vitals-check, crash-review and device-code.

Use this to review and tighten privacy on a laptop. KillerBench reads the current settings, shows which ones policy or device management already own, and changes only the settings you pick, one at a time, with an exact undo.

Review the current settings

  1. Open Privacy.
  2. Tick the areas you want to review. Every area starts unchecked.
  3. Press Run diagnosis. The report shows the current value for this machine and the account running KillerBench, and flags settings owned by policy.

Change a setting

  1. Choose the setting in Privacy setting, such as camera, microphone, location, diagnostic data, advertising, clipboard history, cloud content search or search highlights.
  2. Choose the new value and tick Apply when I select Run diagnosis.
  3. Press Run diagnosis. KillerBench checks for a policy owner, records the current value, makes the one change and reads it back.

Settings owned by group policy or device management are left alone. Change those where they are managed.

Undo a change

Each verified change keeps a journal. The matching undo restores the exact previous value, again after a policy check.

Declutter Windows

For suggestions, consumer content, Recall and AI features, taskbar and Start clutter, Edge and preinstalled software, open Maintenance and choose Declutter Windows. The review is read-only and nothing is selected automatically.

From the command line

killerbench-cli privacy-plan --select Camera --select ClipboardSync
killerbench-cli privacy-setting camera-access off --execute
killerbench-cli privacy-setting-undo camera-access VERIFIED_JOURNAL --execute
killerbench-cli debloat-review --area TelemetryAndReporting

See privacy-plan, privacy-setting, privacy-setting-undo and debloat-review. An unsupported key lists the supported choices.

Use this when preparing a new or freshly reset PC. KillerBench reviews the computer, the applications you plan to install and the name you want to give it, then points to the guarded tools that make each change.

Start with a baseline

  1. Run Full system scan from Diagnostics and keep the report as a record of the computer's starting state.
  2. Install pending updates. See Fix Windows Update if any fail.

Review applications and configuration

  1. Open Onboarding and choose Onboarding.
  2. Select the applications and configuration groups you plan to set up and press Run diagnosis. The review compares them with what is already installed. KillerBench does not download or run installers.
  3. Before running a vendor installer, verify it from the command line. KillerBench trusts it only when it carries a valid signature from that vendor's exact organization name.

Name the computer

  1. Choose Computer name, enter the name and press Run diagnosis to review it against the current identity and domain role.
  2. On a workgroup computer, tick Rename this workgroup PC after fresh checks to rename it. A restart is needed to finish.

Protect and tidy it

  • Encrypt a drive with BitLocker and back up the recovery key.
  • Make Windows more private and review Declutter Windows in Maintenance.

Step-by-step guides: Encrypt a drive with BitLocker.

Using the BitLocker tool

Choose the drive letter and an Operation, then press Run diagnosis.

  • Inspect reads encryption state, protection status and protector identities. It is the default and changes nothing.
  • Back up recovery writes the selected recovery password to a new file outside the protected drive and verifies it. Press Find recovery protectors first, choose the protector, then confirm the backup.
  • Encrypt backs up the selected recovery password, verifies the backup, then starts encryption once with the method you choose. The Windows drive needs a TPM protector and a recovery password. A data drive needs only a recovery password.
  • Resume protection turns protection back on for a fully encrypted drive where it was suspended.

Each of these needs its own confirmation box, and KillerBench rechecks the drive immediately before it acts.

More BitLocker actions

Open More BitLocker actions for changes that sit outside Run diagnosis. Choose an action, press Preview to read exactly what it requires, then confirm and press Run action.

  • Turn on auto-unlock makes an encrypted data drive unlock when Windows starts. The Windows drive must be fully encrypted with protection on.
  • Add a TPM protector or Add a recovery password creates one new protector. KillerBench never shows or logs a new recovery password, so back it up straight away.
  • Back up the recovery password to Active Directory or Microsoft Entra ID sends the protector you selected above. KillerBench reports that Windows accepted the request. It cannot read the directory copy, so confirm it there.
  • Decrypt this drive starts decryption, for example before encrypting again with a required method. It needs a second confirmation because the drive is unprotected afterwards, and it refuses the Windows drive while other drives auto-unlock from it.

An action says it is blocked

A blocked result means the requested action could not proceed. Read the message and journal to see whether it stopped before dispatch or after an earlier step. Do not assume a partially completed operation was rolled back. The most common prerequisite reasons are below.

  • Administrator access is required. Close KillerBench and start it again with Run as administrator.
  • Restart readiness must be clear. Windows has a restart pending. Restart the computer, then run the action again.
  • Managed policy is present. Group policy or device management owns the setting. Change it there instead.
  • Evidence changed. Something changed between the first check and the final recheck. Run the tool again to read the new state.

A previous request needs reconciliation

KillerBench found a pending record from an interrupted request. Run the same action again. It checks what happened and reports the real outcome without repeating the request. On the command line, use the matching -recover command, for example killerbench-cli bitlocker-auto-unlock-recover.

A check shows Incomplete or Unknown

The evidence could not be read, often because KillerBench was not running as administrator or a Windows service was unavailable. KillerBench reports this honestly instead of assuming the computer is healthy.

Where files are kept

Journals, pending records and saved evidence live under %LOCALAPPDATA%\KillerBench. Each guarded action keeps its own folder. Keep them when you need a record of what changed.

KillerBench is in development. Include the exported report and the activity log when you report a problem, and remove anything you would not share.
