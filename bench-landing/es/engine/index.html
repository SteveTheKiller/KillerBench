El KillerBench.Engine

Las guías detalladas enlazadas desde esta página están en inglés.

KillerBench.Engine es una biblioteca de diagnóstico y reparación de Windows para aplicaciones que necesitan evidencias estructuradas en lugar de una colección de scripts opacos. Impulsa las herramientas de escritorio y de línea de comandos de KillerBench y puede integrarse en otro anfitrión .NET.

Qué ofrece

  • Flujos de diagnóstico delimitados para mantenimiento de Windows, dispositivos, almacenamiento, redes, impresión, seguridad, aplicaciones, perfiles y otras áreas del sistema
  • Evidencias tipadas con estados explícitos de completo, incompleto, desconocido e histórico
  • Recetas de reparación que exigen evidencias actuales exactas antes de ejecutarse
  • Diarios persistentes para verificar reparaciones y recuperar ejecuciones interrumpidas
  • Funciones de devolución de llamada de progreso para vistas en directo, como la actividad de mantenimiento
  • Texto, JSON, HTML y resultados estructurados de .NET para informes e integraciones
  • Paquetes de conocimiento versionados para códigos de error, identificadores de hardware, proveedores y referencias de asistencia

Diseñado para la trazabilidad

Cada hallazgo está vinculado a las evidencias que lo produjeron. Los eventos históricos siguen siendo históricos. La falta de datos no se convierte en un diagnóstico de buen estado. Un proveedor que falla no se presenta como un resultado vacío. Engine indica el alcance de lo inspeccionado para que el anfitrión pueda explicar qué se sabe y qué sigue siendo desconocido.

Primero el diagnóstico

La mayoría de las operaciones de Engine son de solo lectura. La compatibilidad con reparaciones es deliberadamente más limitada que la cobertura de diagnóstico. Una reparación exige una receta compatible, evidencias recientes de elegibilidad, autorización explícita del anfitrión, un registro persistente de preparación, una acción nativa delimitada y verificación posterior.

El análisis completo del sistema es solo diagnóstico, incluso cuando un flujo específico tiene activada la reparación automática. Las capturas guardadas y los eventos históricos nunca autorizan una reparación. La validación de reparaciones nativas sigue limitada a las evidencias conservadas de máquinas Windows de prueba desechables, documentadas en el archivo del repositorio VM-VALIDATION.md.

Anfitrión de escritorio

La interfaz de escritorio presenta la salida de Engine mediante las vistas Salida sin procesar e Informe legible. Sus confirmaciones y diálogos Abrir, Guardar y Carpeta siguen el tema activo. Estos controles pertenecen al anfitrión de escritorio. Un anfitrión que integre la biblioteca debe aportar su propia interfaz de revisión y autorización, conservando los controles de evidencias, requisitos, diario y verificación de Engine.

Estado actual

Engine está dirigido a .NET 10 y Windows. Está en desarrollo activo y actualmente se utiliza mediante una referencia de proyecto dentro del repositorio KillerBench. No se ha publicado un paquete público.

Elegir una guía

  • Primeros pasos muestra un primer flujo de solo lectura.
  • Flujos de diagnóstico explica las comprobaciones específicas y el análisis completo del sistema.
  • Evidencias y resultados explica estados, diarios, progreso e informes.
  • Reparaciones y seguridad describe los controles de evidencias y el modelo de recuperación.
  • Guía de CLI cubre el descubrimiento de comandos y las salidas de texto y JSON.
  • Guía de API presenta los principales puntos de entrada públicos.
  • Arquitectura explica los límites de Engine y sus capas internas.
  • Paquetes de conocimiento cubre datos de referencia actualizables.
