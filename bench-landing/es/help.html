Empieza aquí

KillerBench es un banco de trabajo de diagnóstico y reparación de Windows para técnicos. Primero comprueba el equipo, explica lo que encontró junto con las evidencias de cada hallazgo y solo cambia Windows cuando eliges una corrección concreta y la confirmas.

KillerBench está en desarrollo. Todavía no hay descarga pública. Estas páginas describen la compilación actual.

Qué hace

  • Ejecuta diagnósticos de solo lectura sobre Windows Update, dispositivos, almacenamiento, redes, impresión, seguridad, apps y perfiles, y después redacta un informe legible.
  • Ofrece reparaciones protegidas que solo se ejecutan cuando evidencias recientes demuestran el problema exacto, y verifica el resultado después.
  • Cubre tareas de configuración y refuerzo como BitLocker, la configuración de privacidad, despejar Windows y poner en marcha un equipo nuevo.
  • Ejecuta los diagnósticos y el análisis de informes en local, sin IA y sin cuenta de KillerBench. Algunas acciones seleccionadas, como las descargas y la copia de la clave de recuperación en Entra ID, pueden contactar con servicios externos.
  • Usa el tema activo de la app en la consola, los informes, las confirmaciones y los cuadros de diálogo Abrir, Guardar y Carpeta.

Windows y runtime

  • El destino de publicación actual es Windows x64. Windows 11 x64 es la referencia actual de validación nativa. No se ofrecen distribuciones nativas para ARM64, x86 ni Windows Server.
  • KillerBench se empaqueta de dos formas. El instalador es dependiente del framework y requiere .NET Desktop Runtime 10 para Windows x64. El .NET Runtime básico, ASP.NET Core Runtime y .NET Framework no incluyen WPF. La edición portátil lleva su propio runtime y no necesita una instalación aparte. La herramienta de línea de comandos killerbench-cli.exe necesita .NET 10 Runtime para Windows x64. El SDK solo hace falta para desarrollo, no para el uso normal.
  • Usa una versión de Windows compatible con .NET 10 en Windows. Que el runtime sea compatible no significa que las reparaciones de KillerBench estén validadas en todas las ediciones o compilaciones compatibles. La cobertura de Windows 10 sigue pendiente y sus ediciones compatibles dependen de los requisitos actuales del ciclo de vida de Microsoft.
  • Obtén el Desktop Runtime solo desde la página de descarga de .NET 10 de Microsoft, eligiendo .NET Desktop Runtime, Windows, x64. Sigue las normas de instalación de software de tu organización.

Si dotnet está disponible, dotnet --list-runtimes debería mostrar Microsoft.WindowsDesktop.App 10.0.x para la instalación x64. Un runtime instalado solo para otra arquitectura no sirve para el paquete de instalación x64.

Cuando se publique un paquete

  1. Usa la descarga oficial enlazada desde este sitio web. Todavía no hay ningún enlace de descarga de KillerBench activo.
  2. Lee los requisitos de ese paquete, la licencia GPLv3, las instrucciones de Código fuente correspondiente, los avisos de terceros incluidos y la información de firma y suma de comprobación. El nombre del archivo por sí solo no demuestra su autenticidad.
  3. Ejecuta el instalador para la cuenta actual, o para todos los usuarios tras una solicitud de elevación. Añade un acceso directo en el menú Inicio, un acceso directo opcional en el escritorio y una entrada en Agregar o quitar programas. La edición portátil se ejecuta sin instalación.
  4. Inicia KillerBench con tu cuenta normal y sigue Tu primer diagnóstico. Los fallos de acceso del diagnóstico siguen visibles; la elevación es una decisión aparte y deliberada.

No te saltes las advertencias de seguridad de Windows para ejecutar una copia no verificada. Mantén una copia de seguridad actual antes de seleccionar cualquier acción que cambie el equipo.

Al iniciarse, KillerBench consulta GitHub en busca de una versión estable más reciente y pregunta antes de instalarla. La descarga debe coincidir con la suma de comprobación SHA-256 publicada. Desactiva la comprobación con Buscar actualizaciones al iniciar en Acerca de.

Código fuente, licencia y soporte

KillerBench tiene licencia GPLv3. Las instrucciones de entrega del código fuente y los permisos de las fuentes tipográficas de terceros siguen pendientes para el primer paquete público. Lee Acerca de KillerBench para conocer la disponibilidad del código fuente, los avisos de distribución, la privacidad de las evidencias y la información de soporte. Empieza por Descarga y configuración y después ejecuta un Análisis completo del sistema. Recopila evidencias de diagnóstico y guarda un diario local; no ejecuta reparaciones. Un hallazgo describe el alcance inspeccionado, no todos los fallos posibles del equipo.

Ejecutar el análisis

  1. Abre KillerBench. La sección Diagnóstico se abre con Análisis completo del sistema seleccionado.
  2. Deja Reparar automáticamente problemas confirmados desactivado en tu primera ejecución.
  3. Pulsa Ejecutar diagnóstico. El progreso aparece en Salida sin procesar, a la derecha, mientras se ejecuta cada comprobación.
  4. Al terminar, el panel de salida cambia al Informe legible.

Empieza sin elevación. Algunas evidencias de Windows, como los protectores de BitLocker y los servicios protegidos, necesitan derechos de administrador. Con una cuenta estándar, esas comprobaciones indican que la evidencia no está disponible. Si necesitas esa evidencia, termina la ejecución actual, guarda el informe y vuelve a abrir KillerBench a propósito con Ejecutar como administrador. La elevación no selecciona ni aprueba ninguna reparación.

Leer el informe

El informe empieza con los recuentos de Por revisar, Reparaciones verificadas, Incompletas y Comprobadas, seguidos de un siguiente paso recomendado.

  • Qué necesita atención enumera los problemas que respaldan las evidencias, empezando por los más importantes.
  • Información recopilada muestra lo que se leyó, incluidas las evidencias incompletas o no disponibles.
  • Los eventos históricos se marcan como historial. Un error del mes pasado no se trata como un fallo actual.

La falta de evidencias nunca cuenta como buen estado. Si una comprobación no pudo ejecutarse, el informe lo dice.

Elegir tú las comprobaciones

Abre Elegir comprobaciones (avanzado) para elegir comprobaciones concretas en lugar del análisis completo. Cada sección de la app también tiene herramientas específicas, descritas en las páginas de Secciones de esta guía.

Corregir lo que encontraste

Cuando el informe recomienda una corrección, indica qué sección y qué herramienta abrir. Lee Cómo se mantienen seguros los cambios antes de tu primera reparación. La validación nativa sigue en curso; un diagnóstico correcto no demuestra que cada reparación ofrecida se haya probado en tu compilación de Windows. Mantén copias de seguridad y revisa el destino exacto y las consecuencias antes de cualquier cambio.

La ventana de KillerBench tiene tres paneles que siguen tu forma de trabajar: eliges una sección a la izquierda, configuras las opciones de la herramienta en el centro y lees la salida a la derecha. Debajo de las opciones se puede abrir un registro de actividad.

Secciones

La barra lateral de la izquierda enumera todas las herramientas en doce secciones: Diagnóstico, Reparación, Actualizaciones, Dispositivos, Red, Apps, Mantenimiento, Puesta en marcha, Seguridad, BitLocker, Privacidad y Almacenamiento. Arrastra su borde para cambiar su tamaño, o arrástralo más allá de su ancho mínimo para cerrarla.

Opciones de la herramienta

El panel central muestra la sección seleccionada, su lista de herramientas y las opciones de la herramienta elegida. Las opciones que podrían cambiar el equipo siempre están desactivadas de forma predeterminada. Pulsa Ejecutar diagnóstico para iniciar la herramienta. Cuando Reparar automáticamente problemas confirmados está activado, el mismo botón dice Ejecutar reparación. Detener termina la ejecución cuando acaba el comando en curso.

Salida

El panel de salida de la derecha tiene dos vistas.

  • Salida sin procesar muestra las evidencias técnicas a medida que se recopilan, con los números de línea originales. Se abre sola mientras se ejecuta una herramienta.
  • Informe legible muestra el informe terminado de la última ejecución. Sustituye a la salida sin procesar cuando termina la ejecución.

Usa el cuadro de filtro de Salida sin procesar para mostrar solo las líneas que coinciden. Exportar informe guarda el informe con sus rutas de origen y fragmentos de evidencia. Fuentes de sesión enumera cada evidencia reunida en esta sesión.

Registro de actividad

El registro de actividad, bajo las opciones de la herramienta, anota lo que KillerBench hizo en esta sesión.

KillerBench trata el diagnóstico y el cambio como tareas distintas. El diagnóstico solo lee. El análisis completo del sistema nunca ejecuta reparaciones. Selecciona una reparación o acción concreta, revisa sus opciones y requisitos previos y confirma el cambio propuesto.

Antes de un cambio

  1. Evidencias recientes. La herramienta vuelve a leer el estado actual. Un informe guardado o un evento antiguo nunca autoriza un cambio.
  2. Elegibilidad exacta. El cambio solo se ofrece cuando las evidencias coinciden con el problema exacto que corrige. Cualquier dato incompleto lo bloquea.
  3. Tu confirmación. Revisa la acción seleccionada en su cuadro de confirmación. Algunas acciones, como descifrar una unidad, necesitan una segunda confirmación. El cuadro sigue el tema activo de la app; su aspecto no cambia los requisitos de la acción.
  4. Requisitos previos. Se comprueban los derechos de administrador, el estado de reinicio y la propiedad por directiva o administración de dispositivos. La configuración que pertenece a una directiva no se toca.
  5. Un registro pendiente. KillerBench anota lo que va a hacer antes de pedírselo a Windows.
  6. Una comprobación final. Todo se comprueba de nuevo justo antes de la solicitud, así que cualquier cambio intermedio la detiene.

Después de un cambio

  • KillerBench vuelve a leer el resultado y solo indica Verificado cuando Windows muestra el estado esperado.
  • Si Windows devuelve éxito pero el estado no cambió, el resultado lo dice y no se repite nada.
  • Cada cambio se guarda en un diario en %LOCALAPPDATA%\KillerBench.

Si algo se interrumpe

Las acciones compatibles con diario conservan un registro pendiente cuando una solicitud pudo llegar a Windows y la verificación no terminó. Usa la ruta de conciliación documentada de la acción, o su comando -recover correspondiente, para inspeccionar ese registro. La conciliación no es una reversión automática. Conserva el diario cuando el resultado sea incierto y no repitas el cambio a mano. El comportamiento ante bloqueos, cancelaciones y arranques posteriores aún necesita validación nativa específica de cada acción.

Lo que KillerBench no hará

  • Borrar un TPM, eliminar protectores que no creó ni mostrar contraseñas de recuperación.
  • Cambiar una configuración que controlan la directiva de grupo o la administración de dispositivos.
  • Ejecutar una reparación solo porque un evento histórico o un informe importado mencione un problema.

Los diagnósticos y el análisis de informes se ejecutan en local. Una acción que selecciones puede contactar con un destino externo, como descargas de software o la copia de la clave de recuperación en Active Directory o Entra ID. Revisa el destino antes de confirmar. Las capturas guardadas y las evidencias sin procesar pueden incluir la identidad del equipo y rutas de origen, así que revísalas antes de compartirlas.

Estado de desarrollo

La cobertura de reparaciones sigue creciendo. Una compilación correcta o una comprobación simulada no demuestra el comportamiento nativo de una reparación. El archivo VM-VALIDATION.md del repositorio registra los escenarios en máquinas Windows desechables y la validación pendiente.

Guías paso a paso

Usa esta guía cuando las actualizaciones fallan, se quedan paradas o se reinstalan una y otra vez. KillerBench lee primero la cadena de actualización, explica el fallo con las evidencias que lo respaldan y solo inicia un servicio o repara el almacén de componentes cuando evidencias recientes demuestran ese problema exacto.

Antes de empezar

  • Ejecuta KillerBench como administrador. Los servicios de actualización, el almacén de componentes y los archivos protegidos del sistema necesitan elevación para obtener evidencias completas.
  • Reinicia primero si Windows ya tiene un reinicio pendiente. Muchas reparaciones de actualizaciones están bloqueadas hasta que no quede ningún reinicio pendiente.
  • Mantén el equipo conectado a la corriente durante el mantenimiento.

Averiguar por qué fallan las actualizaciones

  1. Abre Actualizaciones y elige Windows Update en la barra lateral de herramientas.
  2. Deja Reparar automáticamente problemas confirmados desactivado en la primera pasada y pulsa Ejecutar diagnóstico.
  3. Lee el Informe legible. Enumera los servicios de actualización detenidos, los reinicios pendientes, el poco espacio libre, los daños del almacén de componentes y los códigos de error exactos que registró Windows, con un siguiente paso recomendado.
  4. Si el informe menciona un código de error, las comprobaciones de seguimiento correspondientes se ejecutan automáticamente. También puedes buscar uno tú mismo con killerbench-cli update-code 0x80070002.

Vigilar una actualización que parece atascada

Elige Monitor de actividad de mantenimiento en Actualizaciones y pulsa Ejecutar diagnóstico. Toma instantáneas repetidas de la actividad de actualización, Setup e Installer, de los totales de transferencia y de los indicadores de reinicio. La actividad se muestra solo como evidencia; nunca afirma por sí sola que haya un atasco o un fallo.

Reparar lo que encontró el informe

  1. Vuelve a ejecutar Windows Update con Reparar automáticamente problemas confirmados activado. Puede iniciar servicios de actualización habilitados que estén confirmados como detenidos, y solo ejecuta DISM o SFC cuando la comprobación en vivo confirma daños.
  2. Para un único servicio, elige su herramienta específica, como Servicio BITS, Servicios de cifrado, Instalador de módulos de Windows o Servicio Update Orchestrator. Cada una ofrece recuperación solo para ese servicio exacto.
  3. Cuando el informe diga que reinicies, reinicia antes de ejecutar nada más. KillerBench registra los resultados que requieren reinicio y aplaza el trabajo posterior hasta que se haya reiniciado.

Cada reparación queda en el diario y se vuelve a leer. Consulta Cómo se mantienen seguros los cambios para ver la secuencia completa.

Instalar una actualización concreta

  1. Elige Actualizaciones disponibles en Actualizaciones y pulsa Ejecutar diagnóstico para descubrir las actualizaciones del origen configurado.
  2. Selecciona las actualizaciones que quieras y pulsa Previsualizar seleccionadas. La vista previa enumera exactamente lo que se instalaría y cualquier reinicio necesario.
  3. Instala solo después de leer la vista previa. KillerBench nunca selecciona ni aprueba una actualización por ti.

Desde la línea de comandos

killerbench-cli update-search
killerbench-cli update-history
killerbench-cli servicing-monitor --samples 10
killerbench-cli update-plan --select GUID:REVISION --execute

Consulta update-search, update-history, servicing-monitor y update-plan. Si se interrumpió una instalación, ejecuta update-recover; comprueba el resultado y nunca reintenta la actualización.

Usa esta guía cuando los componentes de Windows están dañados: las características no se instalan, las actualizaciones informan de errores de componentes o las herramientas del sistema se bloquean. KillerBench solo ejecuta DISM y SFC después de que una comprobación en vivo confirme daños, y después verifica el resultado.

Antes de empezar

  • Ejecuta KillerBench como administrador.
  • Resuelve primero cualquier reinicio pendiente.
  • Si el equipo está administrado, comprueba si una directiva dirige DISM a un origen de reparación concreto. KillerBench informa de esa directiva y no la cambia.

Buscar daños

  1. Abre Reparación y elige Archivos del sistema.
  2. Deja Reparar automáticamente problemas confirmados desactivado y pulsa Ejecutar diagnóstico.
  3. Lee el informe. Hace inventario de los estados de los paquetes de mantenimiento, las características opcionales y las capacidades, comprueba los requisitos previos y analiza los archivos protegidos del sistema. Un resultado limpio significa que no se ofrece ninguna reparación.

Reparar daños confirmados

  1. Activa Reparar automáticamente problemas confirmados y pulsa Ejecutar reparación. KillerBench elige DISM o SFC solo cuando la comprobación en vivo confirma daños.
  2. Espera a la verificación. El informe muestra Verificado solo cuando la comprobación de seguimiento lee un estado reparado.
  3. Si el informe dice que el almacén no se puede recuperar o que el origen de reparación no está disponible, detente ahí. Repetir la reparación no cambiará el resultado.

Una ejecución interrumpida de DISM o SFC se concilia en el siguiente arranque sin repetir el comando de mantenimiento.

Limpiar el almacén de componentes

Elige Limpieza del almacén de componentes en Actualizaciones. Primero pregunta a Windows si se recomienda la limpieza. El mantenimiento opcional quita los componentes reemplazados y vuelve a analizar. Nunca usa ResetBase y nunca borra contenido de WinSxS a mano.

Desde la línea de comandos

killerbench-cli component-repair-source
killerbench-cli repair dism
killerbench-cli repair sfc --execute
killerbench-cli servicing-logs

Consulta component-repair-source, repair y servicing-logs. repair muestra una vista previa de forma predeterminada y solo actúa con --execute.

Usa esta guía cuando a una unidad le queda poco espacio. KillerBench muestra en qué se va el espacio, previsualiza lo que quitaría cada destino de limpieza y solo borra después de que actives la limpieza permanente.

Ver cuánto espacio queda

  1. Abre Almacenamiento y elige Almacenamiento.
  2. Pulsa Ejecutar diagnóstico. El informe marca cada volumen con letra de unidad que tenga menos del 10 % de espacio libre y muestra la asignación de instantáneas, los valores predeterminados de cuota y la directiva de Sensor de almacenamiento.
  3. Para los volcados de memoria y el contenido antiguo de actualizaciones, ejecuta también Constantes vitales en Diagnóstico y Windows Update en Actualizaciones; el tamaño de la caché de actualizaciones aparece allí.

Previsualizar una limpieza

  1. Abre Mantenimiento y elige Limpieza.
  2. Marca los destinos que quieras, como Archivos temporales del usuario actual, Archivos temporales de Windows, Cachés de navegador del usuario actual, Caché de Delivery Optimization o Papelera de reciclaje del usuario actual. Pasa el puntero sobre un destino para leer exactamente qué carpetas abarca.
  3. Ajusta Antigüedad mínima (días) y Archivos máximos por destino.
  4. Pulsa Ejecutar diagnóstico con Realizar la limpieza permanente seleccionada después de comprobaciones actualizadas desactivado. El informe enumera los candidatos y el espacio estimado de cada destino. No se borra nada.

Quitar los archivos

  1. Activa Realizar la limpieza permanente seleccionada después de comprobaciones actualizadas y pulsa Ejecutar diagnóstico.
  2. KillerBench vuelve a comprobar cada candidato antes de quitarlo, omite los archivos recientes, protegidos o en uso, y registra cada resultado en el diario.

La limpieza permanente no pasa por la Papelera de reciclaje y no se puede deshacer. Quitar los informes de errores y los volcados de memoria descarta evidencias que podrías necesitar para investigar bloqueos, así que revísalos primero.

Quitar la instalación anterior de Windows

Después de una actualización de características, Instalación anterior de Windows en Limpieza puede quitar la copia de reversión mediante la solicitud de eliminación de reversión compatible de Windows. Se ejecuta por separado, necesita Respaldé todos los archivos y configuraciones que necesito de la instalación anterior y quita para siempre la posibilidad de volver a la versión anterior.

Desde la línea de comandos

killerbench-cli volume-capacity C:
killerbench-cli cleanup --user-temp --windows-temp --days 7 --max-files 500
killerbench-cli cleanup --user-temp --windows-temp --days 7 --max-files 500 --execute

Consulta volume-capacity, cleanup y previous-windows.

  • Comprobar y reparar una unidad

Usa esta guía cuando un volumen informa de errores, Windows pide analizar una unidad o los archivos no se abren. KillerBench comprueba primero el volumen en modo de solo lectura y solo programa o ejecuta una reparación del sistema de archivos después de que confirmes que tienes una copia de seguridad.

Antes de empezar

  • Haz una copia de seguridad de los datos importantes del volumen. Una reparación del sistema de archivos puede cambiar o quitar archivos dañados.
  • Ejecuta KillerBench como administrador.

Comprobar el volumen

  1. Abre Almacenamiento y elige Almacenamiento.
  2. Elige la unidad en Volumen para comprobar y pulsa Ejecutar diagnóstico.
  3. Lee el informe. Muestra el estado del disco y del volumen, el bit de volumen sucio, la autorreparación de NTFS en línea, los errores de controladora y de dispositivos de disco, los contadores de confiabilidad y los eventos de almacenamiento recientes, como reinicios, reintentos y extracciones inesperadas.

Una comprobación limpia significa que no se ofrece ninguna reparación. La temperatura del disco, el desgaste y los contadores de E/S no corregidos son evidencias para revisar y no activan una reparación por sí solos.

Reparar el sistema de archivos

  1. Pulsa Revisar reparación de sistema de archivos y elige Reparación puntual o Análisis y reparación sin conexión.

Antes de empezar

  • Ejecuta KillerBench como administrador.
  • La unidad de Windows necesita un protector de TPM y un protector de contraseña de recuperación. Una unidad de datos solo necesita una contraseña de recuperación.

Comprobar la unidad

  1. Abre BitLocker y elige la unidad en Volumen.
  2. Deja la operación en Inspeccionar y pulsa Ejecutar diagnóstico. El informe muestra el estado de cifrado, el estado de protección y las identidades de los protectores.
  3. Si el TPM está presente pero no está listo, prepáralo primero desde Seguridad. KillerBench nunca borra un TPM.

  1. Abre Más acciones de BitLocker.
  2. Elige Agregar un protector de TPM o Agregar una contraseña de recuperación, pulsa Vista previa, marca Hacer este cambio en la unidad seleccionada cuando pulse Ejecutar acción y pulsa Ejecutar acción.
  3. Haz enseguida una copia de la nueva contraseña de recuperación. KillerBench no la muestra.

Hacer copia de la clave de recuperación y cifrar

  1. Pulsa Buscar protectores de recuperación y selecciona el protector de contraseña de recuperación.
  2. Escribe una ruta completa para el archivo de copia, fuera de la unidad que vas a cifrar.
  3. Elige Cifrar, elige el método de cifrado y marca Hacer copia de la clave de recuperación seleccionada y luego iniciar el cifrado cuando seleccione Ejecutar diagnóstico.
  4. Pulsa Ejecutar diagnóstico. KillerBench escribe la copia, la verifica y después inicia el cifrado una sola vez.
  5. El cifrado continúa en segundo plano. Ejecuta Inspeccionar más tarde para confirmar que la unidad aparece totalmente cifrada y con la protección activada.

Hacer copia en Active Directory o Entra ID

En Más acciones de BitLocker, elige la copia en el directorio para el protector seleccionado. KillerBench informa de que Windows aceptó la solicitud, pero no puede leer la copia del directorio, así que confírmala en Active Directory o en el centro de administración de Entra.

Secciones

Diagnóstico es donde debería empezar cada visita. Cada herramienta lee el equipo y redacta un informe. Nada de aquí cambia Windows. La herramienta predeterminada, el análisis completo del sistema, ejecuta un conjunto amplio de comprobaciones de solo lectura y ordena lo que necesita atención.

Guías paso a paso: Investigar bloqueos y pantallas azules y Reparar archivos del sistema.

Herramientas de esta sección

Comprueba primero el equipo y después lee en el informe qué necesita atención y cuál es el siguiente paso seguro.

Análisis completo del sistema

Inspecciona 49 áreas de diagnóstico y después evalúa todas las recetas de recuperación de servicios instaladas junto con las recetas de mantenimiento, DHCP, impresión, Defender, hora y WMI. Las comprobaciones pueden tardar varios minutos. La reparación automática es opcional y requiere las evidencias actuales, los requisitos previos del equipo y las comprobaciones de dependencias propias de cada receta. Las reparaciones elegibles pueden renovar concesiones DHCP que faltan, liberar trabajos de impresión en cola, resincronizar el reloj, actualizar las firmas de Defender, restaurar servicios elegibles y reparar daños confirmados de Windows. Los servicios automáticos detenidos pueden iniciarse después de verificar su ventana de inicio y sus dependencias. Un servicio de inicio a petición detenido no se cambia cuando el estado inactivo es la única evidencia; los flujos de trabajo más específicos solo pueden exigirlo cuando evidencias actuales de la característica respaldan el inicio. Se conservan los tipos de inicio, las definiciones de tareas, los informes, los volcados, las suscripciones, las credenciales, la configuración de los canales, la directiva del firewall y la configuración administrada. Las instantáneas históricas, de copias de seguridad y de transferencias son de solo lectura. El contenido de los volcados no se abre. La inspección del bit de volumen sucio no programa reparaciones ni reinicios. Este flujo de trabajo no instala actualizaciones, no cambia controladores, no borra archivos ni realiza una prueba completa del hardware.

Constantes vitales

Captura la memoria disponible, el estado de los discos que indica el proveedor y el estado de protección de BitLocker, y después relaciona las constantes vitales actuales con los problemas de dispositivos, el historial de confiabilidad, los registros de errores de hardware, las evidencias de bloqueos, los apagados inesperados y los resultados del Diagnóstico de memoria de Windows. Los indicadores de reinicio, el espacio libre del disco del sistema, la elevación y la configuración del servicio de actualización siguen visibles. No se recopilan contraseñas de recuperación. Este flujo de trabajo no ejecuta reparaciones. El resultado combinado no es una prueba completa del hardware, del software ni de la estabilidad.

Historial de confiabilidad

Lee los registros del Monitor de confiabilidad de Windows de los últimos 14 días junto con los errores recientes de Aplicación y los eventos de apagado inesperado, y devuelve una única conclusión histórica delimitada. Los registros históricos no establecen el estado actual ni la causa raíz. No se selecciona ninguna reparación y no se cambia ninguna aplicación, servicio ni configuración.

Rendimiento del inicio

Lee los metadatos de los eventos de rendimiento de inicio y apagado de Windows de los últimos 14 días, conservando solo la identidad del proveedor y campos numéricos de duración delimitados, y los relaciona con los indicadores de reinicio pendiente compatibles. Las rutas, los nombres de procesos, las cuentas y el resto de la carga útil de los eventos se quitan antes de guardar las evidencias. Los registros históricos de degradación no identifican un cuello de botella actual ni autorizan cambios de inicio, servicios, aplicaciones, controladores, tareas, energía, reinicio ni directivas.

Historial de errores de hardware

Lee el historial de Windows Hardware Error Architecture y del Diagnóstico de memoria de los últimos 14 días, los problemas actuales de dispositivos Plug and Play, el estado de los discos físicos y los contadores de confiabilidad del proveedor, y devuelve una única conclusión delimitada sobre el hardware. Los registros deben relacionarse con su carga útil, los diagnósticos del firmware y las pruebas de hardware del fabricante. No se deduce ningún componente defectuoso ni causa raíz, no se selecciona ninguna reparación y no se cambia ningún hardware, firmware, controlador, disco, grupo, volumen, archivo, servicio, energía, reinicio ni configuración.

Historial de instalación de controladores

Lee el final conservado del historial de instalación de dispositivos de Windows SetupAPI, relaciona las secciones fallidas con las identidades Plug and Play exactas actuales y devuelve una única conclusión delimitada. Las secciones históricas del registro no demuestran que un dispositivo siga presente ni que un fallo sea actual. No se instala, quita, revierte ni actualiza ningún controlador.

Puntos de Restaurar sistema

Enumera hasta 256 puntos de Restaurar sistema disponibles, revisa la elegibilidad explícita para crear uno y devuelve una única conclusión de disponibilidad delimitada. El inventario no demuestra que la protección esté activada en todos los volúmenes ni que una restauración vaya a funcionar. Durante el diagnóstico no se crea, elimina ni aplica ningún punto de restauración.

Entorno de recuperación de Windows

Lee la configuración actual del Entorno de recuperación de Windows con REAgentC, relaciona una ubicación local habilitada con el disco y la partición exactos actuales, y devuelve una única conclusión de disponibilidad delimitada. La reparación automática opcional puede habilitar una configuración existente deshabilitada y después verificar el estado indicado. La imagen de recuperación no se descarga, traslada ni sustituye, no se inicia ningún arranque de recuperación y Windows no se reinicia. El estado habilitado y la presencia de la partición no demuestran que la imagen de recuperación pueda arrancar o reparar este PC.

Activación de Windows

Comprueba la disponibilidad del servicio Optimizar unidades. La recuperación opcional solo inicia el servicio exacto habilitado y detenido tras comprobaciones de dependencias actualizadas. La actividad de optimización ya programada por Windows puede reanudarse según la directiva de mantenimiento actual. Se conservan los volúmenes, los sistemas de archivos, los datos, las programaciones de optimización, la directiva de mantenimiento, los permisos del servicio y el tipo de inicio. KillerBench no selecciona ningún volumen ni analiza, hace trim, desfragmenta, optimiza o programa ninguna unidad. La verificación abarca solo el estado estable del servicio, no el análisis, la optimización ni el estado del dispositivo.

Referencia

Cada ejecución produce un informe que puedes leer, filtrar y exportar. El informe siempre separa lo que se demostró de lo que solo se observó.

Estados que verás

EstadoSignificado
Por revisarLas evidencias respaldan un problema que merece atención.
InformaciónSe recopilaron evidencias y se muestran como contexto.
Incompletas o DesconocidoUna comprobación no pudo terminar o la evidencia no estaba disponible. Nunca cuenta como buen estado.
HistóricoUn evento del pasado. Explica el historial, pero no demuestra un fallo actual.
VerificadoUna reparación o un cambio se confirmó volviendo a leer el resultado.

La salida sin procesar y el informe legible

Salida sin procesar conserva las evidencias técnicas con los números de línea originales para que puedas seguir cualquier hallazgo hasta su origen. El Informe legible resume la misma ejecución en lenguaje sencillo, con el siguiente paso seguro en primer lugar.

Registros guardados

KillerBench también puede leer registros de Windows guardados, como los de CBS y Setup, sin ejecutar nada en el equipo. Los hallazgos enlazan con la línea exacta que los produjo. Cargar muestra, en Fuentes de sesión, abre un ejemplo sintético que puedes explorar sin riesgo.

Exportar

Exportar informe guarda el informe con sus rutas de origen, las entradas analizadas y los fragmentos de evidencia, para revisarlo antes de adjuntarlo a un ticket. Los registros sin procesar y los fragmentos de evidencia pueden contener nombres de equipos, cuentas, rutas o texto de origen confidencial. Los recopiladores protegidos limitan lo que conservan, pero no se garantiza que las evidencias importadas estén anonimizadas. Revisa y quita la información confidencial antes de compartirla.

killerbench-cli ejecuta el mismo Engine que la app de escritorio desde PowerShell o una consola remota. Todos los comandos que podrían cambiar el equipo muestran una vista previa de forma predeterminada y necesitan una opción explícita, como --execute, antes de actuar. Los comandos imprimen las evidencias JSON en la salida estándar y el progreso en la salida de errores estándar.

Guías paso a paso: Ejecutar KillerBench desde scripts.

El código de salida 0 significa que la vista previa o el resultado verificado tuvo éxito; 1, un error de inicio, de entrada o del diario; 2, que no se reconocieron los argumentos; 3, bloqueado, fallido o sin verificar; 4, que un flujo de trabajo necesita un reinicio antes de poder verificar, y 130, que lo detuviste tú.

Una acción dice que está bloqueada

Un resultado bloqueado significa que la acción solicitada no pudo continuar. Lee el mensaje y el diario para ver si se detuvo antes del envío o después de un paso anterior. No supongas que una operación completada a medias se revirtió. Los motivos de requisitos previos más habituales son estos.

  • Se requiere acceso de administrador. Cierra KillerBench y vuelve a iniciarlo con Ejecutar como administrador.
  • No debe haber un reinicio pendiente. Windows tiene un reinicio pendiente. Reinicia el equipo y vuelve a ejecutar la acción.
  • Hay una directiva administrada. La directiva de grupo o la administración de dispositivos controla la configuración. Cámbiala allí.
  • Las evidencias cambiaron. Algo cambió entre la primera comprobación y la comprobación final. Vuelve a ejecutar la herramienta para leer el nuevo estado.

Una solicitud anterior necesita conciliación

KillerBench encontró un registro pendiente de una solicitud interrumpida. Vuelve a ejecutar la misma acción. Comprueba qué ocurrió e informa del resultado real sin repetir la solicitud. En la línea de comandos, usa el comando -recover correspondiente, por ejemplo killerbench-cli bitlocker-auto-unlock-recover.

Una comprobación muestra Incompletas o Desconocido

No se pudieron leer las evidencias, a menudo porque KillerBench no se estaba ejecutando como administrador o porque un servicio de Windows no estaba disponible. KillerBench lo indica con honestidad en lugar de suponer que el equipo está en buen estado.

Dónde se guardan los archivos

Los diarios, los registros pendientes y las evidencias guardadas están en %LOCALAPPDATA%\KillerBench. Cada acción protegida tiene su propia carpeta. Consérvalos cuando necesites un registro de lo que cambió.

Informar de un problema

KillerBench está en desarrollo. Incluye el informe exportado y el registro de actividad cuando informes de un problema, y quita todo lo que no quieras compartir.
