Hier beginnen

KillerBench ist eine Werkbank für Windows-Diagnose und -Reparatur für Techniker. Sie prüft einen Computer zuerst, erklärt ihre Befunde mit den zugehörigen Nachweisen und ändert Windows nur, wenn Sie eine bestimmte Reparatur auswählen und bestätigen.

KillerBench befindet sich in Entwicklung. Es gibt noch keinen öffentlichen Download. Diese Seiten beschreiben den aktuellen Build.

Was KillerBench tut

  • Führt schreibgeschützte Diagnosen für Windows Update, Geräte, Speicher, Netzwerk, Drucken, Sicherheit, Apps und Profile aus und erstellt einen lesbaren Bericht.
  • Bietet abgesicherte Reparaturen, die nur laufen, wenn aktuelle Nachweise genau das Problem belegen, und überprüft das Ergebnis anschließend.
  • Deckt Einrichtungs- und Härtungsaufgaben ab, etwa BitLocker, Datenschutzeinstellungen, das Entrümpeln von Windows und die Einrichtung eines neuen Computers.
  • Führt Diagnose und Berichtsanalyse lokal aus, ohne KI und ohne KillerBench-Konto. Ausgewählte Aktionen, etwa Downloads und die Sicherung von Wiederherstellungsschlüsseln in Entra ID, können externe Dienste kontaktieren.
  • Verwendet das aktive App-Design für Konsole, Berichte, Bestätigungen sowie die Dialoge zum Öffnen, Speichern und Auswählen von Ordnern.

Windows und Laufzeit

  • Das aktuelle Veröffentlichungsziel ist Windows x64. Windows 11 x64 ist die aktuelle Basis für die native Validierung. Native Pakete für ARM64, x86 und Windows Server werden nicht angeboten.
  • KillerBench wird auf zwei Arten verpackt. Das Installationsprogramm ist framework-abhängig und benötigt die .NET Desktop Runtime 10 für Windows x64. Die reine .NET Runtime, die ASP.NET Core Runtime und das .NET Framework enthalten kein WPF. Die portable Ausgabe bringt ihre eigene Laufzeit mit und benötigt keine separate Installation. Das Befehlszeilenwerkzeug killerbench-cli.exe benötigt die .NET 10 Runtime für Windows x64. Ein SDK wird nur für die Entwicklung benötigt, nicht für die normale Nutzung.
  • Verwenden Sie eine Windows-Version, die von .NET 10 unter Windows unterstützt wird. Unterstützung durch die Laufzeit bedeutet nicht, dass KillerBench-Reparaturen auf jeder unterstützten Edition oder jedem Build validiert sind. Die Abdeckung von Windows 10 steht noch aus, und ihre unterstützten Editionen richten sich nach den aktuellen Lebenszyklusvorgaben von Microsoft.
  • Beziehen Sie die Desktop Runtime nur von Microsofts Downloadseite für .NET 10 und wählen Sie .NET Desktop Runtime, Windows, x64. Beachten Sie die Regeln Ihrer Organisation für die Softwareinstallation.

Wenn dotnet verfügbar ist, sollte dotnet --list-runtimes für die x64-Installation Microsoft.WindowsDesktop.App 10.0.x auflisten. Eine Laufzeit, die nur für eine andere Architektur installiert ist, genügt dem x64-Installationspaket nicht.

Wenn ein Paket veröffentlicht ist

  1. Verwenden Sie den offiziellen Download, der auf dieser Website verlinkt ist. Noch ist kein KillerBench-Downloadlink aktiv.
  2. Lesen Sie die Anforderungen des Pakets, die GPLv3-Lizenz, die Hinweise zum korrespondierenden Quellcode, die enthaltenen Hinweise zu Drittanbietern sowie die Angaben zu Signatur und Prüfsumme. Ein Dateiname allein belegt keine Echtheit.
  3. Führen Sie das Installationsprogramm für das aktuelle Konto aus oder nach einer Erhöhungsabfrage für alle Benutzer. Es legt eine Verknüpfung im Startmenü, auf Wunsch eine Desktopverknüpfung und einen Eintrag unter „Programme hinzufügen oder entfernen“ an. Die portable Ausgabe läuft ohne Installation.
  4. Starten Sie KillerBench mit Ihrem normalen Konto und folgen Sie Ihre erste Diagnose. Fehlgeschlagene Diagnosezugriffe bleiben sichtbar; die Erhöhung ist eine eigene, bewusste Entscheidung.

Umgehen Sie keine Windows-Sicherheitswarnungen, um eine nicht überprüfte Kopie auszuführen. Halten Sie eine aktuelle Sicherung bereit, bevor Sie eine Aktion auswählen, die den Computer verändert.

Beim Start sucht KillerBench auf GitHub nach einer neueren stabilen Version und fragt nach, bevor es sie installiert. Der Download muss mit der veröffentlichten SHA-256-Prüfsumme übereinstimmen. Mit Beim Start nach Updates suchen unter „Info“ schalten Sie die Prüfung aus.

Aktuelle Grenzen

Der aktuelle Build umfasst zwölf Bereiche, schreibgeschützte Diagnose, Berichte und einzeln auswählbare Reparaturen. Die native Validierung der Reparaturen läuft noch. Eine funktionierende Oberfläche, ein erfolgreicher Build oder ein Testergebnis mit Prüfdaten belegt kein Reparaturverhalten auf einem echten Computer. Siehe Wie Änderungen sicher bleiben.

Die Beispielkonsole auf der Startseite zeigt simulierte Ausgaben. Endgültige Screenshots der Anwendung und das erste öffentliche Paket stehen noch aus.

Quellcode, Lizenz und Support

KillerBench steht unter der GPLv3. Hinweise zur Bereitstellung des Quellcodes und die Genehmigungen für Schriftarten von Drittanbietern stehen für das erste öffentliche Paket noch aus. Lesen Sie Über KillerBench zu Quellcodeverfügbarkeit, Vertriebshinweisen, Datenschutz bei Nachweisen und Support. Das Engine-Handbuch richtet sich an Entwickler mit einem autorisierten Quellcode-Checkout; es bedeutet nicht, dass ein öffentliches Engine-Paket verfügbar ist.

Beginnen Sie mit Download und Einrichtung und führen Sie dann eine vollständige Systemprüfung aus. Sie sammelt Diagnosenachweise und speichert ein lokales Journal; Reparaturen führt sie nicht aus. Ein Befund beschreibt den geprüften Bereich, nicht jeden möglichen Fehler des Computers.

Prüfung ausführen

  1. Öffnen Sie KillerBench. Der Bereich Diagnose öffnet sich mit ausgewählter Vollständige Systemprüfung.
  2. Lassen Sie Bestätigte Probleme automatisch reparieren beim ersten Durchlauf ausgeschaltet.
  3. Drücken Sie Diagnose ausführen. Der Fortschritt erscheint rechts in der Rohausgabe, während jede Prüfung läuft.
  4. Danach wechselt der Ausgabebereich zur Ansicht Lesbarer Bericht.

Starten Sie ohne Erhöhung. Manche Windows-Nachweise, etwa BitLocker-Schutzvorrichtungen und geschützte Dienste, erfordern Administratorrechte. Diese Prüfungen melden unter einem Standardkonto nicht verfügbare Nachweise. Wenn Sie diese Nachweise brauchen, schließen Sie den aktuellen Durchlauf ab, behalten Sie den Bericht und öffnen Sie KillerBench dann bewusst mit Als Administrator ausführen erneut. Die Erhöhung wählt keine Reparatur aus und genehmigt keine.

Bericht lesen

Der Bericht beginnt mit den Zählern für Zu prüfen, Überprüfte Reparaturen, Unvollständig und Geprüft und nennt dann einen empfohlenen nächsten Schritt.

  • Was Aufmerksamkeit braucht listet die Probleme auf, die die Nachweise stützen, das wichtigste zuerst.
  • Gesammelte Informationen zeigt, was gelesen wurde, einschließlich unvollständiger oder nicht verfügbarer Nachweise.
  • Historische Ereignisse sind als Verlauf gekennzeichnet. Ein Fehler vom letzten Monat gilt nicht als aktueller Fehler.

Fehlende Nachweise gelten nie als fehlerfrei. Wenn eine Prüfung nicht laufen konnte, sagt der Bericht das.

Prüfungen selbst auswählen

Öffnen Sie Prüfungen auswählen (erweitert), um statt der vollständigen Prüfung einzelne Prüfungen zu wählen. Jeder Bereich der App hat außerdem gezielte Werkzeuge, die auf den Seiten unter Bereiche in diesem Handbuch beschrieben sind.

Das Gefundene beheben

Wenn der Bericht eine Reparatur empfiehlt, nennt er den Bereich und das Werkzeug, das Sie öffnen sollen. Lesen Sie vor Ihrer ersten Reparatur Wie Änderungen sicher bleiben. Die native Validierung läuft noch; eine erfolgreiche Diagnose belegt nicht, dass jede angebotene Reparatur auf Ihrem Windows-Build getestet wurde. Halten Sie Sicherungen bereit und prüfen Sie vor jeder Änderung das genaue Ziel und die Folgen.

Das KillerBench-Fenster hat drei Bereiche, die Ihrer Arbeitsweise folgen: links einen Bereich wählen, in der Mitte die Optionen des Werkzeugs festlegen und rechts die Ausgabe lesen. Unter den Optionen lässt sich ein Aktivitätsprotokoll öffnen.

Bereiche

Die Seitenleiste links listet jedes Werkzeug in zwölf Bereichen: Diagnose, Reparatur, Updates, Geräte, Netzwerk, Apps, Wartung, Einrichtung, Sicherheit, BitLocker, Datenschutz und Speicher. Ziehen Sie ihren Rand, um die Breite zu ändern, oder über die Mindestbreite hinaus, um sie einzuklappen.

Werkzeugoptionen

Der mittlere Bereich zeigt den gewählten Bereich, seine Werkzeugliste und die Optionen des gewählten Werkzeugs. Optionen, die den Computer verändern könnten, sind standardmäßig immer ausgeschaltet. Drücken Sie Diagnose ausführen, um das Werkzeug zu starten. Ist Bestätigte Probleme automatisch reparieren eingeschaltet, heißt dieselbe Schaltfläche Reparatur ausführen. Stopp beendet den Durchlauf, sobald der aktuelle Befehl abgeschlossen ist.

Ausgabe

Der Ausgabebereich rechts hat zwei Ansichten.

  • Rohausgabe zeigt die technischen Nachweise, während sie gesammelt werden, mit den ursprünglichen Zeilennummern. Sie öffnet sich automatisch, während ein Werkzeug läuft.
  • Lesbarer Bericht zeigt den fertigen Bericht des letzten Durchlaufs. Er ersetzt die Rohausgabe, sobald der Durchlauf endet.

Mit dem Filterfeld in der Rohausgabe zeigen Sie nur passende Zeilen an. Bericht exportieren speichert den Bericht mit seinen Quellpfaden und Nachweisauszügen. Sitzungsquellen listet jeden Nachweis auf, der in dieser Sitzung gesammelt wurde.

Aktivitätsprotokoll

Das Aktivitätsprotokoll unter den Werkzeugoptionen hält fest, was KillerBench in dieser Sitzung getan hat.

Die Leiste zwischen Seitenleiste und Werkzeugoptionen enthält die Designauswahl, die Sprachauswahl, die Liste der Tastenkürzel und den Schalter für das Aktivitätsprotokoll. KillerBench bietet 13 Designs und 19 Sprachen.

KillerBench behandelt Diagnose und Änderung als getrennte Aufgaben. Die Diagnose liest nur. Die vollständige Systemprüfung führt nie Reparaturen aus. Wählen Sie eine bestimmte Reparatur oder Aktion, prüfen Sie ihre Optionen und Voraussetzungen und bestätigen Sie die vorgeschlagene Änderung.

Vor einer Änderung

  1. Aktuelle Nachweise. Das Werkzeug liest den aktuellen Zustand erneut. Ein gespeicherter Bericht oder ein altes Ereignis berechtigt nie zu einer Änderung.
  2. Genaue Eignung. Die Änderung wird nur angeboten, wenn die Nachweise genau das Problem zeigen, das sie behebt. Alles Unvollständige blockiert sie.
  3. Ihre Bestätigung. Prüfen Sie die gewählte Aktion in ihrem Bestätigungsdialog. Manche Aktionen, etwa das Entschlüsseln eines Laufwerks, benötigen eine zweite Bestätigung. Der Dialog folgt dem aktiven App-Design; sein Aussehen ändert nichts an den Anforderungen der Aktion.
  4. Voraussetzungen. Administratorrechte, Neustartzustand und die Zuständigkeit von Richtlinien oder Geräteverwaltung werden geprüft. Einstellungen, die eine Richtlinie verwaltet, bleiben unverändert.
  5. Ein ausstehender Eintrag. KillerBench schreibt auf, was es tun wird, bevor es Windows dazu auffordert.
  6. Eine letzte Gegenprüfung. Unmittelbar vor der Anfrage wird alles erneut geprüft, sodass eine zwischenzeitliche Änderung die Aktion stoppt.

Nach einer Änderung

  • KillerBench liest das Ergebnis zurück und meldet Überprüft nur, wenn Windows den erwarteten Zustand zeigt.
  • Meldet Windows Erfolg, ohne dass sich der Zustand geändert hat, sagt das Ergebnis das, und nichts wird wiederholt.
  • Jede Änderung wird in einem Journal unter %LOCALAPPDATA%\KillerBench gespeichert.

Wenn etwas unterbrochen wird

Unterstützte Aktionen mit Journal behalten einen ausstehenden Eintrag, wenn eine Anfrage Windows möglicherweise erreicht hat und die Überprüfung nicht abgeschlossen ist. Verwenden Sie den dokumentierten Abgleich der Aktion oder ihren passenden -recover-Befehl, um diesen Eintrag zu prüfen. Der Abgleich ist kein automatisches Zurücksetzen. Behalten Sie das Journal, wenn ein Ergebnis unsicher ist, und wiederholen Sie die Änderung nicht von Hand. Absturz, Abbruch und das Verhalten nach einem späteren Start müssen für jede Aktion noch nativ validiert werden.

Was KillerBench nicht tut

  • Ein TPM löschen, Schutzvorrichtungen entfernen, die es nicht selbst angelegt hat, oder Wiederherstellungskennwörter anzeigen.
  • Eine Einstellung ändern, die eine Gruppenrichtlinie oder Geräteverwaltung steuert.
  • Eine Reparatur ausführen, nur weil ein historisches Ereignis oder ein importierter Bericht ein Problem erwähnt.

Diagnose und Berichtsanalyse laufen lokal. Eine Aktion, die Sie auswählen, kann ein externes Ziel kontaktieren, etwa Software-Downloads oder die Sicherung von Wiederherstellungsschlüsseln in Active Directory oder Entra ID. Prüfen Sie das Ziel vor der Bestätigung. Gespeicherte Erfassungen und Rohnachweise können Computeridentität und Quellpfade enthalten, prüfen Sie sie daher vor dem Weitergeben.

Entwicklungsstand

Die Reparaturabdeckung wächst noch. Ein erfolgreicher Build oder eine simulierte Prüfung belegt kein natives Reparaturverhalten. Die Datei VM-VALIDATION.md im Repository verfolgt Szenarien auf wegwerfbaren Windows-Maschinen und die noch ausstehende Validierung.

Schritt-für-Schritt-Anleitungen

Verwenden Sie diese Anleitung, wenn Updates fehlschlagen, hängen bleiben oder sich immer wieder neu installieren. KillerBench liest zuerst die Update-Kette, erklärt den Fehler mit den zugehörigen Nachweisen und startet einen Dienst oder repariert den Komponentenspeicher nur, wenn aktuelle Nachweise genau dieses Problem belegen.

Bevor Sie beginnen

  • Führen Sie KillerBench als Administrator aus. Update-Dienste, der Komponentenspeicher und geschützte Systemdateien benötigen für vollständige Nachweise eine Erhöhung.
  • Starten Sie zuerst neu, wenn Windows bereits einen Neustart erwartet. Viele Update-Reparaturen sind blockiert, bis die Neustartbereitschaft geklärt ist.
  • Lassen Sie den Computer bei Wartungsarbeiten am Netzteil.

Herausfinden, warum Updates fehlschlagen

  1. Öffnen Sie Updates und wählen Sie in der Werkzeugleiste Windows Update.
  2. Lassen Sie Bestätigte Probleme automatisch reparieren beim ersten Durchlauf aus und drücken Sie Diagnose ausführen.
  3. Lesen Sie den Bericht unter Lesbarer Bericht. Er listet angehaltene Update-Dienste, ausstehende Neustarts, wenig freien Speicher, Beschädigungen im Komponentenspeicher und die genauen von Windows aufgezeichneten Fehlercodes mit einem empfohlenen nächsten Schritt.
  4. Nennt der Bericht einen Fehlercode, laufen die passenden Folgeprüfungen automatisch. Sie können einen Code auch selbst mit killerbench-cli update-code 0x80070002 nachschlagen.

Ein Update beobachten, das zu hängen scheint

Wählen Sie unter Updates den Wartungsaktivitätsmonitor und drücken Sie Diagnose ausführen. Er erstellt wiederholte Momentaufnahmen der Update-, Setup- und Installer-Aktivität, der Übertragungssummen und der Neustartanzeigen. Die Aktivität wird nur als Nachweis gezeigt; der Monitor behauptet nie von sich aus einen Stillstand oder Fehler.

Reparieren, was der Bericht gefunden hat

  1. Führen Sie Windows Update erneut mit eingeschaltetem Bestätigte Probleme automatisch reparieren aus. Das Werkzeug kann aktivierte Update-Dienste starten, die nachweislich angehalten sind, und führt DISM oder SFC nur aus, wenn die Live-Prüfung eine Beschädigung bestätigt.
  2. Für einen einzelnen Dienst wählen Sie stattdessen sein gezieltes Werkzeug, etwa BITS-Dienst, Kryptografiedienste, Windows Modules Installer oder Update Orchestrator Service. Jedes bietet die Wiederherstellung nur für genau diesen Dienst an.
  3. Wenn der Bericht einen Neustart verlangt, starten Sie neu, bevor Sie etwas anderes ausführen. KillerBench hält Ergebnisse fest, die einen Neustart erfordern, und stellt spätere Arbeiten bis nach dem Neustart zurück.

Jede Reparatur wird im Journal festgehalten und zurückgelesen. Den vollständigen Ablauf beschreibt Wie Änderungen sicher bleiben.

Ein bestimmtes Update installieren

  1. Wählen Sie unter Updates das Werkzeug Verfügbare Updates und drücken Sie Diagnose ausführen, um Updates aus der konfigurierten Quelle zu finden.
  2. Wählen Sie die gewünschten Updates aus und drücken Sie Ausgewählte in der Vorschau anzeigen. Die Vorschau listet genau, was installiert würde, und jede Neustartanforderung.
  3. Installieren Sie erst, nachdem Sie die Vorschau gelesen haben. KillerBench wählt oder genehmigt nie ein Update für Sie.

Über die Befehlszeile

killerbench-cli update-search
killerbench-cli update-history
killerbench-cli servicing-monitor --samples 10
killerbench-cli update-plan --select GUID:REVISION --execute

Siehe update-search, update-history, servicing-monitor und update-plan. Wurde eine Installation unterbrochen, führen Sie update-recover aus; der Befehl prüft das Ergebnis und versucht das Update nie erneut.

Verwandte Themen

Verwenden Sie diese Anleitung, wenn Windows-Komponenten beschädigt sind: Features lassen sich nicht installieren, Updates melden Komponentenfehler oder Systemwerkzeuge stürzen ab. KillerBench führt DISM und SFC erst aus, nachdem eine Live-Prüfung eine Beschädigung bestätigt hat, und überprüft dann das Ergebnis.

Bevor Sie beginnen

  • Führen Sie KillerBench als Administrator aus.
  • Erledigen Sie zuerst einen ausstehenden Neustart.
  • Ist der Computer verwaltet, prüfen Sie, ob eine Richtlinie DISM auf eine bestimmte Reparaturquelle verweist. KillerBench meldet diese Richtlinie und ändert sie nicht.

Auf Beschädigung prüfen

  1. Öffnen Sie Reparatur und wählen Sie Systemdateien.
  2. Lassen Sie Bestätigte Probleme automatisch reparieren aus und drücken Sie Diagnose ausführen.
  3. Lesen Sie den Bericht. Er erfasst die Zustände von Wartungspaketen, optionalen Features und Funktionen, prüft Voraussetzungen und durchsucht geschützte Systemdateien. Ein sauberes Ergebnis bedeutet, dass keine Reparatur angeboten wird.

Bestätigte Beschädigung reparieren

  1. Schalten Sie Bestätigte Probleme automatisch reparieren ein und drücken Sie Reparatur ausführen. KillerBench wählt DISM oder SFC nur, wenn die Live-Prüfung eine Beschädigung bestätigt.
  2. Warten Sie die Überprüfung ab. Der Bericht zeigt Überprüft nur, wenn die Folgeprüfung einen reparierten Zustand zurückliest.
  3. Meldet der Bericht, dass der Speicher nicht wiederherstellbar oder die Reparaturquelle nicht verfügbar ist, hören Sie dort auf. Eine Wiederholung der Reparatur ändert das Ergebnis nicht.

Ein unterbrochener DISM- oder SFC-Lauf wird beim nächsten Start abgeglichen, ohne den Wartungsbefehl zu wiederholen.

Den Komponentenspeicher bereinigen

Wählen Sie unter Updates die Komponentenspeicher-Bereinigung. Sie fragt Windows zuerst, ob eine Bereinigung empfohlen wird. Die optionale Wartung entfernt ersetzte Komponenten und analysiert erneut. Sie verwendet nie ResetBase und löscht nie WinSxS-Inhalte von Hand.

Über die Befehlszeile

killerbench-cli component-repair-source
killerbench-cli repair dism
killerbench-cli repair sfc --execute
killerbench-cli servicing-logs

Siehe component-repair-source, repair und servicing-logs. repair zeigt standardmäßig eine Vorschau und handelt nur mit --execute.

Verwandte Themen

  • Windows Update reparieren
  • Bereich Reparatur
  • Wie Änderungen sicher bleiben

Verwenden Sie diese Anleitung, wenn ein Laufwerk knapp wird. KillerBench zeigt, wohin der Speicher geht, zeigt vorab, was jedes Bereinigungsziel entfernen würde, und löscht erst, wenn Sie die dauerhafte Bereinigung einschalten.

Prüfen, wie viel Platz bleibt

  1. Öffnen Sie Speicher und wählen Sie Speicher.
  2. Drücken Sie Diagnose ausführen. Der Bericht markiert jedes Volume mit Laufwerksbuchstaben unter 10 % freiem Speicher und zeigt die Zuteilung für Schattenkopien, Kontingentstandards und die Speicheroptimierungsrichtlinie.
  3. Für Absturzabbilder und alte Update-Inhalte führen Sie zusätzlich Vitalwerte unter Diagnose und Windows Update unter Updates aus; dort erscheint die Größe des Update-Caches.

Eine Bereinigung in der Vorschau ansehen

  1. Öffnen Sie Wartung und wählen Sie Bereinigung.
  2. Markieren Sie die gewünschten Ziele, etwa Temporäre Dateien des aktuellen Benutzers, Temporäre Windows-Dateien, Browser-Caches des aktuellen Benutzers, Delivery Optimization-Cache oder Papierkorb des aktuellen Benutzers. Zeigen Sie auf ein Ziel, um zu lesen, welche Ordner es genau umfasst.
  3. Legen Sie Mindestalter (Tage) und Maximale Dateien pro Ziel fest.
  4. Drücken Sie Diagnose ausführen, während Ausgewählte dauerhafte Bereinigung nach frischen Prüfungen durchführen ausgeschaltet ist. Der Bericht listet die Kandidaten und den geschätzten Speicher für jedes Ziel. Nichts wird gelöscht.

Die Dateien entfernen

  1. Schalten Sie Ausgewählte dauerhafte Bereinigung nach frischen Prüfungen durchführen ein und drücken Sie Diagnose ausführen.
  2. KillerBench prüft jeden Kandidaten vor dem Entfernen erneut, überspringt neue, geschützte oder verwendete Dateien und hält jedes Ergebnis im Journal fest.

Die dauerhafte Bereinigung umgeht den Papierkorb und lässt sich nicht rückgängig machen. Das Entfernen von Fehlerberichten und Absturzabbildern verwirft Nachweise, die Sie zur Untersuchung von Abstürzen brauchen könnten; prüfen Sie diese daher zuerst.

Die vorherige Windows-Installation entfernen

Verwenden Sie diese Anleitung, um BitLocker einzuschalten, den Wiederherstellungsschlüssel zu sichern und zu bestätigen, dass das Laufwerk geschützt ist. Bevor Sie beginnen

  • Führen Sie KillerBench als Administrator aus.

  5. Die Verschlüsselung läuft im Hintergrund weiter. Führen Sie Prüfen später aus, um zu bestätigen, dass das Laufwerk vollständig verschlüsselt ist und der Schutz eingeschaltet ist.

Vollständige Systemprüfung

Prüft 49 Diagnosebereiche und bewertet dann jedes installierte Rezept zur Dienstwiederherstellung zusammen mit den Rezepten für Wartung, DHCP, Drucken, Defender, Zeit und WMI. Die Prüfungen können einige Minuten dauern. Die automatische Reparatur ist optional und verlangt für jedes Rezept eigene aktuelle Nachweise, Voraussetzungen des Computers und Abhängigkeitsprüfungen. Geeignete Reparaturen können fehlende DHCP-Leases erneuern, wartende Druckaufträge freigeben, die Uhr neu synchronisieren, Defender-Signaturen aktualisieren, geeignete Dienste wiederherstellen und bestätigte Windows-Beschädigungen reparieren. Eine Aktion meldet, dass sie blockiert ist

Ein blockiertes Ergebnis bedeutet, dass die angeforderte Aktion nicht fortfahren konnte. Lesen Sie Meldung und Journal, um zu sehen, ob sie vor dem Senden oder nach einem früheren Schritt gestoppt hat. Gehen Sie nicht davon aus, dass ein teilweise abgeschlossener Vorgang zurückgesetzt wurde. Die häufigsten Gründe bei den Voraussetzungen stehen unten.

  • Administratorzugriff ist erforderlich. Schließen Sie KillerBench und starten Sie es erneut mit Als Administrator ausführen.
  • Die Neustartbereitschaft muss geklärt sein. Windows erwartet einen Neustart. Starten Sie den Computer neu und führen Sie die Aktion dann erneut aus.
  • Eine verwaltete Richtlinie ist vorhanden. Eine Gruppenrichtlinie oder Geräteverwaltung steuert die Einstellung. Ändern Sie sie stattdessen dort.
  • Die Nachweise haben sich geändert. Zwischen der ersten Prüfung und der letzten Gegenprüfung hat sich etwas geändert. Führen Sie das Werkzeug erneut aus, um den neuen Zustand zu lesen.

Eine frühere Anfrage muss abgeglichen werden

KillerBench hat einen ausstehenden Eintrag einer unterbrochenen Anfrage gefunden. Führen Sie dieselbe Aktion erneut aus. Sie prüft, was passiert ist, und meldet das tatsächliche Ergebnis, ohne die Anfrage zu wiederholen. In der Befehlszeile verwenden Sie den passenden -recover-Befehl, zum Beispiel killerbench-cli bitlocker-auto-unlock-recover.

Eine Prüfung zeigt „Unvollständig“ oder „Unbekannt“

Die Nachweise konnten nicht gelesen werden, oft weil KillerBench nicht als Administrator lief oder ein Windows-Dienst nicht verfügbar war. KillerBench meldet das ehrlich, statt anzunehmen, der Computer sei fehlerfrei.

Wo Dateien gespeichert werden

Journale, ausstehende Einträge und gespeicherte Nachweise liegen unter %LOCALAPPDATA%\KillerBench. Jede abgesicherte Aktion hat ihren eigenen Ordner. Behalten Sie sie, wenn Sie eine Aufzeichnung der Änderungen benötigen.

Ein Problem melden

KillerBench befindet sich in Entwicklung. Fügen Sie bei einer Problemmeldung den exportierten Bericht und das Aktivitätsprotokoll bei und entfernen Sie alles, was Sie nicht weitergeben würden.
