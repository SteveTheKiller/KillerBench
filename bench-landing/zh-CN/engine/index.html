KillerBench.Engine

本页链接的详细指南以英语提供。

KillerBench.Engine 是 Windows 诊断与修复库，适用于需要结构化证据而非一组不透明脚本的应用。它为 KillerBench 桌面和命令行工具提供支持，也可以嵌入其他 .NET 宿主应用。

它提供什么

  • 具有明确范围的诊断流程，涵盖 Windows 维护、设备、存储、网络、打印、安全、应用、用户配置文件及其他系统领域
  • 带有明确的完整、不完整、未知和历史状态的类型化证据
  • 运行前需要准确且当前有效的证据的修复方案
  • 持久保存的日志，用于修复验证和中断运行恢复
  • 用于维护活动等实时显示的进度回调
  • 用于报告和集成的文本、JSON、HTML 及结构化 .NET 结果
  • 包含错误代码、硬件标识符、厂商和支持参考资料的版本化知识包

专为可追溯性设计

每项发现都关联着产生它的证据。历史事件仍是历史事件。缺少数据并不代表系统健康。数据提供程序失败不会被当作空结果。Engine 会报告检查范围的边界，让宿主应用能够说明哪些情况已知，哪些仍然未知。

诊断优先

Engine 的大多数操作仅执行读取。修复支持的范围有意小于诊断范围。修复必须具备受支持的方案、新的适用性证据、宿主应用的明确授权、持久保存的准备记录、范围受限的原生操作，以及操作后的验证。

全系统扫描仅用于诊断，即使某个专门流程启用了自动修复也是如此。保存的采集记录和历史事件绝不会授权修复。原生修复验证仍限于保留的一次性 Windows 测试机证据，这些证据记录在仓库中的以下文件： VM-VALIDATION.md.

桌面宿主应用

桌面界面通过“原始输出”和“可读报告”视图展示 Engine 输出。确认提示以及打开、保存和文件夹对话框都遵循当前应用主题。这些控件属于桌面宿主应用；嵌入 Engine 的宿主应用必须提供自己的审查和授权界面，同时保留 Engine 对证据、前提条件、日志记录和验证的要求。

当前状态

Engine 面向 .NET 10 和 Windows。它正在积极开发，目前通过 KillerBench 仓库内的项目引用使用。尚未发布公开软件包。
