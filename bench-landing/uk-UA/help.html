Як користуватися

Кожен розділ та інструмент: що він робить і як крок за кроком виконати типові завдання.

Клацніть рядок, щоб відкрити його. Як KillerBench працює всередині, описано на сторінці Технічні деталі.

Почніть тут

KillerBench є робочим інструментом для діагностики й виправлення Windows, створеним для технічних фахівців. Спершу він перевіряє комп'ютер, пояснює знайдене разом із даними, що підтверджують кожен результат, і змінює Windows лише тоді, коли ви вибираєте конкретне виправлення й підтверджуєте його.

KillerBench перебуває в розробці. Загальнодоступного завантаження поки немає. На цих сторінках описано поточну збірку.

Що він робить

  • Виконує діагностику лише для читання щодо Windows Update, пристроїв, сховища, мережі, друку, безпеки, застосунків і профілів, а потім створює зрозумілий звіт.
  • Пропонує захищені виправлення, які запускаються лише тоді, коли свіжі дані підтверджують саме цю проблему, і після цього перевіряє результат.
  • Охоплює налаштування й посилення захисту, як-от BitLocker, параметри конфіденційності, наведення ладу у Windows і підготовку нового комп'ютера.
  • Виконує діагностику та аналіз звітів локально, без ШІ та без облікового запису KillerBench. Вибрані дії, наприклад завантаження та резервне копіювання ключа відновлення в Entra ID, можуть звертатися до зовнішніх служб.
  • Використовує активну тему застосунку для консолі, звітів, підтверджень і діалогів «Відкрити», «Зберегти» та «Папка».

Розробники, які хочуть вбудувати діагностику у власні інструменти, можуть прочитати Посібник розробника Engine.

KillerBench 1.0.0 ще не випущено. Загальнодоступного пакета чи завантаження KillerBench поки немає. На цій сторінці описано поточні вимоги до пакета, щоб ви могли підготуватися, не завантажуючи неофіційну копію.

Windows і середовище виконання

  • Поточна ціль публікації: Windows x64. Поточна база нативної перевірки: Windows 11 x64. Нативних дистрибутивів для ARM64, x86 і Windows Server немає.
  • KillerBench постачається у двох варіантах. Інсталятор залежить від платформи й потребує .NET Desktop Runtime 10 for Windows x64. Звичайні .NET Runtime, ASP.NET Core Runtime і .NET Framework не надають WPF. Портативна версія містить власне середовище виконання й не потребує окремого встановлення. Для інструмента командного рядка killerbench-cli.exe потрібне .NET 10 Runtime for Windows x64. SDK потрібен для розробки, а не для звичайного використання.
  • Використовуйте версію Windows, яку підтримує .NET 10 on Windows. Підтримка середовища виконання не означає, що виправлення KillerBench перевірено в кожному підтримуваному випуску чи збірці. Охоплення Windows 10 ще не завершено, а її підтримувані випуски обмежено поточними вимогами життєвого циклу Microsoft.
  • Отримуйте Desktop Runtime лише зі сторінки завантаження .NET 10 від Microsoft, вибравши .NET Desktop Runtime, Windows, x64. Дотримуйтеся правил установлення програм, прийнятих у вашій організації.

Якщо доступна команда dotnet, команда dotnet --list-runtimes має показати Microsoft.WindowsDesktop.App 10.0.x для установки x64. Середовище виконання, встановлене лише для іншої архітектури, не підходить для пакета інсталятора x64.

Коли пакет буде опубліковано

  1. Використовуйте офіційне завантаження за посиланням із цього сайту. Посилання на завантаження KillerBench поки не активне.
  2. Прочитайте вимоги цього пакета, ліцензію GPLv3, інструкції щодо відповідного вихідного коду, додані повідомлення третіх сторін, а також відомості про підпис і контрольну суму. Саме лише ім'я файлу не підтверджує справжності.
  3. Запустіть інсталятор для поточного облікового запису або, після запиту на підвищення прав, для всіх користувачів. Він додає ярлик у меню «Пуск», необов'язковий ярлик на робочому столі та запис у списку встановлення й видалення програм. Портативна версія працює без установлення.
  4. Запустіть KillerBench під своїм звичайним обліковим записом і виконайте кроки зі сторінки Перша діагностика. Помилки доступу під час діагностики залишаються видимими; підвищення прав є окремим свідомим вибором.

Не обходьте попереджень безпеки Windows, щоб запустити неперевірену копію. Перш ніж вибрати будь-яку дію, що змінює комп'ютер, створіть актуальну резервну копію.

Під час запуску KillerBench перевіряє на GitHub наявність новішого стабільного випуску й запитує дозвіл перед установленням. Завантаження має збігатися з опублікованою контрольною сумою SHA-256. Вимкнути перевірку можна параметром Перевіряти оновлення під час запуску в розділі «Про програму».

Поточні обмеження

Поточна збірка має дванадцять розділів, діагностику лише для читання, звіти та окремо вибирані виправлення. Нативна перевірка виправлень ще триває. Робочий інтерфейс, успішна збірка чи результат тестового набору не підтверджують поведінки виправлення на реальному комп'ютері. Див. Як зміни залишаються безпечними.

Ілюстративна консоль на головній сторінці показує синтетичний вивід. Остаточні знімки екрана застосунку та перший загальнодоступний пакет ще не готові.

Вихідний код, ліцензія та підтримка

KillerBench поширюється за ліцензією GPLv3. Інструкції з надання вихідного коду й дозволи на шрифти третіх сторін для першого загальнодоступного пакета ще не готові. Відомості про доступність вихідного коду, повідомлення про поширення, конфіденційність даних і підтримку наведено на сторінці Про KillerBench. Посібник з Engine призначено для розробників з авторизованою копією вихідного коду; він не означає, що загальнодоступний пакет Engine існує.

Почніть зі сторінки Завантаження й налаштування, а потім запустіть повну перевірку системи. Вона збирає діагностичні дані й зберігає локальний журнал; виправлень вона не запускає. Результат описує перевірену область, а не всі можливі несправності комп'ютера.

Запуск перевірки

  1. Відкрийте KillerBench. Відкриється розділ Діагностика з вибраною Повною перевіркою системи.
  2. Під час першого запуску залиште параметр Автоматично виправляти підтверджені проблеми вимкненим.
  3. Натисніть Запустити діагностику. Під час кожної перевірки хід роботи відображається праворуч у поданні Вихідні дані.
  4. Після завершення панель виводу перемикається на Зрозумілий звіт.

Починайте без підвищення прав. Для деяких даних Windows, як-от засобів захисту BitLocker і захищених служб, потрібні права адміністратора. Під звичайним обліковим записом ці перевірки повідомлять, що дані недоступні. Якщо вони вам потрібні, завершіть поточний запуск, збережіть звіт і свідомо відкрийте KillerBench знову через Запуск від імені адміністратора. Підвищення прав не вибирає й не схвалює виправлення.

Читання звіту

Звіт починається з лічильників Потребують огляду, Підтверджені виправлення, Незавершені та Перевірено, після яких іде рекомендований наступний крок.

  • Що потребує уваги містить проблеми, підтверджені даними, починаючи з найважливіших.
  • Зібрані відомості показують, що було прочитано, включно з неповними або недоступними даними.
  • Історичні події позначено як історію. Помилку минулого місяця не вважають поточною несправністю.

Відсутні дані ніколи не вважаються справним станом. Якщо перевірку не вдалося виконати, звіт про це повідомить.

Самостійний вибір перевірок

Відкрийте Вибрати перевірки (додатково), щоб вибрати окремі перевірки замість повної. У кожному розділі застосунку також є цільові інструменти, описані на сторінках Розділи цього посібника.

Виправлення знайденого

Коли звіт рекомендує виправлення, він називає розділ та інструмент, які потрібно відкрити. Перед першим виправленням прочитайте сторінку Як зміни залишаються безпечними. Нативна перевірка ще триває; успішна діагностика не означає, що кожне запропоноване виправлення перевірено на вашій збірці Windows. Перед будь-якою зміною майте резервні копії та перегляньте точну ціль і наслідки.

Вікно KillerBench складається з трьох панелей, що відповідають порядку роботи: ліворуч ви вибираєте розділ, посередині задаєте параметри інструмента, а праворуч читаєте вивід. Під параметрами може відкриватися журнал дій.

Розділи

Бічна панель ліворуч містить усі інструменти в дванадцяти розділах: Діагностика, Виправлення, Оновлення, Пристрої, Мережа, Застосунки, Обслуговування, Підготовка, Безпека, BitLocker, Конфіденційність і Сховище. Перетягніть її край, щоб змінити ширину, або перетягніть за мінімальну ширину, щоб згорнути.

Параметри інструмента

Центральна панель показує вибраний розділ, список його інструментів і параметри вибраного інструмента. Параметри, які можуть змінити комп'ютер, за замовчуванням завжди вимкнено. Щоб запустити інструмент, натисніть Запустити діагностику. Коли ввімкнено параметр Автоматично виправляти підтверджені проблеми, та сама кнопка називається Запустити виправлення. Кнопка Зупинити завершує запуск після закінчення поточної команди.

Вивід

Панель виводу праворуч має два подання.

  • Вихідні дані показують технічні дані під час збирання з оригінальними номерами рядків. Це подання відкривається саме, поки працює інструмент.
  • Зрозумілий звіт показує готовий звіт за останнім запуском. Після завершення запуску він замінює вихідні дані.

Поле фільтра у вихідних даних залишає лише рядки, що збігаються. Експортувати звіт зберігає звіт разом зі шляхами до джерел і фрагментами даних. Джерела сеансу містять усі дані, зібрані в цьому сеансі.

Журнал дій

Журнал дій під параметрами інструмента фіксує, що KillerBench зробив у цьому сеансі.

Теми, мови та сполучення клавіш

На смузі між бічною панеллю та параметрами інструмента розміщено вибір теми, вибір мови, список сполучень клавіш і перемикач журналу дій. У KillerBench 13 тем і 20 мов.

Консоль у стилі димчастого скла та зрозумілі звіти дотримуються активної теми. Підтвердження та діалоги «Відкрити», «Зберегти» й «Папка» використовують той самий стиль родини, включно з темою 98SE. Виберіть тему до відкриття діалогу, щоб цей вигляд зберігався протягом усієї процедури.

Утримуйте Ctrl або Alt+Shift, щоб побачити цей шар. Наведіть вказівник на підсвічену клавішу, щоб побачити її дію.

KillerBench розглядає діагностику та зміну як різні завдання. Діагностика лише читає. Повна перевірка системи ніколи не запускає виправлень. Виберіть конкретне виправлення чи дію, перегляньте параметри й передумови та підтвердьте запропоновану зміну.

Перед зміною

  1. Свіжі дані. Інструмент знову зчитує поточний стан. Збережений звіт чи стара подія ніколи не дають права на зміну.
  2. Точна придатність. Зміну пропонують лише тоді, коли дані точно відповідають проблемі, яку вона усуває. Будь-яка неповнота її блокує.
  3. Ваше підтвердження. Перегляньте вибрану дію в діалозі підтвердження. Деяким діям, наприклад розшифруванню диска, потрібне друге підтвердження. Діалог дотримується активної теми застосунку; його вигляд не змінює вимог до дії.
  4. Передумови. Перевіряються права адміністратора, стан перезавантаження та належність параметра політиці або системі керування пристроями. Параметри, якими володіє політика, залишаються без змін.
  5. Очікувальний запис. KillerBench записує, що збирається зробити, перш ніж попросити про це Windows.
  6. Остання повторна перевірка. Безпосередньо перед запитом усе перевіряється ще раз, тож зміна, що сталася тим часом, зупиняє дію.

Після зміни

  • KillerBench зчитує результат і повідомляє Підтверджено лише тоді, коли Windows показує очікуваний стан.
  • Якщо Windows повідомляє про успіх, але стан не змінився, результат про це каже, і нічого не повторюється.
  • Кожна зміна зберігається в журналі в %LOCALAPPDATA%\KillerBench.

Якщо щось перервалося

Підтримувані дії з журналом зберігають очікувальний запис, якщо запит міг дійти до Windows, а перевірка не завершилася. Щоб переглянути цей запис, скористайтеся задокументованим шляхом узгодження для дії або відповідною командою -recover. Узгодження не є автоматичним відкатом. Якщо результат неясний, збережіть журнал і не повторюйте зміну вручну. Поведінка під час збою, скасування та подальшого завантаження все ще потребує нативної перевірки для кожної дії.

Чого KillerBench не робить

  • Не очищає TPM, не видаляє засоби захисту, які не створював, і не показує паролі відновлення.
  • Не змінює параметр, яким керує групова політика або система керування пристроями.
  • Не запускає виправлення лише тому, що історична подія чи імпортований звіт згадує проблему.

Діагностика та аналіз звітів виконуються локально. Вибрана вами дія може звертатися до зовнішньої адреси, зокрема для завантаження програм або резервного копіювання ключа відновлення в Active Directory чи Entra ID. Перед підтвердженням перегляньте ціль. Збережені знімки та вихідні дані можуть містити ідентифікатори комп'ютера й шляхи до джерел, тож перегляньте їх перед поширенням.

Стан розробки

Охоплення виправлень ще розширюється. Успішна збірка чи імітована перевірка не підтверджують нативну поведінку виправлень. Файл VM-VALIDATION.md у репозиторії відстежує сценарії на одноразових комп'ютерах із Windows і перевірки, що залишилися.

Покрокові посібники

Користуйтеся цим порядком, коли оновлення завершуються помилкою, зависають або встановлюються знову й знову. KillerBench спершу читає ланцюжок оновлень, пояснює збій разом із даними й запускає службу чи виправляє сховище компонентів лише тоді, коли свіжі дані підтверджують саме цю проблему.

Перед початком

  • Запустіть KillerBench від імені адміністратора. Для повних даних службам оновлення, сховищу компонентів і захищеним системним файлам потрібні підвищені права.
  • Якщо Windows уже очікує перезавантаження, спершу перезавантажте комп'ютер. Багато виправлень оновлень заблоковано, доки стан перезавантаження не стане чистим.
  • Під час обслуговування тримайте комп'ютер підключеним до мережі живлення.

З'ясуйте, чому оновлення не встановлюються

  1. Відкрийте Оновлення й виберіть Windows Update на бічній панелі інструментів.
  2. Під час першого проходу залиште Автоматично виправляти підтверджені проблеми вимкненим і натисніть Запустити діагностику.
  3. Прочитайте Зрозумілий звіт. У ньому наведено зупинені служби оновлення, очікувані перезавантаження, брак вільного місця, пошкодження сховища компонентів і точні коди помилок, записані Windows, разом із рекомендованим наступним кроком.
  4. Якщо у звіті вказано код помилки, відповідні додаткові перевірки запускаються автоматично. Код можна знайти й самостійно командою killerbench-cli update-code 0x80070002.

Спостереження за оновленням, яке здається завислим

У розділі Оновлення виберіть Монітор активності обслуговування й натисніть Запустити діагностику. Він робить повторні знімки активності оновлень, Setup та інсталятора, підсумків передавання й ознак перезавантаження. Активність показано лише як дані; сама по собі вона ніколи не стверджує про зависання чи несправність.

Виправлення знайденого у звіті

  1. Знову запустіть Windows Update з увімкненим параметром Автоматично виправляти підтверджені проблеми. Він може запустити ввімкнені служби оновлення, зупинку яких підтверджено, а DISM чи SFC запускає лише тоді, коли жива перевірка підтверджує пошкодження.
  2. Для окремої служби натомість виберіть її цільовий інструмент, як-от Служба BITS, Служби криптографії, Інсталятор модулів Windows або Служба Update Orchestrator. Кожен із них пропонує відновлення лише для своєї служби.
  3. Якщо звіт вимагає перезавантаження, перезавантажте комп'ютер, перш ніж запускати щось інше. KillerBench записує результати, що потребують перезавантаження, і відкладає подальшу роботу до його виконання.

Кожне виправлення записується в журнал і зчитується повторно. Повну послідовність описано на сторінці Як зміни залишаються безпечними.

Установлення конкретного оновлення

  2. Виберіть потрібні оновлення та натисніть Попередній перегляд вибраного. Попередній перегляд точно показує, що буде встановлено, і чи потрібне перезавантаження.
  3. Установлюйте лише після прочитання попереднього перегляду. KillerBench ніколи не вибирає й не схвалює оновлення замість вас.

  1. Відкрийте Виправлення й виберіть Системні файли.
  2. Залиште Автоматично виправляти підтверджені проблеми вимкненим і натисніть Запустити діагностику.
  3. Прочитайте звіт. Він інвентаризує стани пакетів обслуговування, додаткових компонентів і можливостей, перевіряє передумови й сканує захищені системні файли. Чистий результат означає, що виправлення не пропонується.

Виправлення підтвердженого пошкодження

  1. Увімкніть Автоматично виправляти підтверджені проблеми й натисніть Запустити виправлення. KillerBench вибирає DISM чи SFC лише тоді, коли жива перевірка підтверджує пошкодження.
  2. Дочекайтеся перевірки. Звіт показує Підтверджено лише тоді, коли подальша перевірка зчитує виправлений стан.
  3. Якщо звіт повідомляє, що сховище неможливо відновити або джерело відновлення недоступне, зупиніться. Повторення виправлення не змінить результату.

Перерваний запуск DISM чи SFC узгоджується під час наступного завантаження без повторення команди обслуговування.

  1. Відкрийте Обслуговування й виберіть Очищення.
  2. Позначте потрібні цілі, як-от Тимчасові файли поточного користувача, Тимчасові файли Windows, Кеші браузерів поточного користувача, Кеш Delivery Optimization або Кошик поточного користувача. Наведіть вказівник на ціль, щоб точно дізнатися, які папки вона охоплює.

  4. Натисніть Запустити діагностику, коли параметр Виконати вибране остаточне очищення після нових перевірок вимкнено. Звіт містить кандидатів і оцінку місця для кожної цілі. Нічого не видаляється.

Видалення файлів

  1. Увімкніть Виконати вибране остаточне очищення після нових перевірок і натисніть Запустити діагностику.
  2. KillerBench повторно перевіряє кожного кандидата перед видаленням, пропускає нещодавні, захищені й використовувані файли та записує кожен результат у журнал.

Остаточне очищення оминає кошик і не може бути скасоване. Видалення звітів про помилки й аварійних дампів знищує дані, які можуть знадобитися для розслідування збоїв, тож спершу перегляньте їх.

Чиста перевірка означає, що виправлення не пропонується. Температура диска, знос і лічильники невиправлених помилок введення-виведення є даними для огляду й самі по собі не запускають виправлення.

  4. Залиште Автоматично виправляти підтверджені проблеми вимкненим і натисніть Запустити діагностику.

Відповідь шлюзу не доводить доступу до інтернету, а невдалий пошук через налаштований розпізнавач не означає, що сайт не працює.

  1. Знову запустіть Мережа з увімкненим параметром Автоматично виправляти підтверджені проблеми. Інструмент може запустити ввімкнені служби DNS-клієнт, DHCP-клієнт, клієнт SMB, Служба відомостей про підключені мережі, Служба списку мереж і Допоміжна служба IP, а також поновити оренду для підключених фізичних адаптерів DHCP без придатної адреси IPv4.
  2. Під час поновлення з'єднання ненадовго перерветься. Статичні адреси та віртуальні адаптери ніколи не змінюються.
  3. Для одного хибного імені в кеші використовуйте очищення кешу DNS для цього конкретного хоста замість повного очищення.

Маршрути, записи Hosts, DNS-сервери, правила брандмауера, постачальники Winsock і мережні профілі завжди зберігаються.

Бездротова мережа, дротовий вхід і проксі

  • Бездротова мережа перевіряє адаптер і службу автонастроювання WLAN та може запустити службу, якщо її зупинено.
  • Дротова автентифікація (802.1X) робить те саме для служби автонастроювання дротової мережі в мережах, де потрібен вхід на порту.
  • Автоматичний проксі WinHTTP показує збережені параметри проксі для комп'ютера та поточного облікового запису. Під час діагностики KillerBench ніколи не завантажує URL файлу PAC і не змінює параметри проксі.

  2. Натисніть Знайти локальні принтери й виберіть чергу, що працює неправильно. Щоб перевірити всі черги, виберіть Використати загальні перевірки друку.
  3. Залиште Автоматично виправляти підтверджені проблеми вимкненим і натисніть Запустити діагностику.
  4. Прочитайте звіт. Він показує стан диспетчера друку, призупинені черги, автономний режим, видимі завдання, стани драйверів, реєстрації портів, нещодавні помилки PrintService, а для мережних принтерів одну спробу з'єднання з призначеною адресою принтера.

Успішне з'єднання чи чистий код стану не доводять, що в принтері є папір, тонер або справний механізм.

Виправлення черги

  1. Знову запустіть Друк з увімкненим параметром Автоматично виправляти підтверджені проблеми. Інструмент може запустити ввімкнений диспетчер друку, відновити точну призупинену чергу з очікуваними завданнями та вимкнути автономний режим.
  2. Вимкнення автономного режиму може вивільнити очікувані завдання, тож переконайтеся, що їх досі потрібно друкувати.
  3. Черга, яку хтось навмисно призупинив і в якій нічого не очікує, залишається призупиненою.

Видалення одного завислого завдання

  1. Натисніть Знайти заблоковані завдання друку.
  2. Виберіть завдання зі станом «Помилка» або «Заблоковано» й позначте Скасувати лише це вибране завдання.
  3. Натисніть Запустити діагностику. Скасовується лише це завдання, а результат зчитується повторно.

Виправлення принтера за замовчуванням

Виберіть чергу, яка має бути за замовчуванням, позначте Виправити відсутній або конфліктний принтер за замовчуванням за допомогою цієї черги й натисніть Запустити діагностику. Дія виконується, лише якщо принтер за замовчуванням відсутній або конфліктує.

killerbench-cli print-job-list
killerbench-cli print-job-cancel "Office Laser" 12 --execute

Користуйтеся цим порядком, щоб увімкнути BitLocker, створити резервну копію ключа відновлення й переконатися, що диск захищено. KillerBench зберігає та перевіряє пароль відновлення до початку шифрування й ніколи не показує та не записує пароль відновлення в журнал.

Перед початком

  • Запустіть KillerBench від імені адміністратора.
  • Диску Windows потрібні засіб захисту TPM і засіб захисту з паролем відновлення. Диску з даними потрібен лише пароль відновлення.
  • Вирішіть, куди буде збережено ключ відновлення: у файл поза диском, який шифруєте, і за бажанням в Active Directory чи Microsoft Entra ID.

Перевірка диска

  1. Відкрийте BitLocker і виберіть диск у полі Том.
  2. Залиште операцію Перевірити й натисніть Запустити діагностику. Звіт показує стан шифрування, стан захисту та ідентифікатори засобів захисту.
  3. Якщо TPM наявний, але не готовий, спершу підготуйте його в розділі Безпека. KillerBench ніколи не очищає TPM.

Додавання потрібних засобів захисту

  1. Відкрийте Інші дії BitLocker.
  2. Виберіть Додати засіб захисту TPM або Додати пароль відновлення, натисніть Попередній перегляд, позначте Внести цю зміну на вибраному диску, коли натисну «Виконати дію» й натисніть Виконати дію.
  3. Одразу збережіть новий пароль відновлення. KillerBench його не показує.

Збереження ключа відновлення та шифрування

  1. Натисніть Знайти засоби захисту відновлення й виберіть засіб захисту з паролем відновлення.
  2. Введіть повний шлях до файлу резервної копії поза диском, який шифруєте.
  3. Виберіть Зашифрувати, укажіть метод шифрування й позначте Створити резервну копію вибраного ключа відновлення, потім почати шифрування, коли я виберу «Запустити діагностику».
  4. Натисніть Запустити діагностику. KillerBench записує резервну копію, перевіряє її й один раз запускає шифрування.
  5. Шифрування триває у фоновому режимі. Пізніше запустіть Перевірити, щоб переконатися, що диск повністю зашифровано й захист увімкнено.

Збереження в Active Directory або Entra ID

У розділі Інші дії BitLocker виберіть збереження в каталог для вибраного засобу захисту. KillerBench повідомляє, що Windows прийняла запит, але не може прочитати копію в каталозі, тож перевірте її в Active Directory або в центрі адміністрування Entra.

Користуйтеся цим порядком, коли Windows неочікувано перезавантажується, показує помилку зупинки або застосунок постійно аварійно завершується. KillerBench збирає в одному звіті дані про збої, завершення роботи, апаратні помилки та надійність. Він описує те, що було записано, і ніколи не вгадує першопричину.

Перевірка комп'ютера

  1. Відкрийте Діагностика й виберіть Основні показники.
  2. Натисніть Запустити діагностику. Звіт поєднує пам'ять, стан дисків, проблеми пристроїв, історію монітора надійності, записи апаратних помилок, звіти про збої, неочікувані завершення роботи та результати засобу діагностики пам'яті Windows.
  3. Прочитайте висновок і дані під ним. Історичні збої пояснюють, що сталося; вони не доводять, що несправність досі є.

Звуження кола

  • Історія апаратних помилок читає записи WHEA та діагностики пам'яті разом із проблемами пристроїв і станом дисків.
  • Історія надійності групує збої застосунків, зависання й неочікувані завершення роботи за останні 14 днів.
  • Помилки застосунків зосереджуються на програмах, що аварійно завершуються.
  • Історія встановлення драйверів показує невдалі встановлення драйверів, зіставлені з пристроями, наявними зараз.
  • Проблеми пристроїв містять пристрої з кодами помилок диспетчера пристроїв.

Читання аварійних дампів

KillerBench показує конфігурацію дампів і метадані файлів дампів та може аналізувати структуру мінідампа, щоб отримати виняток та імена модулів. Вміст дампів ніколи не відкривається в настільному застосунку. Якщо завантажено пакет знань із кодами помилок зупинки, коди зупинки зіставляються з їхнім задокументованим значенням.

Зберігайте дампи до завершення розслідування. Очищення може їх видалити, але тоді дані буде втрачено.

killerbench-cli device-code 43

Користуйтеся цим порядком, щоб переглянути й посилити конфіденційність на ноутбуці. KillerBench читає поточні параметри, показує, якими з них уже володіє політика чи система керування пристроями, і змінює лише вибрані вами параметри, по одному, з точним скасуванням.

Перегляд поточних параметрів

  1. Відкрийте Конфіденційність.
  2. Позначте області, які хочете переглянути. Спочатку жодна область не позначена.
  3. Натисніть Запустити діагностику. Звіт показує поточне значення для цього комп'ютера та облікового запису, від імені якого запущено KillerBench, і позначає параметри, якими володіє політика.

Зміна параметра

  1. Виберіть параметр у полі Налаштування конфіденційності, наприклад камеру, мікрофон, розташування, діагностичні дані, рекламу, журнал буфера обміну, хмарний пошук вмісту чи виділення в пошуку.
  2. Виберіть нове значення й позначте Застосувати, коли я виберу «Запустити діагностику».
  3. Натисніть Запустити діагностику. KillerBench перевіряє власника політики, записує поточне значення, вносить одну зміну й зчитує її повторно.

Параметри, якими володіє групова політика чи система керування пристроями, залишаються без змін. Змінюйте їх там, де ними керують.

  3. Перш ніж запускати інсталятор постачальника, перевірте його з командного рядка. KillerBench довіряє інсталятору, лише якщо він має дійсний підпис із точною назвою організації цього постачальника.

Розділи

З діагностики має починатися кожен візит. Кожен інструмент читає комп'ютер і створює звіт. Тут ніщо не змінює Windows. Інструмент за замовчуванням, повна перевірка системи, виконує широкий набір перевірок лише для читання й ранжує те, що потребує уваги.

Покрокові посібники: Розслідування збоїв і синіх екранів і Відновлення системних файлів.

Інструменти цього розділу

Спершу перевірте комп'ютер, а потім прочитайте у звіті, що потребує уваги та який наступний безпечний крок.

Повна перевірка системи

Перевіряє 49 діагностичних областей, а потім оцінює кожен установлений рецепт відновлення служб разом із рецептами для обслуговування, DHCP, друку, Defender, часу й WMI. Перевірки можуть тривати кілька хвилин. Автоматичне виправлення необов'язкове й потребує для кожного рецепта власних поточних даних, передумов комп'ютера та перевірок залежностей. Придатні виправлення можуть поновити відсутню оренду DHCP, вивільнити завдання друку з черги, повторно синхронізувати годинник, оновити сигнатури Defender, відновити придатні служби й виправити підтверджене пошкодження Windows. Зупинені автоматичні служби можна запустити після перевірки вікна запуску й залежностей. Зупинена служба із запуском на вимогу залишається без змін, якщо єдиним доказом є її бездіяльність; вузько спрямовані процедури можуть вимагати її лише тоді, коли поточні дані про функцію підтверджують потребу в запуску. Параметри охоплюють вибір діагностичних даних і реклами, журнал буфера обміну, 17 параметрів дозволів застосунків, як-от камери, мікрофона й розташування, хмарний пошук вмісту для особистих і робочих облікових записів і виділення в пошуку.

Інструменти цього розділу

Переглядайте та змінюйте дозволи застосунків, рекомендації, параметри пошуку й реклами.

Конфіденційність

Зчитує вибрані параметри конфіденційності в реєстрі для цього комп'ютера та облікового запису, від імені якого запущено KillerBench. Окремі явні елементи керування можуть змінити журнал буфера обміну або підтримуваний параметр облікового запису після свіжих перевірок політики, надійної підготовки та точної перевірки. Інші варіанти конфіденційності залишаються лише для читання. Знімки реєстру не доводять фактичних дозволів чи належності політиці.

Перевіряйте диски, томи, дискові простори та служби обслуговування дисків. Діагностика не вибирає дискову операцію; кожна підтримувана дія, що змінює комп'ютер, потребує власної точної цілі, передумов і підтвердження.

Покрокові посібники: Перевірка й виправлення диска і Звільнення місця на диску.

Інструменти цього розділу

Сховище

Зіставляє обмежені ідентифікатори дисків, розділів і томів із літерами дисків, оцінює брак вільного місця менше ніж 10 % на кожному томі з літерою, перевіряє виділення сховища тіньових копій VSS і квоти за замовчуванням для кожного тому, коротко показує хід поточних завдань модуля Storage, перевіряє вибраний том NTFS і його стан оперативного самовідновлення, а також перевіряє дискові пристрої та контролери цього комп'ютера. Пороги ємності, параметри квот і стани завдань є даними для огляду й не вибирають очищення, зміну розміру, зміну квот чи керування завданнями. Зіставлення літер дисків відображає конкретний момент і охоплює не всі шляхи підключення. Результати щодо пристроїв не прив'язуються до вибраного тому. За замовчуванням вибрано том Windows. Файли, знімки, завдання й драйвери не змінюються, параметри не змінюються, томи не відключаються, перезавантаження не плануються.

Дискові простори

Інвентаризує непервинні пули дискових просторів і віртуальні диски, включно зі станом справності, робочим станом, ємністю, виділенням і стійкістю, а потім повертає один обмежений робочий висновок. Відповідаючи на цей запит лише для читання, Windows може запустити на вимогу свого постачальника керування дисковими просторами. Пули, віртуальні диски, фізичні диски, томи, стійкість, виділення, параметри обслуговування, політика й тип запуску зберігаються. Жодні операції з пулами, дисками, томами, виділенням, підключенням, виправленням, оптимізацією чи параметрами не запитуються. Результати постачальника не підтверджують доступності пулу, надлишковості, цілісності даних, можливості відновлення з резервної копії чи введення-виведення застосунків.

Служба сховища

Перевіряє обмежений набір поточних завдань модуля Storage, точну історію збоїв служби й поточну готовність служби сховища. Неповні дані мають пріоритет. Стан завдань та історичні збої не дають права на відновлення служби чи зміну сховища. Необов'язкове відновлення запускає лише точну ввімкнену та зупинену службу після свіжих перевірок залежностей. Наявні сповіщення сховища й дії сховища, керовані політикою, можуть відновитися. Томи, розділи, файлові системи, точки підключення, пристрої, драйвери, параметри контролю пам'яті, політика обслуговування, дозволи служби й тип запуску зберігаються. KillerBench не вибирає жодних операцій із завданнями, томами, розділами, точками підключення, файлами, пристроями, драйверами чи параметрами сховища. Перевірка охоплює лише стабільний стан служби, а не результат завдань чи операції з пристроями, томами й політикою сховища.

Служба оптимізації дисків

Перевіряє доступність служби оптимізації дисків. Необов'язкове відновлення запускає лише точну ввімкнену та зупинену службу після свіжих перевірок залежностей. Наявна оптимізація, запланована Windows, може відновитися відповідно до поточної політики обслуговування. Томи, файлові системи, дані, розклади оптимізації, політика обслуговування, дозволи служби й тип запуску зберігаються. KillerBench не вибирає том і не аналізує, не виконує Trim, не дефрагментує, не оптимізує й не планує жоден диск. Перевірка охоплює лише стабільний стан служби, а не аналіз, оптимізацію чи стан пристрою.

Довідник

Кожен запуск створює звіт, який можна читати, фільтрувати й експортувати. Звіт завжди відокремлює доведене від того, що було лише помічено.

Вихідні дані та зрозумілий звіт

Вихідні дані зберігають технічні дані з оригінальними номерами рядків, щоб будь-який результат можна було простежити до джерела. Зрозумілий звіт викладає той самий запуск простою мовою й починає з наступного безпечного кроку.

Збережені журнали

KillerBench також може читати збережені журнали Windows, як-от журнали CBS і Setup, нічого не запускаючи на комп'ютері. Результати посилаються на той самий рядок, з якого їх отримано. Кнопка Завантажити зразок у джерелах сеансу відкриває синтетичний приклад, який можна безпечно дослідити.

Експорт

Експортувати звіт зберігає звіт разом зі шляхами до джерел, розібраними записами та фрагментами даних, щоб його можна було переглянути перед додаванням до заявки. Вихідні журнали та фрагменти даних можуть містити імена комп'ютерів, облікові записи, шляхи або конфіденційний вихідний текст. Захищені збирачі обмежують те, що зберігають, але для імпортованих даних приховування не гарантоване. Перед поширенням перевірте та видаліть конфіденційні відомості.

killerbench-cli запускає той самий Engine, що й настільний застосунок, із PowerShell або віддаленої консолі. Кожна команда, яка може змінити комп'ютер, за замовчуванням показує попередній перегляд і потребує явного прапорця, наприклад --execute, перш ніж діяти. Команди виводять дані JSON у стандартний вивід, а перебіг у стандартний потік помилок.

Покрокові посібники: Запуск KillerBench зі скриптів.

Код завершення 0 означає, що попередній перегляд чи підтверджений результат успішні, 1 означає помилку запуску, введення чи журналу, 2 означає, що аргументи не розпізнано, 3 означає заблоковано, невдало чи не підтверджено, 4 означає, що процедурі потрібен перезапуск перед перевіркою, а 130 означає, що ви її зупинили.

Запустіть killerbench-cli без аргументів, щоб вивести цей список на власному комп'ютері.

Дія повідомляє, що її заблоковано

Заблокований результат означає, що запитана дія не змогла продовжитися. Прочитайте повідомлення та журнал, щоб зрозуміти, чи зупинилася вона до надсилання чи після одного з попередніх кроків. Не вважайте, що частково виконану операцію було скасовано. Нижче наведено найпоширеніші причини, пов'язані з передумовами.

  • Потрібні права адміністратора. Закрийте KillerBench і знову запустіть його через Запуск від імені адміністратора.
  • Стан перезавантаження має бути чистим. Windows очікує перезавантаження. Перезавантажте комп'ютер, а потім знову запустіть дію.
  • Діє керована політика. Параметром володіє групова політика або система керування пристроями. Змініть його там.
  • Дані змінилися. Між першою перевіркою та останньою повторною перевіркою щось змінилося. Запустіть інструмент знову, щоб прочитати новий стан.

Попередній запит потребує узгодження

KillerBench знайшов очікувальний запис від перерваного запиту. Знову запустіть ту саму дію. Вона перевірить, що сталося, і повідомить фактичний результат, не повторюючи запит. У командному рядку використовуйте відповідну команду -recover, наприклад killerbench-cli bitlocker-auto-unlock-recover.

Перевірка показує «Незавершені» або «Невідомо»

Дані не вдалося прочитати; часто це трапляється, бо KillerBench запущено не від імені адміністратора або служба Windows була недоступна. KillerBench чесно про це повідомляє, а не вважає комп'ютер справним.

Де зберігаються файли

Журнали, очікувальні записи та збережені дані розміщено в %LOCALAPPDATA%\KillerBench. Кожна захищена дія має власну папку. Зберігайте їх, коли вам потрібен запис про те, що змінилося.
