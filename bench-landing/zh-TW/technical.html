技術解析

深入了解 KillerBench 如何讀取 Windows 電腦、如何保證證據的準確性，以及如何決定何時允許更改。

技術棧

KillerBench 是原生 Windows 應用。桌面應用、命令列及其底層的 Engine 共享相同的診斷證據和修復工作流程。

元件詳細資訊
介面基於 .NET 10 的 WPF（net10.0-windows），Windows x64，自訂視窗邊框
EngineEngine.Core、Engine 和 Engine.Windows，不引用 WPF 或桌面控制項
命令列killerbench-cli，基於同一 Engine 的獨立主機
Windows 提供程式.NET、Windows API、PowerShell 和 Windows 命令列工具，每個都在固定的時間、記錄數和大小限制內執行
報告原始輸出、可讀報告、HTML、文字和 JSON
參考資料帶版本的知識套件，涵蓋錯誤碼、硬體識別碼、供應商和支援參考
打包安裝程式：依賴框架，需要 .NET Desktop Runtime 10 for Windows x64。可攜式版本：獨立包含，無需安裝執行階段
外觀13 種系列佈景主題和 19 種語言

診斷優先

KillerBench 將診斷和更改視為兩項不同的工作。診斷唯讀取。只有當你選擇具體的修復或操作、檢視其選項和前提條件並確認後，才會進行更改。

完整系統掃描僅執行診斷，即使某個專用工作流程開啟了自動修復也是如此。已儲存的擷取、匯入的記錄和歷史事件永遠不能授權修復。

有範圍限制的收集

每個原生命令和 Windows 提供程式都在固定的時間、記錄數和大小限制內執行。提供程式會記錄其退出狀態、逾時、截斷、標準輸出和錯誤輸出。失敗或被截斷的提供程式結果永遠不會被視為乾淨的空結果。

最小化保留

收集器只保留結論所需的內容。許多結果會保留名稱、類別、數量、狀態和時間戳，而不保留認證、命令列、完整路徑、帳戶識別、網路端點和無關的事件負載。

可追溯的證據

每個結論都與產生它的證據相關聯，報告始終將已證明的內容與僅觀察到的內容區分開來。

狀態含義
需要審閱證據支援一個值得關注的問題。
資訊已收集證據並作為背景資訊顯示。
未完成或未知檢查未能完成，或證據不可用。永遠不會被視為正常。
歷史過去的事件。它可以解釋歷史，但不能證明目前存在故障。
已驗證透過讀回結果確認了修復或更改。

未知也是一種結果

未知表示存取被拒絕、來源缺失、提供程式失敗、輸出格式錯誤、超出限制或證據相互矛盾。KillerBench 會顯示這一限制以及下一步有用的操作，而不是將其隱藏。

歷史仍是歷史

事件記錄和匯入的記錄描述的是過去某個時間記錄的內容。它們可以指向某個錯誤碼或下一個診斷範圍，但不能證明故障仍然存在。

記錄和中斷

在請求 Windows 進行更改之前，KillerBench 會先寫下即將執行的操作。每項更改都儲存在 %LOCALAPPDATA%\KillerBench 下的記錄中。

更改之後，KillerBench 會讀回結果，只有當 Windows 顯示預期狀態時才報告 已驗證。如果 Windows 報告成功但狀態沒有變化，結果會如實說明，並且不會重複任何操作。

處理程序可能會在 Windows 收到請求之後、驗證完成之前停止。此時待處理記錄會保留下來，之後的核對會讀取新狀態以確定發生了什麼。核對不是自動復原，也絕不會重複原始更改。結果不確定時請保留記錄。

演示模式

啟動 KillerBench.exe --demo，即可在虛構的工作站上試用 執行診斷。每個工作流程都會產生合成證據和定時進度。不會呼叫任何 Windows 提供程式，不會執行任何修復命令，也不會寫入任何記錄。執行診斷 之外的單獨工具按鈕仍會實際執行，因此請勿將其作為演示操作使用。

KillerBench.exe --demo-screenshot 會為一臺固定的虛構電腦開啟唯讀的完整系統掃描報告。工作區中的按一下、快速鍵和檔案拖放都會被阻止。

更新和簽名

啟動時，KillerBench 會在四秒限制內向 GitHub 查詢最新的穩定版本，並且僅在該版本較新時才提供更新。你可以在「關於」中透過 啟動時檢查更新，或在更新提示中關閉此檢查。下載的是與目前執行副本相匹配的軟體套件（安裝程式或可攜式版本），並且在安裝任何內容之前，其 SHA-256 必須與該版本的 SHA256SUMS.txt 匹配。應用會自行關閉並重新開啟以完成更新。沒有背景服務。

「關於」卡片會顯示版本、代碼簽名釋出者和指紋，以及正在執行的可執行檔案的 SHA-256，以便你檢查手中的副本。

本機化

介面提供 19 種語言：英語、孟加拉語、捷克語、德語、西班牙語、法語、匈牙利語、義大利語、日語、哈薩克語、挪威語、波蘭語、葡萄牙語（巴西）、俄語、土耳其語、烏克蘭語、越南語，以及簡體中文和繁體中文。更改語言會立即生效，包括區段和工作流程名稱、歡迎文字以及已開啟的可讀報告。缺失的文字會以英語顯示。

證據、Engine 結論、記錄和原始輸出與 Windows 記錄一樣保持英語，因此報告在每臺電腦上的內容都相同，並且可以搜尋確切的文字。

命令列和結束代碼

隱私和網路

診斷和記錄分析在本機執行，無需 AI 服務或 KillerBench 帳戶。記錄和保留的證據儲存在本機帳戶的 %LOCALAPPDATA%\KillerBench 資料夾中。

你選擇的操作可能會連線其目標，例如 Windows Update、軟體下載服務，或將修復金鑰備份到 Active Directory 或 Entra ID。啟動時的更新檢查會連線 GitHub，知識更新和 KillerMCP 安裝程式會連線其已設定的服務。使用 KillerMCP 的 AI 客戶端可能會收到它所請求的參考結果。

原始記錄、匯入的檔案和匯出的證據可能包含電腦名稱、帳戶、路徑或敏感的源文字。共享前請先檢查，並且絕不要在公開報告中包含修復金鑰、認證或客戶資料。

安裝、資料夾和資料

KillerBench 提供兩種形式。安裝程式是標準下載，支援按使用者安裝或為所有使用者安裝。可攜式版本自帶 .NET 執行階段，無需安裝即可執行。

KillerBench 以啟動它的帳戶的權限執行，不會自行提高權限。當受保護的證據（例如 BitLocker 保護裝置）或修復需要系統管理員存取權限時，請透過 以系統管理員身分執行 啟動它。提高權限永遠不會選擇或核准修復。

安裝程式的作用

安裝程式會驗證應用程式並將其解壓縮到 %LOCALAPPDATA%\Programs\KillerBench\，或者在為所有使用者安裝時經提高權限提示後解壓縮到 %ProgramFiles%\KillerBench\。它會新增開始選單捷徑、可選的桌面捷徑，以及支援普通解除安裝和無訊息解除安裝的「新增或刪除程式」項目。可攜式版本會為目前執行驗證其負載並將其解壓縮到 %LOCALAPPDATA%\KillerBench\Portable\，並在下次啟動時清理遺留的副本。

受保護的修復

修復是具有適用條件、執行、驗證和復原規則的類型化操作，而不是從記錄行中挑出的命令字串。每項受支援的修復都遵循相同的流程：

  1. 收集完整的目前證據。
  2. 匹配一個受支援的方案。
  3. 檢視必需的選項和後果。
  4. 確認管理和原則方面的前提條件。
  5. 在更改前立即重新收集決定性證據。
  6. 寫入持久的準備記錄。
  7. 執行一個有範圍限制的原生操作。
  8. 收集新的驗證證據。
  9. 記錄已驗證、已阻止、已停止或不確定的結果。

如果決定性證據在操作執行前發生變化，KillerBench 會停止而不執行該操作。

明確的選擇

依賴選項的修復需要你做出確切的選擇，例如磁碟區、印表機佇列、修復金鑰備份位置、電源值、套件版本或修復來源。KillerBench 絕不會自行編造這些值。

受管理的電腦

群組原則和裝置管理可能會使本機更改無效或不合適。受支援的修復會檢查設定的所有者，並在所有權受管理或未知時停止。由原則擁有的設定保持不變。

自動修復

自動修復只允許符合條件的方案繼續執行。它不會繞過證據、選擇缺失的選項、忽略原則、重試不確定的操作、重新啟動 Windows，也不會將需要審閱的結論變成修復。

不會做的事

  • 清除 TPM、刪除不是由它建立的保護裝置，或顯示修復密碼。
  • 更改由群組原則或裝置管理控制的設定。
  • 僅因為歷史事件或匯入的報告提到了某個問題就執行修復。
  • 將缺失、部分或失敗的證據變成執行正常的結論。

報告

每次執行都會產生一份可以閱讀、篩選和匯出的報告。報告會分別說明：

  1. 檢查了什麼
  2. 發現了什麼問題
  3. 哪些證據支援該結論
  4. 提出或執行了什麼操作
  5. 如何驗證結果
  6. 哪些內容仍未知或需要重新啟動

原始輸出 會保留技術證據及其原始行號，因此可以將任何結論追溯到其來源。可讀報告 用通俗的語言總結同一次執行，並將安全的下一步放在最前面。HTML 報告使用 Killer Tools 佈景主題系統，即使沒有應用也能閱讀。文字便於移植，JSON 則為其他程式保留結構化欄位。

已儲存的記錄和擷取

KillerBench 可以在不在電腦上執行任何內容的情況下調查證據。將文字記錄拖放到視窗中，或者貼上其路徑並選擇 開啟記錄。CBS、CSI 和 Setup 行會連同時間戳一起解析，結論會連結到確切的原始行。EVTX 和事件 XML 檔案也可以用同樣的方式匯入。

掃描 Windows Update 會按需以唯讀方式收集 CBS、DISM、Panther 和復原 Setup 記錄、更新和維護事件通道、更新服務狀態、可用空間、執行時間、待處理的重新啟動指示以及所選的更新原則。儲存擷取 會將保留的證據寫入 .kbench 檔案。開啟擷取 會在沒有原始檔案的情況下重新開啟該檔案，並使用已安裝的規則重新評估，因此相同的規則會得出相同的結論。

知識套件

大量且經常更新的參考資料存放在知識套件中，而不是診斷邏輯中：Windows 和 Setup 錯誤碼、供應商和裝置識別碼、PCI、USB、ACPI 和 UEFI 參考、網路 OUI 供應商資料、驅動程式和支援位置以及精選的支援連結。

每個知識套件都會標明其格式、架構版本、來源、來源修訂、產生時間和內容雜湊，KillerBench 會在使用前對其進行驗證。未知或無效的知識套件會保持不可用，而不會回退為猜測。更新會下載到臨時位置並經過驗證，然後一步替換目前的知識套件，因此更新失敗時會保留之前的知識套件。

知識資料可以解釋某個識別碼或建議下一步檢視的位置。它不能將歷史代碼變成目前故障、自動選擇驅動程式或授權修復。

KillerMCP

KillerBench 不包含 AI 代理程式。KillerMCP 可以將代理程式連線到同一 Engine。「關於」中的 KillerMCP 選項 決定該代理程式可以執行的操作：

設定效果
關閉（預設）代理程式無法請求修復。
允許 KillerMCP 執行安全修復代理程式可以請求被歸類為安全的修復。
同時允許破壞性修復破壞性修復變為可用，並且每項修復仍需核准。

只有在這臺電腦前的人才能提高階別。在修復結果不確定後，KillerMCP 會寫入一個鎖定，代理程式修復會一直被阻止，直到有人在「關於」中解除該鎖定。

架構

Engine 分為三個不含介面的專案。Engine.Core 提供基礎類型和宣告式方案，Engine 負責共享的工作流程和證據，Engine.Windows 註冊原生提供程式。桌面應用、CLI 和測試是獨立的主機。

層職責
功能收集器讀取一個確切範圍內有範圍限制的 Windows 狀態
證據解析器驗證形狀、識別、完整性和限制
診斷解釋將證據轉換為明確的工作流程狀態
工作流程編排組合檢查、進度、方案和記錄
修復協調器重新檢查適用條件、準備、更改、驗證和核對
報告呈現問題、操作、結果和限制
知識套件在不更改邏輯的情況下解析帶版本的參考資料

當識別不明確、輸出格式錯誤、超出限制或無法檢查所需的權限時，收集器會失效關閉。Engine 目前面向 Windows，不跨平臺。Engine 開發人員指南 介紹 API、CLI 以及如何將 Engine 嵌入到其他 .NET 主機中。

開發狀態

KillerBench 正在開發中，目前還沒有公開下載。修復範圍仍在擴充套件，實機修復驗證仍在進行中。產生成功或模擬檢查並不能證明實機修復的行為。我們使用一次性 Windows 虛擬機器，在不同的 Windows 版本和故障狀態下驗證每項原生更改。完整的安全模型請參閱 如何保證更改安全。

CBSComponent-Based Servicing，安裝更新和功能的 Windows 子系統。其記錄為 CBS.log。
DISMDeployment Image Servicing and Management，檢查和修復元件存放區的 Windows 工具。
PantherWindows Setup 寫入升級記錄的資料夾。
SFCSystem File Checker，驗證和還原受保護系統檔案的 Windows 工具。
TPMTrusted Platform Module，BitLocker 用來保護磁碟機金鑰的安全晶片。
方案具有自己的適用條件、執行、驗證和復原規則的類型化修復。
待處理保護標記將某項更改標記為可能已傳送到 Windows 的記錄。在核對讀取結果之前，它會阻止重複執行。
提高權限在 Windows 提示後以系統管理員權限執行。KillerBench 絕不會自行提高權限。
工作流程一個工具的一次執行：它收集的檢查、它可能使用的方案以及它產生的報告。
核對在中斷後讀取新狀態以了解發生了什麼，而不重複更改。
記錄在更改前寫入、在更改後更新的本機 JSON 記錄，以便之後檢視中斷的操作。
擷取包含保留證據的已儲存 .kbench 檔案，無需原始電腦即可再次檢視。
知識套件經過驗證的帶版本參考資料檔案，例如錯誤碼或硬體識別碼。
證據KillerBench 實際從 Windows 讀取的內容，與其來源一起保留，以便追溯結論。
失效關閉當證據不明確、缺失或過大時，結果為未知，並且不允許任何更改。
已驗證結果已從 Windows 讀回，並且與更改應達到的狀態一致。
原則所有者控制某項設定的群組原則或裝置管理。KillerBench 不會更改有所有者的設定。
