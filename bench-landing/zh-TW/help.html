從這裡開始

KillerBench 是面向技術人員的 Windows 診斷和修復工作台。它會先檢查電腦，並用每項結論背後的證據解釋所發現的問題；只有在你選擇具體的修復並確認後，才會更改 Windows。

KillerBench 正在開發中，目前還沒有公開下載。這些頁面介紹的是目前版本。

功能

  • 對 Windows Update、裝置、儲存、網路、列印、安全、應用和設定檔執行唯讀診斷，然後產生可讀報告。
  • 提供受保護的修復，僅在新證據準確證明問題時才執行，並在之後驗證結果。
  • 涵蓋 BitLocker、隱私設定、Windows 精簡和新電腦準備等設定與加固工作。
  • 診斷和報告分析在本機執行，無需 AI 或 KillerBench 帳戶。所選操作（例如下載和將修復金鑰備份到 Entra ID）可能會連線外部服務。
  • 主控台、報告、確認框以及「開啟」「儲存」和「資料夾」對話方塊都使用應用的目前佈景主題。

Windows 和執行階段

  • 目前的釋出目標是 Windows x64。Windows 11 x64 是目前實機驗證的基準。不提供原生 ARM64、x86 和 Windows Server 發行版。
  • KillerBench 有兩種打包方式。安裝程式 依賴框架，需要 .NET Desktop Runtime 10 for Windows x64。普通的 .NET Runtime、ASP.NET Core Runtime 和 .NET Framework 不提供 WPF。可攜式版本自帶執行階段，無需單獨安裝。命令列工具 killerbench-cli.exe 需要 .NET 10 Runtime for Windows x64。SDK 僅用於開發，日常使用不需要。
  • 請使用 .NET 10 on Windows 支援的 Windows 版本。執行階段受支援並不表示 KillerBench 的修復已在每個受支援的版本或內部版本上經過驗證。Windows 10 的支援仍待定，其受支援的版本受 Microsoft 目前生命週期要求的限制。
  • 請僅從 Microsoft 的 .NET 10 下載頁面 取得 Desktop Runtime，並選擇 .NET Desktop Runtime、Windows、x64。請遵守所在組織的軟體安裝規定。

如果 dotnet 可用，dotnet --list-runtimes 應列出 x64 安裝的 Microsoft.WindowsDesktop.App 10.0.x。僅為其他架構安裝的執行階段不滿足 x64 安裝程式軟體套件的要求。

軟體套件釋出後

  1. 請使用本網站連結的官方下載。目前還沒有可用的 KillerBench 下載連結。
  2. 閱讀該軟體套件的要求、GPLv3 許可證、對應原始碼的取得說明、隨附的第三方宣告以及簽名和校驗和資訊。僅憑檔名無法證明真實性。
  3. 為目前帳戶執行安裝程式，或在提高權限提示後為所有使用者執行安裝程式。它會新增開始選單捷徑、可選的桌面捷徑以及「新增或刪除程式」項目。可攜式版本無需安裝即可執行。
  4. 以普通帳戶啟動 KillerBench，並按照 首次診斷 操作。診斷時的存取失敗會保持可見；提高權限是另一項有意的選擇。

不要為了執行未經驗證的副本而繞過 Windows 安全警告。在選擇任何會更改電腦的操作之前，請保留最新的備份。

啟動時，KillerBench 會在 GitHub 上檢查是否有更新的穩定版本，並在安裝前徵求你的同意。下載內容必須與公佈的 SHA-256 校驗和匹配。可以在「關於」中透過 啟動時檢查更新 關閉此檢查。

目前限制

目前版本包含十二個區段、唯讀診斷、報告以及單獨選擇的修復功能。實機修復驗證仍在進行中。介面能夠執行、建置成功或測試資料的結果都不能證明在真實電腦上的修復行為。請參閱 如何保證更改安全。

產品首頁上的示意主控台是合成輸出。應用的最終截圖和首個公開軟體套件仍在準備中。

原始碼、許可證和支援

KillerBench 採用 GPLv3 許可證。首個公開軟體套件的原始碼提供說明和第三方字型許可仍待定。有關原始碼可用性、分發宣告、證據隱私和支援資訊，請閱讀 關於 KillerBench。Engine 指南 面向擁有授權原始碼檢出的開發人員，並不表示已有公開的 Engine 軟體套件。

先閱讀 下載和設定，然後執行完整系統掃描。掃描會收集診斷證據並儲存本機記錄，但不會執行修復。結論描述的是所檢查的範圍，而不是電腦上所有可能的故障。

執行掃描

  1. 開啟 KillerBench。診斷 區段會開啟，並已選中 完整系統掃描。
  2. 首次執行時，請保持 自動修復已確認的問題 處於關閉狀態。
  3. 按 執行診斷。每項檢查執行時，右側的 原始輸出 中會顯示進度。
  4. 完成後，輸出窗格會切換到 可讀報告。

請先以非提高權限啟動。部分 Windows 證據（例如 BitLocker 保護裝置和受保護的服務）需要系統管理員權限。在標準帳戶下，這些檢查會報告證據不可用。如果需要這些證據，請先完成目前執行並保留報告，然後有意地透過 以系統管理員身分執行 重新開啟 KillerBench。提高權限不會選擇或核准任何修復。

閱讀報告

報告開頭會顯示 需要檢閱、已驗證的修復、未完成 和 已檢查 的數量，然後是建議的下一步。

  • 需要注意的問題 按重要性列出證據所支援的問題。
  • 收集的資訊 顯示已讀取的內容，包括不完整或不可用的證據。
  • 過去的事件會標記為歷史記錄。上個月的錯誤不會被視為目前故障。

缺失的證據永遠不會被視為正常。如果某項檢查無法執行，報告會明確說明。

自行選擇檢查

開啟 選擇檢查項目（進階） 可以選擇單項檢查，而不是執行完整掃描。應用中的每個區段還有專門的工具，本指南的 區段 頁面對此有介紹。

修復發現的問題

當報告建議修復時，會指明要開啟的區段和工具。首次修復前，請閱讀 如何保證更改安全。實機驗證仍在進行中；診斷成功並不表示所提供的每項修復都已在你的 Windows 版本上經過測試。在進行任何更改之前，請保留備份，並仔細檢視確切的目標和後果。

KillerBench 視窗有三個窗格，與你的工作方式一致：在左側選擇區段，在中間設定工具選項，在右側閱讀輸出。選項下方可以開啟活動記錄。

區段

左側邊欄將所有工具分為十二個區段：診斷、修復、更新、裝置、網路、應用、維護、電腦準備、安全、BitLocker、隱私和儲存。拖動其邊緣可以調整大小，拖過最小寬度則會將其收起。

工具選項

中間窗格顯示所選區段、其工具列表以及所選工具的選項。可能更改電腦的選項預設始終處於關閉狀態。按 執行診斷 啟動工具。開啟 自動修復已確認的問題 後，同一按鈕會顯示為 執行修復。停止 會在目前命令完成後結束執行。

輸出

右側的輸出窗格有兩種檢視。

  • 原始輸出 在收集過程中顯示技術證據及其原始行號。工具執行時它會自動開啟。
  • 可讀報告 顯示上一次執行的完整報告。執行結束後，它會替換原始輸出。

使用原始輸出中的篩選框可以只顯示匹配的行。匯出報告 會將報告連同其來源路徑和證據摘錄一起儲存。工作階段來源 列出本次工作階段中收集的所有證據。

活動記錄

工具選項下方的活動記錄會記下 KillerBench 在本次工作階段中執行的操作。

佈景主題、語言和快速鍵

側邊欄與工具選項之間的導軌上有佈景主題選擇器、語言選擇器、快速鍵列表和活動記錄開關。KillerBench 提供 13 種佈景主題和 19 種語言。

煙燻玻璃風格的主控台和可讀報告會跟隨目前佈景主題。確認框以及「開啟」「儲存」和「資料夾」對話方塊使用相同的系列樣式，包括 98SE 佈景主題。請在開啟對話方塊之前選擇佈景主題，以便在整個工作流程中使用該外觀。

KillerBench 將診斷和更改視為兩項不同的工作。診斷唯讀取。完整系統掃描從不執行修復。請選擇具體的修復或操作，檢視其選項和前提條件，然後確認建議的更改。

更改之前

  1. 新證據。 工具會重新讀取目前狀態。已儲存的報告或舊事件永遠不能授權更改。
  2. 確切的適用條件。 只有當證據與更改所修復的問題完全匹配時，才會提供該更改。任何不完整的情況都會阻止更改。
  3. 你的確認。 在確認對話方塊中檢視所選操作。某些操作（例如解密磁碟機）需要第二次確認。對話方塊跟隨應用的目前佈景主題，其外觀不會改變操作的要求。
  4. 前提條件。 會檢查系統管理員權限、重新啟動狀態以及原則或裝置管理對設定的所有權。由原則擁有的設定保持不變。
  5. 待處理記錄。 KillerBench 會在請求 Windows 執行操作之前，先記錄即將執行的內容。
  6. 最後複查。 在發出請求前會立即再次檢查所有內容，因此期間發生的變化會讓操作停止。

更改之後

  • KillerBench 會讀回結果，只有當 Windows 顯示預期狀態時才報告 已驗證。
  • 如果 Windows 返回成功但狀態沒有變化，結果會如實說明，並且不會重複任何操作。
  • 每項更改都儲存在 %LOCALAPPDATA%\KillerBench 下的記錄中。

如果操作被中斷

當請求可能已到達 Windows 但驗證尚未完成時，受支援的寫入記錄的操作會保留待處理記錄。請使用該操作文件中說明的核對方式或相應的 -recover 命令來檢查該記錄。核對不是自動復原。結果不確定時請保留記錄，不要手動重複更改。當機、取消和下次啟動時的行為仍需針對每項操作進行實機驗證。

KillerBench 不會做的事

  • 清除 TPM、刪除不是由它建立的保護裝置，或顯示修復密碼。
  • 更改由群組原則或裝置管理控制的設定。
  • 僅因為歷史事件或匯入的報告提到了某個問題就執行修復。

診斷和報告分析在本機執行。你選擇的操作可能會連線外部目標，包括軟體下載或將修復金鑰備份到 Active Directory 或 Entra ID。確認之前請檢查目標。已儲存的擷取和原始證據可能包含電腦識別和來源路徑，因此共享前請先檢查。

開發狀態

修復範圍仍在擴大。建置成功或模擬檢查並不能證明實機修復的行為。儲存庫中的 VM-VALIDATION.md 記錄了在一次性 Windows 電腦上的場景以及剩餘的驗證工作。

操作指南

當更新失敗、停滯或反覆重新安裝時使用本指南。KillerBench 會先讀取更新鏈，用其背後的證據解釋故障，並且只有在新證據準確證明該問題時，才會啟動服務或修復元件存放區。

開始之前

  • 以系統管理員身份執行 KillerBench。更新服務、元件存放區和受保護的系統檔案需要提高權限才能獲得完整證據。
  • 如果 Windows 已有待處理的重新啟動，請先重新啟動。在重新啟動狀態清除之前，許多更新修復都會被阻止。
  • 執行維護工作時，請讓電腦連線交流電源。

找出更新失敗的原因

  1. 開啟 更新，並在工具列表中選擇 Windows Update。
  2. 第一次執行時保持 自動修復已確認的問題 關閉，然後按 執行診斷。
  3. 閱讀 可讀報告。它會列出已停止的更新服務、待處理的重新啟動、可用空間不足、元件存放區損壞以及 Windows 記錄的確切錯誤碼，並給出建議的下一步。
  4. 如果報告中出現錯誤碼，相應的後續檢查會自動執行。你也可以使用 killerbench-cli update-code 0x80070002 自行查詢。

監視看似停滯的更新

在 更新 中選擇 維護活動監視器，然後按 執行診斷。它會反覆拍攝更新、Setup 和 Installer 活動、傳輸總量以及重新啟動指示的快照。活動僅作為證據顯示，它本身絕不會斷定存在停滯或故障。

修復報告發現的問題

  1. 開啟 自動修復已確認的問題，再次執行 Windows Update。它可以啟動已確認停止的已啟用更新服務，並且僅在實時檢查確認損壞時才執行 DISM 或 SFC。
  2. 對於單個服務，請改用其專用工具，例如 BITS 服務、加密服務、Windows 模組安裝程式 或 Update Orchestrator 服務。每個工具只針對該服務提供復原。
  3. 當報告要求重新啟動時，請先重新啟動，再執行其他任何內容。KillerBench 會記錄需要重新啟動的結果，並將後續工作推遲到重新啟動完成之後。

每項修復都會寫入記錄並讀回。完整流程請參閱 如何保證更改安全。

安裝特定更新

  1. 在 更新 中選擇 可用更新，然後按 執行診斷，從已設定的來源查詢更新。
  2. 選擇所需的更新，然後按 預覽已選擇項目。預覽會準確列出將要安裝的內容以及是否需要重新啟動。
  3. 請在閱讀預覽後再安裝。KillerBench 絕不會替你選擇或核准更新。

透過命令列

killerbench-cli update-search
killerbench-cli update-history
killerbench-cli servicing-monitor --samples 10
killerbench-cli update-plan --select GUID:REVISION --execute

請參閱 update-search、update-history、servicing-monitor 和 update-plan。如果安裝被中斷，請執行 update-recover；它會檢查結果，並且絕不會重試更新。

當 Windows 元件損壞時使用本指南，例如功能無法安裝、更新報告元件錯誤或系統工具當機。KillerBench 只有在實時檢查確認損壞後才執行 DISM 和 SFC，然後驗證結果。

開始之前

  • 以系統管理員身份執行 KillerBench。
  • 先完成所有待處理的重新啟動。
  • 如果電腦受管理，請檢查原則是否將 DISM 指向特定的修復來源。KillerBench 會報告該原則，但不會更改它。

檢查損壞

  1. 開啟 修復，然後選擇 系統檔案。
  2. 保持 自動修復已確認的問題 關閉，然後按 執行診斷。
  3. 閱讀報告。它會清點維護套件、可選功能和功能的狀態，檢查前提條件，並掃描受保護的系統檔案。結果正常則表示不提供修復。

修復已確認的損壞

  1. 開啟 自動修復已確認的問題，然後按 執行修復。只有當實時檢查確認損壞時，KillerBench 才會選擇 DISM 或 SFC。
  2. 等待驗證。只有當後續檢查讀回已修復的狀態時，報告才會顯示 已驗證。
  3. 如果報告指出元件存放區無法復原或修復來源不可用，請就此停止。重複修復不會改變結果。

在 更新 中選擇 元件存放區清理。它會先詢問 Windows 是否建議清理。可選的維護會刪除被取代的元件並再次分析。它絕不會使用 ResetBase，也絕不會手動刪除 WinSxS 內容。

killerbench-cli servicing-logs

請參閱 component-repair-source、repair 和 servicing-logs。repair 預設只顯示預覽，僅在使用 --execute 時才會執行。

當磁碟區報告錯誤、Windows 要求掃描磁碟機或檔案無法開啟時使用本指南。KillerBench 會先以唯讀方式檢查磁碟區，只有在你確認已備份後才會排程或執行檔案系統修復。

  1. 開啟 儲存，然後選擇 儲存。
  2. 在 要檢查的磁碟區 中選擇磁碟機，然後按 執行診斷。
  3. 閱讀報告。它會顯示磁碟和磁碟區的執行狀況、髒位元、NTFS 線上自我修復、控制器和磁碟裝置錯誤、可靠性計數器，以及重置、重試和意外移除等最近的儲存事件。

  1. 按 檢視檔案系統修復，然後選擇 定點修復 或 離線掃描與修復。

  3. 勾選 此磁碟區上的重要資料已備份。
  4. 確認修復。KillerBench 會在執行前立即重新檢查該磁碟區，並先記錄一個待處理項目。
  5. 對於已排程的修復，請在方便時重新啟動。KillerBench 會在重新啟動後驗證結果，而不會再次執行修復。

當電腦無法上網、無法存取伺服器或名稱，或者連線頻繁斷開時使用本指南。KillerBench 會依次檢查介面卡、位址、閘道、DNS 和防火牆，並且只有在新證據證明確有必要時，才會續訂租約或啟動服務。

檢查連線

  1. 開啟 網路，然後選擇 網路。
  2. 要測試特定目標，請填寫 主機名稱查詢（可選），或者 TCP 目的地（可選） 和 TCP 連接埠。若只檢查本機設定，請留空。不會傳送任何應用程式資料。
  3. 如果網路較慢，請設定 每次查詢或連線的逾時（秒）。
  4. 保持 自動修復已確認的問題 關閉，然後按 執行診斷。
  5. 閱讀報告。它會區分缺少位址、缺少閘道或閘道不可存取、DNS 設定問題、Proxy設定、防火牆設定檔不匹配以及查詢或連線失敗，併為每種情況給出下一步。

閘道有回應並不能證明可以存取 Internet；透過已設定的解析程式查詢失敗，也不代表該網站已停止執行。

修復報告發現的問題

  1. 開啟 自動修復已確認的問題，再次執行 網路。它可以啟動已啟用的 DNS Client、DHCP Client、SMB 客戶端、Network Location Awareness、Network List 和 IP Helper 服務，併為缺少可用 IPv4 位址的已連線實體 DHCP 介面卡續訂租約。
  2. 續訂期間連線可能會短暫斷開。靜態位址和虛擬介面卡永遠不會被更改。
  3. 對於快取中某個錯誤的名稱，請使用針對該確切主機的 DNS 快取重新整理，而不是清除所有內容。

路由、Hosts 項目、DNS 伺服器、防火牆規則、Winsock 提供程式和網路設定檔始終保持不變。

無線、有線登入和Proxy

  • 無線網路 會檢查介面卡和 WLAN AutoConfig，並在服務停止時啟動它。
  • 有線身份驗證 (802.1X) 會針對需要在連接埠登入的網路，對 Wired AutoConfig 執行相同的操作。
  • WinHTTP 自動 Proxy 會顯示電腦和目前帳戶已儲存的Proxy設定。KillerBench 在診斷期間絕不會取得 PAC URL 或更改Proxy設定。

透過命令列

killerbench-cli workflow network --host example.com --tcp example.com 443
killerbench-cli dns-check example.com --timeout-seconds 5
killerbench-cli tcp-check fileserver 445
killerbench-cli dhcp-renew
killerbench-cli dns-cache example.com --execute

請參閱 workflow、dns-check、tcp-check、dhcp-renew 和 dns-cache。

最佳化磁碟機服務

檢查最佳化磁碟機服務的可用性。選用的復原會在重新檢查相依性後，僅啟動已啟用且已停止的確切服務。Windows 已排程的現有最佳化活動可能會按照目前維護原則繼續。磁碟區、檔案系統、資料、最佳化排程、維護原則、服務權限和啟動類型保持不變。KillerBench 不會選擇磁碟區，也不會對任何磁碟機進行分析、修整、磁碟重組、最佳化或排程。驗證僅涵蓋服務的穩定狀態，不包括分析、最佳化或裝置執行狀況。

操作顯示被阻止

被阻止的結果表示所請求的操作無法繼續。請閱讀訊息和記錄，了解它是在傳送之前停止，還是在之前的某個步驟之後停止。不要以為部分完成的操作已經復原。最常見的前提條件原因如下。

  • 需要系統管理員存取權限。 關閉 KillerBench，然後透過 以系統管理員身分執行 重新啟動。
  • 重新啟動狀態必須已清除。 Windows 有待處理的重新啟動。請重新啟動電腦，然後再次執行該操作。
  • 存在受管理的原則。 該設定由群組原則或裝置管理擁有。請在那裡更改。
  • 證據已變化。 在首次檢查和最後複查之間發生了變化。請再次執行工具以讀取新狀態。

之前的請求需要核對

KillerBench 發現了一個來自中斷請求的待處理記錄。請再次執行同一操作。它會檢查發生了什麼，並在不重複請求的情況下報告實際結果。在命令列中，請使用相應的 -recover 命令，例如 killerbench-cli bitlocker-auto-unlock-recover。

檢查顯示未完成或未知

無法讀取證據，通常是因為 KillerBench 未以系統管理員身份執行，或者某個 Windows 服務不可用。KillerBench 會如實報告這一點，而不會假定電腦正常。

檔案儲存位置

記錄、待處理記錄和已儲存的證據位於 %LOCALAPPDATA%\KillerBench 下。每個受保護的操作都有自己的資料夾。如果需要保留更改記錄，請保留這些檔案。
