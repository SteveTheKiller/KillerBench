Commencer ici

KillerBench est un atelier de diagnostic et de réparation de Windows destiné aux techniciens. Il vérifie d'abord l'ordinateur, explique ce qu'il a trouvé avec les preuves qui soutiennent chaque constat, et ne modifie Windows que lorsque vous choisissez une correction précise et la confirmez.

KillerBench est en développement. Aucun téléchargement public n'est encore disponible. Ces pages décrivent la version actuelle.

Ce qu'il fait

  • Exécute des diagnostics en lecture seule sur Windows Update, les périphériques, le stockage, le réseau, l'impression, la sécurité, les applications et les profils, puis rédige un rapport lisible.
  • Propose des réparations protégées qui ne s'exécutent que lorsque des preuves récentes démontrent le problème exact, et vérifie ensuite le résultat.
  • Couvre les tâches de configuration et de durcissement comme BitLocker, les paramètres de confidentialité, le désencombrement de Windows et la mise en service d'un nouvel ordinateur.
  • Exécute les diagnostics et l'analyse des rapports en local, sans IA ni compte KillerBench. Certaines actions sélectionnées, comme les téléchargements et la sauvegarde de la clé de récupération dans Entra ID, peuvent contacter des services externes.
  • Utilise le thème actif de l'application pour la console, les rapports, les confirmations et les boîtes de dialogue Ouvrir, Enregistrer et Dossier.

Windows et runtime

  • La cible de publication actuelle est Windows x64. Windows 11 x64 est la référence actuelle de validation native. Aucune distribution native ARM64, x86 ou Windows Server n'est fournie.
  • KillerBench est empaqueté de deux façons. Le programme d'installation dépend du framework et nécessite .NET Desktop Runtime 10 pour Windows x64. Le .NET Runtime de base, ASP.NET Core Runtime et .NET Framework ne fournissent pas WPF. L'édition portable embarque son propre runtime et ne nécessite aucune installation séparée. L'outil en ligne de commande killerbench-cli.exe nécessite le .NET 10 Runtime pour Windows x64. Un SDK n'est nécessaire que pour le développement, pas pour un usage normal.
  • Utilisez une version de Windows prise en charge par .NET 10 sur Windows. La prise en charge du runtime ne signifie pas que les réparations de KillerBench sont validées sur chaque édition ou version prise en charge. La couverture de Windows 10 reste en attente et ses éditions prises en charge dépendent des exigences actuelles du cycle de vie de Microsoft.
  • Procurez-vous le Desktop Runtime uniquement sur la page de téléchargement .NET 10 de Microsoft, en choisissant .NET Desktop Runtime, Windows, x64. Respectez les règles d'installation de logiciels de votre organisation.

Si dotnet est disponible, dotnet --list-runtimes doit afficher Microsoft.WindowsDesktop.App 10.0.x pour l'installation x64. Un runtime installé uniquement pour une autre architecture ne convient pas au paquet d'installation x64.

Lorsqu'un paquet sera publié

  1. Utilisez le téléchargement officiel accessible depuis ce site. Aucun lien de téléchargement de KillerBench n'est encore actif.
  2. Lisez les exigences de ce paquet, la licence GPLv3, les instructions relatives au Code source correspondant, les avis de tiers inclus et les informations de signature et de somme de contrôle. Un nom de fichier ne suffit pas à prouver l'authenticité.
  3. Exécutez le programme d'installation pour le compte actuel, ou pour tous les utilisateurs après une demande d'élévation. Il ajoute un raccourci dans le menu Démarrer, un raccourci facultatif sur le bureau et une entrée dans Ajout/Suppression de programmes. L'édition portable s'exécute sans installation.
  4. Lancez KillerBench avec votre compte habituel et suivez Votre premier diagnostic. Les échecs d'accès du diagnostic restent visibles ; l'élévation est un choix distinct et délibéré.

Ne contournez pas les avertissements de sécurité de Windows pour exécuter une copie non vérifiée. Conservez une sauvegarde à jour avant de sélectionner une action qui modifie l'ordinateur.

Au démarrage, KillerBench interroge GitHub pour savoir s'il existe une version stable plus récente et demande votre accord avant de l'installer. Le téléchargement doit correspondre à la somme de contrôle SHA-256 publiée. Désactivez cette vérification avec Rechercher les mises à jour au démarrage dans À propos.

Lancer l'analyse

  1. Ouvrez KillerBench. La section Diagnostics s'ouvre avec Analyse complète du système sélectionnée.
  2. Laissez Réparer automatiquement les problèmes confirmés désactivé pour votre première exécution.
  3. Appuyez sur Exécuter le diagnostic. La progression s'affiche dans Sortie brute, à droite, pendant l'exécution de chaque vérification.
  4. À la fin, le volet de sortie passe au Rapport lisible.

Commencez sans élévation. Certaines preuves Windows, comme les protecteurs BitLocker et les services protégés, nécessitent des droits d'administrateur. Avec un compte standard, ces vérifications signalent que la preuve n'est pas disponible. Si vous avez besoin de cette preuve, terminez l'exécution en cours, conservez le rapport, puis rouvrez volontairement KillerBench avec Exécuter en tant qu'administrateur. L'élévation ne sélectionne ni n'approuve aucune réparation.

Lire le rapport

Le rapport commence par les nombres de À examiner, Réparations vérifiées, Incomplètes et Contrôlées, suivis d'une étape suivante recommandée.

  • Ce qui demande de l'attention liste les problèmes étayés par les preuves, du plus important au moins important.
  • Informations collectées montre ce qui a été lu, y compris les preuves incomplètes ou indisponibles.
  • Les événements historiques sont marqués comme historiques. Une erreur du mois dernier n'est pas traitée comme une panne actuelle.

L'absence de preuve ne compte jamais comme un bon état. Si une vérification n'a pas pu s'exécuter, le rapport le dit.

Choisir vous-même les vérifications

Ouvrez Choisir les vérifications (avancé) pour sélectionner des vérifications individuelles plutôt que l'analyse complète. Chaque section de l'application propose aussi des outils ciblés, décrits dans les pages Sections de ce guide.

Corriger ce que vous avez trouvé

Lorsque le rapport recommande une correction, il indique la section et l'outil à ouvrir. Lisez Comment les modifications restent sûres avant votre première réparation. La validation native est encore en cours ; un diagnostic réussi ne prouve pas que chaque réparation proposée a été testée sur votre version de Windows. Conservez des sauvegardes et examinez la cible exacte et les conséquences avant toute modification.

La fenêtre de KillerBench comporte trois volets qui suivent votre façon de travailler : choisissez une section à gauche, réglez les options de l'outil au centre et lisez la sortie à droite. Un journal d'activité peut s'ouvrir sous les options.

Sections

La barre latérale de gauche répertorie tous les outils dans douze sections : Diagnostics, Réparation, Mises à jour, Périphériques, Réseau, Applications, Maintenance, Mise en service, Sécurité, BitLocker, Confidentialité et Stockage. Faites glisser son bord pour la redimensionner, ou au-delà de sa largeur minimale pour la refermer.

Options de l'outil

Le volet central affiche la section sélectionnée, sa liste d'outils et les options de l'outil choisi. Les options qui pourraient modifier l'ordinateur sont toujours désactivées par défaut. Appuyez sur Exécuter le diagnostic pour lancer l'outil. Quand Réparer automatiquement les problèmes confirmés est activé, le même bouton devient Exécuter la réparation. Arrêter met fin à l'exécution une fois la commande en cours terminée.

Sortie

Le volet de sortie à droite propose deux vues.

  • Sortie brute affiche les preuves techniques au fur et à mesure de leur collecte, avec les numéros de ligne d'origine. Elle s'ouvre d'elle-même pendant l'exécution d'un outil.
  • Rapport lisible affiche le rapport terminé de la dernière exécution. Il remplace la sortie brute à la fin de l'exécution.

Utilisez la zone de filtre de Sortie brute pour n'afficher que les lignes correspondantes. Exporter le rapport enregistre le rapport avec ses chemins sources et ses extraits de preuves. Sources de session liste chaque preuve recueillie pendant cette session.

Journal d'activité

Le journal d'activité, sous les options de l'outil, consigne ce que KillerBench a fait pendant cette session.

Thèmes, langues et raccourcis

Le rail situé entre la barre latérale et les options de l'outil contient le sélecteur de thème, le sélecteur de langue, la liste des raccourcis et le bouton du journal d'activité. KillerBench propose 13 thèmes et 20 langues.

La console en verre fumé et les rapports lisibles suivent le thème actif. Les confirmations et les boîtes de dialogue Ouvrir, Enregistrer et Dossier utilisent le même style de la famille, y compris le thème 98SE. Choisissez le thème avant d'ouvrir une boîte de dialogue pour conserver cette apparence tout au long du flux.

KillerBench traite le diagnostic et la modification comme deux tâches distinctes. Le diagnostic ne fait que lire. L'analyse complète du système n'exécute jamais de réparation. Sélectionnez une réparation ou une action précise, examinez ses options et ses prérequis, puis confirmez la modification proposée.

Avant une modification

  1. Des preuves récentes. L'outil relit l'état actuel. Un rapport enregistré ou un ancien événement n'autorise jamais une modification.
  2. Une éligibilité exacte. La modification n'est proposée que si les preuves correspondent au problème exact qu'elle corrige. Tout élément incomplet la bloque.
  3. Votre confirmation. Examinez l'action sélectionnée dans sa boîte de confirmation. Certaines actions, comme le déchiffrement d'un lecteur, demandent une seconde confirmation. La boîte suit le thème actif de l'application ; son apparence ne change pas les exigences de l'action.
  4. Les prérequis. Les droits d'administrateur, l'état de redémarrage et le contrôle par une stratégie ou par la gestion des appareils sont vérifiés. Les paramètres contrôlés par une stratégie ne sont pas touchés.
  5. Un enregistrement en attente. KillerBench consigne ce qu'il s'apprête à faire avant de le demander à Windows.
  6. Une dernière vérification. Tout est revérifié juste avant la demande, si bien qu'un changement entre-temps l'arrête.

Après une modification

  • KillerBench relit le résultat et n'indique Vérifié que lorsque Windows affiche l'état attendu.
  • Si Windows signale une réussite mais que l'état n'a pas changé, le résultat le dit et rien n'est répété.
  • Chaque modification est enregistrée dans un journal sous %LOCALAPPDATA%\KillerBench.

En cas d'interruption

Les actions journalisées prises en charge conservent un enregistrement en attente lorsqu'une demande a pu atteindre Windows sans que la vérification soit terminée. Utilisez le chemin de rapprochement documenté de l'action, ou sa commande -recover correspondante, pour inspecter cet enregistrement. Le rapprochement n'est pas une restauration automatique. Conservez le journal quand le résultat est incertain et ne répétez pas la modification à la main. Le comportement en cas de plantage, d'annulation ou de démarrage ultérieur doit encore faire l'objet d'une validation native propre à chaque action.

Ce que KillerBench ne fera pas

  • Effacer un TPM, supprimer des protecteurs qu'il n'a pas créés ou afficher des mots de passe de récupération.
  • Modifier un paramètre contrôlé par une stratégie de groupe ou par la gestion des appareils.
  • Exécuter une réparation simplement parce qu'un événement historique ou un rapport importé mentionne un problème.

Les diagnostics et l'analyse des rapports s'exécutent en local. Une action que vous sélectionnez peut contacter une destination externe, comme un téléchargement de logiciel ou la sauvegarde de la clé de récupération dans Active Directory ou Entra ID. Vérifiez la cible avant de confirmer. Les captures enregistrées et les preuves brutes peuvent contenir l'identité de l'ordinateur et des chemins sources ; examinez-les avant de les partager.

État du développement

La couverture des réparations continue de s'étendre. Une compilation réussie ou une vérification simulée ne prouve pas le comportement natif d'une réparation.

Guides pas à pas

Utilisez ce guide lorsque les mises à jour échouent, se bloquent ou se réinstallent sans cesse. KillerBench lit d'abord la chaîne de mise à jour, explique l'échec avec les preuves qui le soutiennent, et ne démarre un service ou ne répare le magasin de composants que lorsque des preuves récentes démontrent ce problème exact.

Avant de commencer

  • Exécutez KillerBench en tant qu'administrateur. Les services de mise à jour, le magasin de composants et les fichiers système protégés nécessitent une élévation pour fournir des preuves complètes.
  • Redémarrez d'abord si Windows attend déjà un redémarrage. De nombreuses réparations de mise à jour restent bloquées tant qu'un redémarrage est en attente.
  • Laissez l'ordinateur branché sur secteur pendant la maintenance.

Comprendre pourquoi les mises à jour échouent

  1. Ouvrez Mises à jour et choisissez Windows Update dans la barre latérale des outils.
  2. Laissez Réparer automatiquement les problèmes confirmés désactivé pour le premier passage et appuyez sur Exécuter le diagnostic.
  3. Lisez le Rapport lisible. Il liste les services de mise à jour arrêtés, les redémarrages en attente, le manque d'espace libre, les corruptions du magasin de composants et les codes d'erreur exacts enregistrés par Windows, avec une étape suivante recommandée.
  4. Si le rapport mentionne un code d'erreur, les vérifications de suivi correspondantes s'exécutent automatiquement. Vous pouvez aussi en rechercher un vous-même avec killerbench-cli update-code 0x80070002.

Surveiller une mise à jour qui semble bloquée

Choisissez Moniteur d'activité de maintenance dans Mises à jour et appuyez sur Exécuter le diagnostic. Il prend des instantanés répétés de l'activité de mise à jour, de Setup et d'Installer, des totaux de transfert et des indicateurs de redémarrage. L'activité est présentée uniquement comme preuve ; elle n'affirme jamais d'elle-même un blocage ou une panne.

Réparer ce que le rapport a trouvé

  1. Relancez Windows Update avec Réparer automatiquement les problèmes confirmés activé. Il peut démarrer des services de mise à jour activés dont l'arrêt est confirmé, et n'exécute DISM ou SFC que lorsque la vérification en direct confirme une corruption.
  2. Pour un seul service, choisissez plutôt son outil ciblé, comme Service BITS, Services de chiffrement, Programme d'installation pour les modules Windows ou Service Update Orchestrator. Chacun ne propose une récupération que pour ce service exact.
  3. Quand le rapport demande un redémarrage, redémarrez avant d'exécuter quoi que ce soit d'autre. KillerBench consigne les résultats qui exigent un redémarrage et reporte les tâches suivantes jusqu'au redémarrage.

Chaque réparation est journalisée et relue. Voir Comment les modifications restent sûres pour la séquence complète.

Installer une mise à jour précise

  1. Choisissez Mises à jour disponibles dans Mises à jour et appuyez sur Exécuter le diagnostic pour découvrir les mises à jour de la source configurée.
  2. Sélectionnez les mises à jour voulues et appuyez sur Prévisualiser la sélection. L'aperçu indique exactement ce qui serait installé et tout redémarrage nécessaire.
  3. Lisez l'aperçu, cochez la case de confirmation, puis appuyez sur Installer. La case se décoche après chaque exécution, et KillerBench ne sélectionne ni n'approuve jamais une mise à jour à votre place.

Depuis la ligne de commande

killerbench-cli update-search
killerbench-cli update-history
killerbench-cli servicing-monitor --samples 10
killerbench-cli update-plan --select GUID:REVISION --execute

Voir update-search, update-history, servicing-monitor et update-plan. Si une installation a été interrompue, exécutez update-recover ; il vérifie le résultat et ne relance jamais la mise à jour.

Utilisez ce guide lorsque des composants Windows sont corrompus : des fonctionnalités refusent de s'installer, des mises à jour signalent des erreurs de composants ou des outils système plantent. KillerBench n'exécute DISM et SFC qu'après qu'une vérification en direct a confirmé une corruption, puis vérifie le résultat.

Avant de commencer

  • Exécutez KillerBench en tant qu'administrateur.
  • Effectuez d'abord tout redémarrage en attente.
  • Si l'ordinateur est géré, vérifiez si une stratégie dirige DISM vers une source de réparation précise. KillerBench signale cette stratégie et ne la modifie pas.

Rechercher une corruption

  1. Ouvrez Réparation et choisissez Fichiers système.
  2. Laissez Réparer automatiquement les problèmes confirmés désactivé et appuyez sur Exécuter le diagnostic.
  3. Lisez le rapport. Il inventorie les états des packages de maintenance, des fonctionnalités facultatives et des capacités, vérifie les prérequis et analyse les fichiers système protégés. Un résultat propre signifie qu'aucune réparation n'est proposée.

Réparer une corruption confirmée

  1. Activez Réparer automatiquement les problèmes confirmés et appuyez sur Exécuter la réparation. KillerBench ne choisit DISM ou SFC que lorsque la vérification en direct confirme une corruption.
  2. Attendez la vérification. Le rapport n'affiche Vérifié que lorsque la vérification de suivi relit un état réparé.
  3. Si le rapport indique que le magasin est irrécupérable ou que la source de réparation est indisponible, arrêtez-vous là. Répéter la réparation ne changera pas le résultat.

Une exécution interrompue de DISM ou de SFC est rapprochée au démarrage suivant sans répéter la commande de maintenance.

Nettoyer le magasin de composants

Choisissez Nettoyage du magasin de composants dans Mises à jour. Il demande d'abord à Windows si un nettoyage est recommandé. La maintenance facultative supprime les composants remplacés et relance l'analyse. Il n'utilise jamais ResetBase et ne supprime jamais de contenu WinSxS à la main.

Depuis la ligne de commande

killerbench-cli component-repair-source
killerbench-cli repair dism
killerbench-cli repair sfc --execute
killerbench-cli servicing-logs

Voir component-repair-source, repair et servicing-logs. repair affiche un aperçu par défaut et n'agit qu'avec --execute.

Utilisez ce guide lorsqu'un lecteur manque d'espace. KillerBench montre où part l'espace, prévisualise ce que chaque cible de nettoyage supprimerait et ne supprime qu'après que vous avez activé le nettoyage permanent.

Voir l'espace restant

  1. Ouvrez Stockage et choisissez Stockage.
  2. Appuyez sur Exécuter le diagnostic. Le rapport signale chaque volume doté d'une lettre de lecteur ayant moins de 10 % d'espace libre et affiche l'allocation des clichés instantanés, les quotas par défaut et la stratégie de l'Assistant Stockage.
  3. Pour les vidages sur incident et l'ancien contenu de mise à jour, exécutez aussi Signes vitaux dans Diagnostics et Windows Update dans Mises à jour ; la taille du cache des mises à jour y apparaît.

Prévisualiser un nettoyage

  1. Ouvrez Maintenance et choisissez Nettoyage.
  2. Cochez les cibles voulues, comme Fichiers temporaires de l'utilisateur actuel, Fichiers temporaires Windows, Caches de navigateur de l'utilisateur actuel, Cache Delivery Optimization ou Corbeille de l'utilisateur actuel. Survolez une cible pour lire exactement les dossiers qu'elle couvre.
  3. Réglez Âge minimum (jours) et Nombre maximal de fichiers par cible.
  4. Appuyez sur Exécuter le diagnostic avec Effectuer le nettoyage permanent sélectionné après des vérifications fraîches désactivé. Le rapport liste les candidats et l'espace estimé pour chaque cible. Rien n'est supprimé.

Supprimer les fichiers

  1. Activez Effectuer le nettoyage permanent sélectionné après des vérifications fraîches et appuyez sur Exécuter le diagnostic.
  2. KillerBench revérifie chaque candidat avant de le supprimer, ignore les fichiers récents, protégés ou en cours d'utilisation, et consigne chaque résultat dans le journal.

Le nettoyage permanent contourne la Corbeille et ne peut pas être annulé. Supprimer les rapports d'erreurs et les vidages sur incident élimine des preuves dont vous pourriez avoir besoin pour enquêter sur des plantages ; examinez-les d'abord.

Supprimer l'installation Windows précédente

Après une mise à niveau de fonctionnalités, Installation Windows précédente dans Nettoyage peut supprimer la copie de restauration au moyen de la demande de suppression de restauration prise en charge par Windows. Elle s'exécute seule, nécessite J'ai sauvegardé tous les fichiers et paramètres dont j'ai besoin depuis l'installation précédente, et supprime définitivement la possibilité de revenir à la version antérieure.

Depuis la ligne de commande

killerbench-cli volume-capacity C:
killerbench-cli cleanup --user-temp --windows-temp --days 7 --max-files 500
killerbench-cli cleanup --user-temp --windows-temp --days 7 --max-files 500 --execute

Voir volume-capacity, cleanup et previous-windows.

Utilisez ce guide lorsqu'un volume signale des erreurs, que Windows demande d'analyser un lecteur ou que des fichiers refusent de s'ouvrir. KillerBench vérifie d'abord le volume en lecture seule et ne planifie ou n'exécute une réparation du système de fichiers qu'après que vous avez confirmé disposer d'une sauvegarde.

Vérifier le volume

  1. Ouvrez Stockage et choisissez Stockage.
  2. Choisissez le lecteur dans Volume à vérifier et appuyez sur Exécuter le diagnostic.
  3. Lisez le rapport. Il affiche l'état du disque et du volume, le bit d'intégrité, l'autoréparation NTFS en ligne, les erreurs de contrôleur et de périphériques de disque, les compteurs de fiabilité et les événements de stockage récents, comme les réinitialisations, les nouvelles tentatives et les retraits inattendus.

Une vérification propre signifie qu'aucune réparation n'est proposée. La température du disque, l'usure et les compteurs d'E/S non corrigées sont des preuves à examiner et ne déclenchent pas de réparation à eux seuls.

  3. Cochez Les données importantes de ce volume sont sauvegardées.
  4. Confirmez la réparation. KillerBench revérifie le volume exact juste avant d'agir et consigne d'abord une entrée en attente.
  5. Pour une réparation planifiée, redémarrez quand cela vous convient. KillerBench vérifie le résultat après le redémarrage sans relancer la réparation.

Avant de commencer

  • Exécutez KillerBench en tant qu'administrateur.
  • Le lecteur Windows a besoin d'un protecteur TPM et d'un protecteur de mot de passe de récupération. Un lecteur de données n'a besoin que d'un mot de passe de récupération.

  1. Ouvrez BitLocker et choisissez le lecteur dans Volume.
  2. Laissez l'opération sur Inspecter et appuyez sur Exécuter le diagnostic. Le rapport affiche l'état du chiffrement, l'état de la protection et les identités des protecteurs.
  3. Si le TPM est présent mais pas prêt, préparez-le d'abord depuis Sécurité. KillerBench n'efface jamais un TPM.

  1. Ouvrez Autres actions BitLocker.
  2. Choisissez Ajouter un protecteur TPM ou Ajouter un mot de passe de récupération, appuyez sur Aperçu, cochez Appliquer cette modification au lecteur sélectionné quand j'appuie sur Exécuter l'action, puis appuyez sur Exécuter l'action.
  3. Sauvegardez immédiatement le nouveau mot de passe de récupération. KillerBench ne l'affiche pas.

  1. Appuyez sur Trouver les protecteurs de récupération et sélectionnez le protecteur de mot de passe de récupération.
  2. Saisissez un chemin complet pour le fichier de sauvegarde, hors du lecteur que vous chiffrez.
  3. Choisissez Chiffrer, sélectionnez la méthode de chiffrement et cochez Sauvegarder la clé de récupération sélectionnée, puis démarrer le chiffrement quand je sélectionne Exécuter le diagnostic.
  4. Appuyez sur Exécuter le diagnostic. KillerBench écrit la sauvegarde, la vérifie, puis lance le chiffrement une seule fois.
  5. Le chiffrement se poursuit en arrière-plan. Exécutez Inspecter plus tard pour confirmer que le lecteur est entièrement chiffré avec la protection activée.

Sauvegarder dans Active Directory ou Entra ID

Dans Autres actions BitLocker, choisissez la sauvegarde dans l'annuaire pour le protecteur sélectionné. KillerBench signale que Windows a accepté la demande, mais il ne peut pas lire la copie de l'annuaire ; confirmez-la donc dans Active Directory ou le centre d'administration Entra.

Sections

Diagnostics est le point de départ de chaque intervention. Chaque outil lit l'ordinateur et rédige un rapport. Rien ici ne modifie Windows. L'outil par défaut, l'analyse complète du système, exécute un large ensemble de vérifications en lecture seule et classe ce qui demande de l'attention.

Guides pas à pas : Enquêter sur les plantages et les écrans bleus et Réparer les fichiers système.

Outils de cette section

Vérifiez d'abord l'ordinateur, puis lisez dans le rapport ce qui demande de l'attention et la prochaine étape sûre.

Analyse complète du système

Inspecte 49 domaines de diagnostic et évalue les recettes de réparation installées au regard des preuves actuelles. Les vérifications peuvent prendre plusieurs minutes. L'analyse complète du système est uniquement diagnostique. Utilisez un flux de travail de réparation ciblé pour sélectionner et confirmer une action prise en charge après avoir examiné des prérequis récents. Les instantanés historiques, de sauvegarde et de transfert restent en lecture seule. Le contenu des vidages n'est pas ouvert. L'inspection du bit d'intégrité ne planifie ni réparation ni redémarrage. Cette analyse n'installe pas de mises à jour, ne modifie pas les pilotes, ne supprime pas de fichiers et n'effectue pas de test complet du matériel.

Signes vitaux

Capture la mémoire disponible, l'état des disques indiqué par le fournisseur et l'état de la protection BitLocker, puis met en corrélation les signes vitaux actuels avec les problèmes de périphériques, l'historique de fiabilité, les enregistrements d'erreurs matérielles, les preuves de plantage, les arrêts inattendus et les résultats de l'Outil Diagnostics de mémoire Windows. Les indicateurs de redémarrage, l'espace libre du disque système, l'élévation et la configuration du service de mise à jour restent visibles. Les mots de passe de récupération ne sont pas collectés. Ce flux de travail n'exécute aucune réparation. Le résultat combiné n'est pas un test complet du matériel, du logiciel ni de la stabilité.

Historique de fiabilité

Lit les enregistrements du Moniteur de fiabilité de Windows des 14 derniers jours avec les erreurs récentes du journal Application et les événements d'arrêt inattendu, puis renvoie une seule conclusion historique délimitée. Les enregistrements historiques n'établissent ni l'état actuel ni la cause profonde. Aucune réparation n'est sélectionnée et aucune application, aucun service ni aucun paramètre n'est modifié.

Performances du démarrage

Lit les métadonnées des événements de performances de démarrage et d'arrêt de Windows des 14 derniers jours, en ne conservant que l'identité du fournisseur et des champs numériques de durée délimités, puis les met en corrélation avec les indicateurs de redémarrage en attente pris en charge. Les chemins, les noms de processus, les comptes et le reste de la charge utile des événements sont supprimés avant l'enregistrement des preuves. Les enregistrements historiques de dégradation n'identifient pas un goulot d'étranglement actuel et n'autorisent aucune modification du démarrage, des services, des applications, des pilotes, des tâches, de l'alimentation, du redémarrage ou des stratégies.

Historique des erreurs matérielles

Lit l'historique de Windows Hardware Error Architecture et du diagnostic de la mémoire des 14 derniers jours, les problèmes actuels des périphériques Plug-and-Play, l'état des disques physiques et les compteurs de fiabilité du fournisseur, puis renvoie une seule conclusion matérielle délimitée. Les enregistrements doivent être mis en corrélation avec leur charge utile, les diagnostics du micrologiciel et les tests matériels du fabricant. Aucun composant défaillant ni aucune cause profonde n'est déduit, aucune réparation n'est sélectionnée, et aucun matériel, micrologiciel, pilote, disque, pool, volume, fichier, service, réglage d'alimentation, redémarrage ou paramètre n'est modifié.

Historique d'installation des pilotes

Lit la fin conservée de l'historique d'installation des périphériques Windows SetupAPI, met en corrélation les sections en échec avec les identités Plug-and-Play exactes actuelles et renvoie une seule conclusion délimitée. Les sections historiques du journal ne prouvent pas qu'un périphérique est toujours présent ni qu'un échec est actuel. Aucun pilote n'est installé, supprimé, restauré ou mis à jour.

Points de restauration du système

Liste jusqu'à 256 points de restauration du système disponibles, examine l'éligibilité explicite à la création et renvoie une seule conclusion de disponibilité délimitée. L'inventaire ne prouve pas que la protection est activée pour chaque volume ni qu'une restauration réussira. Aucun point de restauration n'est créé, supprimé ou appliqué pendant le diagnostic.

Cartographie de manière délimitée les identités des disques, des partitions et des volumes dotés d'une lettre de lecteur, évalue la pression à 10 % d'espace libre sur chaque volume doté d'une lettre, inspecte l'allocation du stockage des clichés instantanés VSS et les quotas par défaut de chaque volume, résume la progression actuelle des tâches du module Storage, vérifie le volume NTFS sélectionné et son état d'autoréparation en ligne, et inspecte les périphériques de disque et de contrôleur de ce PC. Les seuils de capacité, les paramètres de quota et les états des tâches sont des preuves à examiner et ne sélectionnent ni nettoyage, ni redimensionnement, ni modification de quota, ni contrôle de tâche. La correspondance des lettres de lecteur est ponctuelle et ne couvre pas tous les chemins de montage. Les constats sur les périphériques ne sont pas associés au volume sélectionné. Le volume Windows est sélectionné par défaut. Aucun fichier, cliché, tâche ou pilote n'est modifié, aucun paramètre n'est changé, aucun volume n'est démonté et aucun redémarrage n'est planifié.

Espaces de stockage

Inventorie les pools d'Espaces de stockage non primordiaux et les disques virtuels, y compris leur intégrité, leur état opérationnel, leur capacité, leur allocation et leur résilience, puis renvoie une seule conclusion opérationnelle délimitée. Windows peut démarrer à la demande son fournisseur de gestion des Espaces de stockage pour répondre à cette requête en lecture seule. Les pools, les disques virtuels, les disques physiques, les volumes, la résilience, l'allocation, les paramètres de maintenance, la stratégie et le type de démarrage sont conservés. Aucune opération de pool, de disque, de volume, d'allocation, d'attachement, de réparation, d'optimisation ou de paramétrage n'est demandée. Les résultats du fournisseur ne vérifient ni l'accessibilité du pool, ni la redondance, ni l'intégrité des données, ni la possibilité de restaurer les sauvegardes, ni les E/S des applications.

Service de stockage

Examine de manière délimitée les tâches actuelles du module Storage, l'historique exact des défaillances du service et la disponibilité actuelle du Service de stockage. Les preuves incomplètes sont prioritaires. L'état des tâches et les défaillances historiques ne peuvent pas autoriser la récupération du service ni des modifications de stockage. La récupération facultative ne démarre que le service exact activé et arrêté, après de nouvelles vérifications des dépendances. Les notifications de stockage existantes et l'activité de stockage gérée par stratégie peuvent reprendre. Les volumes, les partitions, les systèmes de fichiers, les points de montage, les périphériques, les pilotes, les paramètres de l'Assistant Stockage, la stratégie de maintenance, les autorisations du service et le type de démarrage sont conservés. KillerBench ne sélectionne aucune opération de tâche, de volume, de partition, de point de montage, de fichier, de périphérique, de pilote ou de paramètre de stockage. La vérification ne couvre que l'état stable du service, pas le résultat des tâches ni les opérations de périphérique, de volume ou de stratégie de stockage.

Service Optimiser les lecteurs

Vérifie la disponibilité du service Optimiser les lecteurs. La récupération facultative ne démarre que le service exact activé et arrêté, après de nouvelles vérifications des dépendances. L'activité d'optimisation déjà planifiée par Windows peut reprendre selon la stratégie de maintenance actuelle. Les volumes, les systèmes de fichiers, les données, les planifications d'optimisation, la stratégie de maintenance, les autorisations du service et le type de démarrage sont conservés. KillerBench ne sélectionne aucun volume et ne lance aucune analyse, aucune commande TRIM, aucune défragmentation, aucune optimisation ni aucune planification sur un lecteur. La vérification ne couvre que l'état stable du service, pas l'analyse, l'optimisation ni l'intégrité du périphérique.

Référence

Chaque exécution produit un rapport que vous pouvez lire, filtrer et exporter. Le rapport sépare toujours ce qui a été prouvé de ce qui a seulement été observé.

Les états que vous verrez

ÉtatSignification
À examinerLes preuves étayent un problème qui mérite votre attention.
InformationDes preuves ont été collectées et sont affichées pour le contexte.
Incomplètes ou InconnuUne vérification n'a pas pu se terminer ou la preuve n'était pas disponible. Cela ne compte jamais comme un bon état.
HistoriqueUn événement passé. Il explique l'historique mais ne prouve pas une panne actuelle.
VérifiéUne réparation ou une modification a été confirmée en relisant le résultat.

La sortie brute et le rapport lisible

Sortie brute conserve les preuves techniques avec les numéros de ligne d'origine pour que vous puissiez remonter de chaque constat à sa source. Le Rapport lisible résume la même exécution en langage clair, en commençant par la prochaine étape sûre.

Journaux enregistrés

KillerBench peut aussi lire des journaux Windows enregistrés, comme ceux de CBS et de Setup, sans rien exécuter sur l'ordinateur. Les constats renvoient à la ligne exacte qui les a produits. Charger un exemple, dans Sources de session, ouvre un exemple synthétique que vous pouvez explorer sans risque.

Exporter

Exporter le rapport enregistre le rapport avec ses chemins sources, ses entrées analysées et ses extraits de preuves, pour relecture avant de le joindre à un ticket. Les rapports exportés incluent le nom de cet ordinateur, et les journaux bruts et les extraits de preuves peuvent aussi contenir des comptes, des chemins ou du texte source sensible. Les collecteurs protégés limitent ce qu'ils conservent, mais les preuves importées ne sont pas forcément expurgées. Examinez et retirez les informations sensibles avant de partager.

killerbench-cli exécute la même Engine que l'application de bureau depuis PowerShell ou une console distante. Toute commande susceptible de modifier l'ordinateur affiche un aperçu par défaut et nécessite une option explicite, comme --execute, avant d'agir. Les commandes impriment les preuves JSON sur la sortie standard et la progression sur la sortie d'erreur standard.

Guides pas à pas : Exécuter KillerBench depuis des scripts.

Le code de sortie 0 signifie que l'aperçu ou le résultat vérifié a réussi ; 1, une erreur de démarrage, de saisie ou de journal ; 2, que les arguments n'ont pas été reconnus ; 3, bloqué, échoué ou non vérifié ; 4, qu'un flux de travail a besoin d'un redémarrage avant de pouvoir vérifier ; et 130, que vous l'avez arrêtée.

Exécutez killerbench-cli sans argument pour afficher cette liste sur votre propre ordinateur.

Une action indique qu'elle est bloquée

Un résultat bloqué signifie que l'action demandée n'a pas pu se poursuivre. Lisez le message et le journal pour savoir si elle s'est arrêtée avant l'envoi ou après une étape précédente. Ne supposez pas qu'une opération partiellement terminée a été annulée. Les causes de prérequis les plus fréquentes sont les suivantes.

  • Un accès administrateur est requis. Fermez KillerBench et relancez-le avec Exécuter en tant qu'administrateur.
  • Aucun redémarrage ne doit être en attente. Windows attend un redémarrage. Redémarrez l'ordinateur, puis relancez l'action.
  • Une stratégie gérée est présente. La stratégie de groupe ou la gestion des appareils contrôle ce paramètre. Modifiez-le à cet endroit.
  • Les preuves ont changé. Quelque chose a changé entre la première vérification et la vérification finale. Relancez l'outil pour lire le nouvel état.

Une demande précédente doit être rapprochée

KillerBench a trouvé un enregistrement en attente provenant d'une demande interrompue. Relancez la même action. Elle vérifie ce qui s'est passé et signale le résultat réel sans répéter la demande. En ligne de commande, utilisez la commande -recover correspondante, par exemple killerbench-cli bitlocker-auto-unlock-recover.

Une vérification affiche Incomplètes ou Inconnu

Les preuves n'ont pas pu être lues, souvent parce que KillerBench ne s'exécutait pas en tant qu'administrateur ou qu'un service Windows était indisponible. KillerBench le signale honnêtement au lieu de supposer que l'ordinateur est en bon état.

Où les fichiers sont conservés

Les journaux, les enregistrements en attente et les preuves enregistrées se trouvent sous %LOCALAPPDATA%\KillerBench. Chaque action protégée possède son propre dossier. Conservez-les lorsque vous avez besoin d'une trace de ce qui a changé.

KillerBench est en développement. Joignez le rapport exporté et le journal d'activité lorsque vous signalez un problème, et retirez tout ce que vous ne voulez pas partager.
