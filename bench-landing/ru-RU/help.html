Как пользоваться

Каждый раздел и инструмент: что он делает и как шаг за шагом выполнить типичные задачи.

Щёлкните строку, чтобы открыть её. О том, как KillerBench устроен внутри, рассказывает страница Технические детали.

Начните здесь

KillerBench представляет собой рабочий инструмент для диагностики и исправления Windows, предназначенный для технических специалистов. Сначала он проверяет компьютер, объясняет найденное вместе с доказательствами для каждого результата и изменяет Windows только тогда, когда вы выбираете конкретное исправление и подтверждаете его.

KillerBench находится в разработке. Общедоступной загрузки пока нет. На этих страницах описана текущая сборка.

Что он делает

  • Выполняет диагностику только для чтения по Windows Update, устройствам, хранилищу, сети, печати, безопасности, приложениям и профилям, а затем формирует читаемый отчёт.
  • Предлагает защищённые исправления, которые запускаются только тогда, когда свежие доказательства подтверждают именно эту проблему, и затем проверяет результат.
  • Охватывает настройку и усиление защиты, например BitLocker, параметры конфиденциальности, наведение порядка в Windows и подготовку нового компьютера.
  • Выполняет диагностику и анализ отчётов локально, без ИИ и без учётной записи KillerBench. Выбранные действия, например загрузки и сохранение ключа восстановления в Entra ID, могут обращаться к внешним службам.
  • Использует активную тему приложения для консоли, отчётов, подтверждений и диалогов «Открыть», «Сохранить» и «Папка».

KillerBench 1.0.0 ещё не выпущен. Общедоступного пакета или загрузки KillerBench пока нет. На этой странице описаны текущие требования к пакету, чтобы вы могли подготовиться, не загружая неофициальную копию.

Windows и среда выполнения

  • Текущая цель публикации: Windows x64. Текущая база нативной проверки: Windows 11 x64. Нативные дистрибутивы для ARM64, x86 и Windows Server не предоставляются.
  • KillerBench поставляется в двух видах. Установщик зависит от платформы и требует .NET Desktop Runtime 10 for Windows x64. Обычные .NET Runtime, ASP.NET Core Runtime и .NET Framework не предоставляют WPF. Переносная версия содержит собственную среду выполнения и не требует отдельной установки. Для инструмента командной строки killerbench-cli.exe нужна .NET 10 Runtime for Windows x64. SDK нужен для разработки, а не для обычного использования.
  • Используйте версию Windows, которую поддерживает .NET 10 on Windows. Поддержка среды выполнения не означает, что исправления KillerBench проверены в каждом поддерживаемом выпуске или сборке. Охват Windows 10 пока не завершён, а её поддерживаемые выпуски ограничены текущими требованиями жизненного цикла Майкрософт.
  • Получайте Desktop Runtime только со страницы загрузки .NET 10 от Майкрософт, выбрав .NET Desktop Runtime, Windows, x64. Следуйте правилам установки программ, принятым в вашей организации.

Если доступна команда dotnet, команда dotnet --list-runtimes должна показать Microsoft.WindowsDesktop.App 10.0.x для установки x64. Среда выполнения, установленная только для другой архитектуры, не подходит для пакета установщика x64.

Когда пакет будет опубликован

  1. Используйте официальную загрузку по ссылке с этого сайта. Ссылка на загрузку KillerBench пока не активна.
  2. Прочитайте требования этого пакета, лицензию GPLv3, инструкции по соответствующему исходному коду, приложенные уведомления третьих сторон, а также сведения о подписи и контрольной сумме. Одно лишь имя файла не подтверждает подлинность.
  3. Запустите установщик для текущей учётной записи или, после запроса на повышение прав, для всех пользователей. Он добавляет ярлык в меню «Пуск», необязательный ярлык на рабочем столе и запись в списке установки и удаления программ. Переносная версия работает без установки.
  4. Запустите KillerBench под своей обычной учётной записью и выполните шаги со страницы Первая диагностика. Ошибки доступа при диагностике остаются видимыми; повышение прав остаётся отдельным осознанным выбором.

Не обходите предупреждения безопасности Windows, чтобы запустить непроверенную копию. Прежде чем выбрать любое действие, изменяющее компьютер, создайте актуальную резервную копию.

При запуске KillerBench проверяет на GitHub наличие более нового стабильного выпуска и спрашивает разрешения перед установкой. Загрузка должна совпадать с опубликованной контрольной суммой SHA-256. Отключить проверку можно параметром Проверять обновления при запуске в разделе «О программе».

Текущие ограничения

В текущей сборке двенадцать разделов, диагностика только для чтения, отчёты и отдельно выбираемые исправления. Нативная проверка исправлений ещё продолжается. Работающий интерфейс, успешная сборка или результат тестового набора не подтверждают поведение исправления на реальном компьютере. См. Как изменения остаются безопасными.

Иллюстративная консоль на главной странице показывает синтетический вывод. Окончательные снимки экрана приложения и первый общедоступный пакет ещё не готовы.

Исходный код, лицензия и поддержка

KillerBench распространяется по лицензии GPLv3. Инструкции по предоставлению исходного кода и разрешения на шрифты третьих сторон для первого общедоступного пакета ещё не готовы. Сведения о доступности исходного кода, уведомлениях о распространении, конфиденциальности доказательств и поддержке приведены на странице О программе KillerBench. Руководство по Engine предназначено для разработчиков с авторизованной копией исходного кода; оно не означает, что общедоступный пакет Engine существует.

Начните со страницы Загрузка и настройка, а затем запустите полную проверку системы. Она собирает диагностические доказательства и сохраняет локальный журнал; исправления она не запускает. Результат описывает проверенную область, а не все возможные неисправности компьютера.

Запуск проверки

  1. Откройте KillerBench. Откроется раздел Диагностика с выбранной Полной проверкой системы.
  2. При первом запуске оставьте параметр Автоматически исправлять подтверждённые проблемы выключенным.
  3. Нажмите Запустить диагностику. Во время выполнения каждой проверки ход работы отображается справа в представлении Необработанный вывод.
  4. По завершении панель вывода переключается на Читаемый отчёт.

Начинайте без повышения прав. Для некоторых доказательств Windows, например предохранителей BitLocker и защищённых служб, нужны права администратора. Под обычной учётной записью эти проверки сообщат, что доказательства недоступны. Если они вам нужны, завершите текущий запуск, сохраните отчёт и осознанно откройте KillerBench снова через Запуск от имени администратора. Повышение прав не выбирает и не одобряет исправление.

Чтение отчёта

Отчёт начинается со счётчиков Требуют проверки, Подтверждённые исправления, Не завершено и Проверено, за которыми следует рекомендуемый следующий шаг.

  • Что требует внимания перечисляет проблемы, подтверждённые доказательствами, начиная с самых важных.
  • Собранные сведения показывают, что было прочитано, включая неполные или недоступные доказательства.
  • Исторические события помечены как история. Ошибка прошлого месяца не считается текущей неисправностью.

Отсутствующие доказательства никогда не считаются исправным состоянием. Если проверку не удалось выполнить, отчёт сообщит об этом.

Самостоятельный выбор проверок

Откройте Выбрать проверки (расширенные), чтобы выбрать отдельные проверки вместо полной. В каждом разделе приложения также есть целевые инструменты, описанные на страницах Разделы этого руководства.

Исправление найденного

Когда отчёт рекомендует исправление, он называет раздел и инструмент, которые нужно открыть. Перед первым исправлением прочитайте страницу Как изменения остаются безопасными. Нативная проверка ещё продолжается; успешная диагностика не означает, что каждое предлагаемое исправление проверено на вашей сборке Windows. Перед любым изменением держите резервные копии и проверьте точную цель и последствия.

Окно KillerBench состоит из трёх панелей, которые повторяют порядок работы: слева вы выбираете раздел, в центре задаёте параметры инструмента, а справа читаете вывод. Под параметрами может открываться журнал активности.

Разделы

Боковая панель слева перечисляет все инструменты в двенадцати разделах: Диагностика, Исправление, Обновления, Устройства, Сеть, Приложения, Обслуживание, Подготовка, Безопасность, BitLocker, Конфиденциальность и Хранилище. Перетащите её край, чтобы изменить ширину, или перетащите за минимальную ширину, чтобы свернуть.

Параметры инструмента

Центральная панель показывает выбранный раздел, список его инструментов и параметры выбранного инструмента. Параметры, способные изменить компьютер, по умолчанию всегда выключены. Чтобы запустить инструмент, нажмите Запустить диагностику. Когда включён параметр Автоматически исправлять подтверждённые проблемы, та же кнопка называется Запустить исправление. Кнопка Стоп завершает запуск после окончания текущей команды.

Вывод

Панель вывода справа имеет два представления.

  • Необработанный вывод показывает технические доказательства по мере сбора с исходными номерами строк. Он открывается сам, пока работает инструмент.
  • Читаемый отчёт показывает готовый отчёт по последнему запуску. По завершении запуска он заменяет необработанный вывод.

Поле фильтра в необработанном выводе оставляет только совпадающие строки. Экспорт отчёта сохраняет отчёт вместе с путями к источникам и фрагментами доказательств. Источники сессии перечисляют все доказательства, собранные в этой сессии.

Журнал активности

Журнал активности под параметрами инструмента фиксирует, что KillerBench сделал в этой сессии.

Темы, языки и сочетания клавиш

На полосе между боковой панелью и параметрами инструмента находятся выбор темы, выбор языка, список сочетаний клавиш и переключатель журнала активности. В KillerBench 13 тем и 20 языков.

Консоль в стиле дымчатого стекла и читаемые отчёты следуют активной теме. Подтверждения и диалоги «Открыть», «Сохранить» и «Папка» используют тот же семейный стиль, включая тему 98SE. Выберите тему до открытия диалога, чтобы этот вид сохранялся на протяжении всей процедуры.

Удерживайте Ctrl или Alt+Shift, чтобы увидеть этот слой. Наведите указатель на подсвеченную клавишу, чтобы увидеть её действие.

KillerBench разделяет диагностику и изменение как разные задачи. Диагностика только читает. Полная проверка системы никогда не запускает исправления. Выберите конкретное исправление или действие, изучите его параметры и предварительные условия и подтвердите предлагаемое изменение.

Перед изменением

  1. Свежие доказательства. Инструмент заново считывает текущее состояние. Сохранённый отчёт или старое событие никогда не дают права на изменение.
  2. Точная применимость. Изменение предлагается только тогда, когда доказательства точно соответствуют проблеме, которую оно устраняет. Любая неполнота его блокирует.
  3. Ваше подтверждение. Проверьте выбранное действие в диалоге подтверждения. Некоторым действиям, например расшифровке диска, нужно второе подтверждение. Диалог следует активной теме приложения; его внешний вид не меняет требования к действию.
  4. Предварительные условия. Проверяются права администратора, состояние перезагрузки и принадлежность параметра политике или системе управления устройствами. Параметры, которыми владеет политика, остаются без изменений.
  5. Ожидающая запись. KillerBench записывает, что собирается сделать, прежде чем попросить об этом Windows.
  6. Последняя повторная проверка. Непосредственно перед запросом всё проверяется ещё раз, поэтому изменение, произошедшее за это время, останавливает действие.

После изменения

  • KillerBench считывает результат и сообщает Подтверждено только тогда, когда Windows показывает ожидаемое состояние.
  • Если Windows сообщает об успехе, но состояние не изменилось, результат говорит об этом и ничего не повторяется.
  • Каждое изменение сохраняется в журнале в %LOCALAPPDATA%\KillerBench.

Если что-то прервалось

Поддерживаемые действия с журналом сохраняют ожидающую запись, если запрос мог дойти до Windows, а проверка не завершилась. Чтобы изучить эту запись, используйте документированный путь согласования для этого действия или соответствующую команду -recover. Согласование не является автоматическим откатом. Если результат неясен, сохраните журнал и не повторяйте изменение вручную. Поведение при сбое, отмене и последующей загрузке по-прежнему требует нативной проверки для каждого действия.

Чего KillerBench не делает

  • Не очищает TPM, не удаляет предохранители, которые не создавал, и не показывает пароли восстановления.
  • Не изменяет параметр, которым управляет групповая политика или система управления устройствами.
  • Не запускает исправление только потому, что историческое событие или импортированный отчёт упоминает проблему.

Диагностика и анализ отчётов выполняются локально. Выбранное вами действие может обращаться к внешнему адресу, включая загрузку программ или сохранение ключа восстановления в Active Directory или Entra ID. Перед подтверждением проверьте цель. Сохранённые захваты и необработанные доказательства могут содержать идентификаторы компьютера и пути к источникам, поэтому проверьте их перед передачей.

Состояние разработки

Охват исправлений ещё расширяется. Успешная сборка или имитационная проверка не подтверждают нативное поведение исправлений. Файл VM-VALIDATION.md в репозитории отслеживает сценарии на одноразовых компьютерах с Windows и оставшиеся проверки.

Пошаговые руководства

Используйте этот порядок, когда обновления завершаются ошибкой, зависают или устанавливаются снова и снова. KillerBench сначала читает цепочку обновлений, объясняет сбой вместе с доказательствами и запускает службу или исправляет хранилище компонентов только тогда, когда свежие доказательства подтверждают именно эту проблему.

Перед началом

  • Запустите KillerBench от имени администратора. Для полных доказательств службам обновления, хранилищу компонентов и защищённым системным файлам нужны повышенные права.
  • Если Windows уже ожидает перезагрузки, сначала перезагрузите компьютер. Многие исправления обновлений заблокированы, пока состояние перезагрузки не станет чистым.
  • Во время обслуживания держите компьютер подключённым к сети питания.

Выясните, почему обновления не устанавливаются

  1. Откройте Обновления и выберите Windows Update на боковой панели инструментов.
  2. При первом проходе оставьте Автоматически исправлять подтверждённые проблемы выключенным и нажмите Запустить диагностику.

Исправление найденного в отчёте

  1. Снова запустите Windows Update с включённым параметром Автоматически исправлять подтверждённые проблемы. Он может запустить включённые службы обновления, остановка которых подтверждена, а DISM или SFC запускает только тогда, когда живая проверка подтверждает повреждение.
  2. Для отдельной службы выберите вместо этого её целевой инструмент, например Служба BITS, Службы криптографии, Установщик модулей Windows или Служба Update Orchestrator. Каждый из них предлагает восстановление только для своей службы.
  3. Если отчёт требует перезагрузки, перезагрузите компьютер, прежде чем запускать что-либо ещё. KillerBench записывает результаты, требующие перезагрузки, и откладывает дальнейшую работу до её выполнения.

Каждое исправление записывается в журнал и считывается повторно. Полная последовательность описана на странице Как изменения остаются безопасными.

  1. Откройте Обслуживание и выберите Очистка.
  2. Отметьте нужные цели, например Временные файлы текущего пользователя, Временные файлы Windows, Кэши браузеров текущего пользователя, Кэш оптимизации доставки или Корзина текущего пользователя. Наведите указатель на цель, чтобы точно узнать, какие папки она охватывает.

  4. Нажмите Запустить диагностику при выключенном параметре Выполнить выбранную безвозвратную очистку после новых проверок. Отчёт перечисляет кандидатов и оценку места для каждой цели. Ничего не удаляется.

Удаление файлов

  1. Включите Выполнить выбранную безвозвратную очистку после новых проверок и нажмите Запустить диагностику.
  2. KillerBench повторно проверяет каждого кандидата перед удалением, пропускает недавние, защищённые и используемые файлы и записывает каждый результат в журнал.

Безвозвратная очистка минует корзину и не может быть отменена. Удаление отчётов об ошибках и аварийных дампов уничтожает доказательства, которые могут понадобиться для расследования сбоев, поэтому сначала проверьте их.

Разделы

С диагностики должен начинаться каждый визит. Каждый инструмент читает компьютер и формирует отчёт. Здесь ничто не изменяет Windows. Инструмент по умолчанию, полная проверка системы, выполняет широкий набор проверок только для чтения и ранжирует то, что требует внимания.

Пошаговые руководства: Расследование сбоев и синих экранов и Восстановление системных файлов.

Инструменты этого раздела

Сначала проверьте компьютер, а затем прочитайте в отчёте, что требует внимания и каков следующий безопасный шаг.

Полная проверка системы

Проверяет 49 диагностических областей, а затем оценивает каждый установленный рецепт восстановления служб вместе с рецептами для обслуживания, DHCP, печати, Defender, времени и WMI. Проверки могут занять несколько минут. Автоматическое исправление необязательно и требует для каждого рецепта собственных текущих доказательств, предварительных условий компьютера и проверок зависимостей. Применимые исправления могут продлить отсутствующую аренду DHCP, освободить задания печати из очереди, повторно синхронизировать часы, обновить сигнатуры Defender, восстановить подходящие службы и исправить подтверждённое повреждение Windows. Остановленные автоматические службы могут быть запущены после проверки окна запуска и зависимостей. Остановленная служба с запуском по требованию остаётся без изменений, если единственным доказательством служит её бездействие; узконаправленные процедуры могут требовать её только тогда, когда текущие доказательства о функции подтверждают необходимость запуска. Типы запуска, определения задач, отчёты, дампы, подписки, учётные данные, параметры каналов, политика брандмауэра и управляемые параметры сохраняются. Исторические снимки, снимки резервных копий и передач доступны только для чтения. Содержимое дампов не открывается. Проверка «грязного» бита тома не планирует исправление или перезагрузку. Эта процедура не устанавливает обновления, не изменяет драйверы, не удаляет файлы и не выполняет полное тестирование оборудования.

Основные показатели

Фиксирует доступную память, состояние дисков по данным поставщика и состояние защиты BitLocker, а затем сопоставляет текущие показатели с проблемами устройств, журналом стабильности, записями аппаратных ошибок, доказательствами сбоев, неожиданными завершениями работы и результатами средства проверки памяти Windows. Признаки перезагрузки, свободное место на системном диске, повышение прав и конфигурация службы обновления остаются видимыми. Пароли восстановления не собираются. В этой процедуре исправления не запускаются. Сводный результат не является полным тестом оборудования, программ или стабильности.

Журнал стабильности

Читает записи монитора стабильности системы Windows за последние 14 дней вместе с недавними ошибками журнала «Приложение» и событиями неожиданного завершения работы, а затем возвращает одно ограниченное историческое заключение. Исторические записи не определяют текущее состояние или первопричину. Исправление не выбирается, приложения, службы и параметры не изменяются.

Производительность запуска

Читает метаданные событий производительности запуска и завершения работы Windows за последние 14 дней, сохраняя только идентификатор поставщика и ограниченные числовые поля длительности, а затем сопоставляет их с поддерживаемыми признаками ожидающей перезагрузки. Пути, имена процессов, учётные записи и прочие данные событий удаляются до сохранения доказательств. Исторические записи о замедлении не определяют текущее узкое место и не дают права на изменения запуска, служб, приложений, драйверов, задач, питания, перезагрузки или политики.

История аппаратных ошибок

Читает историю Windows Hardware Error Architecture и диагностики памяти за последние 14 дней, текущие проблемы устройств Plug and Play, состояние физических дисков и счётчики надёжности поставщика, а затем возвращает одно ограниченное заключение об оборудовании. Записи требуют сопоставления с их данными, диагностикой микропрограммы и аппаратными тестами поставщика. Неисправный компонент или первопричина не выводятся, исправление не выбирается, и не изменяются оборудование, микропрограмма, драйвер, диск, пул, том, файл, служба, питание, перезагрузка или параметры.

История установки драйверов

Читает сохранённый конец истории установки устройств Windows SetupAPI, сопоставляет неудачные разделы с точными текущими идентификаторами Plug and Play и возвращает одно ограниченное заключение. Исторические разделы журнала не доказывают, что устройство всё ещё присутствует или что сбой актуален. Драйверы не устанавливаются, не удаляются, не откатываются и не обновляются.

Точки восстановления системы

Перечисляет до 256 доступных точек восстановления системы, проверяет явную возможность создания точки и возвращает одно ограниченное заключение о готовности. Список не доказывает, что защита включена для каждого тома или что восстановление пройдёт успешно. Во время диагностики точки восстановления не создаются, не удаляются и не применяются.

Среда восстановления Windows

Читает текущую конфигурацию среды восстановления Windows с помощью REAgentC, сопоставляет включённое локальное расположение с точным текущим диском и разделом и возвращает одно ограниченное заключение о готовности. Необязательное автоматическое исправление может включить существующую отключённую конфигурацию, а затем проверить её состояние. Образ восстановления не загружается, не перемещается и не заменяется, загрузка в режим восстановления не инициируется, Windows не перезагружается. Включённое состояние и наличие раздела не доказывают, что образ восстановления может загрузить или исправить этот компьютер.

Активация Windows

Читает текущее состояние лицензии Windows без сбора полных или частичных ключей продукта, сохраняет очищенные метаданные предупреждений, ошибок и критических событий защиты программного обеспечения за последние семь дней, а затем возвращает одно ограниченное рабочее заключение. Данные событий удаляются до сохранения доказательств. Исторические записи остаются контекстом, когда текущее лицензирование сообщает состояние «Лицензировано». Никакие действия с активацией, ключом продукта, маркером, лицензией, учётной записью, службой или политикой не выбираются. Состояние поставщика и история событий не доказывают право на подписку, доступность сервера активации, целостность хранилища маркеров, будущую действительность или первопричину.

Службы Windows

Инвентаризирует имена установленных служб, отображаемые имена, состояния, режимы запуска и ограниченные по конфиденциальности типы действий восстановления, не собирая учётные записи, пути к исполняемым файлам, команды восстановления и сообщения о перезагрузке. Проверяет согласованность режимов запуска, идентификаторы и циклы прямых зависимостей, повторяет точные ожидающие состояния, проверяет поддерживаемые службы и зависимости остановленных служб, а затем сопоставляет недавние сбои диспетчера управления службами, только если присутствует ровно одно точное имя службы или уникальное отображаемое имя. Использование групп порядка загрузки подсчитывается без раскрытия состава, а неоднозначные идентификаторы остаются неразрешёнными. Остановленные службы с запуском по требованию могут быть нормой. Ни одна служба не запускается, параметры запуска, зависимостей и восстановления сохраняются. Когда конкретной функции нужно восстановление, используйте соответствующую процедуру в разделе «Исправление».

Ошибки приложений

Читает недавние ошибки и критические события журнала «Приложение» вместе с ограниченной историей монитора стабильности системы, а затем возвращает одно заключение об истории стабильности. Исторические записи не доказывают текущую неисправность или первопричину и лишь направляют к более узкой диагностике. Приложения не останавливаются, не исправляются, не удаляются и не перенастраиваются.

Устройства отображения

Проверяет видеоадаптеры и мониторы на наличие сообщений об ошибках устройств, идентификаторы оборудования и версии установленных драйверов. Без установки драйверов, сброса устройств и изменения разрешения. Качество изображения и физические подключения не проверяются.

Устройства ввода

Проверяет ошибки клавиатур, мышей и устройств HID и список драйверов. Нажатия клавиш не записываются, устройства не сбрасываются, драйверы не изменяются. Физическая работа ввода не проверяется.

Проблемы устройств

Находит ненулевые коды ошибок конфигурации Plug and Play во всех классах устройств, а затем сопоставляет доказательства по присутствующим устройствам с ограниченной историей SetupAPI об установке драйверов, настройке устройств и Plug and Play. Одни исторические записи не определяют текущую неисправность. Проверьте точный идентификатор устройства и доказательства одобренного драйвера, не изменяя оборудование, драйверы или конфигурацию. Отсутствующие устройства и физическая работа не проверяются.

Исправление собирает инструменты, которые могут что-то исправить. Каждый из них сначала выполняет диагностику. Исправление предлагается только тогда, когда свежие доказательства показывают именно ту проблему, которую оно устраняет, и запускается только после того, как вы включите Автоматически исправлять подтверждённые проблемы или сами подтвердите отдельное исправление. Каждое исправление записывается в журнал и затем проверяется.

Пошаговые руководства: Восстановление системных файлов и Исправление Windows Update.

Для отдельного исправления обслуживания откройте Расширенные: журналы и ручные исправления и выберите Исправления. Выберите Хранилище компонентов (DISM) или Системные файлы (SFC), прочитайте предпросмотр, отметьте Выполнить это исправление на этом ПК и нажмите Запустить исправление. Совместно проверяет службы Питание, Plug and Play, Диспетчер пользователей, Клиент групповой политики, Служба интерфейса сохранения сети, Сопоставитель конечных точек RPC, Удалённый вызов процедур (RPC), Модуль запуска процессов DCOM-сервера, Служба инфраструктуры фоновых задач и CoreMessaging. Системные файлы

Читаемые регистрации объединяются; для нечитаемого содержимого может потребоваться переустановка поставщика. Клиенты управления могут быть прерваны. Без сброса, удаления и автоматического отката.

Системные уведомления Windows

Читает недавнюю историю диспетчера управления службами, а затем совместно проверяет систему событий COM+ и службу уведомления о системных событиях. Необязательное восстановление проверяет готовность системы событий COM+ перед запуском SENS. Существующие уведомления о входе, сети, питании и COM+ могут возобновиться в текущей конфигурации. Каталоги COM+, подписки, регистрации уведомлений, потребители, учётные записи, разрешения, параметры восстановления, политика и типы запуска сохраняются. Подписки, регистрации, потребители, учётные записи, разрешения и политика не изменяются. Проверка охватывает только стабильное состояние служб, а не сквозную доставку уведомлений.

Служба политики диагностики

Проверяет ограниченную рабочую историю политики диагностики, точную историю сбоев службы и текущую готовность службы. Неполные доказательства имеют приоритет. Необязательное восстановление запускает только точную включённую и остановленную службу после свежих проверок зависимостей. Существующие сценарии диагностики могут возобновиться. Политика, данные устранения неполадок и тип запуска сохраняются. Средства устранения неполадок и предлагаемые исправления не запускаются. Проверка охватывает только стабильное состояние службы, а не обнаружение неисправностей, завершение диагностики или результат исправления.

Исторические отчёты не определяют текущую неисправность или первопричину и не дают права на восстановление. Необязательное восстановление запускает только точную включённую и остановленную службу после свежих проверок зависимостей. Существующие отчёты в очереди могут возобновиться в соответствии с текущей политикой. Архивы отчётов, дампы, согласие, политика отправки и тип запуска сохраняются. Отправка и удаление не запрашиваются. Проверка охватывает только стабильное состояние службы, а не создание, отправку или доставку отчётов, решение проблемы или диагностику сбоя.

Сборщик событий Windows

Проверяет ограниченный список подписок сборщика событий Windows, точную историю сбоев службы и текущую готовность службы. Отдельно подтверждаемое целевое действие может включить один точный отключённый неуправляемый диагностический канал, сохранив все остальные указанные параметры. Журналы, разрешения каналов, хранение, ограничения размера, типы запуска и управляемые параметры сохраняются. Успешная доставка событий и ёмкость архива остаются непроверенными.

Необязательное восстановление запускает только точную включённую и остановленную службу после свежих проверок зависимостей. Существующие запросы на вход в учётную запись Майкрософт могут возобновиться в соответствии с текущей политикой. Исторические события не дают права на восстановление и не определяют текущее состояние учётной записи. Учётные записи, учётные данные, маркеры, регистрация устройства, данные приложений, разрешения, состояние входа, политика, разрешения службы и тип запуска сохраняются. KillerBench не выбирает никаких операций с учётными записями, учётными данными, маркерами, регистрацией, разрешениями или входом. Проверка охватывает только стабильное состояние службы, а не проверку подлинности, подключение учётной записи или доступ приложений.

BitLocker проверяет шифрование дисков, предохранители и сведения для восстановления, а затем помогает сохранить, защитить или изменить диск. Он работает только на этом компьютере.

Пошаговые руководства: Шифрование диска с помощью BitLocker.

Использование инструмента BitLocker

Выберите букву диска и Операция, затем нажмите Запустить диагностику.

  • Проверить читает состояние шифрования, состояние защиты и идентификаторы предохранителей. Эта операция выбрана по умолчанию и ничего не изменяет.
  • Резервная копия восстановления записывает выбранный пароль восстановления в новый файл вне защищённого диска и проверяет его. Сначала нажмите Найти предохранители восстановления, выберите предохранитель, затем подтвердите резервное копирование.
  • Зашифровать сохраняет выбранный пароль восстановления, проверяет резервную копию и один раз запускает шифрование выбранным методом. Диску Windows нужны предохранитель TPM и пароль восстановления. Диску с данными нужен только пароль восстановления.
  • Возобновить защиту снова включает защиту на полностью зашифрованном диске, где она была приостановлена.

Для каждой из этих операций нужен собственный флажок подтверждения, а KillerBench повторно проверяет диск непосредственно перед действием.

Другие действия BitLocker

Для изменений вне Запустить диагностику откройте Другие действия BitLocker. Выберите действие, нажмите Предпросмотр, чтобы прочитать точные требования, затем подтвердите и нажмите Выполнить действие.

  • Включить автоматическую разблокировку обеспечивает разблокировку зашифрованного диска с данными при запуске Windows. Диск Windows должен быть полностью зашифрован с включённой защитой.
  • Добавить предохранитель TPM или Добавить пароль восстановления создаёт один новый предохранитель. KillerBench никогда не показывает и не записывает в журнал новый пароль восстановления, поэтому сразу сохраните его.
  • Сохранить пароль восстановления в Active Directory или Microsoft Entra ID отправляет предохранитель, выбранный выше. KillerBench сообщает, что Windows приняла запрос. Копию в каталоге он прочитать не может, поэтому проверьте её там.
  • Расшифровать этот диск запускает расшифровку, например перед повторным шифрованием требуемым методом. Для этого нужно второе подтверждение, потому что после этого диск не защищён; действие отклоняется для диска Windows, пока от него автоматически разблокируются другие диски.

TPM и FIPS

Если TPM присутствует, но не готов, раздел «Безопасность» может подготовить его без очистки. KillerBench никогда не очищает TPM, потому что это уничтожает ключи, хранимые BitLocker и Windows Hello. Переключатель политики алгоритмов FIPS доступен как явное и обратимое исправление для организаций, которым нужны ПИН-коды BitLocker, одобренные FIPS.

Инструменты этого раздела

Хранилище

Сопоставляет ограниченные идентификаторы дисков, разделов и томов с буквами дисков, оценивает нехватку свободного места менее 10 % на каждом томе с буквой, проверяет выделение хранилища теневых копий VSS и квоты по умолчанию для каждого тома, кратко показывает ход текущих заданий модуля Storage, проверяет выбранный том NTFS и его состояние оперативного самовосстановления, а также проверяет дисковые устройства и контроллеры этого компьютера. Пороги ёмкости, параметры квот и состояния заданий служат доказательствами для проверки и не выбирают очистку, изменение размера, изменение квот или управление заданиями. Сопоставление букв дисков отражает конкретный момент и охватывает не все пути подключения. Результаты по устройствам не привязываются к выбранному тому. По умолчанию выбран том Windows. Файлы, снимки, задания и драйверы не изменяются, параметры не меняются, тома не отключаются, перезагрузка не планируется.

Дисковые пространства

Инвентаризирует непервичные пулы дисковых пространств и виртуальные диски, включая состояние работоспособности, рабочее состояние, ёмкость, выделение и устойчивость, а затем возвращает одно ограниченное рабочее заключение. Отвечая на этот запрос только для чтения, Windows может запустить по требованию своего поставщика управления дисковыми пространствами. Пулы, виртуальные диски, физические диски, тома, устойчивость, выделение, параметры обслуживания, политика и тип запуска сохраняются. Никакие операции с пулами, дисками, томами, выделением, подключением, исправлением, оптимизацией или параметрами не запрашиваются. Результаты поставщика не подтверждают доступность пула, избыточность, целостность данных, возможность восстановления из резервной копии или ввод-вывод приложений.

Служба хранилища

Проверяет ограниченный набор текущих заданий модуля Storage, точную историю сбоев службы и текущую готовность службы хранилища. Неполные доказательства имеют приоритет. Состояние заданий и исторические сбои не дают права на восстановление службы или изменение хранилища. Необязательное восстановление запускает только точную включённую и остановленную службу после свежих проверок зависимостей. Существующие уведомления хранилища и действия хранилища, управляемые политикой, могут возобновиться. Тома, разделы, файловые системы, точки подключения, устройства, драйверы, параметры контроля памяти, политика обслуживания, разрешения службы и тип запуска сохраняются. KillerBench не выбирает никаких операций с заданиями, томами, разделами, точками подключения, файлами, устройствами, драйверами или параметрами хранилища. Проверка охватывает только стабильное состояние службы, а не результат заданий или операции с устройствами, томами и политикой хранилища.

Служба оптимизации дисков

Проверяет доступность службы оптимизации дисков. Необязательное восстановление запускает только точную включённую и остановленную службу после свежих проверок зависимостей. Существующая оптимизация, запланированная Windows, может возобновиться в соответствии с текущей политикой обслуживания. Тома, файловые системы, данные, расписания оптимизации, политика обслуживания, разрешения службы и тип запуска сохраняются. KillerBench не выбирает том и не анализирует, не выполняет trim, не дефрагментирует, не оптимизирует и не планирует ни один диск. Проверка охватывает только стабильное состояние службы, а не анализ, оптимизацию или состояние устройства.

Действие сообщает, что оно заблокировано

Заблокированный результат означает, что запрошенное действие не смогло продолжиться. Прочитайте сообщение и журнал, чтобы понять, остановилось ли оно до отправки или после одного из предыдущих шагов. Не считайте, что частично выполненная операция была откачена. Ниже перечислены самые частые причины, связанные с предварительными условиями.

  • Нужны права администратора. Закройте KillerBench и снова запустите его через Запуск от имени администратора.
  • Состояние перезагрузки должно быть чистым. Windows ожидает перезагрузки. Перезагрузите компьютер, затем снова запустите действие.
  • Действует управляемая политика. Параметром владеет групповая политика или система управления устройствами. Измените его там.
  • Доказательства изменились. Между первой проверкой и последней повторной проверкой что-то изменилось. Запустите инструмент снова, чтобы прочитать новое состояние.

Предыдущий запрос требует согласования

KillerBench нашёл ожидающую запись от прерванного запроса. Снова запустите то же действие. Оно проверит, что произошло, и сообщит фактический результат, не повторяя запрос. В командной строке используйте соответствующую команду -recover, например killerbench-cli bitlocker-auto-unlock-recover.

Проверка показывает «Не завершено» или «Неизвестно»

Доказательства не удалось прочитать; часто это происходит потому, что KillerBench был запущен не от имени администратора или служба Windows была недоступна. KillerBench честно сообщает об этом, а не предполагает, что компьютер исправен.

Где хранятся файлы
