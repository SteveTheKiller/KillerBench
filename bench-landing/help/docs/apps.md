# Apps

Apps reviews installed programs, Store packages, Office and Outlook, browser extensions, startup apps and search. Removal and reset tools always show a review first and change only what you select.

Step-by-step guides: [Set up a new computer](set-up-new-pc.html).

## Tools in this section

Review installed applications, Store packages, Office and Outlook, browser extensions and search.

### Installed applications

Read application uninstall registrations in the selected machine or running-account scope, then combine that scope with bounded Application error, Reliability Monitor and restart evidence. Other accounts and portable apps are excluded. Registrations and broad history are not exact application-health or ownership proof. No installer, uninstaller, application, process, service, file, registration, account, policy or restart action is selected.

### App packages

Inventory registered Appx/MSIX packages for the selected account scope. Running account is the default; all users requires administrator access. Report exact identities, framework and non-removable flags, and dependency counts. Provisioned packages, Win32 applications, managed ownership and application data are not evaluated. No packages are removed.

### Browser extensions

Inventory bounded Chrome, Edge, Brave and Firefox extension identities from the running account. Browser history, credentials, extension settings, manifest contents, commands and policy values are excluded. Presence does not prove enablement, trust, ownership or safe removal. No browser, extension or policy is changed.

### Startup applications

Inventory machine and running-account Run and RunOnce registration names, Startup folder file names, Windows startup approval states, and boot or logon scheduled-task names and states, then return one startup-environment conclusion. Command lines, target paths, binary approval timestamps, task actions, arguments, accounts and credentials are not collected. Registration does not prove an item ran, caused a delay, is unwanted or is safe to disable. Approval state does not prove a matching registration exists. No registration, file, application, task, service or policy change is selected.

### Microsoft app removal

Review selected OneDrive, Outlook, Office/M365, Project and Teams registrations with account-scope and retention choices. Machine, running-account and registered-package inventories are correlated; all-user review also includes packages provisioned for new users. A supported current-account package can receive a separate exact safeguard plan in the desktop or CLI. Native removal remains disconnected. No process, application, package, file, credential, folder location, registry value or user data is changed.

### Outlook reset

Review New Outlook, Classic Outlook or both with explicit choices for caches, profile settings, authentication, OST files, add-ins and New Outlook reinstall. Running-account review checks bounded known locations, exact registrations and closed-process readiness. A separately confirmed cache-only action retains exact cache directories under unique recovery names and verifies every move. All-user review and other reset areas remain review-only. No retained cache, profile, OST file, credential, add-in, package or setting is removed.

### Foxit inventory

Inventory machine-installed Foxit products and updater registry values in both views. User installations, effective policy and product ownership are not verified. No applications or settings are changed.

### Windows Installer service

Check Installer restriction, rollback, elevation, logging and debug policy, in-progress markers, engine binaries and registered cached-package visibility before service recovery. Correlate recent failed and successful outcomes only for exact reported product identities. If prerequisites pass, auto-repair can start the enabled service and verify Running. Historical outcomes, logging, cache visibility and debug findings do not authorize package or policy changes. Policies, logs, transaction markers, startup types and cached packages are preserved. A specific package installation is not tested.

### Windows Search

Check Windows Search service availability, current SystemIndex activity and recent Search event history. Auto-repair can start a stopped, enabled service and verify running state. A separate explicit index-rebuild choice retains the prior index, starts a fresh index and verifies exact service and directory state. Indexed locations, policy, startup type and retained data are preserved. Starting the service or rebuilding the index can resume background indexing. Search result completeness remains untested.

### App Readiness

Check App Readiness service availability. Optional recovery starts only the enabled, stopped exact service after fresh dependency checks. Existing first-sign-in and application provisioning may resume under current policy. Packages, registrations, licenses, user profiles, application data, policy and startup type are preserved. KillerBench selects no package operation. Verification covers stable service state only, not sign-in, provisioning or application launch.
