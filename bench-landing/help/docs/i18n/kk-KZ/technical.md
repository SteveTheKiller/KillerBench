# KillerBench технологиялары

Капот астына көз салу: KillerBench Windows компьютерін қалай оқиды, дәлелдерін қалай адал сақтайды және өзгеріске қашан рұқсат етілетінін қалай шешеді.

## Технологиялық стек

KillerBench жергілікті Windows қолданбасы. Жұмыс үстелі қолданбасы, пәрмен жолы және олардың негізіндегі Engine бірдей диагностикалық дәлелдер мен жөндеу жұмыс ағындарын пайдаланады.

| Компонент | Толығырақ |
| --- | --- |
| Интерфейс | .NET 10 негізіндегі WPF (`net10.0-windows`), Windows x64, терезенің өз жақтауы |
| Engine | `Engine.Core`, `Engine` және `Engine.Windows`, WPF-ке немесе жұмыс үстелі басқару элементтеріне сілтемесіз |
| Пәрмен жолы | `killerbench-cli`, сол Engine негізіндегі бөлек хост |
| Windows провайдерлері | .NET, Windows API, PowerShell және Windows пәрмен жолы құралдары, әрқайсысы уақыт, жазба саны және өлшем бойынша бекітілген шектерде жұмыс істейді |
| Есептер | Шикі шығыс, Оқылатын есеп, HTML, мәтін және JSON |
| Анықтамалық деректер | Қате кодтары, жабдық идентификаторлары, жеткізушілер мен қолдау сілтемелері үшін нұсқасы бар білім пакеттері |
| Пакеттеу | Орнатушы: платформаға тәуелді, .NET Desktop Runtime 10 for Windows x64 қажет. Тасымалы нұсқа: дербес, орындау ортасын орнату қажет емес |
| Көрініс | Отбасының 13 тақырыбы және 20 тіл |

## Орнату, қалталар және деректер

KillerBench екі түрде таратылады. Орнатушы стандартты жүктеу болып табылады және бір пайдаланушыға немесе барлық пайдаланушыларға орнатуды қолдайды. Тасымалы нұсқа өзінің .NET орындау ортасын қамтиды және орнатусыз жұмыс істейді.

KillerBench оны іске қосқан тіркелгінің құқықтарымен жұмыс істейді. Ол өз құқықтарын өздігінен көтермейді. BitLocker қорғағыштары сияқты қорғалған дәлелдер немесе жөндеу әкімші қатынасын қажет еткенде, оны **Әкімші ретінде іске қосу** арқылы бастаңыз. Құқықтарды көтеру ешқашан жөндеуді таңдамайды және мақұлдамайды.

### Орнатушы не істейді

Орнатушы қолданбаны тексеріп, `%LOCALAPPDATA%\Programs\KillerBench\` ішіне немесе барлық пайдаланушылар үшін құқықтарды көтеру сұрауынан кейін `%ProgramFiles%\KillerBench\` ішіне шығарады. Ол Бастау мәзіріне таңбаша, қосымша жұмыс үстелі таңбашасын және қалыпты және үнсіз жоюы бар Бағдарламаларды қосу немесе жою жазбасын қосады. Тасымалы нұсқа өз жүктемесін ағымдағы іске қосу үшін `%LOCALAPPDATA%\KillerBench\Portable\` ішіне тексеріп шығарады және келесі іске қосылғанда қалып қойған көшірмелерді тазалайды.

### Не қайда сақталады

| Орын | Мазмұны |
| --- | --- |
| `%LOCALAPPDATA%\KillerBench\appearance.json` | Тақырып, екпін түсі, интерфейс масштабы және тіл |
| `%LOCALAPPDATA%\KillerBench\Workflows\` | Әр жұмыс ағынын іске қосуға бір JSON журналы: шешімдер, шектелген пәрмен шығысы және жөндеу нәтижелері |
| `%LOCALAPPDATA%\KillerBench\Repairs\` | DISM және SFC сияқты қызмет көрсету жөндеулерінің орындалу журналдары |
| `%LOCALAPPDATA%\KillerBench\` ішіндегі функция қалталары | Жеке қорғалған әрекеттердің күтудегі жазбалары мен нәтижелері, мысалы `BitLockerBackup`, `Time`, `Firewall` және `Profiles` |
| `%LOCALAPPDATA%\KillerBench\agent-repairs.json` | «Бағдарлама туралы» ішінде таңдалған KillerMCP жөндеу деңгейі |
| `HKCU` немесе `HKLM\Software\KillerBench` | Сәйкес орнату ауқымы үшін орнатылған жол |
| Сіз таңдаған `.kbench` файлы | Сақталған дәлелдері бар сақталған түсірілім |

Журналдар осы компьютерде сақталады және KillerBench оларды жүктеп жібермейді. Журналды белгісіз нәтиженің дәлелі енді қажет болмағанда ғана жойыңыз.

## Әуелі диагностика

KillerBench диагностика мен өзгерісті әртүрлі жұмыс ретінде қарастырады. Диагностика тек оқиды. Өзгеріс нақты жөндеуді немесе әрекетті таңдап, оның параметрлері мен алғышарттарын қарап шығып, оны растағанда ғана болады.

Жүйені толық тексеру, тіпті мақсатты жұмыс ағынында автоматты жөндеу қосулы болса да, тек диагностикалық болып қалады. Сақталған түсірілімдер, импортталған журналдар және бұрынғы оқиғалар ешқашан жөндеуге негіз болмайды.

### Шектелген жинау

Әр жергілікті пәрмен мен Windows провайдері уақыт, жазба саны және өлшем бойынша бекітілген шектерде жұмыс істейді. Провайдер шығу күйін, күту уақытының бітуін, қысқартуды, стандартты шығысты және қате шығысын жазады. Сәтсіз немесе қысқартылған провайдер нәтижесі ешқашан таза, бос жауап ретінде оқылмайды.

### Ең аз сақтау

Жинаушылар қорытындыға қажет нәрсені сақтайды. Көптеген нәтижелер атауларды, санаттарды, сандарды, күйлерді және уақыт белгілерін сақтайды, ал тіркелгі деректерін, пәрмен жолдарын, толық жолдарды, тіркелгі сәйкестендіргіштерін, желінің соңғы нүктелерін және қатысы жоқ оқиға жүктемесін сақтамайды.

## Қадағалауға болатын дәлелдер

Әр қорытынды оны тудырған дәлелмен байланысты және есеп әрқашан дәлелденгенді тек байқалғаннан бөліп көрсетеді.

| Күй | Мағынасы |
| --- | --- |
| Қарап шығу керек | Дәлелдер назар аударуды қажет ететін мәселені растайды. |
| Ақпарат | Дәлелдер жиналып, контекст үшін көрсетілген. |
| Аяқталмаған немесе Белгісіз | Тексеру аяқталмады немесе дәлел қолжетімсіз болды. Ол ешқашан жарамды деп саналмайды. |
| Тарихи | Өткен оқиға. Ол тарихты түсіндіреді, бірақ ағымдағы ақауды дәлелдемейді. |
| Расталды | Жөндеу немесе өзгеріс нәтижені қайта оқу арқылы расталды. |

### Белгісіз де нәтиже

Белгісіз қатынасқа тыйым салынғанын, көздің жоқ екенін, провайдердің істен шыққанын, шығыстың пішімі бұзылғанын, шектің асып кеткенін немесе дәлелдердің бір-біріне қайшы келгенін білдіреді. KillerBench бұл шектеуді жасырмай, оны және келесі пайдалы қадамды көрсетеді.

### Тарих тарих болып қалады

Оқиға жазбалары мен импортталған журналдар өткен уақытта не жазылғанын сипаттайды. Олар қате кодына немесе келесі диагностика ауқымына нұсқай алады. Олар ақаудың әлі белсенді екенін дәлелдемейді.

## Қорғалған жөндеулер

Жөндеулер жарамдылық, орындау, растау және қалпына келтіру ережелері бар типтелген әрекеттер. Олар журнал жолынан алынған пәрмен жолдары емес. Қолдау көрсетілетін әр жөндеу бірдей реттілікпен жүреді:

1. Толық ағымдағы дәлелдерді жинау.
2. Қолдау көрсетілетін бір рецептпен сәйкестендіру.
3. Міндетті параметрлер мен салдарларды қарап шығу.
4. Әкімшілік және саясат алғышарттарын растау.
5. Өзгеріс алдында шешуші дәлелдерді дереу қайта жинау.
6. Тұрақты дайындық жазбасын жазу.
7. Бір шектелген жергілікті әрекетті орындау.
8. Жаңа растау дәлелдерін жинау.
9. Расталған, бұғатталған, тоқтатылған немесе белгісіз нәтижені жазу.

Әрекет орындалмас бұрын шешуші дәлелдер өзгерсе, KillerBench оны орындамай тоқтайды.

### Айқын таңдаулар

Параметрге тәуелді жөндеулер сізден том, принтер кезегі, қалпына келтіру кілтінің сақталатын орны, қуат мәні, пакет нұсқасы немесе жөндеу көзі сияқты нақты таңдауды талап етеді. KillerBench бұл мәндерді ешқашан ойдан шығармайды.

### Басқарылатын компьютерлер

Топтық саясат пен құрылғыларды басқару жүйесі жергілікті өзгерісті тиімсіз немесе орынсыз етуі мүмкін. Қолдау көрсетілетін жөндеулер параметрдің кімге тиесілі екенін тексереді және иелік басқарылатын немесе белгісіз болғанда тоқтайды. Саясатқа тиесілі параметрлер өзгертілмейді.

### Автоматты жөндеу

Автоматты жөндеу тек жарамды рецептерге жалғасуға мүмкіндік береді. Ол дәлелдерді айналып өтпейді, жоқ параметрлерді таңдамайды, саясатты елемейді, белгісіз әрекетті қайталамайды, Windows-ты қайта іске қоспайды және қарап шығуды қажет ететін қорытындыны жөндеуге айналдырмайды.

## Журналдар және үзілістер

KillerBench Windows-тан өзгеріс жасауды сұрамас бұрын не істейтінін жазып қояды. Әр өзгеріс `%LOCALAPPDATA%\KillerBench` ішіндегі журналда сақталады.

Өзгерістен кейін KillerBench нәтижені қайта оқиды және Windows күтілген күйді көрсеткенде ғана **Расталды** деп хабарлайды. Егер Windows сәттілік хабарласа, бірақ күй өзгермесе, нәтиже мұны айтады және ештеңе қайталанбайды.

Процесс Windows сұрауды алғаннан кейін, бірақ растау аяқталмай тұрып тоқтауы мүмкін. Күтудегі жазба қалады, ал кейінгі салыстыру не болғанын анықтау үшін жаңа күйді оқиды. Салыстыру автоматты кері қайтару емес және бастапқы өзгерісті ешқашан қайталамайды. Нәтиже белгісіз болғанда журналды сақтаңыз.

## Не істемейді

- TPM-ді тазаламайды, өзі жасамаған қорғағыштарды жоймайды және қалпына келтіру құпия сөздерін көрсетпейді.
- Топтық саясат немесе құрылғыларды басқару жүйесі басқаратын параметрді өзгертпейді.
- Бұрынғы оқиға немесе импортталған есеп мәселені атап өткені үшін ғана жөндеуді іске қоспайды.
- Жоқ, ішінара немесе сәтсіз дәлелді жарамдылық туралы қорытындыға айналдырмайды.

## Есептер

Әр іске қосу оқуға, сүзуге және экспорттауға болатын есеп жасайды. Есеп мыналарды бөліп көрсетеді:

1. Не тексерілді
2. Қандай мәселе табылды
3. Қорытындыны қандай дәлелдер растайды
4. Қандай әрекет ұсынылды немесе орындалды
5. Нәтиже қалай расталды
6. Не белгісіз болып қалады немесе қайта іске қосуды қажет етеді

**Шикі шығыс** техникалық дәлелдерді бастапқы жол нөмірлерімен сақтайды, сондықтан кез келген қорытындыны оның көзіне дейін қадағалай аласыз. **Оқылатын есеп** сол іске қосуды қарапайым тілмен қорытындылайды және келесі қауіпсіз қадамнан басталады. HTML есептер Killer Tools тақырыптар жүйесін пайдаланады және қолданбасыз да оқылады. Мәтін тасымалдауға ыңғайлы, ал JSON басқа бағдарлама үшін құрылымдық өрістерді сақтайды.

## Сақталған журналдар мен түсірілімдер

KillerBench компьютерде ештеңе іске қоспай-ақ дәлелдерді зерттей алады. Мәтіндік журналды терезеге сүйреп әкеліңіз немесе оның жолын қойып, **Журналды ашу** таңдаңыз. CBS, CSI және Setup жолдары уақыт белгілерімен талданады, ал қорытындылар нақты бастапқы жолға сілтеме береді. EVTX және оқиға XML файлдарын да осылай импорттауға болады.

**Windows Update сканерлеу** CBS, DISM, Panther және кері қайтару Setup журналдарын, жаңарту мен қызмет көрсету оқиғаларының арналарын, жаңарту қызметтерінің күйлерін, бос орынды, жұмыс уақытын, күтудегі қайта іске қосу көрсеткіштерін және таңдалған жаңарту саясатын сұраныс бойынша тек оқу режимінде жинайды. **Түсірілімді сақтау** сақталған дәлелдерді `.kbench` файлына жазады. **Түсірілімді ашу** оны бастапқы файлдарсыз қайта ашады және орнатылған ережелермен қайта бағалайды, сондықтан бірдей ережелер бірдей қорытындылар береді.

## Демо режимі

Ойдан шығарылған жұмыс станциясында **Диагнозды іске қосу** байқап көру үшін `KillerBench.exe --demo` іске қосыңыз. Әр жұмыс ағыны синтетикалық дәлелдер мен уақыты бар барысты жасайды. Ешқандай Windows провайдері шақырылмайды, ешқандай жөндеу пәрмені орындалмайды және ешқандай журнал жазылмайды. **Диагнозды іске қосу** аясынан тыс бөлек құрал түймелері жұмыс істей береді, сондықтан оларды демо әрекеттері ретінде пайдаланбаңыз.

`KillerBench.exe --demo-screenshot` бекітілген ойдан шығарылған компьютер үшін тек көруге арналған Жүйені толық тексеру есебін ашады. Жұмыс аймағындағы басулар, пернелер тіркесімдері және файлдарды сүйреп әкелу бұғатталады.

## Білім пакеттері

Үлкен және жиі жаңартылатын анықтамалық деректер диагностикалық логикада емес, білім пакеттерінде сақталады: Windows пен Setup қате кодтары, жеткізуші мен құрылғы идентификаторлары, PCI, USB, ACPI және UEFI анықтамалары, желілік OUI жеткізушілер деректері, драйвер мен қолдау орындары және іріктелген қолдау сілтемелері.

Әр пакет өзінің пішімін, схема нұсқасын, көзін, көз редакциясын, жасалу уақытын және мазмұн хешін көрсетеді, ал KillerBench оларды пайдаланбас бұрын тексереді. Белгісіз немесе жарамсыз пакет болжамға ауыспай, қолжетімсіз болып қалады. Жаңарту уақытша орынға жүктеледі, тексеріледі, содан кейін белсенді пакетті бір қадамда ауыстырады, сондықтан сәтсіз жаңарту алдыңғы пакетті орнында қалдырады.

Білім деректері идентификаторды түсіндіре алады немесе келесі қайда қарау керектігін ұсына алады. Олар бұрынғы кодты ағымдағы ақауға айналдыра алмайды, драйверді автоматты түрде таңдай алмайды немесе жөндеуге негіз бола алмайды.

## Жаңартулар және қол қою

Іске қосылғанда KillerBench GitHub-тан ең соңғы тұрақты шығарылымды төрт секундтық шекпен сұрайды және сол шығарылым жаңарақ болғанда ғана жаңартуды ұсынады. Тексеруді «Бағдарлама туралы» ішіндегі **Іске қосылғанда жаңартуларды тексеру** арқылы немесе жаңарту сұрауында өшіре аласыз. Іске қосылған көшірмеге сәйкес келетін пакет, орнатушы немесе тасымалы нұсқа жүктеледі, және ештеңе орнатылмас бұрын оның SHA-256 мәні шығарылымның `SHA256SUMS.txt` файлына сәйкес келуі керек. Аяқтау үшін қолданба жабылып, қайта ашылады. Фондық қызмет жоқ.

«Бағдарлама туралы» картасы нұсқаны, код қолтаңбасының жариялаушысы мен саусақ ізін және іске қосылған орындалатын файлдың SHA-256 мәнін көрсетеді, сондықтан қолыңыздағы көшірмені тексере аласыз.

## KillerMCP

KillerBench құрамында ЖИ агенті жоқ. [KillerMCP](../mcp.html) агентті сол Engine-ге қоса алады. «Бағдарлама туралы» ішіндегі **KillerMCP параметрлері** сол агентке не істеуге болатынын анықтайды:

| Параметр | Әсері |
| --- | --- |
| Өшірулі (әдепкі) | Агент жөндеуді сұрай алмайды. |
| KillerMCP-ге қауіпсіз жөндеулерді орындауға рұқсат ету | Агент қауіпсіз деп жіктелген жөндеулерді сұрай алады. |
| Жұмысты бөлетін жөндеулерге де рұқсат ету | Жұмысты бөлетін жөндеулер қолжетімді болады және әрқайсысы бәрібір мақұлдауды қажет етеді. |

Деңгейді тек осы компьютердің алдындағы адам көтере алады. Белгісіз жөндеу нәтижесінен кейін KillerMCP құлып жазады және агент жөндеулері біреу оны «Бағдарлама туралы» ішінде алып тастағанша бұғатталған күйде қалады.

## Локализация

Интерфейс 20 тілде қолжетімді: ағылшын, бенгал, чех, неміс, испан, француз, венгр, итальян, жапон, қазақ, норвег, поляк, португал (Бразилия), орыс, словен, түрік, украин, вьетнам, сондай-ақ жеңілдетілген және дәстүрлі қытай тілдері. Тілді өзгерту бірден, соның ішінде бөлімдер мен жұмыс ағындарының атауларына, сәлемдесу мәтініне және ашық оқылатын есепке қолданылады. Жоқ мәтін ағылшын тілінде көрсетіледі.

Дәлелдер, Engine қорытындылары, журналдар және Шикі шығыс Windows журналы сияқты ағылшын тілінде қалады, сондықтан есеп әр компьютерде бірдей оқылады және онда нақты мәтінді іздеуге болады.

## Пәрмен жолы және шығу кодтары

`killerbench-cli` жұмыс үстелі қолданбасынсыз сол Engine-ді іске қосады. Барыс стандартты қате ағынына, ал JSON стандартты шығысқа жіберіледі. Көптеген пәрмендер әдепкі бойынша алдын ала қарау көрсетеді, ал өзгеріс үшін `--execute` қажет. Сәйкес `-recover` пәрмендері үзілген әрекетті қайталамай қарап шығады. [KillerBench-ті скрипттерден іске қосу](use-the-cli.html) және [пәрмендер анықтамасы](cli.html) беттерін қараңыз.

| Шығу коды | Жұмыс ағыны пәрмендері | Сканерлеу және ашу |
| --- | --- | --- |
| 0 | Тексерілген ауқымдарда шешілмеген мәселе жоқ | Қамту аяқталды |
| 1 | Іске қосу немесе журнал қатесі | Сәтсіздік |
| 2 | Жарамсыз аргументтер | Жарамсыз аргументтер |
| 3 | Назар аудару қажет | Ішінара жинау |
| 4 | Растау алдында қайта іске қосу қажет | |
| 130 | Тоқтатылды | Бас тартылды немесе жалпы күту уақыты бітті |

Ешқандай шығу коды компьютердің жарамды екенін куәландырмайды.

## Архитектура

Engine интерфейссіз үш жобаға бөлінген. `Engine.Core` примитивтер мен декларативті рецептерді береді, `Engine` ортақ жұмыс ағындары мен дәлелдерге жауап береді, ал `Engine.Windows` жергілікті провайдерлерді тіркейді. Жұмыс үстелі қолданбасы, CLI және тесттер бөлек хосттар болып табылады.

| Деңгей | Жауапкершілігі |
| --- | --- |
| Мүмкіндік жинаушылары | Бір нақты ауқым үшін Windows-тың шектелген күйін оқиды |
| Дәлел талдаушылары | Пішінді, сәйкестікті, толықтықты және шектерді тексереді |
| Диагностикалық түсіндіру | Дәлелдерді жұмыс ағынының айқын күйлеріне айналдырады |
| Жұмыс ағындарын үйлестіру | Тексерулерді, барысты, рецептер мен журналдарды біріктіреді |
| Жөндеу үйлестірушілері | Жарамдылықты қайта тексереді, дайындайды, өзгертеді, растайды және салыстырады |
| Есептер | Мәселелерді, әрекеттерді, нәтижелер мен шектеулерді көрсетеді |
| Білім пакеттері | Логиканы өзгертпей, нұсқасы бар анықтамалық деректерді шешеді |

Сәйкестік анық болмағанда, шығыс пішімі бұзылғанда, шек асқанда немесе қажетті өкілеттікті тексеру мүмкін болмағанда, жинаушылар белгісіздікте бұғатталады. Engine бүгін Windows-қа бағытталған және кросс-платформалы емес. [Engine әзірлеуші нұсқаулығы](../engine/index.html) API-ды, CLI-ды және Engine-ді басқа .NET хостына енгізуді сипаттайды.

## Құпиялылық және желі

Диагностика мен журнал талдауы ЖИ қызметінсіз немесе KillerBench тіркелгісінсіз жергілікті түрде орындалады. Журналдар мен сақталған дәлелдер жергілікті тіркелгінің `%LOCALAPPDATA%\KillerBench` қалталарында қалады.

Сіз таңдаған әрекеттер Windows Update, бағдарламаларды жүктеу қызметтері немесе қалпына келтіру кілтін Active Directory не Entra ID жүйесіне сақтау сияқты өз мақсатты орнына қосылуы мүмкін. Іске қосылғандағы жаңартуды тексеру GitHub-қа, ал білім жаңартулары мен KillerMCP орнатушысы өздерінің бапталған қызметтеріне қосылады. [KillerMCP](../mcp.html) пайдаланатын ЖИ клиенті өзі сұраған анықтамалық нәтижені алуы мүмкін.

Шикі журналдарда, импортталған файлдарда және экспортталған дәлелдерде компьютер атаулары, тіркелгілер, жолдар немесе құпия бастапқы мәтін болуы мүмкін. Бөліспес бұрын оларды қарап шығыңыз және жалпыға ашық есепке ешқашан қалпына келтіру кілттерін, тіркелгі деректерін немесе тұтынушы деректерін қоспаңыз.

## Әзірлеу күйі

KillerBench әзірленуде және жалпыға жүктеу әлі жоқ. Жөндеулердің қамтуы әлі кеңейіп келеді, ал жергілікті жөндеуді тексеру әлі жүріп жатыр. Сәтті құрастыру немесе модельденген тексеру жергілікті жөндеудің мінез-құлқын дәлелдемейді. Әр жергілікті өзгерісті Windows нұсқалары мен ақау күйлері бойынша тексеру үшін бір реттік Windows виртуалды машиналары пайдаланылады. Толық қауіпсіздік үлгісі үшін [Өзгерістер қалай қауіпсіз болады](safety.html) бетін қараңыз.
