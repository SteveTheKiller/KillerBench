# ストレージ

ディスク、ボリューム、記憶域スペース、ドライブのメンテナンス サービスを確認します。診断がディスク操作を選択することはありません。コンピューターを変更する対応操作には、それぞれ正確な対象、前提条件、確認が必要です。

手順ガイド: [ドライブを確認して修復する](check-a-drive.html) と [ディスク領域を解放する](free-disk-space.html)。

## このセクションのツール

### ストレージ

ディスク、パーティション、ドライブ文字付きボリュームの識別情報を範囲を限定して対応付け、すべてのドライブ文字付きボリュームについて空き容量 10% のしきい値を評価し、VSS シャドウ ストレージの割り当てとボリュームごとのクォータの既定値を確認し、Storage モジュールの現在のジョブの進行状況をまとめ、選択した NTFS ボリュームとそのオンライン自己修復の状態を確認し、この PC 全体のディスクとコントローラーのデバイスを確認します。容量のしきい値、クォータの設定、ジョブの状態は確認用の証拠であり、クリーンアップ、サイズ変更、クォータの変更、ジョブの制御を選択するものではありません。ドライブ文字の対応付けはその時点のもので、すべてのマウント パスを網羅するものではありません。デバイスの結論は選択したボリュームに対応付けられません。既定では Windows のボリュームが選択されます。ファイル、スナップショット、ジョブ、ドライバーは変更されず、設定も変更されず、ボリュームのマウント解除や再起動のスケジュールも行われません。

### 記憶域スペース

初期状態ではない記憶域スペースのプールと仮想ディスクを、正常性、動作状態、容量、割り当て、回復性を含めて一覧にし、範囲を限定した 1 つの動作に関する結論を返します。この読み取り専用のクエリに応答する間、Windows が記憶域スペース管理プロバイダーを要求時に開始する場合があります。プール、仮想ディスク、物理ディスク、ボリューム、回復性、割り当て、メンテナンス設定、ポリシー、スタートアップの種類は保持されます。プール、ディスク、ボリューム、割り当て、接続、修復、最適化、設定の操作は要求されません。プロバイダーの結果は、プールへのアクセス、冗長性、データの整合性、バックアップからの回復可能性、アプリケーションの I/O を検証するものではありません。

### ストレージ サービス

Storage モジュールの現在のジョブ、サービスの正確な障害履歴、ストレージ サービスの現在の準備状態を、範囲を限定して確認します。不完全な証拠が優先されます。ジョブの状態や過去の障害によって、サービスの回復やストレージの変更が許可されることはありません。オプションの回復では、新たな依存関係チェックの後で、有効かつ停止している対象のサービスのみを開始します。既存のストレージ通知とポリシーで管理されたストレージの活動が再開する場合があります。ボリューム、パーティション、ファイル システム、マウント ポイント、デバイス、ドライバー、ストレージ センサーの設定、メンテナンス ポリシー、サービスのアクセス許可、スタートアップの種類は保持されます。KillerBench は、ジョブ、ボリューム、パーティション、マウント ポイント、ファイル、デバイス、ドライバー、ストレージ設定の操作を選択しません。検証の対象はサービスの安定した状態のみで、ジョブの結果やデバイス、ボリューム、ストレージ ポリシーの動作は含まれません。

### ドライブの最適化サービス

ドライブの最適化サービスの可用性を確認します。オプションの回復では、新たな依存関係チェックの後で、有効かつ停止している対象のサービスのみを開始します。Windows がスケジュールした既存の最適化の活動が、現在のメンテナンス ポリシーに従って再開する場合があります。ボリューム、ファイル システム、データ、最適化のスケジュール、メンテナンス ポリシー、サービスのアクセス許可、スタートアップの種類は保持されます。KillerBench がボリュームを選択したり、ドライブの分析、トリム、デフラグ、最適化、スケジュール設定を行ったりすることはありません。検証の対象はサービスの安定した状態のみで、分析、最適化、デバイスの正常性は含まれません。
