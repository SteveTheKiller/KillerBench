# KillerBench の技術

KillerBench が Windows コンピューターをどのように読み取り、証拠を正確に保ち、変更を許可するかどうかをどう判断するかを、内部の仕組みから説明します。

## 技術スタック

KillerBench はネイティブの Windows アプリです。デスクトップ アプリ、コマンド ライン、その基盤となる Engine は、同じ診断の証拠と修復のワークフローを共有しています。

| コンポーネント | 詳細 |
| --- | --- |
| UI | .NET 10 上の WPF (`net10.0-windows`)、Windows x64、独自のウィンドウ フレーム |
| Engine | `Engine.Core`、`Engine`、`Engine.Windows`。WPF やデスクトップのコントロールへの参照はありません |
| コマンド ライン | `killerbench-cli`。同じ Engine 上の別のホストです |
| Windows プロバイダー | .NET、Windows API、PowerShell、Windows のコマンド ライン ツール。いずれも時間、レコード数、サイズの固定された上限の範囲内で実行されます |
| レポート | 生の出力、読みやすいレポート、HTML、テキスト、JSON |
| 参照データ | エラー コード、ハードウェア識別子、ベンダー、サポート情報のための、バージョン付きナレッジ パック |
| パッケージ | インストーラー: フレームワーク依存で、.NET Desktop Runtime 10 for Windows x64 が必要です。ポータブル版: 自己完結型で、ランタイムのインストールは不要です |
| 外観 | ファミリー共通の 13 のテーマと 19 の言語 |

## インストール、フォルダー、データ

KillerBench には 2 つの形態があります。インストーラーは標準のダウンロードで、ユーザーごとのインストールとすべてのユーザー向けのインストールに対応します。ポータブル版は独自の .NET ランタイムを含み、インストールせずに実行できます。

KillerBench は、起動したアカウントの権限で実行されます。自分で昇格することはありません。BitLocker の保護機能などの保護された証拠や修復に管理者アクセスが必要な場合は、**管理者として実行** で起動してください。昇格によって修復が選択されたり承認されたりすることはありません。

### インストーラーの処理内容

インストーラーはアプリケーションを検証して `%LOCALAPPDATA%\Programs\KillerBench\` に展開します。すべてのユーザー向けの場合は、昇格のプロンプトの後で `%ProgramFiles%\KillerBench\` に展開します。スタート メニューのショートカット、任意のデスクトップ ショートカット、通常のアンインストールとサイレント アンインストールを備えたプログラムの追加と削除のエントリを追加します。ポータブル版は、現在の実行のためにペイロードを検証して `%LOCALAPPDATA%\KillerBench\Portable\` に展開し、次回の起動時に残されたコピーを片付けます。

### 保存場所

| 場所 | 内容 |
| --- | --- |
| `%LOCALAPPDATA%\KillerBench\appearance.json` | テーマ、アクセント カラー、インターフェイスの拡大率、言語 |
| `%LOCALAPPDATA%\KillerBench\Workflows\` | ワークフローの実行ごとの JSON ジャーナル。判断、範囲を限定したコマンド出力、修復の結果を含みます |
| `%LOCALAPPDATA%\KillerBench\Repairs\` | DISM や SFC などのサービシング修復の実行ジャーナル |
| `%LOCALAPPDATA%\KillerBench\` 内の機能別フォルダー | 個々の保護付き操作の保留中のレコードと結果。例: `BitLockerBackup`、`Time`、`Firewall`、`Profiles` |
| `%LOCALAPPDATA%\KillerBench\agent-repairs.json` | このアプリについてで選択した KillerMCP の修復レベル |
| `HKCU` または `HKLM\Software\KillerBench` | 対応するインストール範囲のインストール パス |
| 選択した `.kbench` ファイル | 保持された証拠を含む保存済みのキャプチャ |

何もアップロードされません。ジャーナルは、不確かな結果の証拠が不要になってから削除してください。

## まず診断

KillerBench は、診断と変更を別々の作業として扱います。診断は読み取るだけです。変更が行われるのは、具体的な修復や操作を選び、そのオプションと前提条件を確認して承認した場合だけです。

システム全体のスキャンは、対象を絞ったワークフローで自動修復が有効になっている場合でも、診断のみを行います。保存されたキャプチャ、インポートしたログ、過去のイベントによって修復が許可されることはありません。

### 範囲を限定した収集

すべてのネイティブ コマンドと Windows プロバイダーは、時間、レコード数、サイズの固定された上限の範囲内で実行されます。プロバイダーは、終了状態、タイムアウト、切り詰め、標準出力、エラー出力を記録します。失敗した、または切り詰められたプロバイダーの結果が、問題のない空の回答として読まれることはありません。

### 最小限の保持

コレクターは、結論に必要なものだけを保持します。多くの結果では、名前、カテゴリ、件数、状態、タイムスタンプを保持し、資格情報、コマンド ライン、完全なパス、アカウントの識別情報、ネットワークのエンドポイント、無関係なイベントの内容は保持しません。

## たどることができる証拠

すべての結論は、それを生み出した証拠と結び付いており、レポートでは証明されたことと観察されただけのことが常に区別されます。

| 状態 | 意味 |
| --- | --- |
| 要確認 | 証拠が、注意すべき問題を裏付けています。 |
| 情報 | 証拠が収集され、参考情報として表示されています。 |
| 未完了または不明 | チェックを完了できなかったか、証拠を取得できませんでした。正常とみなされることはありません。 |
| 履歴 | 過去のイベントです。経緯の説明にはなりますが、現在の障害を証明するものではありません。 |
| 検証済み | 修復や変更が、結果を読み直すことで確認されました。 |

### 不明も結果の 1 つ

不明とは、アクセスが拒否された、ソースが存在しない、プロバイダーが失敗した、出力の形式が正しくない、上限を超えた、または証拠が食い違っていることを意味します。KillerBench はその制限を隠さず、次に役立つ手順とともに示します。

### 履歴は履歴のまま

イベントの記録やインポートしたログは、過去のある時点で記録された内容を示すものです。エラー コードや次に診断すべき範囲の手がかりにはなりますが、障害が現在も続いていることを証明するものではありません。

## 保護付きの修復

修復は、適格性、実行、検証、回復のルールを持つ型付きの操作です。ログの行から取り出したコマンド文字列ではありません。対応するすべての修復は、同じ手順に従います。

1. 現在の証拠を完全に収集する。
2. 対応する 1 つのレシピに照合する。
3. 必須のオプションと影響を確認する。
4. 管理上の前提条件とポリシー上の前提条件を確認する。
5. 変更の直前に決定的な証拠を再収集する。
6. 永続的な準備レコードを書き込む。
7. 範囲を限定した 1 つのネイティブ操作を実行する。
8. 新しい検証用の証拠を収集する。
9. 検証済み、ブロック、停止、不確かのいずれかの結果を記録する。

操作の実行前に決定的な証拠が変化した場合、KillerBench は操作を行わずに停止します。

### 明示的な選択

オプションに依存する修復では、ボリューム、プリンター キュー、回復キーのバックアップ先、電源の値、パッケージのバージョン、修復ソースなど、ユーザーによる正確な選択が必要です。KillerBench がこれらの値を勝手に決めることはありません。

### 管理されたコンピューター

グループ ポリシーやデバイス管理によって、ローカルの変更が効果を持たなかったり、不適切になったりする場合があります。対応する修復では設定の所有者を確認し、所有が管理されている場合や不明な場合は停止します。ポリシーが所有する設定は変更されません。

### 自動修復

自動修復は、適格なレシピの続行を許可するだけです。証拠を省略したり、不足しているオプションを選んだり、ポリシーを無視したり、不確かな操作を再試行したり、Windows を再起動したり、確認が必要な結論を修復に変えたりすることはありません。

## ジャーナルと中断

KillerBench は、Windows に変更を依頼する前に、これから行う内容を書き留めます。各変更は `%LOCALAPPDATA%\KillerBench` のジャーナルに保存されます。

変更の後、KillerBench は結果を読み直し、Windows が期待どおりの状態を示した場合にのみ **検証済み** と報告します。Windows が成功を報告しても状態が変わっていない場合は、結果にそのことが示され、何も繰り返されません。

Windows が要求を受け取った後、検証が完了する前にプロセスが停止する場合があります。保留中のレコードは残り、後の照合で新しい状態を読み取って何が起きたかを判断します。照合は自動ロールバックではなく、元の変更を繰り返すことはありません。結果が不確かなときはジャーナルを保持してください。

## 定数と上限

| 仕様 | 値 |
| --- | --- |
| 診断の対象範囲 | システム全体のスキャンで 49 の診断領域を実行し、96 の保護付き修復レシピを確認 |
| テキスト ソースの読み取り | ソースあたり 1,000,000 文字、一致する行を 2,000 行表示 |
| セッションソース | サイドバーに 12 件。キャプチャには最大 24 のソースと 64 MB を保持 |
| イベントのクエリ | 過去 7 日間について、チャネルごとに最新の 200 件のイベント |
| Windows Update のスキャン | ソースごとに 15 秒、全体で 2 分 |
| ログの調査 | 解析済みエントリ 10,000 件、異なるコード 256 種類、コードごとに 320 文字の抜粋を 8 件 |
| 圧縮された CBS アーカイブ | アーカイブ 256 MiB、ログ メンバー 512 MiB、展開 30 秒 |
| 読み取り専用の CHKDSK | 10 分。修復の上限は 65 分 |
| DNS と TCP のチェック | 既定で 10 秒、最大 1 分 |
| サービスの一覧 | インストール済みのサービス最大 1,024 個 |
| ナレッジ パック | 同時に最大 32 個まで開く |
| 大きなファイルの確認 | 100 MB 以上のファイル |
| サービシング アクティビティ モニター | 間隔 1 から 60 秒、スナップショット 1 から 120 回 |
| スケジュールされたタスクの下書き | 実行時間の上限 1 から 4,320 分 |
| カスタムの時刻ソース | NTP ピア最大 8 個 |
| アクティビティのエクスポート | 保持されたエントリ最大 150 件 |
| 言語とテーマ | 19 の言語、アクセントのバリエーションを持つ 13 のテーマ |

## 行わないこと

- TPM のクリア、自身が作成していない保護機能の削除、回復パスワードの表示。
- グループ ポリシーやデバイス管理が制御する設定の変更。
- 過去のイベントやインポートしたレポートが問題に触れているという理由だけでの修復の実行。
- 欠落した証拠、一部だけの証拠、失敗した証拠を正常という結論に変えること。

## レポート

実行のたびに、読む、フィルターする、エクスポートすることができるレポートが作成されます。レポートでは次の項目が区別されます。

1. 何を確認したか
2. どのような問題が見つかったか
3. 結論を裏付ける証拠は何か
4. どの操作が提案または実行されたか
5. 結果がどのように検証されたか
6. 何が不明のままか、または再起動が必要か

**生の出力** は、技術的な証拠を元の行番号とともに保持するため、どの結論もそのソースまでたどることができます。**読みやすいレポート** は、同じ実行をわかりやすい言葉で要約し、安全な次の手順を最初に示します。HTML レポートは Killer Tools のテーマ システムを使い、アプリがなくても読めます。テキストは持ち運びやすさを重視し、JSON はほかのプログラム向けに構造化されたフィールドを保持します。

## 保存されたログとキャプチャ

KillerBench は、コンピューターで何も実行せずに証拠を調査できます。テキストのログをウィンドウにドロップするか、そのパスを貼り付けて **ログを開く** を選びます。CBS、CSI、Setup の行はタイムスタンプとともに解析され、結論は元の行に正確にリンクします。EVTX ファイルとイベント XML ファイルも同じ方法でインポートできます。

**Windows Update をスキャン** は、CBS、DISM、Panther、ロールバック Setup のログ、更新とサービシングのイベント チャネル、更新サービスの状態、空き容量、稼働時間、保留中の再起動のインジケーター、選択した更新ポリシーを、必要なときに読み取り専用で収集します。**キャプチャを保存** は、保持された証拠を `.kbench` ファイルに書き込みます。**キャプチャを開く** は、元のファイルがなくてもそのキャプチャを開き直し、インストール済みのルールで再評価するため、同じルールからは同じ結論が得られます。

## デモ モード

`KillerBench.exe --demo` を起動すると、架空のワークステーションで **診断を実行** を試せます。すべてのワークフローが合成の証拠と時間経過に応じた進行状況を生成します。Windows プロバイダーは呼び出されず、修復コマンドは実行されず、ジャーナルも書き込まれません。**診断を実行** 以外の個別のツール ボタンは実際に動作するため、デモ用の操作として使わないでください。

`KillerBench.exe --demo-screenshot` は、固定された架空のコンピューターについて、表示専用のシステム全体のスキャンのレポートを開きます。ワークスペース内のクリック、ショートカット、ファイルのドロップはブロックされます。

## ナレッジ パック

大量で頻繁に更新される参照データは、診断ロジックではなくナレッジ パックに格納されます。Windows と Setup のエラー コード、ベンダーとデバイスの識別子、PCI、USB、ACPI、UEFI の参照、ネットワークの OUI ベンダー データ、ドライバーとサポートの場所、厳選したサポート リンクが含まれます。

各パックは、形式、スキーマのバージョン、ソース、ソースのリビジョン、生成日時、内容のハッシュを示し、KillerBench は使用前にそれらを検証します。不明なパックや無効なパックは、推測で代用されることなく利用できないままになります。更新は一時的な場所にダウンロードされて検証され、その後 1 回の手順で有効なパックを置き換えるため、更新が失敗しても以前のパックがそのまま残ります。

ナレッジ データは、識別子を説明したり、次に調べる場所を示したりできます。過去のコードを現在の障害に変えたり、ドライバーを自動的に選んだり、修復を許可したりすることはできません。

## 更新と署名

起動時に KillerBench は 4 秒の制限で GitHub に最新の安定版リリースを問い合わせ、そのリリースが新しい場合にのみ更新を提示します。この確認は、このアプリについての **起動時に更新を確認する**、または更新のプロンプトでオフにできます。ダウンロードされるのは実行中のコピーに対応するパッケージ (インストーラーまたはポータブル版) で、何かをインストールする前に、その SHA-256 がリリースの `SHA256SUMS.txt` と一致する必要があります。アプリは自身を閉じてから開き直して処理を完了します。バックグラウンド サービスはありません。

このアプリについてのカードには、バージョン、コード署名の発行元と拇印、実行中の実行可能ファイルの SHA-256 が表示されるため、手元のコピーを確認できます。

## KillerMCP

KillerBench には AI エージェントは含まれていません。[KillerMCP](../mcp.html) を使うと、同じ Engine にエージェントを接続できます。このアプリについての **KillerMCP のオプション** で、そのエージェントに許可する内容を決めます。

| 設定 | 効果 |
| --- | --- |
| オフ (既定) | エージェントは修復を要求できません。 |
| KillerMCP に安全な修復の実行を許可する | エージェントは、安全と分類された修復を要求できます。 |
| 影響の大きい修復も許可する | 影響の大きい修復が利用可能になりますが、それぞれに引き続き承認が必要です。 |

レベルを上げられるのは、このコンピューターの前にいる人だけです。修復の結果が不確かだった場合、KillerMCP はロックを書き込み、誰かがこのアプリについてでロックを解除するまで、エージェントによる修復はブロックされたままになります。

## ローカライズ

インターフェイスは 19 の言語で利用できます。英語、ベンガル語、チェコ語、ドイツ語、スペイン語、フランス語、ハンガリー語、イタリア語、日本語、カザフ語、ノルウェー語、ポーランド語、ポルトガル語 (ブラジル)、ロシア語、トルコ語、ウクライナ語、ベトナム語、簡体字中国語、繁体字中国語です。言語の変更は、セクション名やワークフロー名、ようこそのテキスト、開いている読みやすいレポートを含め、すぐに反映されます。翻訳がないテキストは英語で表示されます。

証拠、Engine の結論、ジャーナル、生の出力は、Windows のログと同じく英語のままです。そのため、レポートはどのコンピューターでも同じように読め、正確なテキストで検索できます。

## コマンド ラインと終了コード

`killerbench-cli` は、デスクトップ アプリなしで同じ Engine を実行します。進行状況は標準エラーに、JSON は標準出力に出力されます。ほとんどのコマンドは既定でプレビューを表示し、変更には `--execute` が必要です。対応する `-recover` コマンドは、中断された操作を繰り返さずに確認します。[スクリプトから KillerBench を実行する](use-the-cli.html) と [コマンド リファレンス](cli.html) を参照してください。

| 終了コード | ワークフロー コマンド | スキャンとオープン |
| --- | --- | --- |
| 0 | 確認した範囲に未解決の問題なし | 対象範囲を完了 |
| 1 | 起動またはジャーナルのエラー | 失敗 |
| 2 | 無効な引数 | 無効な引数 |
| 3 | 注意が必要 | 一部のみ収集 |
| 4 | 検証の前に再起動が必要 | |
| 130 | 停止 | キャンセルまたは全体のタイムアウト |

どの終了コードも、コンピューターが正常であることを保証するものではありません。

## アーキテクチャ

Engine は、UI を持たない 3 つのプロジェクトに分かれています。`Engine.Core` は基本要素と宣言型のレシピを提供し、`Engine` は共通のワークフローと証拠を担い、`Engine.Windows` はネイティブ プロバイダーを登録します。デスクトップ アプリ、CLI、テストはそれぞれ別のホストです。

| レイヤー | 役割 |
| --- | --- |
| 機能コレクター | 1 つの正確な範囲について、範囲を限定した Windows の状態を読み取る |
| 証拠パーサー | 形式、識別情報、完全性、上限を検証する |
| 診断の解釈 | 証拠を明示的なワークフローの状態に変換する |
| ワークフローの調整 | チェック、進行状況、レシピ、ジャーナルを組み合わせる |
| 修復コーディネーター | 適格性を再確認し、準備、変更、検証、照合を行う |
| レポート | 問題、操作、結果、制限を提示する |
| ナレッジ パック | ロジックを変更せずに、バージョン付きの参照データを解決する |

識別情報があいまいな場合、出力の形式が正しくない場合、上限を超えた場合、必要な権限を確認できない場合、コレクターはフェイルクローズします。Engine は現在 Windows を対象としており、クロスプラットフォームではありません。[Engine 開発者ガイド](../engine/index.html) では、API、CLI、ほかの .NET ホストへの Engine の組み込みについて説明しています。

## プライバシーとネットワーク

診断とログ分析は、AI サービスや KillerBench アカウントなしでローカルに実行されます。ジャーナルと保持された証拠は、ローカル アカウントの `%LOCALAPPDATA%\KillerBench` フォルダーに保存されます。

選択した操作は、Windows Update、ソフトウェアのダウンロード サービス、Active Directory や Entra ID への回復キーのバックアップなど、それぞれの接続先に接続する場合があります。起動時の更新確認は GitHub に接続し、ナレッジの更新と KillerMCP インストーラーは、それぞれ構成されたサービスに接続します。[KillerMCP](../mcp.html) を使う AI クライアントは、要求した参照結果を受け取る場合があります。

生のログ、インポートしたファイル、エクスポートした証拠には、コンピューター名、アカウント、パス、機密性のあるソース テキストが含まれる可能性があります。共有する前に確認し、公開レポートには回復キー、資格情報、顧客データを決して含めないでください。

## 開発状況

KillerBench は開発中で、公開ダウンロードはまだありません。修復の対象範囲は拡大を続けており、ネイティブ修復の検証もまだ進行中です。ビルドの成功やシミュレーションによるチェックは、ネイティブ修復の動作を証明するものではありません。使い捨ての Windows 仮想マシンを使って、ネイティブの変更ごとに Windows のバージョンや障害の状態をまたいで検証しています。安全モデルの全体については、[変更の安全性を保つ仕組み](safety.html) を参照してください。

## 用語集

このページで使われている用語を、五十音順でわかりやすく説明します。

| 用語 | 意味 |
| --- | --- |
| BITS | Background Intelligent Transfer Service。更新プログラムやその他のファイルをバックグラウンドでダウンロードする Windows のサービスです。 |
| CBS | Component-Based Servicing。更新プログラムと機能をインストールする Windows のサブシステムです。ログは `CBS.log` です。 |
| DISM | Deployment Image Servicing and Management。コンポーネント ストアを確認して修復する Windows のツールです。 |
| Panther | Windows Setup がアップグレードのログを書き込むフォルダーです。 |
| SFC | System File Checker。保護されたシステム ファイルを検証して復元する Windows のツールです。 |
| TPM | Trusted Platform Module。BitLocker がドライブのキーを保護するために使うセキュリティ チップです。 |
| キャプチャ | 保持された証拠を含む保存済みの `.kbench` ファイルです。元のコンピューターがなくても再確認できます。 |
| 検証済み | 結果を Windows から読み直し、変更で実現すべき状態と一致したことを示します。 |
| ジャーナル | 変更の前に書き込まれ、変更の後に更新されるローカルの JSON 記録です。中断された操作を後で確認できます。 |
| 昇格 | Windows のプロンプトの後に管理者権限で実行することです。KillerBench が自分で昇格することはありません。 |
| 証拠 | KillerBench が Windows から実際に読み取った内容です。結論をたどれるよう、ソースとともに保持されます。 |
| 照合 | 中断の後に、変更を繰り返さずに何が起きたかを知るため、新しい状態を読み取ることです。 |
| ナレッジ パック | エラー コードやハードウェア識別子などの参照データを含む、バージョン付きで検証済みのファイルです。 |
| フェイルクローズ | 証拠があいまい、欠落、または大きすぎる場合、結果は不明となり、変更は一切許可されません。 |
| ポリシー所有者 | 設定を制御するグループ ポリシーまたはデバイス管理です。KillerBench は所有者のいる設定を変更しません。 |
| 保留中レコード | 変更が Windows に送信された可能性があることを示すレコードです。照合で結果を読み取るまで、繰り返しをブロックします。 |
| レシピ | 独自の適格性、実行、検証、回復のルールを持つ型付きの修復です。 |
| ワークフロー | 1 つのツールの実行です。収集するチェック、使用できるレシピ、作成するレポートで構成されます。 |
