# 报告和证据

每次运行都会生成一份可以阅读、筛选和导出的报告。报告始终将已证明的内容与仅观察到的内容区分开来。

## 你会看到的状态

| 状态 | 含义 |
| --- | --- |
| 需要审阅 | 证据支持一个值得关注的问题。 |
| 信息 | 已收集证据并作为背景信息显示。 |
| 未完成或未知 | 检查未能完成，或证据不可用。永远不会被视为正常。 |
| 历史 | 过去的事件。它可以解释历史，但不能证明当前存在故障。 |
| 已验证 | 通过读回结果确认了修复或更改。 |

## 原始输出和可读报告

**原始输出** 会保留技术证据及其原始行号，因此可以将任何结论追溯到其来源。**可读报告** 用通俗的语言总结同一次运行，并将安全的下一步放在最前面。

## 已保存的日志

KillerBench 还可以读取已保存的 Windows 日志（例如 CBS 和 Setup 日志），而无需在计算机上运行任何内容。结论会链接到产生它的确切行。会话来源中的 **加载示例** 会打开一个可以安全探索的合成示例。

## 导出

**导出报告** 会将报告连同其来源路径、已解析的条目和证据摘录一起保存，便于在附加到工单之前进行检查。原始日志和证据摘录可能包含计算机名称、账户、路径或敏感的源文本。受保护的收集器会限制其保留的内容，但导入的证据不保证已经过脱敏处理。共享前请检查并删除敏感信息。
