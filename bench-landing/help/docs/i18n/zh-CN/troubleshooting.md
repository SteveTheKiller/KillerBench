# 疑难解答

## 操作显示被阻止

被阻止的结果表示所请求的操作无法继续。请阅读消息和日志，了解它是在发送之前停止，还是在之前的某个步骤之后停止。不要以为部分完成的操作已经回滚。最常见的前提条件原因如下。

- **需要管理员访问权限。** 关闭 KillerBench，然后通过 **以管理员身份运行** 重新启动。
- **重启状态必须已清除。** Windows 有待处理的重启。请重启计算机，然后再次运行该操作。
- **存在受管理的策略。** 该设置由组策略或设备管理拥有。请在那里更改。
- **证据已变化。** 在首次检查和最后复查之间发生了变化。请再次运行工具以读取新状态。

## 之前的请求需要核对

KillerBench 发现了一个来自中断请求的待处理记录。请再次运行同一操作。它会检查发生了什么，并在不重复请求的情况下报告实际结果。在命令行中，请使用相应的 `-recover` 命令，例如 `killerbench-cli bitlocker-auto-unlock-recover`。

## 检查显示未完成或未知

无法读取证据，通常是因为 KillerBench 未以管理员身份运行，或者某个 Windows 服务不可用。KillerBench 会如实报告这一点，而不会假定计算机正常。

## 文件保存位置

日志、待处理记录和已保存的证据位于 `%LOCALAPPDATA%\KillerBench` 下。每个受保护的操作都有自己的文件夹。如果需要保留更改记录，请保留这些文件。

## 报告问题

KillerBench 正在开发中。报告问题时，请附上导出的报告和活动日志，并删除任何不愿共享的内容。
