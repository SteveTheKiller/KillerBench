# KillerBench 技术解析

深入了解 KillerBench 如何读取 Windows 计算机、如何保证证据的准确性，以及如何决定何时允许更改。

## 技术栈

KillerBench 是原生 Windows 应用。桌面应用、命令行及其底层的 Engine 共享相同的诊断证据和修复工作流程。

| 组件 | 详细信息 |
| --- | --- |
| 界面 | 基于 .NET 10 的 WPF（`net10.0-windows`），Windows x64，自定义窗口边框 |
| Engine | `Engine.Core`、`Engine` 和 `Engine.Windows`，不引用 WPF 或桌面控件 |
| 命令行 | `killerbench-cli`，基于同一 Engine 的独立主机 |
| Windows 提供程序 | .NET、Windows API、PowerShell 和 Windows 命令行工具，每个都在固定的时间、记录数和大小限制内运行 |
| 报告 | 原始输出、可读报告、HTML、文本和 JSON |
| 参考数据 | 带版本的知识包，涵盖错误代码、硬件标识符、供应商和支持参考 |
| 打包 | 安装程序：依赖框架，需要 .NET Desktop Runtime 10 for Windows x64。便携版：独立包含，无需安装运行时 |
| 外观 | 13 种系列主题和 19 种语言 |

## 安装、文件夹和数据

KillerBench 提供两种形式。安装程序是标准下载，支持按用户安装或为所有用户安装。便携版自带 .NET 运行时，无需安装即可运行。

KillerBench 以启动它的账户的权限运行，不会自行提升权限。当受保护的证据（例如 BitLocker 保护器）或修复需要管理员访问权限时，请通过 **以管理员身份运行** 启动它。提升权限永远不会选择或批准修复。

### 安装程序的作用

安装程序会验证应用程序并将其解压到 `%LOCALAPPDATA%\Programs\KillerBench\`，或者在为所有用户安装时经提升权限提示后解压到 `%ProgramFiles%\KillerBench\`。它会添加开始菜单快捷方式、可选的桌面快捷方式，以及支持普通卸载和静默卸载的“添加或删除程序”条目。便携版会为当前运行验证其负载并将其解压到 `%LOCALAPPDATA%\KillerBench\Portable\`，并在下次启动时清理遗留的副本。

### 数据存放位置

| 位置 | 内容 |
| --- | --- |
| `%LOCALAPPDATA%\KillerBench\appearance.json` | 主题、强调色、界面缩放和语言 |
| `%LOCALAPPDATA%\KillerBench\Workflows\` | 每次工作流程运行一个 JSON 日志：决策、有范围限制的命令输出和修复结果 |
| `%LOCALAPPDATA%\KillerBench\Repairs\` | DISM 和 SFC 等维护修复的执行日志 |
| `%LOCALAPPDATA%\KillerBench\` 下的功能文件夹 | 各个受保护操作的待处理记录和结果，例如 `BitLockerBackup`、`Time`、`Firewall` 和 `Profiles` |
| `%LOCALAPPDATA%\KillerBench\agent-repairs.json` | 在“关于”中选择的 KillerMCP 修复级别 |
| `HKCU` 或 `HKLM\Software\KillerBench` | 对应安装范围的安装路径 |
| 你选择的 `.kbench` 文件 | 包含保留证据的已保存捕获 |

不会上传任何内容。只有在不再需要某个不确定结果的证据时，才删除对应的日志。

## 诊断优先

KillerBench 将诊断和更改视为两项不同的工作。诊断只读取。只有当你选择具体的修复或操作、查看其选项和前提条件并确认后，才会进行更改。

完整系统扫描仅执行诊断，即使某个专用工作流程开启了自动修复也是如此。已保存的捕获、导入的日志和历史事件永远不能授权修复。

### 有范围限制的收集

每个原生命令和 Windows 提供程序都在固定的时间、记录数和大小限制内运行。提供程序会记录其退出状态、超时、截断、标准输出和错误输出。失败或被截断的提供程序结果永远不会被视为干净的空结果。

### 最小化保留

收集器只保留结论所需的内容。许多结果会保留名称、类别、数量、状态和时间戳，而不保留凭据、命令行、完整路径、账户标识、网络终结点和无关的事件负载。

## 可追溯的证据

每个结论都与产生它的证据相关联，报告始终将已证明的内容与仅观察到的内容区分开来。

| 状态 | 含义 |
| --- | --- |
| 需要审阅 | 证据支持一个值得关注的问题。 |
| 信息 | 已收集证据并作为背景信息显示。 |
| 未完成或未知 | 检查未能完成，或证据不可用。永远不会被视为正常。 |
| 历史 | 过去的事件。它可以解释历史，但不能证明当前存在故障。 |
| 已验证 | 通过读回结果确认了修复或更改。 |

### 未知也是一种结果

未知表示访问被拒绝、来源缺失、提供程序失败、输出格式错误、超出限制或证据相互矛盾。KillerBench 会显示这一限制以及下一步有用的操作，而不是将其隐藏。

### 历史仍是历史

事件记录和导入的日志描述的是过去某个时间记录的内容。它们可以指向某个错误代码或下一个诊断范围，但不能证明故障仍然存在。

## 受保护的修复

修复是具有适用条件、执行、验证和恢复规则的类型化操作，而不是从日志行中挑出的命令字符串。每项受支持的修复都遵循相同的流程：

1. 收集完整的当前证据。
2. 匹配一个受支持的方案。
3. 查看必需的选项和后果。
4. 确认管理和策略方面的前提条件。
5. 在更改前立即重新收集决定性证据。
6. 写入持久的准备记录。
7. 运行一个有范围限制的原生操作。
8. 收集新的验证证据。
9. 记录已验证、已阻止、已停止或不确定的结果。

如果决定性证据在操作运行前发生变化，KillerBench 会停止而不执行该操作。

### 明确的选择

依赖选项的修复需要你做出确切的选择，例如卷、打印机队列、恢复密钥备份位置、电源值、包版本或修复来源。KillerBench 绝不会自行编造这些值。

### 受管理的计算机

组策略和设备管理可能会使本地更改无效或不合适。受支持的修复会检查设置的所有者，并在所有权受管理或未知时停止。由策略拥有的设置保持不变。

### 自动修复

自动修复只允许符合条件的方案继续执行。它不会绕过证据、选择缺失的选项、忽略策略、重试不确定的操作、重启 Windows，也不会将需要审阅的结论变成修复。

## 日志和中断

在请求 Windows 进行更改之前，KillerBench 会先写下即将执行的操作。每项更改都保存在 `%LOCALAPPDATA%\KillerBench` 下的日志中。

更改之后，KillerBench 会读回结果，只有当 Windows 显示预期状态时才报告 **已验证**。如果 Windows 报告成功但状态没有变化，结果会如实说明，并且不会重复任何操作。

进程可能会在 Windows 收到请求之后、验证完成之前停止。此时待处理记录会保留下来，之后的核对会读取新状态以确定发生了什么。核对不是自动回滚，也绝不会重复原始更改。结果不确定时请保留日志。

## 不会做的事

- 清除 TPM、删除不是由它创建的保护器，或显示恢复密码。
- 更改由组策略或设备管理控制的设置。
- 仅因为历史事件或导入的报告提到了某个问题就运行修复。
- 将缺失、部分或失败的证据变成运行正常的结论。

## 报告

每次运行都会生成一份可以阅读、筛选和导出的报告。报告会分别说明：

1. 检查了什么
2. 发现了什么问题
3. 哪些证据支持该结论
4. 提出或执行了什么操作
5. 如何验证结果
6. 哪些内容仍未知或需要重启

**原始输出** 会保留技术证据及其原始行号，因此可以将任何结论追溯到其来源。**可读报告** 用通俗的语言总结同一次运行，并将安全的下一步放在最前面。HTML 报告使用 Killer Tools 主题系统，即使没有应用也能阅读。文本便于移植，JSON 则为其他程序保留结构化字段。

## 已保存的日志和捕获

KillerBench 可以在不在计算机上运行任何内容的情况下调查证据。将文本日志拖放到窗口中，或者粘贴其路径并选择 **打开日志**。CBS、CSI 和 Setup 行会连同时间戳一起解析，结论会链接到确切的原始行。EVTX 和事件 XML 文件也可以用同样的方式导入。

**扫描 Windows 更新** 会按需以只读方式收集 CBS、DISM、Panther 和回滚 Setup 日志、更新和维护事件通道、更新服务状态、可用空间、运行时间、待处理的重启指示以及所选的更新策略。**保存捕获** 会将保留的证据写入 `.kbench` 文件。**打开捕获** 会在没有原始文件的情况下重新打开该文件，并使用已安装的规则重新评估，因此相同的规则会得出相同的结论。

## 演示模式

启动 `KillerBench.exe --demo`，即可在虚构的工作站上试用 **运行诊断**。每个工作流程都会生成合成证据和定时进度。不会调用任何 Windows 提供程序，不会运行任何修复命令，也不会写入任何日志。**运行诊断** 之外的单独工具按钮仍会实际运行，因此请勿将其作为演示操作使用。

`KillerBench.exe --demo-screenshot` 会为一台固定的虚构计算机打开只读的完整系统扫描报告。工作区中的单击、快捷键和文件拖放都会被阻止。

## 知识包

大量且经常更新的参考数据存放在知识包中，而不是诊断逻辑中：Windows 和 Setup 错误代码、供应商和设备标识符、PCI、USB、ACPI 和 UEFI 参考、网络 OUI 供应商数据、驱动程序和支持位置以及精选的支持链接。

每个知识包都会标明其格式、架构版本、来源、来源修订、生成时间和内容哈希，KillerBench 会在使用前对其进行验证。未知或无效的知识包会保持不可用，而不会回退为猜测。更新会下载到临时位置并经过验证，然后一步替换当前的知识包，因此更新失败时会保留之前的知识包。

知识数据可以解释某个标识符或建议下一步查看的位置。它不能将历史代码变成当前故障、自动选择驱动程序或授权修复。

## 更新和签名

启动时，KillerBench 会在四秒限制内向 GitHub 查询最新的稳定版本，并且仅在该版本较新时才提供更新。你可以在“关于”中通过 **启动时检查更新**，或在更新提示中关闭此检查。下载的是与当前运行副本相匹配的软件包（安装程序或便携版），并且在安装任何内容之前，其 SHA-256 必须与该版本的 `SHA256SUMS.txt` 匹配。应用会自行关闭并重新打开以完成更新。没有后台服务。

“关于”卡片会显示版本、代码签名发布者和指纹，以及正在运行的可执行文件的 SHA-256，以便你检查手中的副本。

## KillerMCP

KillerBench 不包含 AI 代理。[KillerMCP](../mcp.html) 可以将代理连接到同一 Engine。“关于”中的 **KillerMCP 选项** 决定该代理可以执行的操作：

| 设置 | 效果 |
| --- | --- |
| 关闭（默认） | 代理无法请求修复。 |
| 允许 KillerMCP 运行安全修复 | 代理可以请求被归类为安全的修复。 |
| 同时允许破坏性修复 | 破坏性修复变为可用，并且每项修复仍需批准。 |

只有在这台计算机前的人才能提高级别。在修复结果不确定后，KillerMCP 会写入一个锁定，代理修复会一直被阻止，直到有人在“关于”中解除该锁定。

## 本地化

界面提供 19 种语言：英语、孟加拉语、捷克语、德语、西班牙语、法语、匈牙利语、意大利语、日语、哈萨克语、挪威语、波兰语、葡萄牙语（巴西）、俄语、土耳其语、乌克兰语、越南语，以及简体中文和繁体中文。更改语言会立即生效，包括分区和工作流程名称、欢迎文本以及已打开的可读报告。缺失的文本会以英语显示。

证据、Engine 结论、日志和原始输出与 Windows 日志一样保持英语，因此报告在每台计算机上的内容都相同，并且可以搜索确切的文本。

## 命令行和退出代码

`killerbench-cli` 在没有桌面应用的情况下运行同一 Engine。进度输出到标准错误，JSON 输出到标准输出。大多数命令默认只显示预览，进行更改需要使用 `--execute`。对应的 `-recover` 命令会检查中断的操作而不重复执行。请参阅 [从脚本运行 KillerBench](use-the-cli.html) 和 [命令参考](cli.html)。

| 退出代码 | 工作流程命令 | 扫描和打开 |
| --- | --- | --- |
| 0 | 所检查的范围内没有未解决的问题 | 完成覆盖范围 |
| 1 | 启动或日志错误 | 失败 |
| 2 | 参数无效 | 参数无效 |
| 3 | 需要注意 | 部分收集 |
| 4 | 验证前需要重启 | |
| 130 | 已停止 | 已取消或总体超时 |

没有任何退出代码能证明计算机运行正常。

## 体系结构

Engine 分为三个不含界面的项目。`Engine.Core` 提供基础类型和声明式方案，`Engine` 负责共享的工作流程和证据，`Engine.Windows` 注册原生提供程序。桌面应用、CLI 和测试是独立的主机。

| 层 | 职责 |
| --- | --- |
| 功能收集器 | 读取一个确切范围内有范围限制的 Windows 状态 |
| 证据解析器 | 验证形状、标识、完整性和限制 |
| 诊断解释 | 将证据转换为明确的工作流程状态 |
| 工作流程编排 | 组合检查、进度、方案和日志 |
| 修复协调器 | 重新检查适用条件、准备、更改、验证和核对 |
| 报告 | 呈现问题、操作、结果和限制 |
| 知识包 | 在不更改逻辑的情况下解析带版本的参考数据 |

当标识不明确、输出格式错误、超出限制或无法检查所需的权限时，收集器会失效关闭。Engine 目前面向 Windows，不跨平台。[Engine 开发人员指南](../engine/index.html) 介绍 API、CLI 以及如何将 Engine 嵌入到其他 .NET 主机中。

## 隐私和网络

诊断和日志分析在本地运行，无需 AI 服务或 KillerBench 账户。日志和保留的证据保存在本地账户的 `%LOCALAPPDATA%\KillerBench` 文件夹中。

你选择的操作可能会连接其目标，例如 Windows 更新、软件下载服务，或将恢复密钥备份到 Active Directory 或 Entra ID。启动时的更新检查会连接 GitHub，知识更新和 KillerMCP 安装程序会连接其已配置的服务。使用 [KillerMCP](../mcp.html) 的 AI 客户端可能会收到它所请求的参考结果。

原始日志、导入的文件和导出的证据可能包含计算机名称、账户、路径或敏感的源文本。共享前请先检查，并且绝不要在公开报告中包含恢复密钥、凭据或客户数据。

## 开发状态

KillerBench 正在开发中，目前还没有公开下载。修复范围仍在扩展，实机修复验证仍在进行中。生成成功或模拟检查并不能证明实机修复的行为。我们使用一次性 Windows 虚拟机，在不同的 Windows 版本和故障状态下验证每项原生更改。完整的安全模型请参阅 [如何保证更改安全](safety.html)。

## 术语表

本页所用术语的通俗解释，按拼音顺序排列。

| 术语 | 含义 |
| --- | --- |
| BITS | Background Intelligent Transfer Service，在后台下载更新和其他文件的 Windows 服务。 |
| CBS | Component-Based Servicing，安装更新和功能的 Windows 子系统。其日志为 `CBS.log`。 |
| DISM | Deployment Image Servicing and Management，检查和修复组件存储的 Windows 工具。 |
| Panther | Windows Setup 写入升级日志的文件夹。 |
| SFC | System File Checker，验证和还原受保护系统文件的 Windows 工具。 |
| TPM | Trusted Platform Module，BitLocker 用来保护驱动器密钥的安全芯片。 |
| 捕获 | 包含保留证据的已保存 `.kbench` 文件，无需原始计算机即可再次查看。 |
| 策略所有者 | 控制某项设置的组策略或设备管理。KillerBench 不会更改有所有者的设置。 |
| 待处理保护标记 | 将某项更改标记为可能已发送到 Windows 的记录。在核对读取结果之前，它会阻止重复执行。 |
| 方案 | 具有自己的适用条件、执行、验证和恢复规则的类型化修复。 |
| 工作流程 | 一个工具的一次运行：它收集的检查、它可能使用的方案以及它生成的报告。 |
| 核对 | 在中断后读取新状态以了解发生了什么，而不重复更改。 |
| 日志 | 在更改前写入、在更改后更新的本地 JSON 记录，以便之后查看中断的操作。 |
| 失效关闭 | 当证据不明确、缺失或过大时，结果为未知，并且不允许任何更改。 |
