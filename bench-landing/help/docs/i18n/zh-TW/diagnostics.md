# 診斷

每次處理都應從診斷開始。每個工具都會讀取電腦並產生報告。這裡的任何操作都不會變更 Windows。預設工具「完整系統掃描」會執行一系列廣泛的唯讀檢查，並按重要性排列需要注意的問題。

操作指南：[調查當機和藍色畫面](investigate-crashes.html) 和 [修復系統檔案](repair-system-files.html)。

## 本區段的工具

先檢查電腦，然後在報告中檢視需要注意的問題和安全的下一步。

### 完整系統掃描

檢查 49 個診斷區域，並根據目前證據評估已安裝的修復方案。檢查可能需要幾分鐘。完整系統掃描僅用於診斷。請使用專門的修復工作流程，在檢視最新的必要條件後選擇並確認一項支援的操作。歷史、備份和傳輸快照保持唯讀。不會開啟傾印內容。中途位元檢查不會排定修復或重新啟動。此掃描不會安裝更新、變更驅動程式、刪除檔案或執行完整的硬體測試。

### 關鍵指標

擷取可用記憶體、提供者報告的磁碟執行狀況和 BitLocker 保護狀態，然後將目前指標與裝置問題、可靠性歷史記錄、硬體錯誤記錄、當機證據、意外關機和 Windows 記憶體診斷結果進行關聯。重新啟動指示、系統磁碟可用空間、權限提高和更新服務設定仍會顯示。不會收集修復密碼。此工作流程不執行任何修復。綜合結果並不是完整的硬體、軟體或穩定性測試。

### 可靠性歷史記錄

讀取過去 14 天的 Windows 可靠性監視器記錄以及最近的 Application 錯誤和意外關機事件，然後傳回一個有範圍限制的歷史結論。歷史記錄不能確定目前執行狀況或根本原因。不會選擇任何修復，也不會變更任何應用程式、服務或設定。

### 啟動效能

讀取過去 14 天的 Windows 啟動和關機效能事件中繼資料，僅保留提供者識別和有範圍限制的數值持續時間欄位，然後將其與受支援的待處理重新啟動指示進行關聯。在儲存證據之前，會刪除路徑、處理程序名稱、帳戶和其他事件負載。歷史效能下降記錄不能識別目前的瓶頸，也不能授權變更啟動、服務、應用程式、驅動程式、工作、電源、重新啟動或原則。

### 硬體錯誤歷史記錄

讀取過去 14 天的 Windows 硬體錯誤架構和記憶體診斷歷史記錄、目前的即插即用裝置問題、實體磁碟執行狀況以及提供者的可靠性計數器，然後傳回一個有範圍限制的硬體結論。這些記錄需要與其負載、韌體診斷和供應商硬體測試進行關聯。不會推斷故障元件或根本原因，不會選擇任何修復，也不會變更任何硬體、韌體、驅動程式、磁碟、池、磁碟區、檔案、服務、電源、重新啟動或設定。

### 驅動程式安裝歷史記錄

讀取 Windows SetupAPI 裝置安裝歷史記錄中保留的末尾部分，將失敗的部分與目前確切的即插即用識別進行關聯，並傳回一個有範圍限制的結論。歷史記錄部分不能證明裝置仍然存在或故障仍在發生。不會安裝、刪除、復原或更新任何驅動程式。

### 系統還原點

列出最多 256 個可用的系統還原點，檢視明確的建立條件，並傳回一個有範圍限制的就緒結論。該列表不能證明每個磁碟區都已啟用保護，也不能證明還原會成功。診斷期間不會建立、刪除或應用任何還原點。

### Windows 修復環境

使用 REAgentC 讀取目前的 Windows 修復環境設定，將已啟用的本機位置與目前確切的磁碟和磁碟分割進行關聯，並傳回一個有範圍限制的就緒結論。選用的自動修復可以啟用已停用的現有設定，然後驗證其報告的狀態。不會下載、移動或替換修復映像，不會啟動修復開機，也不會重新啟動 Windows。已啟用狀態和磁碟分割存在並不能證明修復映像能夠啟動或修復此電腦。

### Windows 啟用

在不收集完整或部分產品金鑰的情況下讀取目前 Windows 授權狀態，保留過去七天經過清理的軟體保護警告、錯誤和嚴重事件中繼資料，然後傳回一個有範圍限制的執行結論。在儲存證據之前，會刪除事件負載。目前許可狀態報告為 Licensed 時，歷史記錄僅作為背景資訊。不會選擇任何啟用、產品金鑰、權杖、授權、帳戶、服務或原則操作。提供者狀態和事件歷史不能證明訂閱權利、啟用伺服器可存取性、權杖儲存完整性、未來有效性或根本原因。

### Windows 服務

在不收集帳戶、可執行檔案路徑、復原命令或重新啟動訊息的情況下，清點已安裝服務的名稱、顯示名稱、狀態、啟動模式以及有隱私範圍限制的復原操作類型。檢視啟動模式的一致性、直接相依性的識別和迴圈，重複檢查確切的待處理狀態，檢查受支援的服務和已停止服務的相依性，然後僅在存在一個確切的服務名稱或唯一的顯示名稱時，才關聯最近的服務控制管理員故障。載入順序組的使用會在不展開成員的情況下計數，不明確的識別仍保持未解析狀態。已停止的按需啟動服務可能是正常的。不會啟動任何服務，啟動、相依性和復原設定保持不變。當特定功能需要復原時，請使用相應的修復工作流程。

### 應用程式故障

讀取最近的 Application 錯誤和嚴重事件以及有範圍限制的可靠性監視器歷史記錄，然後傳回一個穩定性歷史結論。歷史記錄不能證明目前故障或根本原因，只能引導更有針對性的診斷。不會停止、修復、刪除或重新設定任何應用程式。

### 顯示裝置

檢查圖形介面卡和顯示器報告的裝置錯誤、硬體 ID 和已安裝的驅動程式版本。不安裝驅動程式、不重設裝置、不變更解析度。不測試畫質和實體連線。

### 輸入裝置

檢查鍵盤、滑鼠和 HID 裝置的錯誤以及驅動程式清單。不擷取按鍵、不重設裝置、不變更驅動程式。不測試實體輸入操作。

### 裝置問題

在所有裝置類別中查詢非零的即插即用設定錯誤碼，然後將存在的裝置證據與有範圍限制的 SetupAPI 驅動程式安裝、裝置設定和即插即用歷史記錄進行關聯。僅憑歷史記錄不能確定目前故障。請在不變更硬體、驅動程式或設定的情況下，檢視確切的裝置識別和已核准的驅動程式證據。不驗證缺失的裝置和實體操作。
