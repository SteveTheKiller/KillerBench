# 報告和證據

每次執行都會產生一份可以閱讀、篩選和匯出的報告。報告始終將已證明的內容與僅觀察到的內容區分開來。

## 你會看到的狀態

| 狀態 | 含義 |
| --- | --- |
| 需要審閱 | 證據支援一個值得關注的問題。 |
| 資訊 | 已收集證據並作為背景資訊顯示。 |
| 未完成或未知 | 檢查未能完成，或證據不可用。永遠不會被視為正常。 |
| 歷史 | 過去的事件。它可以解釋歷史，但不能證明目前存在故障。 |
| 已驗證 | 透過讀回結果確認了修復或更改。 |

## 原始輸出和可讀報告

**原始輸出** 會保留技術證據及其原始行號，因此可以將任何結論追溯到其來源。**可讀報告** 用通俗的語言總結同一次執行，並將安全的下一步放在最前面。

## 已儲存的記錄

KillerBench 還可以讀取已儲存的 Windows 記錄（例如 CBS 和 Setup 記錄），而無需在電腦上執行任何內容。結論會連結到產生它的確切行。工作階段來源中的 **載入範例** 會開啟一個可以安全探索的合成示例。

## 匯出

**匯出報告** 會將報告連同其來源路徑、已解析的項目和證據摘錄一起儲存，便於在附加到工單之前進行檢查。原始記錄和證據摘錄可能包含電腦名稱、帳戶、路徑或敏感的源文字。受保護的收集器會限制其保留的內容，但匯入的證據不保證已經過脫敏處理。共享前請檢查並刪除敏感資訊。
