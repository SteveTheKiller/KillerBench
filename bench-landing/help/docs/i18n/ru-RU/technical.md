# Технологии KillerBench

Взгляд под капот: как KillerBench читает компьютер с Windows, сохраняет честность доказательств и решает, когда изменение допустимо.

## Технологический стек

KillerBench представляет собой нативное приложение Windows. Настольное приложение, командная строка и лежащий в их основе Engine используют одни и те же диагностические доказательства и процедуры исправления.

| Компонент | Подробности |
| --- | --- |
| Интерфейс | WPF на .NET 10 (`net10.0-windows`), Windows x64, собственная рамка окна |
| Engine | `Engine.Core`, `Engine` и `Engine.Windows`, без ссылок на WPF или элементы управления настольного приложения |
| Командная строка | `killerbench-cli`, отдельный хост на том же Engine |
| Поставщики Windows | .NET, API Windows, PowerShell и средства командной строки Windows; каждый работает в фиксированных пределах времени, числа записей и размера |
| Отчёты | Необработанный вывод, Читаемый отчёт, HTML, текст и JSON |
| Справочные данные | Версионированные пакеты знаний с кодами ошибок, идентификаторами оборудования, производителями и ссылками на поддержку |
| Упаковка | Установщик: зависит от платформы, требует .NET Desktop Runtime 10 for Windows x64. Переносная версия: автономная, без установки среды выполнения |
| Внешний вид | 13 тем семейства и 20 языков |

## Установка, папки и данные

KillerBench поставляется в двух видах. Установщик служит стандартной загрузкой и поддерживает установку для одного пользователя или для всех пользователей. Переносная версия содержит собственную среду выполнения .NET и работает без установки.

KillerBench работает с правами учётной записи, которая его запустила. Он не повышает свои права сам. Запустите его через **Запуск от имени администратора**, когда защищённые доказательства, например предохранители BitLocker, или исправление требуют прав администратора. Повышение прав никогда не выбирает и не одобряет исправление.

### Что делает установщик

Установщик проверяет и распаковывает приложение в `%LOCALAPPDATA%\Programs\KillerBench\` или, после запроса на повышение прав для всех пользователей, в `%ProgramFiles%\KillerBench\`. Он добавляет ярлык в меню «Пуск», необязательный ярлык на рабочем столе и запись в списке установки и удаления программ с обычным и тихим удалением. Переносная версия проверяет и распаковывает своё содержимое в `%LOCALAPPDATA%\KillerBench\Portable\` на время текущего запуска и при следующем запуске убирает оставленные копии.

### Где что хранится

| Расположение | Содержимое |
| --- | --- |
| `%LOCALAPPDATA%\KillerBench\appearance.json` | Тема, цвет акцента, масштаб интерфейса и язык |
| `%LOCALAPPDATA%\KillerBench\Workflows\` | Один журнал JSON на каждый запуск процедуры: решения, ограниченный вывод команд и результаты исправлений |
| `%LOCALAPPDATA%\KillerBench\Repairs\` | Журналы выполнения исправлений обслуживания, например DISM и SFC |
| Папки функций в `%LOCALAPPDATA%\KillerBench\` | Ожидающие записи и результаты отдельных защищённых действий, например `BitLockerBackup`, `Time`, `Firewall` и `Profiles` |
| `%LOCALAPPDATA%\KillerBench\agent-repairs.json` | Уровень исправлений KillerMCP, выбранный в разделе «О программе» |
| `HKCU` или `HKLM\Software\KillerBench` | Путь установки для соответствующей области установки |
| Выбранный вами файл `.kbench` | Сохранённый захват с сохранёнными доказательствами |

Журналы остаются на этом компьютере, и KillerBench их не отправляет. Удаляйте журнал только тогда, когда доказательства по неясному результату вам больше не нужны.

## Сначала диагностика

KillerBench разделяет диагностику и изменение как разные задачи. Диагностика только читает. Изменение происходит только тогда, когда вы выбираете конкретное исправление или действие, изучаете его параметры и предварительные условия и подтверждаете его.

Полная проверка системы предназначена только для диагностики, даже если в какой-либо целевой процедуре включено автоматическое исправление. Сохранённые захваты, импортированные журналы и исторические события никогда не дают права на исправление.

### Ограниченный сбор

Каждая нативная команда и каждый поставщик Windows работают в фиксированных пределах времени, числа записей и размера. Поставщик записывает код завершения, тайм-аут, усечение, стандартный вывод и вывод ошибок. Сбой или усечённый вывод поставщика никогда не может быть прочитан как чистый пустой ответ.

### Минимальное хранение

Сборщики сохраняют то, что нужно для результата. Многие результаты сохраняют имена, категории, количества, состояния и отметки времени, исключая учётные данные, командные строки, полные пути, идентификаторы учётных записей, сетевые конечные точки и посторонние данные событий.

## Доказательства, которые можно проследить

Каждый результат привязан к доказательствам, из которых он получен, а отчёт всегда отделяет доказанное от того, что было только замечено.

| Состояние | Значение |
| --- | --- |
| Требуют проверки | Доказательства указывают на проблему, заслуживающую внимания. |
| Сведения | Доказательства собраны и показаны для контекста. |
| Не завершено или Неизвестно | Проверка не смогла завершиться или доказательства были недоступны. Это никогда не считается исправным состоянием. |
| Исторические | Событие из прошлого. Оно объясняет историю, но не доказывает текущую неисправность. |
| Подтверждено | Исправление или изменение подтверждено повторным чтением результата. |

### «Неизвестно» тоже результат

«Неизвестно» означает, что доступ запрещён, источник отсутствует, поставщик дал сбой, вывод повреждён, превышен предел или доказательства противоречат друг другу. KillerBench показывает это ограничение и следующий полезный шаг, а не скрывает его.

### История остаётся историей

Записи событий и импортированные журналы описывают то, что было записано в прошлом. Они могут указать на код ошибки или следующую область диагностики. Они не доказывают, что неисправность всё ещё существует.

## Защищённые исправления

Исправления представляют собой типизированные операции с правилами применимости, выполнения, проверки и восстановления. Это не командные строки, выхваченные из строки журнала. Каждое поддерживаемое исправление проходит одну и ту же последовательность:

1. Собрать полные текущие доказательства.
2. Сопоставить один поддерживаемый рецепт.
3. Изучить обязательные параметры и последствия.
4. Подтвердить административные предварительные условия и условия политики.
5. Повторно собрать решающие доказательства непосредственно перед изменением.
6. Записать надёжную запись о подготовке.
7. Выполнить одно ограниченное нативное действие.
8. Собрать свежие доказательства для проверки.
9. Записать результат: подтверждено, заблокировано, остановлено или неясно.

Если решающие доказательства изменятся до выполнения действия, KillerBench остановится, не выполнив его.

### Явный выбор

Исправлениям, которые зависят от параметра, нужен ваш точный выбор, например том, очередь принтера, место сохранения ключа восстановления, значение питания, версия пакета или источник исправления. KillerBench никогда не придумывает эти значения.

### Управляемые компьютеры

Групповая политика и система управления устройствами могут сделать локальное изменение неэффективным или неуместным. Поддерживаемые исправления проверяют, кто владеет параметром, и останавливаются, если владение управляемое или неизвестное. Параметры, которыми владеет политика, остаются без изменений.

### Автоматическое исправление

Автоматическое исправление лишь позволяет продолжить работу применимым рецептам. Оно не обходит доказательства, не выбирает недостающие параметры, не игнорирует политику, не повторяет неясное действие, не перезагружает Windows и не превращает результат, требующий проверки, в исправление.

## Журналы и прерывания

Прежде чем попросить Windows внести изменение, KillerBench записывает, что собирается сделать. Каждое изменение сохраняется в журнале в `%LOCALAPPDATA%\KillerBench`.

После изменения KillerBench считывает результат и сообщает **Подтверждено** только тогда, когда Windows показывает ожидаемое состояние. Если Windows сообщает об успехе, но состояние не изменилось, результат говорит об этом и ничего не повторяется.

Процесс может остановиться после того, как Windows получила запрос, но до завершения проверки. Ожидающая запись остаётся, а последующее согласование считывает свежее состояние, чтобы выяснить, что произошло. Согласование не является автоматическим откатом и никогда не повторяет исходное изменение. Если результат неясен, сохраните журнал.

## Чего он не делает

- Не очищает TPM, не удаляет предохранители, которые не создавал, и не показывает пароли восстановления.
- Не изменяет параметр, которым управляет групповая политика или система управления устройствами.
- Не запускает исправление только потому, что историческое событие или импортированный отчёт упоминает проблему.
- Не превращает отсутствующие, неполные или неудачные доказательства в заключение об исправном состоянии.

## Отчёты

Каждый запуск создаёт отчёт, который можно читать, фильтровать и экспортировать. Отчёт разделяет:

1. Что было проверено
2. Какая проблема найдена
3. Какие доказательства подтверждают результат
4. Какое действие предложено или выполнено
5. Как проверен результат
6. Что остаётся неизвестным или требует перезагрузки

**Необработанный вывод** сохраняет технические доказательства с исходными номерами строк, чтобы любой результат можно было проследить до источника. **Читаемый отчёт** излагает тот же запуск простым языком и начинает со следующего безопасного шага. Отчёты HTML используют систему тем Killer Tools и остаются читаемыми без приложения. Текст удобен для переносимости, а JSON сохраняет структурированные поля для другой программы.

## Сохранённые журналы и захваты

KillerBench может исследовать доказательства, ничего не запуская на компьютере. Перетащите текстовый журнал в окно или вставьте его путь и выберите **Открыть журнал**. Строки CBS, CSI и Setup разбираются вместе с отметками времени, а результаты ссылаются на точную исходную строку. Файлы EVTX и XML событий можно импортировать тем же способом.

**Проверить Windows Update** выполняет по запросу сбор только для чтения: журналы CBS, DISM, Panther и журналы отката Setup, каналы событий обновления и обслуживания, состояния служб обновления, свободное место, время работы, признаки ожидающей перезагрузки и выбранную политику обновлений. **Сохранить захват** записывает сохранённые доказательства в файл `.kbench`. **Открыть захват** снова открывает его без исходных файлов и заново оценивает установленными правилами, поэтому одни и те же правила дают одни и те же результаты.

## Демонстрационный режим

Запустите `KillerBench.exe --demo`, чтобы опробовать **Запустить диагностику** на вымышленной рабочей станции. Каждая процедура создаёт синтетические доказательства и имитирует ход выполнения. Поставщики Windows не вызываются, команды исправления не запускаются, журналы не записываются. Отдельные кнопки инструментов вне **Запустить диагностику** остаются рабочими, поэтому не используйте их как демонстрационные действия.

`KillerBench.exe --demo-screenshot` открывает отчёт полной проверки системы только для просмотра по фиксированному вымышленному компьютеру. Щелчки в рабочей области, сочетания клавиш и перетаскивание файлов заблокированы.

## Пакеты знаний

Объёмные и часто обновляемые справочные данные хранятся в пакетах знаний, а не в логике диагностики: коды ошибок Windows и Setup, идентификаторы производителей и устройств, справочники PCI, USB, ACPI и UEFI, данные о производителях сетевых OUI, расположения драйверов и поддержки и отобранные ссылки на поддержку.

Каждый пакет указывает свой формат, версию схемы, источник, ревизию источника, время создания и хеш содержимого, а KillerBench проверяет их перед использованием. Неизвестный или недопустимый пакет остаётся недоступным, а не заменяется догадкой. Обновление загружается во временное расположение, проверяется и затем одним шагом заменяет активный пакет, поэтому неудачное обновление оставляет прежний пакет на месте.

Данные знаний могут объяснить идентификатор или подсказать, где искать дальше. Они не могут превратить исторический код в текущую неисправность, автоматически выбрать драйвер или дать право на исправление.

## Обновления и подпись

При запуске KillerBench запрашивает у GitHub последний стабильный выпуск с ограничением в четыре секунды и предлагает обновление, только если этот выпуск новее. Проверку можно отключить параметром **Проверять обновления при запуске** в разделе «О программе» или в запросе на обновление. Загружается пакет, соответствующий запущенной копии, установщик или переносная версия, и его SHA-256 должен совпадать с файлом `SHA256SUMS.txt` выпуска, прежде чем что-либо будет установлено. Для завершения приложение закрывается и открывается снова. Фоновой службы нет.

Карточка «О программе» показывает версию, издателя и отпечаток сертификата подписи кода, а также SHA-256 запущенного исполняемого файла, чтобы вы могли проверить свою копию.

## KillerMCP

KillerBench не содержит ИИ-агента. [KillerMCP](../mcp.html) может подключить агента к тому же Engine. **Параметры KillerMCP** в разделе «О программе» определяют, что этому агенту разрешено:

| Параметр | Действие |
| --- | --- |
| Выключено (по умолчанию) | Агент не может запросить исправление. |
| Разрешить KillerMCP выполнять безопасные исправления | Агент может запрашивать исправления, классифицированные как безопасные. |
| Разрешить и исправления, прерывающие работу | Становятся доступными исправления, прерывающие работу, и каждое из них по-прежнему требует одобрения. |

Повысить уровень может только человек за этим компьютером. После неясного результата исправления KillerMCP записывает блокировку, и исправления агента остаются заблокированными, пока кто-нибудь не снимет её в разделе «О программе».

## Локализация

Интерфейс доступен на 20 языках: английском, бенгальском, чешском, немецком, испанском, французском, венгерском, итальянском, японском, казахском, норвежском, польском, португальском (Бразилия), русском, словенском, турецком, украинском, вьетнамском, а также упрощённом и традиционном китайском. Смена языка применяется сразу, включая названия разделов и процедур, приветственный текст и открытый читаемый отчёт. Отсутствующий текст отображается на английском.

Доказательства, результаты Engine, журналы и необработанный вывод остаются на английском, как и журнал Windows, поэтому отчёт одинаково читается на любом компьютере и по нему можно искать точный текст.

## Командная строка и коды завершения

`killerbench-cli` запускает тот же Engine без настольного приложения. Ход выполнения выводится в стандартный поток ошибок, а JSON в стандартный вывод. Большинство команд по умолчанию выполняют предпросмотр, а изменение требует `--execute`. Соответствующие команды `-recover` проверяют прерванное действие, не повторяя его. См. [Запуск KillerBench из скриптов](use-the-cli.html) и [справочник команд](cli.html).

| Код завершения | Команды процедур | Проверка и открытие |
| --- | --- | --- |
| 0 | В проверенных областях нет нерешённых проблем | Полный охват |
| 1 | Ошибка запуска или журнала | Сбой |
| 2 | Недопустимые аргументы | Недопустимые аргументы |
| 3 | Требуется внимание | Частичный сбор |

## Архитектура

Engine разделён на три проекта без пользовательского интерфейса. `Engine.Core` предоставляет примитивы и декларативные рецепты, `Engine` отвечает за общие процедуры и доказательства, а `Engine.Windows` регистрирует нативных поставщиков. Настольное приложение, CLI и тесты являются отдельными хостами.

| Уровень | Ответственность |
| --- | --- |
| Сборщики возможностей | Читают ограниченное состояние Windows для одной точной области |
| Анализаторы доказательств | Проверяют форму, подлинность, полноту и пределы |
| Диагностическая интерпретация | Преобразует доказательства в явные состояния процедур |
| Оркестрация процедур | Объединяет проверки, ход выполнения, рецепты и журналы |
| Координаторы исправлений | Повторно проверяют применимость, готовят, изменяют, проверяют и согласуют |
| Отчёты | Представляют проблемы, действия, результаты и ограничения |
| Пакеты знаний | Разрешают версионированные справочные данные без изменения логики |

Сборщики блокируют работу, когда идентификатор неоднозначен, вывод повреждён, превышен предел или невозможно проверить нужные полномочия. Сейчас Engine ориентирован на Windows и не является кроссплатформенным. [Руководство разработчика Engine](../engine/index.html) описывает API, CLI и встраивание Engine в другой хост .NET.

## Конфиденциальность и сеть

Диагностика и анализ журналов выполняются локально, без службы ИИ и без учётной записи KillerBench. Журналы и сохранённые доказательства остаются в папках `%LOCALAPPDATA%\KillerBench` локальной учётной записи.

Выбранные вами действия могут обращаться к своему адресу назначения, например к Windows Update, службам загрузки программ или к сохранению ключа восстановления в Active Directory или Entra ID. Проверка обновлений при запуске обращается к GitHub, а обновления базы знаний и установщик KillerMCP обращаются к своим настроенным службам. Клиент ИИ, использующий [KillerMCP](../mcp.html), может получить запрошенный справочный результат.

Необработанные журналы, импортированные файлы и экспортированные доказательства могут содержать имена компьютеров, учётные записи, пути или конфиденциальный исходный текст. Проверяйте их перед передачей и никогда не включайте ключи восстановления, учётные данные или данные клиентов в общедоступный отчёт.

## Состояние разработки

KillerBench находится в разработке, и общедоступной загрузки пока нет. Охват исправлений ещё расширяется, а нативная проверка исправлений продолжается. Успешная сборка или имитационная проверка не подтверждают нативное поведение исправлений. Для проверки каждого нативного изменения на разных версиях Windows и в разных состояниях сбоя используются одноразовые виртуальные машины Windows. Полная модель безопасности описана на странице [Как изменения остаются безопасными](safety.html).

## Глоссарий

Простые определения терминов, используемых на этой странице, в алфавитном порядке.

| Термин | Значение |
| --- | --- |
| BITS | Фоновая интеллектуальная служба передачи, служба Windows, которая загружает обновления и другие файлы в фоновом режиме. |
| CBS | Component-Based Servicing, подсистема Windows, устанавливающая обновления и компоненты. Её журнал: `CBS.log`. |
| DISM | Deployment Image Servicing and Management, средство Windows, которое проверяет и исправляет хранилище компонентов. |
| Panther | Папка, в которую программа установки Windows записывает журналы обновления. |
| SFC | System File Checker, средство Windows, которое проверяет и восстанавливает защищённые системные файлы. |
| TPM | Trusted Platform Module, микросхема безопасности, которую BitLocker использует для защиты ключа диска. |
| Блокировка при неопределённости | Когда доказательства неоднозначны, отсутствуют или слишком велики, результатом будет «Неизвестно», и никакие изменения не допускаются. |
| Владелец политики | Групповая политика или система управления устройствами, которая управляет параметром. KillerBench не трогает такие параметры. |
| Доказательства | То, что KillerBench фактически прочитал из Windows, сохранённое вместе с источником, чтобы результат можно было проследить. |
| Журнал | Локальная запись JSON, создаваемая перед изменением и обновляемая после него, чтобы прерванное действие можно было позже изучить. |
| Захват | Сохранённый файл `.kbench` с сохранёнными доказательствами, который можно снова изучить без исходного компьютера. |
| Ожидающая запись | Запись, отмечающая, что изменение могло быть отправлено в Windows. Она блокирует повтор, пока согласование не прочитает результат. |
| Пакет знаний | Версионированный проверенный файл справочных данных, например кодов ошибок или идентификаторов оборудования. |
| Повышение прав | Работа с правами администратора после запроса Windows. KillerBench никогда не повышает свои права сам. |
| Подтверждено | Результат прочитан из Windows и совпал с тем, чего должно было добиться изменение. |
| Процедура | Один запуск инструмента: собираемые проверки, рецепты, которые он может использовать, и создаваемый отчёт. |
| Рецепт | Типизированное исправление с собственными правилами применимости, выполнения, проверки и восстановления. |
| Согласование | Чтение свежего состояния после прерывания, чтобы узнать, что произошло, без повтора изменения. |
