# Исправление Windows Update

Используйте этот порядок, когда обновления завершаются ошибкой, зависают или устанавливаются снова и снова. KillerBench сначала читает цепочку обновлений, объясняет сбой вместе с доказательствами и запускает службу или исправляет хранилище компонентов только тогда, когда свежие доказательства подтверждают именно эту проблему.

## Перед началом

- Запустите KillerBench от имени администратора. Для полных доказательств службам обновления, хранилищу компонентов и защищённым системным файлам нужны повышенные права.
- Если Windows уже ожидает перезагрузки, сначала перезагрузите компьютер. Многие исправления обновлений заблокированы, пока состояние перезагрузки не станет чистым.
- Во время обслуживания держите компьютер подключённым к сети питания.

## Выясните, почему обновления не устанавливаются

1. Откройте **Обновления** и выберите **Windows Update** на боковой панели инструментов.
2. При первом проходе оставьте **Автоматически исправлять подтверждённые проблемы** выключенным и нажмите **Запустить диагностику**.
3. Прочитайте **Читаемый отчёт**. В нём перечислены остановленные службы обновления, ожидающие перезагрузки, нехватка свободного места, повреждение хранилища компонентов и точные коды ошибок, записанные Windows, вместе с рекомендуемым следующим шагом.
4. Если в отчёте указан код ошибки, соответствующие дополнительные проверки запускаются автоматически. Код можно найти и самостоятельно командой `killerbench-cli update-code 0x80070002`.

## Наблюдение за обновлением, которое кажется зависшим

В разделе **Обновления** выберите **Монитор активности обслуживания** и нажмите **Запустить диагностику**. Он делает повторяющиеся снимки активности обновлений, Setup и установщика, итогов передачи и признаков перезагрузки. Активность показывается только как доказательство; сама по себе она никогда не утверждает о зависании или неисправности.

## Исправление найденного в отчёте

1. Снова запустите **Windows Update** с включённым параметром **Автоматически исправлять подтверждённые проблемы**. Он может запустить включённые службы обновления, остановка которых подтверждена, а DISM или SFC запускает только тогда, когда живая проверка подтверждает повреждение.
2. Для отдельной службы выберите вместо этого её целевой инструмент, например **Служба BITS**, **Службы криптографии**, **Установщик модулей Windows** или **Служба Update Orchestrator**. Каждый из них предлагает восстановление только для своей службы.
3. Если отчёт требует перезагрузки, перезагрузите компьютер, прежде чем запускать что-либо ещё. KillerBench записывает результаты, требующие перезагрузки, и откладывает дальнейшую работу до её выполнения.

Каждое исправление записывается в журнал и считывается повторно. Полная последовательность описана на странице [Как изменения остаются безопасными](safety.html).

## Установка конкретного обновления

1. В разделе **Обновления** выберите **Доступные обновления** и нажмите **Запустить диагностику**, чтобы найти обновления в настроенном источнике.
2. Выберите нужные обновления и нажмите **Предварительный просмотр выбранных**. Предпросмотр точно показывает, что будет установлено, и есть ли требование перезагрузки.
3. Устанавливайте только после прочтения предпросмотра. KillerBench никогда не выбирает и не одобряет обновление за вас.

## Из командной строки

```powershell
killerbench-cli update-search
killerbench-cli update-history
killerbench-cli servicing-monitor --samples 10
killerbench-cli update-plan --select GUID:REVISION --execute
```

См. [update-search](cli.html#cmd-update-search), [update-history](cli.html#cmd-update-history), [servicing-monitor](cli.html#cmd-servicing-monitor) и [update-plan](cli.html#cmd-update-plan). Если установка была прервана, выполните [update-recover](cli.html#cmd-update-recover); команда проверяет результат и никогда не повторяет обновление.
