Comece aqui

O KillerBench é uma bancada de diagnóstico e reparo do Windows para técnicos. Ele verifica o computador primeiro, explica o que encontrou com as evidências de cada constatação e só altera o Windows quando você escolhe uma correção específica e a confirma.

O KillerBench está em desenvolvimento. Ainda não há download público. Estas páginas descrevem a compilação atual.

O que ele faz

  • Executa diagnósticos somente leitura no Windows Update, em dispositivos, armazenamento, rede, impressão, segurança, aplicativos e perfis, e depois gera um relatório legível.
  • Oferece reparos protegidos que só são executados quando evidências atuais comprovam o problema exato, e verifica o resultado em seguida.
  • Abrange tarefas de configuração e proteção como BitLocker, configurações de privacidade, organização do Windows e implantação de um computador novo.
  • Executa diagnósticos e análise de relatórios localmente, sem IA e sem conta do KillerBench. Algumas ações selecionadas, como downloads e o backup da chave de recuperação no Entra ID, podem contatar serviços externos.
  • Usa o tema ativo do aplicativo no console, nos relatórios, nas confirmações e nas caixas de diálogo Abrir, Salvar e Pasta.

Windows e runtime

  • O destino de publicação atual é Windows x64. O Windows 11 x64 é a referência atual de validação nativa. Não há distribuições nativas para ARM64, x86 ou Windows Server.
  • O KillerBench é empacotado de duas formas. O instalador é dependente de framework e exige o .NET Desktop Runtime 10 para Windows x64. O .NET Runtime básico, o ASP.NET Core Runtime e o .NET Framework não fornecem o WPF. A edição portátil traz o próprio runtime e não precisa de instalação separada. A ferramenta de linha de comando killerbench-cli.exe precisa do .NET 10 Runtime para Windows x64. O SDK só é necessário para desenvolvimento, não para o uso normal.
  • Use uma versão do Windows compatível com o .NET 10 no Windows. A compatibilidade do runtime não significa que os reparos do KillerBench foram validados em todas as edições ou compilações compatíveis. A cobertura do Windows 10 continua pendente, e as edições compatíveis dependem dos requisitos atuais de ciclo de vida da Microsoft.
  • Obtenha o Desktop Runtime somente na página de download do .NET 10 da Microsoft, escolhendo .NET Desktop Runtime, Windows, x64. Siga as regras de instalação de software da sua organização.

Se o dotnet estiver disponível, dotnet --list-runtimes deve listar Microsoft.WindowsDesktop.App 10.0.x para a instalação x64. Um runtime instalado só para outra arquitetura não atende ao pacote de instalação x64.

Quando um pacote for publicado

  1. Use o download oficial vinculado a partir deste site. Ainda não há link de download do KillerBench ativo.
  2. Leia os requisitos do pacote, a licença GPLv3, as instruções do Código-fonte correspondente, os avisos de terceiros incluídos e as informações de assinatura e soma de verificação. Só o nome do arquivo não comprova a autenticidade.
  3. Execute o instalador para a conta atual, ou para todos os usuários após uma solicitação de elevação. Ele adiciona um atalho no menu Iniciar, um atalho opcional na área de trabalho e uma entrada em Adicionar ou remover programas. A edição portátil é executada sem instalação.
  4. Inicie o KillerBench com sua conta normal e siga Seu primeiro diagnóstico. As falhas de acesso do diagnóstico continuam visíveis; a elevação é uma escolha separada e deliberada.

Não ignore os avisos de segurança do Windows para executar uma cópia não verificada. Mantenha um backup atualizado antes de selecionar qualquer ação que altere o computador.

Ao iniciar, o KillerBench consulta o GitHub em busca de uma versão estável mais recente e pergunta antes de instalá-la. O download precisa corresponder à soma de verificação SHA-256 publicada. Desative a verificação com Verificar atualizações ao iniciar em Sobre.

Limites atuais

A compilação atual tem doze seções, diagnóstico somente leitura, relatórios e superfícies de reparo selecionadas individualmente. A validação nativa de reparos ainda está em andamento. Uma interface que funciona, uma compilação bem-sucedida ou o resultado de um fixture não comprovam o comportamento de um reparo em um computador real. Consulte Como as alterações continuam seguras.

O console ilustrativo da página inicial é uma saída sintética. As capturas de tela finais do aplicativo e o primeiro pacote público ainda estão pendentes.

Código-fonte, licença e suporte

O KillerBench é licenciado sob a GPLv3. As instruções de entrega do código-fonte e as permissões de fontes de terceiros continuam pendentes para o primeiro pacote público. Leia Sobre o KillerBench para saber sobre a disponibilidade do código-fonte, os avisos de distribuição, a privacidade das evidências e o suporte. O guia do Engine é para desenvolvedores com uma cópia autorizada do código-fonte; ele não indica que haja um pacote público do Engine.

Comece por Download e configuração e depois execute uma Verificação completa do sistema. Ela coleta evidências de diagnóstico e salva um diário local; não executa reparos. Uma constatação descreve o escopo inspecionado, não todas as falhas possíveis do computador.

Executar a verificação

  1. Abra o KillerBench. A seção Diagnósticos abre com Verificação completa do sistema selecionada.
  2. Deixe Reparar automaticamente os problemas confirmados desativado na primeira execução.
  3. Pressione Executar diagnóstico. O progresso aparece em Saída bruta, à direita, enquanto cada verificação é executada.
  4. Ao terminar, o painel de saída muda para o Relatório legível.

Comece sem elevação. Algumas evidências do Windows, como os protetores do BitLocker e os serviços protegidos, exigem direitos de administrador. Em uma conta padrão, essas verificações informam que a evidência não está disponível. Se precisar dela, termine a execução atual, guarde o relatório e reabra o KillerBench de propósito com Executar como administrador. A elevação não seleciona nem aprova nenhum reparo.

Ler o relatório

O relatório começa com as contagens de Para revisar, Reparos verificados, Incompletas e Verificadas, seguidas de uma próxima etapa recomendada.

  • O que precisa de atenção lista os problemas que as evidências sustentam, do mais importante para o menos.
  • Informações coletadas mostra o que foi lido, incluindo evidências incompletas ou indisponíveis.
  • Eventos históricos são marcados como histórico. Um erro do mês passado não é tratado como falha atual.

A falta de evidência nunca conta como integridade. Se uma verificação não pôde ser executada, o relatório informa isso.

Escolher as verificações

Abra Escolher verificações (avançado) para selecionar verificações individuais em vez da verificação completa. Cada seção do aplicativo também tem ferramentas específicas, descritas nas páginas de Seções deste guia.

Corrigir o que você encontrou

Quando o relatório recomenda uma correção, ele indica a seção e a ferramenta a abrir. Leia Como as alterações continuam seguras antes do seu primeiro reparo. A validação nativa ainda está em andamento; um diagnóstico bem-sucedido não comprova que cada reparo oferecido foi testado na sua compilação do Windows. Mantenha backups e revise o destino exato e as consequências antes de qualquer alteração.

A barra lateral à esquerda lista todas as ferramentas em doze seções: Diagnósticos, Reparo, Atualizações, Dispositivos, Rede, Aplicativos, Manutenção, Implantação, Segurança, BitLocker, Privacidade e Armazenamento. Arraste a borda para redimensioná-la, ou além da largura mínima para recolhê-la.

Opções da ferramenta

O painel central mostra a seção selecionada, a lista de ferramentas e as opções da ferramenta escolhida. As opções que poderiam alterar o computador estão sempre desativadas por padrão. Pressione Executar diagnóstico para iniciar a ferramenta. Quando Reparar automaticamente os problemas confirmados está ativado, o mesmo botão passa a mostrar Executar reparo. Parar encerra a execução depois que o comando atual termina.

Saída

O painel de saída à direita tem duas visualizações.

  • Saída bruta mostra as evidências técnicas à medida que são coletadas, com os números de linha originais. Ela abre sozinha enquanto uma ferramenta é executada.
  • Relatório legível mostra o relatório final da última execução. Ele substitui a saída bruta quando a execução termina.

Use a caixa de filtro da Saída bruta para mostrar apenas as linhas correspondentes. Exportar relatório salva o relatório com os caminhos de origem e os trechos de evidência. Fontes da sessão lista cada evidência reunida nesta sessão.

O KillerBench trata diagnóstico e alteração como tarefas diferentes. O diagnóstico apenas lê. A verificação completa do sistema nunca executa reparos. Selecione um reparo ou uma ação específica, revise as opções e os pré-requisitos e confirme a alteração proposta.

Antes de uma alteração

  1. Evidências atuais. A ferramenta lê o estado atual de novo. Um relatório salvo ou um evento antigo nunca autoriza uma alteração.
  2. Elegibilidade exata. A alteração só é oferecida quando as evidências correspondem ao problema exato que ela corrige. Qualquer dado incompleto a bloqueia.
  3. Sua confirmação. Revise a ação selecionada na caixa de confirmação. Algumas ações, como descriptografar uma unidade, exigem uma segunda confirmação. A caixa segue o tema ativo do aplicativo; a aparência não muda os requisitos da ação.
  4. Pré-requisitos. São verificados os direitos de administrador, o estado de reinicialização e o controle por política ou gerenciamento de dispositivos. Configurações controladas por política não são tocadas.
  5. Um registro pendente. O KillerBench anota o que vai fazer antes de pedir ao Windows.
  6. Uma verificação final. Tudo é verificado de novo logo antes da solicitação, então qualquer mudança nesse meio tempo a interrompe.

Depois de uma alteração

  • O KillerBench lê o resultado de volta e só informa Verificado quando o Windows mostra o estado esperado.
  • Se o Windows retornar sucesso mas o estado não tiver mudado, o resultado informa isso e nada é repetido.
  • Cada alteração é salva em um diário em %LOCALAPPDATA%\KillerBench.

Se algo for interrompido

As ações com diário compatíveis mantêm um registro pendente quando uma solicitação pode ter chegado ao Windows e a verificação não foi concluída. Use o caminho de reconciliação documentado da ação, ou o comando -recover correspondente, para inspecionar esse registro. A reconciliação não é uma reversão automática. Guarde o diário quando o resultado for incerto e não repita a alteração manualmente. O comportamento em falhas, cancelamentos e inicializações posteriores ainda precisa de validação nativa específica de cada ação.

O que o KillerBench não fará

  • Limpar um TPM, excluir protetores que ele não criou ou exibir senhas de recuperação.
  • Alterar uma configuração controlada pela política de grupo ou pelo gerenciamento de dispositivos.
  • Executar um reparo só porque um evento histórico ou um relatório importado menciona um problema.

Diagnósticos e análise de relatórios são executados localmente. Uma ação que você selecionar pode contatar um destino externo, como downloads de software ou o backup da chave de recuperação no Active Directory ou no Entra ID. Revise o destino antes de confirmar. Capturas salvas e evidências brutas podem conter a identidade do computador e caminhos de origem, então revise-as antes de compartilhar.

Status do desenvolvimento

A cobertura de reparos ainda está crescendo. Uma compilação bem-sucedida ou uma verificação simulada não comprova o comportamento nativo de um reparo. O arquivo VM-VALIDATION.md do repositório acompanha os cenários em máquinas Windows descartáveis e a validação restante.

Guias passo a passo

Use este guia quando as atualizações falham, travam ou continuam sendo reinstaladas. O KillerBench lê primeiro a cadeia de atualização, explica a falha com as evidências por trás dela e só inicia um serviço ou repara o repositório de componentes quando evidências atuais comprovam esse problema exato.

Antes de começar

  • Execute o KillerBench como administrador. Os serviços de atualização, o repositório de componentes e os arquivos protegidos do sistema exigem elevação para fornecer evidências completas.
  • Reinicie primeiro se o Windows já tiver uma reinicialização pendente. Muitos reparos de atualização ficam bloqueados enquanto houver reinicialização pendente.
  • Mantenha o computador ligado na tomada durante a manutenção.

Descobrir por que as atualizações falham

  1. Abra Atualizações e escolha Windows Update na barra lateral de ferramentas.
  2. Deixe Reparar automaticamente os problemas confirmados desativado na primeira passagem e pressione Executar diagnóstico.
  3. Leia o Relatório legível. Ele lista serviços de atualização parados, reinicializações pendentes, pouco espaço livre, corrupção no repositório de componentes e os códigos de erro exatos que o Windows registrou, com uma próxima etapa recomendada.
  4. Se o relatório citar um código de erro, as verificações complementares correspondentes são executadas automaticamente. Você também pode consultar um código com killerbench-cli update-code 0x80070002.

Acompanhar uma atualização que parece travada

Escolha Monitor de atividade de manutenção em Atualizações e pressione Executar diagnóstico. Ele tira instantâneos repetidos da atividade de atualização, do Setup e do Installer, dos totais de transferência e dos indicadores de reinicialização. A atividade é mostrada apenas como evidência; ela nunca afirma sozinha um travamento ou uma falha.

Reparar o que o relatório encontrou

  1. Execute Windows Update de novo com Reparar automaticamente os problemas confirmados ativado. Ele pode iniciar serviços de atualização habilitados que estejam comprovadamente parados, e só executa o DISM ou o SFC quando a verificação em tempo real confirma corrupção.
  2. Para um único serviço, escolha a ferramenta específica dele, como Serviço BITS, Serviços de Criptografia, Instalador de Módulos do Windows ou Serviço Update Orchestrator. Cada uma oferece recuperação só para aquele serviço exato.
  3. Quando o relatório pedir para reiniciar, reinicie antes de executar qualquer outra coisa. O KillerBench registra os resultados que exigem reinicialização e adia o trabalho seguinte até a reinicialização.

Cada reparo é registrado no diário e lido de volta. Consulte Como as alterações continuam seguras para ver a sequência completa.

Instalar uma atualização específica

  1. Escolha Atualizações disponíveis em Atualizações e pressione Executar diagnóstico para descobrir as atualizações da origem configurada.
  2. Selecione as atualizações desejadas e pressione Visualizar selecionadas. A visualização lista exatamente o que seria instalado e qualquer reinicialização necessária.
  3. Instale somente depois de ler a visualização. O KillerBench nunca seleciona nem aprova uma atualização por você.

Pela linha de comando

killerbench-cli update-search
killerbench-cli update-history
killerbench-cli servicing-monitor --samples 10
killerbench-cli update-plan --select GUID:REVISION --execute

Consulte update-search, update-history, servicing-monitor e update-plan. Se uma instalação foi interrompida, execute update-recover; ele verifica o resultado e nunca tenta a atualização de novo.

Use este guia quando componentes do Windows estão corrompidos: recursos não instalam, atualizações informam erros de componentes ou ferramentas do sistema falham. O KillerBench só executa o DISM e o SFC depois que uma verificação em tempo real confirma a corrupção, e depois verifica o resultado.

Antes de começar

  • Execute o KillerBench como administrador.
  • Resolva antes qualquer reinicialização pendente.
  • Se o computador for gerenciado, verifique se uma política direciona o DISM para uma origem de reparo específica. O KillerBench informa essa política e não a altera.

Procurar corrupção

  1. Abra Reparo e escolha Arquivos do sistema.
  2. Deixe Reparar automaticamente os problemas confirmados desativado e pressione Executar diagnóstico.
  3. Leia o relatório. Ele inventaria os estados dos pacotes de manutenção, dos recursos opcionais e das capacidades, verifica os pré-requisitos e examina os arquivos protegidos do sistema. Um resultado limpo significa que nenhum reparo é oferecido.

Reparar corrupção confirmada

  1. Ative Reparar automaticamente os problemas confirmados e pressione Executar reparo. O KillerBench escolhe o DISM ou o SFC só quando a verificação em tempo real confirma corrupção.
  2. Aguarde a verificação. O relatório só mostra Verificado quando a verificação seguinte lê um estado reparado.
  3. Se o relatório disser que o repositório não pode ser recuperado ou que a origem de reparo está indisponível, pare por aí. Repetir o reparo não muda o resultado.

Uma execução interrompida do DISM ou do SFC é reconciliada na próxima inicialização sem repetir o comando de manutenção.

Limpar o repositório de componentes

Escolha Limpeza do repositório de componentes em Atualizações. Primeiro ela pergunta ao Windows se a limpeza é recomendada. A manutenção opcional remove componentes substituídos e analisa de novo. Ela nunca usa ResetBase e nunca exclui conteúdo do WinSxS manualmente.

Pela linha de comando

killerbench-cli component-repair-source
killerbench-cli repair dism
killerbench-cli repair sfc --execute
killerbench-cli servicing-logs

Consulte component-repair-source, repair e servicing-logs. repair mostra uma visualização por padrão e só age com --execute.

Use este guia quando uma unidade estiver ficando sem espaço. O KillerBench mostra para onde o espaço está indo, visualiza o que cada destino de limpeza removeria e só exclui depois que você ativa a limpeza permanente.

Ver quanto espaço resta

  1. Abra Armazenamento e escolha Armazenamento.
  2. Pressione Executar diagnóstico. O relatório sinaliza cada volume com letra de unidade que tenha menos de 10% de espaço livre e mostra a alocação de cópias de sombra, as cotas padrão e a política do Sensor de Armazenamento.
  3. Para despejos de memória e conteúdo antigo de atualizações, execute também Sinais vitais em Diagnósticos e Windows Update em Atualizações; o tamanho do cache de atualizações aparece lá.

Visualizar uma limpeza

  1. Abra Manutenção e escolha Limpeza.
  2. Marque os destinos desejados, como Arquivos temporários do usuário atual, Arquivos temporários do Windows, Caches de navegador do usuário atual, Cache da Otimização de Entrega ou Lixeira do usuário atual. Passe o ponteiro sobre um destino para ver exatamente quais pastas ele abrange.
  3. Defina Idade mínima (dias) e Máximo de arquivos por alvo.
  4. Pressione Executar diagnóstico com Executar a limpeza permanente selecionada após novas verificações desativado. O relatório lista os candidatos e o espaço estimado de cada destino. Nada é excluído.

Remover os arquivos

  1. Ative Executar a limpeza permanente selecionada após novas verificações e pressione Executar diagnóstico.
  2. O KillerBench verifica cada candidato de novo antes de removê-lo, ignora arquivos recentes, protegidos ou em uso, e registra cada resultado no diário.

A limpeza permanente não passa pela Lixeira e não pode ser desfeita. Remover relatórios de erros e despejos de memória descarta evidências de que você pode precisar para investigar falhas, então revise-os primeiro.

Remover a instalação anterior do Windows

Depois de uma atualização de recursos, Instalação anterior do Windows em Limpeza pode remover a cópia de reversão pela solicitação compatível de remoção de reversão do Windows. Ela é executada sozinha, exige Fiz backup de todos os arquivos e configurações de que preciso da instalação anterior e remove de forma permanente a possibilidade de voltar à versão anterior.

Pela linha de comando

killerbench-cli volume-capacity C:
killerbench-cli cleanup --user-temp --windows-temp --days 7 --max-files 500
killerbench-cli cleanup --user-temp --windows-temp --days 7 --max-files 500 --execute

Consulte volume-capacity, cleanup e previous-windows.

  • Verificar e reparar uma unidade

Use este guia quando um volume informa erros, o Windows pede para verificar uma unidade ou arquivos não abrem. O KillerBench verifica primeiro o volume em modo somente leitura e só agenda ou executa um reparo do sistema de arquivos depois que você confirma que tem backup.

Antes de começar

  • Faça backup dos dados importantes do volume. Um reparo do sistema de arquivos pode alterar ou remover arquivos danificados.
  • Execute o KillerBench como administrador.

Verificar o volume

  1. Abra Armazenamento e escolha Armazenamento.
  2. Escolha a unidade em Volume a verificar e pressione Executar diagnóstico.
  3. Leia o relatório. Ele mostra a integridade do disco e do volume, o bit sujo, a autorrecuperação online do NTFS, erros de controladora e de dispositivos de disco, contadores de confiabilidade e eventos recentes de armazenamento, como redefinições, novas tentativas e remoções inesperadas.

Uma verificação limpa significa que nenhum reparo é oferecido. Temperatura do disco, desgaste e contadores de E/S não corrigidos são evidências para revisar e não disparam um reparo sozinhos.

Reparar o sistema de arquivos

  1. Pressione Revisar reparo do sistema de arquivos e escolha Reparo pontual ou Verificação e reparo offline.
  2. Em um volume de dados, marque Permitir que um volume que não seja do sistema fique offline se puder fechar tudo o que o usa. O volume do Windows não pode ficar offline, então o reparo dele é agendado para a próxima reinicialização.
  3. Marque Os dados importantes deste volume têm backup.

  5. Para um reparo agendado, reinicie quando for conveniente. O KillerBench verifica o resultado após a reinicialização sem executar o reparo de novo.

Use este guia quando um computador não tem internet, não consegue alcançar um servidor ou um nome, ou perde a conexão com frequência. Verificar a conexão

  1. Abra Rede e escolha Rede.
  2. Para testar algo específico, preencha Pesquisa de nome de host (opcional), ou Destino TCP (opcional) e Porta TCP. Deixe-os em branco para verificar só a configuração local. Nenhum dado de aplicativo é enviado.

  2. A conexão pode cair por um instante durante a renovação. Endereços estáticos e adaptadores virtuais nunca são alterados.
  3. Para um único nome em cache incorreto, use a limpeza do cache DNS para aquele host exato em vez de apagar tudo.

Rotas, entradas do Hosts, servidores DNS, regras do firewall, provedores Winsock e perfis de rede são sempre preservados.

  • Proxy automático do WinHTTP mostra as configurações de proxy salvas para o computador e para a conta atual. O KillerBench nunca baixa uma URL de PAC nem altera configurações de proxy durante o diagnóstico.

Use este guia para ativar o BitLocker, fazer backup da chave de recuperação e confirmar que a unidade está protegida. O KillerBench faz backup da senha de recuperação e a verifica antes de iniciar a criptografia, e nunca exibe nem registra uma senha de recuperação.

Antes de começar

  • Execute o KillerBench como administrador.
  • A unidade do Windows precisa de um protetor TPM e de um protetor de senha de recuperação. Uma unidade de dados precisa só de uma senha de recuperação.
  • Decida para onde vai o backup da chave de recuperação: um arquivo fora da unidade que você vai criptografar e, opcionalmente, o Active Directory ou o Microsoft Entra ID.

Verificar a unidade

  1. Abra BitLocker e escolha a unidade em Volume.
  2. Deixe a operação em Inspecionar e pressione Executar diagnóstico. O relatório mostra o estado da criptografia, o status da proteção e as identidades dos protetores.
  3. Se o TPM estiver presente mas não estiver pronto, prepare-o antes em Segurança. O KillerBench nunca limpa um TPM.

Adicionar os protetores necessários

  1. Abra Mais ações do BitLocker.
  2. Escolha Adicionar um protetor TPM ou Adicionar uma senha de recuperação, pressione Visualizar, marque Fazer esta alteração na unidade selecionada quando eu pressionar Executar ação e pressione Executar ação.
  3. Faça backup da nova senha de recuperação imediatamente. O KillerBench não a exibe.

Fazer backup da chave de recuperação e criptografar

  1. Pressione Localizar protetores de recuperação e selecione o protetor de senha de recuperação.
  2. Digite um caminho completo para o arquivo de backup, fora da unidade que você vai criptografar.
  3. Escolha Criptografar, escolha o método de criptografia e marque Fazer backup da chave de recuperação selecionada e iniciar a criptografia quando eu selecionar Executar diagnóstico.
  4. Pressione Executar diagnóstico. O KillerBench grava o backup, verifica-o e inicia a criptografia uma única vez.
  5. A criptografia continua em segundo plano. Execute Inspecionar mais tarde para confirmar que a unidade aparece totalmente criptografada e com a proteção ativada.

Backup no Active Directory ou no Entra ID

Em Mais ações do BitLocker, escolha o backup no diretório para o protetor selecionado. O KillerBench informa que o Windows aceitou a solicitação, mas não consegue ler a cópia no diretório, então confirme-a no Active Directory ou no centro de administração do Entra.

Depois que uma unidade de dados é criptografada, Ativar o desbloqueio automático faz com que ela seja desbloqueada quando o Windows inicia. A unidade do Windows já precisa estar totalmente criptografada e com a proteção ativada.

Consulte bitlocker-protectors, bitlocker-protector-add, bitlocker-encrypt e bitlocker-escrow. Cada um tem um comando -recover correspondente para uma solicitação interrompida.

Seções

Diagnósticos é onde todo atendimento deve começar. Cada ferramenta lê o computador e gera um relatório. Nada aqui altera o Windows. A ferramenta padrão, a verificação completa do sistema, executa um amplo conjunto de verificações somente leitura e classifica o que precisa de atenção.

Guias passo a passo: Investigar falhas e telas azuis e Reparar arquivos do sistema.

Ferramentas desta seção

Verifique o computador primeiro e depois leia no relatório o que precisa de atenção e a próxima etapa segura.

Verificação completa do sistema

Inspeciona 49 áreas de diagnóstico e depois avalia todas as receitas de recuperação de serviços instaladas, junto com as receitas de manutenção, DHCP, impressão, Defender, hora e WMI. As verificações podem levar vários minutos. O reparo automático é opcional e exige as evidências atuais, os pré-requisitos do computador e as verificações de dependências próprios de cada receita. Reparos elegíveis podem renovar concessões DHCP ausentes, liberar trabalhos de impressão na fila, ressincronizar o relógio, atualizar as assinaturas do Defender, restaurar serviços elegíveis e reparar corrupção confirmada do Windows. Serviços automáticos parados podem ser iniciados depois que a janela de inicialização e as dependências forem verificadas. Um serviço de inicialização sob demanda parado não é alterado quando o estado ocioso é a única evidência; fluxos de trabalho mais específicos só podem exigi-lo quando evidências atuais do recurso justificam o início. Tipos de inicialização, definições de tarefas, relatórios, despejos, assinaturas de eventos, credenciais, configurações de canais, política de firewall e configurações gerenciadas são preservados. Instantâneos históricos, de backup e de transferência são somente leitura. O conteúdo dos despejos não é aberto. A inspeção do bit sujo não agenda reparo nem reinicialização. Este fluxo de trabalho não instala atualizações, não altera drivers, não exclui arquivos e não faz um teste completo de hardware.

Sinais vitais

Captura a memória disponível, a integridade dos discos informada pelo provedor e o status da proteção do BitLocker, e relaciona os sinais vitais atuais com problemas de dispositivos, histórico de confiabilidade, registros de erros de hardware, evidências de falhas, desligamentos inesperados e resultados do Diagnóstico de Memória do Windows. Indicadores de reinicialização, espaço livre no disco do sistema, elevação e configuração do serviço de atualização continuam visíveis. Senhas de recuperação não são coletadas. Este fluxo de trabalho não executa reparos. O resultado combinado não é um teste completo de hardware, software ou estabilidade.

Histórico de confiabilidade

Lê os registros do Monitor de Confiabilidade do Windows dos últimos 14 dias junto com os erros recentes de Aplicativo e os eventos de desligamento inesperado, e retorna uma única conclusão histórica delimitada. Registros históricos não estabelecem a integridade atual nem a causa raiz. Nenhum reparo é selecionado e nenhum aplicativo, serviço ou configuração é alterado.

Desempenho da inicialização

Lê os metadados dos eventos de desempenho de inicialização e desligamento do Windows dos últimos 14 dias, mantendo só a identidade do provedor e campos numéricos de duração delimitados, e os relaciona com os indicadores de reinicialização pendente compatíveis. Caminhos, nomes de processos, contas e o restante da carga útil dos eventos são removidos antes de salvar as evidências. Registros históricos de degradação não identificam um gargalo atual nem autorizam alterações de inicialização, serviços, aplicativos, drivers, tarefas, energia, reinicialização ou política.

Histórico de erros de hardware

Lê o histórico do Windows Hardware Error Architecture e do diagnóstico de memória dos últimos 14 dias, os problemas atuais de dispositivos Plug and Play, a integridade dos discos físicos e os contadores de confiabilidade do provedor, e retorna uma única conclusão de hardware delimitada. Os registros precisam ser relacionados com a carga útil, os diagnósticos do firmware e os testes de hardware do fabricante. Nenhum componente com defeito nem causa raiz é deduzido, nenhum reparo é selecionado, e nenhum hardware, firmware, driver, disco, pool, volume, arquivo, serviço, energia, reinicialização ou configuração é alterado.

Histórico de instalação de drivers

Lê o final guardado do histórico de instalação de dispositivos do Windows SetupAPI, relaciona as seções com falha às identidades Plug and Play exatas atuais e retorna uma única conclusão delimitada. Seções históricas do log não comprovam que um dispositivo ainda está presente nem que uma falha é atual. Nenhum driver é instalado, removido, revertido ou atualizado.

Pontos da Restauração do Sistema

Lista até 256 pontos da Restauração do Sistema disponíveis, revisa a elegibilidade explícita para criação e retorna uma única conclusão de prontidão delimitada. O inventário não comprova que a proteção está ativada em todos os volumes nem que uma restauração vai funcionar. Nenhum ponto de restauração é criado, excluído ou aplicado durante o diagnóstico.

Ambiente de Recuperação do Windows

Lê a configuração atual do Ambiente de Recuperação do Windows com o REAgentC, relaciona um local habilitado com o disco e a partição exatos atuais e retorna uma única conclusão de prontidão delimitada. O reparo automático opcional pode habilitar uma configuração existente desabilitada e depois verificar o estado informado. A imagem de recuperação não é baixada, movida nem substituída, nenhuma inicialização de recuperação é iniciada e o Windows não é reiniciado. O status habilitado e a presença da partição não comprovam que a imagem de recuperação consegue iniciar ou reparar este PC.

Ativação do Windows

Lê o status atual da licença do Windows sem coletar chaves do produto completas ou parciais, guarda os metadados anonimizados dos eventos de aviso, erro e críticos da Proteção de Software dos últimos sete dias e retorna uma única conclusão operacional delimitada. A carga útil dos eventos é removida antes de salvar as evidências. Registros históricos continuam como contexto quando a licença atual aparece como Licenciado. Nenhuma ação de ativação, chave do produto, token, licença, conta, serviço ou política é selecionada. O status do provedor e o histórico de eventos não comprovam direito de assinatura, acessibilidade do servidor de ativação, integridade do repositório de tokens, validade futura nem causa raiz.

Usar a ferramenta BitLocker

O código de saída 0 significa que a visualização ou o resultado verificado foi bem-sucedido; 1, um erro de inicialização, de entrada ou do diário; 2, que os argumentos não foram reconhecidos; 3, bloqueado, com falha ou não verificado; 4, que um fluxo de trabalho precisa de reinicialização antes de poder verificar; e 130, que você o interrompeu.

Execute killerbench-cli sem argumentos para imprimir esta lista no seu próprio computador.

Uma ação informa que está bloqueada

Um resultado bloqueado significa que a ação solicitada não pôde prosseguir. Leia a mensagem e o diário para saber se ela parou antes do envio ou depois de uma etapa anterior. Não presuma que uma operação parcialmente concluída foi revertida. Os motivos de pré-requisito mais comuns estão abaixo.

  • É necessário acesso de administrador. Feche o KillerBench e inicie-o de novo com Executar como administrador.
  • Não pode haver reinicialização pendente. O Windows tem uma reinicialização pendente. Reinicie o computador e execute a ação de novo.
  • Há uma política gerenciada. A política de grupo ou o gerenciamento de dispositivos controla a configuração. Altere-a por lá.
  • As evidências mudaram. Algo mudou entre a primeira verificação e a verificação final. Execute a ferramenta de novo para ler o novo estado.

Uma solicitação anterior precisa de reconciliação

O KillerBench encontrou um registro pendente de uma solicitação interrompida. Execute a mesma ação de novo. Ela verifica o que aconteceu e informa o resultado real sem repetir a solicitação. Na linha de comando, use o comando -recover correspondente, por exemplo killerbench-cli bitlocker-auto-unlock-recover.

Uma verificação mostra Incompletas ou Desconhecido

Não foi possível ler as evidências, muitas vezes porque o KillerBench não estava sendo executado como administrador ou um serviço do Windows estava indisponível. O KillerBench informa isso com honestidade em vez de presumir que o computador está íntegro.

Onde os arquivos ficam

Diários, registros pendentes e evidências salvas ficam em %LOCALAPPDATA%\KillerBench. Cada ação protegida tem a própria pasta. Guarde-os quando precisar de um registro do que mudou.
